# 设计计划模板

```markdown
# <结果>

对照版本：<commit，或不可用>

## 证据链

- 表面：`<路径、路由或渲染状态>`
- 问题：<直接观察到的现象>
- 设计证据：`<文档、样式、token、组件、模式或渲染表面>`
- 所有者：`<路径或表面>`
- 范围与受影响表面：`<路径或表面>`
- 不确定：<无，或需要验证的点>

## 设计决定

<写清范围恰当的一处改动，以及它如何消掉根问题。>

## 复用

- `<token、变量、组件、变体或组合>`
- 范例：`<路径>`

若必须新增原语：写明现有系统为何表达不了、原语放在哪、哪些调用方应该共用。

## 改动

1. `<精确路径或表面>`
   - 改：<可以照着做的行为或结构>
   - 保留：<仍然有效的行为或识别度>
   - 验证：<能观察到的结果>

## 范围

- 继承：<会接到这次改动的调用方>
- 核对：<可能受影响、需要看一眼的调用方>
- 排除：<有效例外，以及无关工作>

## 验证

- 产品：<任务与期望结果>
- 界面：<相关路由、状态、极端内容、交互和视口>
- 系统：<确认复用得当，没有另起一套平行模式>
- 仓库：`<精确检查命令>` → <期望结果>

## 停止条件

- 若 <关键假设失败、所有权变化或范围必须扩大> 就停。

## 设计文档

- 接受并验证之后：<要记下的决定和落点，或无>
```
