# 自由画布

给对话里的探索一个现场：模型改源码，画布让内容可看、有名字、可移动、可引用。用项目现有框架、组件、字体、token、主题和访问控制。先找有没有现成画布，不要再造一个。

这是开发用的工作台，默认不进产品主导航。要做成产品功能时转 `project-spec`。

## 怎么开始

- 读仓库规则、路由、组件 API、主题、token 和测试。
- 改范围、加依赖、改共享代码或公开画布之前先问。
- 隔离是否安全不清楚时先问。绝不挂载不安全的预览。
- 其余选合理默认，不要让用户重复已经说清的要求。
- 画布代码放一起。相机和摆放与预览、测试数据、注册表分开。不要做成一套框架。
- 先做一个安全的实时预览、一个能读的名字、一个单独的移动手柄，确认能挂上。
- 再加注册表和用户要的内容，然后才是复制名字、相机、已有主题和保存布局。

## 内容留在源码

注册表是画布条目的类型化列表。每条有稳定 ID、唯一可读名字、组件、安全测试数据、初始位置和尺寸。

- 注册表要好找。加一条不能要求改相机或手势代码。
- 增加、复制、改名、删除都通过改源码。不要做运行时编辑器或删除快捷键。
- 成员、名字、尺寸和实现留在源码。浏览器存储不能凭空造出或藏起条目。
- 绝不把存储里的字符串或模型回复当代码执行。
- 后续请求改现有工作台。保住名字、ID、位置和无关实验。
- 指代不清就问是哪一条。
- 「再试一版」保留原件。新 ID、唯一可读名字、独立状态。
- 「改这一版」原地改。只有用户要求才改名。
- 删除只去掉点名的注册表项。共享组件和无关工作留下。
- 比较一个特性时，其他数据、内容、尺寸和全局主题保持不变。
- 更宽的备选要写明布局差异。用户没要求就不要做完整变体矩阵。
- 新增项放在附近的空白，用测量到的边界。用相机揭开它们，不重排已有项，也不重置视图。
- 内容变高、改变尺寸、刷新之后位置还在。允许有意重叠。重叠时移动手柄仍可点到。

## 工作台保持安静

- 铺满视口，纯色背景，预览边界很淡，固定控件尽量少。
- 用每条预览自己的尺寸。不要把内容拉进过大的框。
- 不要装饰卡片、横幅或背景图案。
- 名字放在预览上方，例如 `价格卡 · 紧凑`。不要用含糊名字或看不懂的 ID 当标签。
- 名字有按钮行为，但不要按钮样式，也不要单独的复制按钮。
- 点击、Enter、Space 或触摸时复制精确名字。不复制 ID、代码或 URL。
- 悬停和键盘焦点时说明「会复制」。只有悬停不能复制。触摸不能依赖悬停。
- 有剪贴板 API 就用。只有成功后才短暂提示「已复制」。提示期间名字仍可见。
- 剪贴板失败或不可用时，给出可选中的文字。不要崩溃，也不要假装成功。
- 标签旁有可见的移动手柄。点标签是复制，不是拖。手柄移动条目，不移动内容本体。
- 按当前缩放把指针位移换算成画布坐标。
- 焦点在手柄上时可用键盘移动。有可见焦点和可访问说明。
- 画布导航表面和手柄用 `cursor: default`，手势进行中也是。
- 预览内部保留文字、链接、输入和缩放光标。不要把光标规则套到所有后代。
- 包含平移、缩放、适配全部、重置相机、一个全局主题选择，以及已保存的布局。
- 明暗和已命名主题用项目现有主题 API，同一主题作用到画布控件、预览、菜单和对话框。
- 不要发明主题，也不要按预览各设主题。项目不支持主题就省略选择器并说明。
- portal 主题走不通公开 API 时，报告限制。
- 除非用户要求，否则不要缩放手柄、宽度预设、对比排列、绘图、连线、目录、属性编辑器、多选、吸附和撤销。
- 用户要移动端或桌面预览时，尺寸写在注册表里。

## 保住真实内容

- 经公开 API 复用生产组件。不改它们的源码、导出、hook 或样式来迁就画布。
- 生产组件不依赖画布代码。
- 实验留在画布里。只有用户要求才挪进生产。
- 挂载前用合成数据、模拟服务、安全 provider 和已有回调，挡住真实请求和写入。
- 不用个人数据或生产凭证。
- 隔离不了就省掉预览并说明。iframe 或另一个文档本身不等于隔离。
- 保住点击、输入、选字、快捷键、焦点、内部滚动和触摸。
- 禁用和只读示例保持真实行为。
- 移动条目、复制名字、换主题、改相机时，不要重挂预览，也不要清掉输入。
- 预览草稿不必活过刷新。
- portal 留在原生根，按屏幕尺寸。定位和模态焦点交给库。
- 只在需要时用公开容器 API。不同缩放下核对 portal 对齐和可点区域。
- 变换弄坏 portal 时，报告限制或提议单独的预览文档。
- 不补丁库、浏览器 API、预览 DOM 或 portal 根。
- 导航（含 portal 内链接）在画布宿主里定义。不改组件链接或路由内部。
- 指向画布条目的链接揭开目标，而不是滚动页面。
- 其他导航不能执行真实的项目操作，也不能悄悄丢掉工作台。

## 手势与预览输入分开

- 从空白处拖拽平移。
- Ctrl/Meta + 滚轮，以及触控板捏合，在空白和预览上方都能缩放。
- 滚轮或捏合时，指针下的画布点保持不动。
- 提供放大、缩小按钮和键盘。它们的缩放中心是视口中心。
- 两个方向都平滑，不跳、不漂。条目位置和预览状态保留。
- 浏览器允许时支持触摸平移和捏合。
- 焦点在画布壳上时，键盘可以移动相机。
- 所有画布控件有可见的键盘焦点。
- 适配全部和重置相机固定且在条目跑出屏幕时仍可到达。
- 布局稳定后再适配全部。适配真实边界，含标题、手柄和边框。不重排条目。
- 重置只动相机。成员、位置、主题和草稿保留。
- Space + 主键拖拽，以及中键拖拽，可以在画布任何地方平移，包括预览上方。
- 明确的平移手势优先于移动条目和复制名字。
- 平移之后不要激活控件、复制标签、跟随链接，或触发中键自动滚动。
- 焦点在可交互控件或可编辑区域时，不要武装 Space 平移。
- 保留 Space 激活按钮和标签。保留预览里的方向键、Escape 和撤销。
- 模态 portal 不参与画布手势。保住它们的焦点、遮罩和原生控件。
- 双指触控板平移覆盖空白和预览。
- 嵌套滚动区在该方向还能滚时，让它滚。否则平移画布。
- 带修饰键的滚轮和捏合优先于滚动路由。其他 portal 滚动保持原生。
- 取消事件和触摸限制只用于画布自己的手势。不要关掉预览内容上的原生输入。
- 一根手指通过手柄移动条目。预览里普通的单指操作保留。
- 双指平移和捏合不能破坏预览的原生手势。浏览器做不到就报告，不要因此禁用预览触摸。
- 记录每个交互归哪一个手势。取消、窗口失焦、标签隐藏时清掉按住的键。
- 处理指针数量变化、指针取消和丢失捕获。
- 拆除时释放捕获，清掉监听、观察器、定时器和动画帧。
- 路由激活期间，给文档视口和画布滚动边界加上 `overscroll-behavior-x: none`。
- 挡住 Chrome 的横向历史滑动。只加一层内包装不能保证挡住。
- 拆除时恢复原来的文档样式。保留内部横向滚动、前进后退和导航快捷键。
- 不要用 `pushState` 困住历史，不要补丁浏览器 API，不要留下永久的全局处理函数。
- 页面原生滚动不能带动画布。屏外键盘焦点靠移动相机揭开。
- 相机坐标、条目位置和缩放必须是有限且有界的数。
- 指针和滚轮更新合并成每帧最多一次变换写入。
- 进行中的手势值不要放进会导致预览重渲染的组件状态（Vue 的大响应式对象、React 的组件级 state 都算）。移动相机不能让预览重渲染。
- 只更新画布自己的包裹。手势期间不改预览 DOM，也不改会影响布局的位置。
- 缓存测量边界。内容、尺寸或布局变化时一起刷新。
- 测量时忽略临时渲染占位。
- 不要每帧测量每个预览，也不要交替读写布局。
- 手势结束后再保存，或有上限的防抖。不要每个指针事件都写存储。
- 拆除时尽量安全地冲掉未保存的写入。
- 避免昂贵效果、永久的逐预览合成提示，以及为移动一条就做整张画布的工作。
- 只有性能分析有证据时才加虚拟化或记忆化。屏外卸载会丢掉输入，并弄坏焦点或 portal。

## 保存布局，不保存内容

- 只保存相机、受支持的主题偏好，以及按稳定注册表 ID 索引的位置。
- 用一份小的带版本文档，键同时区分项目和画布。
- 尊重应用已有偏好和无关的主题配置。不要再造一套主题偏好。
- 保存的布局使用同样的数值界限。用项目约定校验 ID、受支持主题、文档大小和位置数量。
- 渲染当前注册表的每一条。应用有效的已存位置，忽略过期 ID。
- 新条目总是显示。立刻使用源码里的当前名字和尺寸。
- 数据损坏、存储不可用、配额错误时画布仍能用。
- 已知旧格式只保留对当前 ID 有效的相机、主题和位置。
- 丢掉已存的成员关系、名字、尺寸、副本，以及隐藏或已删除状态。未知版本用安全默认。
- 绝不存储或反序列化可执行组件、密钥、令牌、账号数据或表单内容。
- 除非用户明确要求，不保存预览草稿或交互历史。

## 诚实测试和报告

跑仓库要求的检查。确认路由能挂上、import 能解析、控制台无错误。看 diff，确认没有意外的生产改动。

新建画布或改了控制器时，测上面的每一项行为。只改内容时，测受影响的行为，不必重建控制器。包含多种缩放、多种视口，以及带着已有保存布局刷新。

触摸测试用真机。Chrome 历史滑动用真实触控板和一条真实历史记录。

在空白和预览上方两个方向都测缩放，锚点不跳不漂。按钮和键盘缩放绕视口中心。触控板平移覆盖预览内容和嵌套滚动区，包括滚到头。

没跑过的测试不能写成通过。编译和读源码不能证明浏览器行为。设备测不了和浏览器限制要写出来。

声称流畅之前，对一份有代表性内容的画布做性能分析，而不是一个空例子。记录预览数量、浏览器、设备和在平移、缩放、移动期间的测量。追查长任务、反复布局、同步写存储和预览重渲染。只改预览时，不必重建或分析未改的控制器。

报告：

- **改了什么：** 路径、目的、局部实验、共享组件改动、新预览的准确名字。
- **跑过的检查：** 测了什么、结果。
- **不行或没测：** 限制、省略和原因。
- **自行决定的默认：** 没问就选定的。
