# 视觉评审

新界面或改版做完代表性页面、自己看过真实画面之后，用这份标准审一次。已有产品只是对齐现有规范时，不打分，改走 `improve-ui` 的证据门槛；下面第 2 节只作补充。

没有隔离的、能看图的执行者时，自己按同样的标准看，交付写「未独立评审」。看不了画面不打分。

交接时给当前画面、用户任务、设计边界、北极星那一句。存量项目再给不能改的品牌、字体、主色和组件。不给源代码，也不给为自己辩护的说明。

## 1. 新界面与改版

先看会不会直接否决。下面任一成立，就把它列为第一条，总分不超过 7，并标明不可发布。功能走通不能抵消：

- 目标视口、实际字体、100% 阅读尺寸下文字读不清
- 主视觉仍像等着替换的占位
- 把产品名换成无关产品，首屏仍然原样成立（沿用品类基线不算）
- 三秒后说不清主角，或找不到主动作

然后：

1. 把首屏缩到大约 480px 宽看三秒。像某一年的通用模板或组件库默认皮肤，就写出来。
2. 一句话指出品类，以及这是有意偏离还是套了模型的默认版式。
3. 用户要求了动效时，看该动的地方动了没有，手感是否只剩一律淡入上移。用户没要求动效时，不因为「没有动画」扣分。
4. 问题按影响从大到小，最多 5 条。每条写位置、看到了什么、修完要能验收的结果。
5. 骨架仍是默认模板，或主视觉远低于同品类时，第一条写「重做」，点名区块。不要在被否定的骨架上列修补建议。
6. 写一行「保留」：修改时不能磨掉的那一处辨识度。
7. 给出 1 到 10 分，并写离下一档还差什么。

| 分数 | 门槛 |
|------|------|
| 10 | 挑不出可观察的缺陷，至少一处是这个品类里少见的好做法 |
| 9 | 主流程、异常和细节都成立，只剩小处可提升 |
| 8 | 方向鲜明，主流程走得通，没有阻断和数据丢失；缩略图仍认得出特征 |
| 7 | 方向成立，但有一处会让人走错或卡住，或首屏仍是明显的默认模板 |
| 5–6 | 能看出方向，但骨架是默认模板，或主流程多处卡住 |
| 1–4 | 主任务走不通，或有重叠、裁切、看不清 |

会丢数据、走不通、假装已经成功，比任何视觉问题都优先扣分。任务走通不等于 8 分。

第一条是「重做」时，回到方向卡重定那一块的骨架，不逐条补样式。意见来回横跳且画面没有变好，就保留当前最合适的一版并说明取舍。

## 2. 已有界面

不要想象一套新风格。对照该产品现有的色板、间距和组件。

- 指出用了规范以外的颜色、字号、圆角，或明明有组件却又手写了一个。
- 在规范范围内，指出最影响完成度的三处：层级、对齐、留白、多余的线和框。
- 不打分。不建议更换整体品牌色或字体。
