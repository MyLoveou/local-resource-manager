# 修可访问性

优先最小改动。能用原生元素解决的，不要再加 ARIA。不要为了本技能更换组件库。

对比度是否够，在本技能判定。配色刻度跟项目已有色板，不另造一套。命中区域与键盘归这里；圆角、阴影、动效归 `better-ui`。

## 怎么用

做按钮、链接、输入、菜单、对话框、页签、表单、快捷键、焦点、只有图标的控件、仅悬停才出现的内容时，套用下面的规则。

点名文件时输出：引用原片段、一句话说明影响、一处小改法。

## 优先级

| 优先级 | 类别 | 影响 |
|--------|------|------|
| 1 | 可访问名称 | 关键 |
| 2 | 键盘 | 关键 |
| 3 | 焦点与对话框 | 关键 |
| 4 | 语义 | 高 |
| 5 | 表单与错误 | 高 |
| 6 | 播报 | 中高 |
| 7 | 对比度与状态 | 中 |
| 8 | 媒体与动效 | 中低 |
| 9 | 改动边界 | 关键 |

## 1. 可访问名称

- 每个可交互控件都有可访问名称。
- 只有图标的按钮用 `aria-label` 或 `aria-labelledby`。
- `input`、`select`、`textarea` 都有标签。
- 链接文字本身要说清去哪，不要用「点击这里」。
- 装饰性图标 `aria-hidden`。

## 2. 键盘

- 不要把 `div` 或 `span` 当成按钮，除非补齐完整键盘行为。优先改成 `button`。
- 可交互元素都能用 Tab 到达。
- 键盘焦点必须看得见。
- 不要用大于 0 的 `tabindex`。
- 适用时，Escape 关闭对话框或浮层。

## 3. 焦点与对话框

- 打开的模态要困住焦点。
- 关闭后焦点回到触发它的控件。
- 打开时把初始焦点放进对话框。
- 打开对话框不要让页面意外滚动。

## 4. 语义

- 优先 `button`、`a`、`input`，不要用 `role` 仿造。
- 用了 `role`，就必须带上该角色要求的 ARIA。
- 列表用 `ul`/`ol` 加 `li`。
- 不要跳级标题。
- 表格有表头时用 `th`。

## 5. 表单与错误

- 错误用 `aria-describedby` 连到字段。
- 必填要能被读出来。
- 无效字段设置 `aria-invalid`。
- 辅助说明关联到输入。
- 禁用提交时要说明原因。

## 6. 播报

- 关键表单错误使用 `aria-live`。
- 加载用 `aria-busy` 或状态文字。
- 关键信息不能只放在 toast 里。
- 可展开控件使用 `aria-expanded` 和 `aria-controls`。

## 7. 对比度与状态

- 文字和图标对比度要够读。
- 只有悬停才有的操作，必须有键盘等价物。
- 禁用态不能只靠颜色区分。
- 去掉焦点环时，必须换成别的可见焦点。

## 8. 媒体与动效

- 图片有正确的 `alt`：有信息就写，装饰性就空字符串。
- 有语音的视频在相关场景提供字幕。
- 非必要动效尊重 `prefers-reduced-motion`。
- 不要自动播放有声媒体。

## 9. 边界

- 只改相关处，不顺手重构。
- 原生语义已经够用时，不要再加 ARIA。
- 用户没要求就不要迁移 UI 库。
- 菜单、对话框、组合框优先用项目里已有的可访问组件，不要手写一套。

## 常见改法

```html
<!-- 只有图标的按钮 -->
<button aria-label="关闭"><svg aria-hidden="true">...</svg></button>

<!-- 用原生按钮，不要用 div 假装 -->
<button type="button">保存</button>

<!-- 错误连到字段 -->
<input id="email" aria-describedby="email-err" aria-invalid="true" />
<span id="email-err">邮箱格式不对</span>
```

先修关键项：名称、键盘、焦点、边界。报告时引用原片段。
