# 笔记模板

> 每条笔记先写 frontmatter，跨项目检索靠它：

```yaml
---
project: <仓库目录名>
type: 踩坑 | 技术 | 设计 | 学习向 | 图解
tags: [<标签1>, <标签2>]
date: YYYY-MM-DD
---
```

> 四种类型挑一个；骨架一致，差别在「原理」那节的写法。

## 踩坑

```markdown
# <N> · 踩坑-<现象>

> 一句话：<什么现象>，根因是 <根因>，改法是 <改法>。

## 现象

- 什么时候出现：<触发条件>
- 表现：<报错原文 / 错误结果 / 卡在哪一步>
- 误导性线索：<一开始以为是什么，为什么错>

## 根因

<机制层面：谁在什么时候做了什么，导致这个结果>

## 改法

| 改哪 | 怎么改 | 为什么够 |
|------|--------|----------|
| <文件/配置> | <动作> | <覆盖了根因的哪一环> |

## 怎么验证

```bash
<一条能复现的命令>
# 预期：<输出>
```

## 边界

<同类问题还会出现在哪；什么情况下这个改法不适用>

## 延伸

<一条：相关概念 / 官方文档章节>
```

## 图解版（可选叠加）

在任意类型上加一节，用 Mermaid 画结构与时序；图只画「读者会问的那个问题」，不要复刻架构图：

````markdown
## 一图看懂

```mermaid
sequenceDiagram
  participant U as 用户
  participant A as 应用
  participant D as 数据层
  U->>A: 请求
  A->>D: 查询
  D-->>A: 结果
  A-->>U: 响应
```

读图要点：<这张图想让人记住的一件事>
````
