# 设计方向

上级入口是 `skills/oil-ui/SKILL.md`。这里只在方向还没定时读。

## 认品类，拆标杆

先写产品事实。再认品类：用户已经期待什么样的结构和完成度。后面的调性只能在这块地板之上偏离，并说出产品理由。

产品参考和交互参考分开。不要合成一句「干净、好用」。

1. 写出品类，选风格最鲜明的两三家，不一定是最有名的。
2. 对着真实首屏拆产品参考，每条写「是什么样、为什么」。只有「干净、留白、一种强调色」就是没拆到位。拿不到画面就标明「未看图，凭记忆」，字体、色彩、主视觉标为待验证。
3. 单独拆核心动作：触发、对象变化、反馈、下一状态。产品参考里没出现的交互，不得凭它的视觉去推断。
4. 用本产品的受众、内容和任务逐条决定留什么、换什么。

拆的时候分清三样：

- **基线**：用户已经会找的结构，例如商店的购物车在右上角。沿用，不必重学。
- **套路**：这个品类人人都用的默认版式。用户要求比较多个方向时，至少有一个要打破它。
- **撞脸**：字体、配色、主视觉和图标都和某个标杆一样，只换了名字。不允许。

## 先删减

为首屏和每个关键状态各写两句：唯一主角是什么，唯一主动作是什么。然后写一条 `主动作 → 主角或对象变化 → 状态反馈`。动作必须有可见结果。

## 先定调性

用五个刻度，每个都写出依据：

| 刻度 | 两端 | 在画面上看什么 |
|------|------|----------------|
| 能量 | 安静 ↔ 喧闹 | 饱和度、对比、元素是否碰撞 |
| 完成度 | 粗粝 ↔ 精致 | 边缘、颗粒、对齐有多严 |
| 密度 | 疏 ↔ 密 | 留白、叠层、网格 |
| 分量 | 轻 ↔ 重 | 字重、色块面积、阴影硬度 |
| 严肃度 | 活泼 ↔ 庄重 | 圆角、插画、动效幅度 |

证据已经锁定调性时，候选都留在这个调性里，靠构图和主视觉拉开。不要为了「平衡」塞一个安静极简的保底方案。最常见的失败，是证据指向喧闹或粗粝，交付却变成米色卡片、柔和阴影和大留白。

### 模糊词必须翻译

| 模糊词 | 翻译成什么 |
|--------|------------|
| 高级 | 哪一种高级：字体对比、分隔方式、间距尺度、色相数量 |
| 精致 | 公差：对齐到什么网格、阴影几级、色相几种 |
| 克制 | 强调色占画面的上限、色相数量、动效幅度 |
| 史诗 | 展示字多大、主图占多少、明暗对比多强 |
| 简洁 | 密度档位，以及删掉什么、为什么删 |

翻译不出可观察决定的词，从理由里删掉。

## 概念从具体的东西来

每个方向用一个引擎，内容来自这个产品的证据：

- **材质 × 环境**：一种材质放在一个具体环境里，推出光照、边缘和阻尼。
- **一个场景**：有时间、地点和光线。适合情绪型工具。
- **角色**：一个具体性格，决定字体和动作。
- **一场有真实联系的设计语法**：借语法，不贴图案。
- **另一个领域的一两个手法**：页面仍是原来的体裁，不把那个媒介的部件一件件搬来。
- **打破一个具体常规**：改比例、阅读顺序或操作组织，同时保持可读、可学、功能完整。刺眼的颜色不算引擎。

宿主能派一个没有本任务历史的执行者时，只给它事实包，不给主执行者已经想好的风格，收回至少三个概念再选。不能派时自己做，并标明「未独立生成概念」。默认对外只留一个方向。

## 定色彩

品牌、实物和内容画面是第一来源。没有现成主色时，不要把隐喻里的黄铜、木纹、暗房直接当成主色，不同产品会撞进同一组颜色。

写出至少三层：底、强调，以及选中、描边、禁用。黑白灰加一种强调色也算完整身份。几个方向不要只分成「一个亮、一个暗、一个暖」。

落地时一个视图一个强调色，新颜色先用项目已有色板。见 `baseline-ui`。

## 定首屏

唯一主角、主动作和概念确定后，先画灰度，再做有细节的首屏。灰度里分不清主角或状态变化，就重写结构。

- **说服型**（落地页、品牌页、发布页、展览页）：从 [direction-persuasion.md](direction-persuasion.md) 的骨架里选。骨架定好再写文案。
- **来看内容、挑东西、干活**（列表、文档、工具、后台）：首屏就是第一排内容或工作区。顶栏紧凑，第一排内容要出现在首屏里。不放解释这个页面的段落。
- **两种都有**：以用户最常来做的事为准。横幅不能把第一排内容推出首屏。

## 方向卡

每项写具体选择，不填形容词。

| 字段 | 要写到的程度 |
|------|----------------|
| 北极星 | 一句能指导取舍的话 |
| 主角与主动作 | 唯一主角、唯一主动作、动作后的可见结果；其他动作怎样降级 |
| 调性 | 五个刻度及依据 |
| 产品参考与取舍 | 品类、看过的画面、沿用什么、换掉什么 |
| 交互参考与取舍 | 触发到下一状态；没有真实证据就标明 |
| 生成引擎 | 哪一种，来自这个产品的什么 |
| 首屏骨架 | 用户来看什么；灰度里每块占多大、阅读从哪开始 |
| 页面结构 | 首屏以下怎么组织 |
| 字体 | 展示、正文、数字各用什么。项目已有字体时用已有的，不另换字族，除非用户要求 |
| 色彩 | 至少三层，加上它来自产品的什么 |
| 主视觉 | 哪张图或哪种排版承担识别 |
| 图标与控件 | 沿用项目已有的一套。没有时写明形状和手感 |
| 核心交互 | 入口、对象变化、反馈、关键状态 |
| 记忆点 | 集中发力的一两处 |
| 资产与技术 | 素材从哪来、现有依赖够不够。超出现有条件就换方案 |
| 放弃什么 | 这个方向主动不要的常见做法 |

## 差异检验

即使只有一个方向，也要过这些门槛。不过就重写，不降成陪跑：

- 说得清它如何适配受众、品牌和任务。
- 从主动作到结果有路径。
- 素材和技术在现有依赖里做得到。
- 主视口的输入和反馈已经写清。

用户要求多个方向时，再并排比首屏骨架、字体、色彩、主视觉。任意两个方向这四项里至多一项相同。比灰度线框，不比形容词。描述不同、线框却是同一结构，就重选骨架。至少有一个方向不用这个品类的默认版式，但基线仍然保留。

做出来之后眯眼看明暗块面。都是左边一大块、右边一小块，就重做骨架，不靠换颜色补救。

和拆过的标杆并排看，撞脸就重做。沿用基线不算撞脸。

## 北极星、记忆点、参考

北极星落成全页的关系：每屏谁是主角，次要信息怎样退后，哪一处用反差突出主操作。新元素不能加强同一个意图，就不加。

记忆点通常是一次动作的结果，不是整页都用力。去用户会做的动作、任务完成的那一下、空状态里找。让被影响的东西当场变化。跟产品无关的票据、打印机、老游戏机不要套。

参考先说清是借关系、当质量底线，还是精准还原。借鉴时取的是关系，不照搬对方的模块和文案。参考里没有的标题区和装饰，不要替它补上。
