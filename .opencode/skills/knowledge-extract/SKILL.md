# 知识提炼

把「聊过的偏好」和「代码里反复出现的做法」变成可执行资产。写入前必须用户确认（规则 `knowledge-extract`）。

## 何时跑

- 用户明确要求记住 / 提炼 / 写成规则或 Skill
- 同一约束在本会话说了 ≥2 次
- OpenSpec propose/apply/archive 结束前的例行检查
- 用户当场拍板（「就用这个」「方向改成…」）→ 压缩进 `decisions.md`
- 摸底代码时发现稳定惯例但基线/facts 没有

## 步骤

1. **收集候选**（分开三类，不要混）

| 来源 | 怎么取证 |
|------|----------|
| 会话 | 用户原话 + 出现次数；引用原句 |
| 代码 | 路径 + 短摘录（命名、分层、错误处理、目录） |
| 失败 | 踩过的坑与正确命令 |

2. **分级（先提案，不直接改 alwaysApply）**

| 级别 | 条件 | 建议落点 |
|------|------|----------|
| 基线约束 | 一句话不变量、禁止项、验收命令 | `openspec/baseline.md` |
| 实现/方向 | 已确认现状与往哪走 | `docs/product/facts.md` |
| 一次拍板 | 决定/为何/不选（≤8 行） | `docs/product/decisions.md` |
| 全局规则 | 所有任务都该遵守 | 本平台目录 `rules/` |
| 项目规则 | 仅某栈/某目录 | 带 `globs` 的规则 |
| Skill | 有触发词、有步骤、会跳过就出错 | 本平台目录 `skills/<id>/SKILL.md` |

3. **输出【规范待决断】**，等用户勾选

```markdown
## 规范待决断 · {日期}

### 候选 1
- 原话/证据：…
- 建议级别：浓缩基线 / 事实基线 / 决策记忆 / 全局规则 / 项目规则 / Skill
- 建议文本：（≤15 行）
- 不建议：因为只出现一次 / 与现有规则重复 / 像网上教条未经你确认
```

4. **用户确认后**才写入对应文件；改实现或方向则同步 `facts.md`。未确认保持 pending。会话结束有拍板：先追加 `decisions.md`（压缩），facts 变更须确认。

## 反模式

- 把 ECC/网上通用清单直接 alwaysApply
- 把未核实的业务状态机写进基线
- 不经确认改规则
- 只在聊天里「我记下了」而不落文件
- 把整段对话贴进 `decisions.md`（必须压缩）
