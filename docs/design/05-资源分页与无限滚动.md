# 05 · 资源分页与无限滚动

> 状态：**已落地，学习向正文见 [06](06-虚拟滚动与分页.md)**（2026-09-07 实现后）  
> 本文保留实现前的契约草案，便于对照「计划 → 落地」。  
> 关联：里程碑 [00](00-路线图与里程碑.md) MS2 · 虚拟网格已落地 · 列表 API 现为 `GET /library/resources`（offset/limit，无 total）  
> 范围：后端分页契约 + 前端「触底加载」+ 已有 TanStack 虚拟网格的衔接

## 1. 问题与目标

虚拟滚动只减少 **DOM 节点**。当前图片页把 200 条 mock **一次性放进内存**；真实库会到万级，必须再拆一层 **后端分页窗口**。

| 层 | 解决什么 | 不解决什么 |
|----|----------|------------|
| 虚拟滚动（已有） | 同时挂载的卡片数量（约几十） | 一次拉多少 JSON、内存里有多少条 |
| 分页 + 触底加载（本文） | 按页向 SQLite 取数、滚近底部再取下一页 | 跳转到第 N 页、滚动条按全库总高度拖到底 |

**用户能感知的行为**

1. 进入图片/视频页 → 立即请求第一页并渲染。
2. 向下滚，距离已加载列表底部还剩约 **2 行** → 请求下一页，追加后虚拟列表变长。
3. 没有更多 → 不再请求；失败 → 提示且可重试。

**明确不做（本次）**

- 按滚动条位置「跳页」（`count = total` 的窗口加载）。用户说的是触底加载，滚动条高度只反映 **已加载条数**。
- 游标分页（`created_at,id`）。本地库排序简单、插入不频繁，MVP 用 offset。
- 封面 HTTP 文件服务 / `file://` 映射（仍用 `coverPath` 字段；空则占位）。
- 目录扫描入库（MS1）。本设计假定库里已有资源；实现阶段可用一次性 seed 或现有 `POST /resources` 造数。

## 2. 两层模型（必读）

```
SQLite 全库（例如 5 万条）
        │  GET 每页 pageSize 条
        ▼
前端 items[]（已加载窗口，例如 80 → 160 → 240 …）
        │  TanStack 只挂载可视 + overscan
        ▼
DOM（约 20～40 张卡片）
```

触发下一页的依据是 **已加载数组的下标**，不是全库 total：

```
lastVisibleIndex >= items.length - prefetchThreshold
且 hasMore && !loading
→ GET offset = items.length
```

`prefetchThreshold` = `columns * 2`（提前两行，避免滚到空白再等网络）。

## 3. 后端契约

### 3.1 打破现有返回值

当前：`GET /resources` → `Resource[]`。前端无法区分「就这么多」和「还有下一页」。

改为 **分页信封**（破坏性，无线上客户端，允许直接改）：

```http
GET /library/resources
  ?type=image|video          # 可选；类型页必传
  &status=active|trashed|lost  # 类型页默认 active；回收站 trashed
  &limit=80                  # 默认 80，范围 1～200
  &offset=0                  # 默认 0
  &sort=createdAt            # 可选，MVP 只实现 createdAt
  &order=desc                # 默认 desc
```

响应 JSON（camelCase，`ApiModel`）：

```json
{
  "items": [ { "id": 1, "type": "image", "title": "...", "coverPath": null, "status": "active" } ],
  "total": 1280,
  "limit": 80,
  "offset": 0,
  "hasMore": true
}
```

| 字段 | 含义 |
|------|------|
| `items` | 本页资源，顺序与 `sort/order` 一致 |
| `total` | 当前过滤条件下的总数（用于「已加载 x / 共 y」和 `hasMore`） |
| `limit` / `offset` | 回显请求，便于调试 |
| `hasMore` | `offset + len(items) < total`（后端算好，避免前端 off-by-one） |

单条资源仍用现有 `Resource`。列表 **不强制 join files**；封面只用 `coverPath`。

### 3.2 仓储

在现有 `ResourceRepository.list` 上增加同步条件的 `count(...)`。  
同一套 `type` / `status` where；`ORDER BY created_at DESC, id DESC`（加 `id` 保证翻页稳定，避免同时间戳乱序重复/漏条）。

建议一次请求里 `COUNT` + `SELECT` 两次 SQL，不搞窗口函数。`idx_resources_type` / `idx_resources_status` 已有；复合索引可后续加：`(type, status, created_at DESC, id DESC)`，万级可后置。

### 3.3 默认与校验

| 项 | 值 |
|----|-----|
| 默认 `status` | 不传则 **不滤状态**（保持现状）；类型页前端 **显式传 `active`** |
| 默认 `limit` | 80（约 2～4 屏，按 4 列×3/4 卡片估） |
| `offset` | 必须 `>= 0`；`offset >= total` 时 `items=[]`，`hasMore=false` |
| 空库 | `items=[]`，`total=0`，`hasMore=false`，HTTP 200 |

### 3.4 详情/创建

`GET /resources/{id}`、`POST /resources` **不变**。

## 4. 前端架构

```
views/Image（Video 同构）
        │  type=image, status=active
        ▼
hooks/useResourcePage.ts          ← 分页状态机（可复用）
        │  getResources(query)
        ▼
infrastructure/http/resources.ts  ← GET /library/resources
        │
        ▼
VirtualGrid                       ← 仍是dumb：只吃 items
        │  emit near-end
        ▼
loadMore()
```

**依赖方向**：View → hook → http → domain。网格不发请求。

### 4.1 领域类型

```ts
export interface ResourcePageQuery {
  type?: ResourceType
  status?: ResourceStatus
  limit?: number
  offset?: number
  sort?: 'createdAt'
  order?: 'asc' | 'desc'
}

export interface ResourcePage {
  items: Resource[]
  total: number
  limit: number
  offset: number
  hasMore: boolean
}
```

`VirtualGridItem` 由页面映射：`id: String(resource.id)`，`title`，`coverUrl: resource.coverPath ?? ''`。

### 4.2 Hook 状态机

```ts
items: Resource[]
total: number
hasMore: boolean
loading: boolean      // 任意在途请求
loadingMore: boolean  // 仅追加（首屏用 loading）
error: unknown | null
```

| 动作 | 行为 |
|------|------|
| `reset()` / 进入页面 / 筛选变化 | `items=[]`，`offset=0`，拉第一页，**替换** items |
| `loadMore()` | 若 `!hasMore \|\| loading` 则 return；`offset=items.length` 追加；按 `id` 去重 |
| 失败 | 首屏失败：items 空 + 错误态；加载更多失败：**保留已有 items**，`error` 供底栏重试 |

并发：进行中的请求用递增 `requestId`（或 `AbortController`）。筛选变化时作废旧响应，禁止把过期页 append 进新列表。

### 4.3 VirtualGrid 增量

网格仍不感知后端。增加：

| 项 | 说明 |
|----|------|
| `emit('nearEnd')` | 当前可视最大 `index >= items.length - threshold` |
| `threshold` | 默认 `columns * 2`，也可由父级传入固定数字 |
| 底部插槽（可选） | 父级用 `loadingMore` / `!hasMore` 画「加载中」或「没有更多」 |

触发要 **防抖/加锁**：同一滚动帧可能连续满足条件，hook 内 `loading` 已挡住；网格侧同一 `items.length` 只 emit 一次更稳（记录 `lastEmittedLength`）。

`virtualizer.count` **继续等于 `items.length`**，不要设成 `total`。否则滚动条会按全库高度拉长，中间出现空洞，变成未承诺的跳页加载。

### 4.4 页面

- 首屏：`loading && items.length===0` → 居中加载（或 EmptyGuide「加载中」）。
- 空库：`!loading && total===0` → 「暂无图片，请先添加目录」（扫描未做时可写「暂无数据」）。
- 错误：`notify.fromError`；区域可点重试。
- `nearEnd` → `loadMore()`。
- 列表高度：沿用现有 Image 页 `height: 100%` + 网格内部滚动。

视频页同一 hook，只换 `type: 'video'`。

## 5. 交互与边界

```
进入页面
  → loading 首屏
  → 成功：渲染第 1 页
  → 内容不满一屏：mounted 后再判一次 nearEnd（避免「装不满却不加载」）
  → 失败：错误 + 重试

滚动
  → nearEnd 且 hasMore：底部细条「加载中」，追加后列表变长
  → 追加失败：Toast + 底部「点击重试」（不丢已加载）

滚到头
  → hasMore=false：底部文案「已加载全部 {total} 项」
```

| 边界 | 处理 |
|------|------|
| 翻页时库被写入（将来扫描） | offset 可能重/漏；MVP 接受；后续再上 cursor |
| 快速连打 nearEnd | `loading` 互斥，单飞 |
| 切图片 ↔ 视频 | 销毁 hook 或 `reset`，互不串数据 |
| 列数变化 | 只影响 threshold 与布局，不重新请求 |
| HTTP 超时 10s | 走现有 axios timeout + 将来 `notify.fromError` |

## 6. 时序

```
用户打开 /image
  GET .../resources?type=image&status=active&limit=80&offset=0
  ← { items[80], total: 1280, hasMore: true }
  渲染 80 条；DOM ~ 一屏 + overscan

用户下滚接近第 80 条
  GET ...&offset=80
  ← { items[80], total: 1280, hasMore: true }
  items 变为 160；虚拟列表 count=160

… 直至 offset+len >= total，hasMore=false
```

## 8. 验收

- [ ] `GET /library/resources?limit=2&offset=0` 与 `offset=2` 条数、顺序衔接，无重复 id
- [ ] 响应含 `total`、`hasMore`；最后一页 `hasMore=false`
- [ ] 图片页首屏只打一页请求，不一次拉全库
- [ ] 滚到距底部约两行出现第二次请求，`offset=limit`
- [ ] 虚拟列表 DOM 数量不随已加载 500+ 线性涨到 500 个节点
- [ ] 不满一屏但 `hasMore` 时会自动再请求，直到撑满或没有更多
- [ ] 断后端：首屏错误可重试；已有列表时加载更多失败不丢数据
- [ ] 空库友好空态，不转圈死循环（`hasMore=false` 禁止再请求）
