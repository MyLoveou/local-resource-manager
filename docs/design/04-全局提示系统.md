# 04 · 全局提示系统

> 状态：**设计定稿（仅设计，待实现）**（2026-09-03）  
> 关联：架构全景 [经验总结/01](../经验总结/01-架构全景.md)、日志系统 [03-日志系统.md](03-日志系统.md)、WCH 消费反馈 [wch-ui.md](../requirements/features/wch-ui.md) §7

## 1. 背景与目标

桌面应用中存在大量 **用户可感知操作**（保存、扫描、打开外部程序、删除、HTTP 请求等）。若各页面自行 `console.error`、`alert` 或直调 Naive UI，会导致：

- 文案与样式不一致
- 错误信息暴露技术细节或堆栈
- HTTP 层与 UI 层循环依赖
- 难以统一调整时长、位置、去重策略

**目标**：提供渲染进程内统一的 **全局提示系统（Notify）**，作为所有用户反馈的唯一出口。

| 原则 | 说明 |
|------|------|
| 统一入口 | 业务/UI 禁止散落 `alert` / 直调 `useMessage`；用户可感知结果一律走 `notify` |
| 分层清晰 | 领域定义类型与文案规则；application 封装 Naive UI；infrastructure 只打日志 |
| 非阻塞优先 | 短反馈 → Message；需详情/操作 → Notification；不可逆 → Dialog |
| 与日志分工 | **日志**给开发者排障；**提示**给终端用户可读结论，不暴露堆栈/token |
| 可组合 | `fromError()` 将 Axios/未知错误映射为用户文案 |
| 可扩展 | WCH 消费失败、下载完成、扫描进度等复用同一 API |

**明确不做（当前设计范围）**

- 操作系统级通知中心（Windows Toast / macOS Notification Center）
- 多语言 i18n
- 提示历史面板 / 消息 inbox
- 渲染进程外的后端主动推送（WebSocket）

## 2. 提示形态与选用决策

### 2.1 四种形态

```
                    用户操作 / 系统事件
                            │
            ┌───────────────┼───────────────┐
            ▼               ▼               ▼
      需用户确认？      需标题+详情+按钮？   长耗时无进度？
            │               │               │
           是              是              是
            │               │               │
            ▼               ▼               ▼
        Dialog          Notification    LoadingBar
        （模态阻塞）     （右下角卡片）   （顶栏进度条）
            │
           否 ──► 一句话可表达？ ──是──► Message（顶部 Toast）
                            │
                           否 ──► Notification
```

### 2.2 形态对照表

| 形态 | API | Naive UI | 位置 | 阻塞 | 默认时长 | 典型场景 |
|------|-----|----------|------|------|----------|----------|
| **Toast** | `notify.toast.*` | `message` | 顶部居中 | 否 | 3s（error 5s） | 保存成功、复制完成、轻量失败 |
| **Push** | `notify.push()` | `notification` | 右下角 | 否 | 4.5s（可 0=常驻） | 外部打开失败+跳转设置、下载完成 |
| **Confirm** | `notify.confirm()` | `dialog` | 屏幕中央 | **是** | 用户操作前 | 移入回收站、彻底删除、覆盖 |
| **Loading** | `notify.loading.*` | `loadingBar` | 顶栏 | 否（视觉占用） | 手动结束 | 批量扫描、批量抓取启动 |

### 2.3 选用规则（必须遵守）

| 条件 | 选用 | 反例（禁止） |
|------|------|--------------|
| 成功/失败一句话，无后续动作 | Toast | 用 Dialog 弹「保存成功」 |
| 需要「打开设置」等操作按钮 | Push | Toast 里塞可点击链接 |
| 删除/覆盖/退出等不可逆 | Confirm | Toast + 5s 后自动执行 |
| 请求 >300ms 且暂无进度条组件 | LoadingBar | 无任何反馈 |
| 后台任务完成（用户未在该页） | Push | 静默忽略 |
| 开发调试信息 | `logger.debug` | `notify.toast` 打堆栈 |

### 2.4 与 LRM / WCH 场景映射

| 场景 | 形态 | 级别 | 示例文案 |
|------|------|------|----------|
| 元数据保存成功 | Toast | success | 「已保存」 |
| 获取概览失败 | Toast 或 Push | error | 「获取首页概览失败：无法连接后端」 |
| 外部打开失败 | Push | error | 标题「无法打开」+ 按钮「配置打开方式」 |
| 移到回收站 | Confirm | warning | 「确定移入回收站？可在回收站中恢复。」 |
| 彻底删除磁盘文件 | Confirm | error | 「将永久删除文件，此操作不可恢复。」 |
| 目录扫描进行中 | Loading | — | 顶栏 indeterminate → finish |
| 下载任务完成 | Push | info | 「下载完成：xxx.mp4」 |
| 抓取无匹配 | Push | warning | 「未找到匹配元数据，可手动填写」 |
| 用户取消 Confirm | — | — | **不提示、不记日志** |
| 后端启动失败（主进程） | Push | error | 「后端服务启动失败，请查看日志」 |

## 3. 视觉与交互规范

### 3.1 布局示意

```
┌──────────────────────────────────────────────────────────────┐
│ ▓▓▓▓▓▓▓▓▓▓ LoadingBar（indeterminate / determinate）         │  ← 顶栏下方
│  [✓ 已保存]  [✕ 操作失败]     ← Message，最多 3 条，stack 向下   │
│  顶栏 ToolBar：搜索 | 添加目录 | 扫描                           │
├──────────┬───────────────────────────────────┬───────────────┤
│ 菜单      │ 主内容                             │ 信息面板       │
│          │                                   │               │
│          │                                   │               │
└──────────┴───────────────────────────────────┴───────────────┘
                                              ┌─────────────────┐
                                              │ Notification    │
                                              │ 无法打开         │
                                              │ 未找到命令…      │
                                              │ [配置打开方式]   │  ← 右下，最多 5 条
                                              └─────────────────┘
```

### 3.2 样式约定

| 项 | 约定 |
|----|------|
| 组件库 | Naive UI 默认主题，不单独做 Toast 皮肤 |
| 级别色 | success / warning / error / info 与 Naive 一致 |
| 文案语言 | 简体中文；句子简短，单条 ≤ 80 字 |
| 详情长度 | Push `description` 截断至 200 字 |
| 敏感信息 | 禁止展示 token、完整堆栈、Windows 用户目录以上的内部路径可缩短显示 |
| 图标 | 使用 Naive 内置级别图标，不额外引入 |
| 音效 | 默认无；后续可在设置中开关 |

### 3.3 交互细节

| 行为 | 说明 |
|------|------|
| Message  hover | 暂停倒计时（Naive 默认） |
| Notification  action | 最多 1 个主按钮；点击后关闭通知并执行回调 |
| Dialog 默认按钮 | 取消（次要）/ 确定（主要）；destructive 时确定按钮 `type: error` |
| LoadingBar | `start()` 后必须 `finish()` 或 `error()`，避免常驻；`finally` 中调用 |
| 连续相同文案 | 1s 内 dedupe（P1 可选，key = level + title + description） |
| 路由切换 | Toast/Push 不自动清除；LoadingBar 路由切换时 `error()` 并记 warn 日志 |

## 4. 架构与模块落点

### 4.1 分层依赖

```
views / components / hooks / stores
              │
              │  import { notify } from '@/application/notify'
              ▼
application/notify/              ← 对外唯一 Facade
    ├── index.ts                 notify 对象
    ├── discrete.ts              createDiscreteApi 单例
    └── mapHttpError.ts          错误 → 用户文案
              │
              ▼
domain/notify.ts                 类型与常量（无 UI 依赖）
              │
infrastructure/http/client.ts    仅 logger.warn，不 import notify
infrastructure/logging/logger.ts 与 notify 无反向依赖
```

**依赖铁律**

- `domain/notify.ts` 不依赖 Vue、Naive、axios
- `infrastructure/*` 不依赖 `application/notify`
- HTTP 错误是否弹 UI 由 **调用方** 或 **application 层 HTTP 包装** 决定

### 4.2 与主进程 / IPC（设计）

主进程事件（后端启动失败、端口占用）需进入渲染进程提示：

```
主进程                          渲染进程
  │                               │
  │  ipcMain: 'app:notify'        │
  │  { level, title, description }│
  ├──────────────────────────────►│ preload 暴露 onAppNotify
  │                               │ → notify.push(payload)
```

| 事件源 | 通道 | 渲染侧处理 |
|--------|------|------------|
| 后端 spawn 失败 | `app:notify` | Push error |
| 后端 health 超时 | `app:notify` | Push error + 「重试」action（P1） |
| 用户触发的 IPC 错误 | 调用方 await 后 `fromError` | Toast/Push |

IPC payload 类型复用 `domain/notify.ts` 的 `PushPayload`（不含 function，action 用 actionId 映射表）。

### 4.3 初始化时机

```
main.ts
  ├── initNotify()          // createDiscreteApi，早于 mount
  ├── createApp(App)
  ├── use(pinia).use(router)
  ├── registerAppNotifyIpc() // 监听主进程 app:notify（P1）
  └── mount('#app')
```

使用 Naive **`createDiscreteApi`**，无需在 `App.vue` 嵌套 Provider 即可在任意 TS 模块调用。

## 5. 领域类型（domain/notify.ts）

```typescript
/** 提示级别 */
export type NotifyLevel = 'success' | 'info' | 'warning' | 'error'

/** Push 操作按钮（渲染层映射 onClick） */
export interface PromptAction {
  label: string
  onClick?: () => void
  /** IPC / 跨模块时用稳定 id 代替函数 */
  actionId?: string
}

/** 富提示选项 */
export interface PushOptions {
  level: NotifyLevel
  title: string
  description?: string
  duration?: number       // ms；0 = 常驻
  action?: PromptAction
  /** dedupe 键；缺省为 level+title+description */
  key?: string
}

/** 确认框选项 */
export interface ConfirmOptions {
  title: string
  content: string
  level?: 'default' | 'warning' | 'error'
  positiveText?: string   // 默认「确定」
  negativeText?: string   // 默认「取消」
}

/** fromError 选项 */
export interface FromErrorOptions {
  /** 上下文，如「获取首页概览」→ 标题「获取首页概览失败」 */
  context?: string
  /** true 时不弹 UI，仅返回 MappedError */
  silent?: boolean
  /** 强制用 Push 而非 Toast */
  asPush?: boolean
}

/** mapHttpError 输出 */
export interface MappedError {
  title: string
  description?: string
  level?: NotifyLevel     // 默认 error
}

/** IPC 主进程 → 渲染（无函数） */
export interface PushPayload {
  level: NotifyLevel
  title: string
  description?: string
  duration?: number
  actionId?: string
}
```

## 6. 对外 API（application/notify/index.ts）

```typescript
import { notify } from '@/application/notify'

// ── Toast（Message）──
notify.toast.success(content: string): void
notify.toast.info(content: string): void
notify.toast.warning(content: string): void
notify.toast.error(content: string): void

// ── Push（Notification）──
notify.push(options: PushOptions): void

// ── Confirm（Dialog）── 返回 true=确定 false=取消
notify.confirm(options: ConfirmOptions): Promise<boolean>

// ── Loading（LoadingBar）──
notify.loading.start(): void
notify.loading.finish(): void
notify.loading.error(): void

// ── 错误映射 ──
notify.fromError(error: unknown, options?: FromErrorOptions): MappedError
```

### 6.1 默认配置

| 项 | 值 |
|----|-----|
| message `max` | 3 |
| message `placement` | top |
| message `duration` | 3000（error: 5000） |
| notification `max` | 5 |
| notification `placement` | bottom-right |
| notification 默认 `duration` | 4500 |
| dialog 默认 | 确定 / 取消 |

### 6.2 调用示例

```typescript
// 保存成功
notify.toast.success('已保存')

// HTTP 错误（调用方 catch）
try {
  overviewData.value = await getOverview()
} catch (e) {
  notify.fromError(e, { context: '获取首页概览' })
}

// 外部打开失败 + 跳转设置
notify.push({
  level: 'error',
  title: '无法打开外部程序',
  description: '未找到命令：cursor',
  action: { label: '打开设置', onClick: () => router.push('/settings') },
  duration: 0,
})

// 删除确认
if (await notify.confirm({
  title: '移到回收站',
  content: '可在回收站中恢复此资源。',
  level: 'warning',
})) {
  await trashResource(id)
  notify.toast.success('已移入回收站')
}

// 扫描 Loading
notify.loading.start()
try {
  await scanDirectory(path)
  notify.loading.finish()
  notify.toast.success('扫描完成')
} catch (e) {
  notify.loading.error()
  notify.fromError(e, { context: '目录扫描' })
}
```

### 6.3 可选：`withNotify` 包装（P1）

```typescript
// application/http/withNotify.ts
await withNotify(() => getOverview(), { context: '获取首页概览' })
```

仅用于高频、固定文案的请求；复杂 UI 逻辑仍在调用方 catch。

## 7. 错误映射规则（mapHttpError.ts）

| 条件 | title | description |
|------|-------|-------------|
| 无 response + 非 timeout | `{context}失败` | 无法连接后端服务，请确认应用已正常启动 |
| `ECONNABORTED` | `{context}失败` | 请求超时，请稍后重试 |
| HTTP 401 / 403 | `{context}失败` | 无访问权限（优先后端 detail） |
| HTTP 404 | `{context}失败` | 请求的资源不存在 |
| HTTP 5xx | `{context}失败` | 服务异常，请查看日志或稍后重试 |
| FastAPI `detail`  string | `{context}失败` | detail 原文 |
| FastAPI `detail`  array | `{context}失败` | 拼接 `msg` 字段 |
| `Error` 其他 | `{context}失败` | error.message（过滤敏感词） |
| 未知 | `{context}失败` | 发生未知错误 |

**fromError 行为**

1. `mapHttpError(error, options)` → `MappedError`
2. `silent: true` → 只返回，不弹 UI
3. 有 `description` 且 `asPush` 或 description > 40 字 → `push`
4. 否则 → `toast.error(title)` 或 `toast.error(description)`（优先 description 短句）
5. 开发态：`logger.debug` 保留原始 error，不向用户展示堆栈

## 8. 与日志系统协作

| 事件 | 日志 | 提示 |
|------|------|------|
| HTTP 4xx/5xx | `logger.warn('[http] METHOD url -> status')` | 调用方 `fromError` |
| 用户取消 Confirm | 不记 | 不提示 |
| 外部命令失败 | `logger.warn('[consume] …')` | `push` error |
| Toast 展示 | 不记 | — |
| Loading 未关闭就路由跳转 | `logger.warn('[notify] loading leaked')` | `loading.error()` |
| 开发调试 | `logger.debug` 可含 stack | 禁止 |

## 10. 反模式（Code Review 检查项）

| 反模式 | 正确做法 |
|--------|----------|
| `views` 内 `import { useMessage } from 'naive-ui'` | `import { notify } from '@/application/notify'` |
| `infrastructure/http/client` 里 `notify.fromError` | 拦截器只 `logger.warn`，调用方 catch |
| 删除前不 confirm | `await notify.confirm()` |
| catch 后静默 | 至少 `fromError` 或 intentional `silent: true` 注释 |
| `alert()` / `window.confirm()` | 禁止 |
| Loading 无 finally | try/finally 保证 finish/error |
