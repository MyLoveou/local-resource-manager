# 监视目录配置（前端接入）· 需求

> 状态：**已定稿**（2026-10-07 用户确认「按此实现」）
> Feature ID：`watch-source-dirs`
> 上游：D-20260927-01（常驻监视源目录口径）；`shared/utils/file_watcher.py` 监视器已实现按类型分发

## 1. 问题

文件监视器已支持按资源类型分组注册目录（后端 env 配置）。但用户无法在界面里配置：加哪个目录、监视哪些类型。需要前端设置入口 + 后端持久化 + 运行时重配。

## 2. IN / OUT

| 做 | 不做 |
|----|------|
| 设置弹窗新增「监视」页签：按类型增删监视目录 | 扫描根管理、目录预扫 |
| 保存后持久化（settings KV）并**即时重配**监视器 | 监视结果 UI（导入已有）、增量 schedule/unschedule |
| 原生目录选择器选目录（复用 `selectDirectory` IPC） | 监视事件的去重/导入逻辑（已存在） |
| env 配置时锁定 UI（沿用刮削凭证模式） | 环境变量与 DB 合并 |

## 3. 用户故事与验收

- **US-W.1** 打开设置 → 「监视」页签 → 看到按类型的目录列表（初始为空或已有）
- **US-W.2** 对「图片」点「添加目录」→ 原生选目录 → 出现在图片列表中
- **US-W.3** 删除某目录 → 从列表移除
- **US-W.4** 点「保存」→ 后端持久化 + 监视器按新配置重启 → toast 成功
- **US-W.5** env 配置了 `BACKEND_WATCH_DIRS` → UI 提示「由环境变量提供」且禁用编辑
- **US-W.6** 目录不存在时保存 → 400 提示，前端不落表

验收：
- [ ] GET /settings 返回 `watch.dirs`（camelCase）
- [ ] PATCH /settings/watch 保存并重配；重配后向监视目录放文件能触发对应类型事件
- [ ] envLocked 生效
- [ ] 目录不存在 400
