> 状态：**L1 已定稿**（2026-10-25）
> Feature ID：`smart-import`
> 关联：[by-type/video.md](../../by-type/video.md) · [by-type/anime.md](../../by-type/anime.md) · [by-type/image.md](../../by-type/image.md) · [import-directory-scan](../import-directory-scan/需求.md)
> L3：[实现方案.md](实现方案.md)（S1：名称清洗 + 建议审阅）；S2 / S3 待各切片启动时再出。

## 1. 背景

用户原话（2026-10-25）：

> 对于我导入的一个番剧，可以根据目录进行智能导入和修改名称，去掉一些不必要的文字，但是要保留源名称，这只是一类资源导入时的动作……如果导入的是图片资源，是否可以清洗名称，给出一个基本分类然后供我选择是否采纳，但是需要考虑批量导入的情况（图片资源），然后考虑可扩展性，后续其他资源导入的时候。

所以本需求**不是**「导入时自动跑 AI」，而是：**导入时按资源类型产出一组可解释、带置信度的建议，由用户选择是否采纳**。AI 只是这些建议的来源之一。

## 2. 现状（带代码证据）

| 现状 | 证据 |
|---|---|
| 导入链路无任何 AI | `import_service` 阶段为 `hash → copy → probe → cover → thumb → index`，其中 `index` 是**入队刮削**，不是 AI |
| CLIP 建索引已全自动 | `settings.auto_index=True`，`main.py` 每 30 秒补索引——本需求不需要重做 |
| 名称解析极窄 | `video_naming.parse_video_name` 只支持 **bilidown 合集命名** + **用户自定义正则**（命名组 `title/author/bv/ep/date`），其余一律返回 `None` |
| 无置信度、无解释 | `ParsedVideoName` 只有字段，没有 score / reason / 采纳状态 |
| 只覆盖系列作品 | `parse_video_name` 只在 `_run_series` 里被调用；单文件视频、图片都没有 |
| 图片无分类建议 | 导入后分类为空，只能手动选 |

结论：缺的不是模型能力，是一层**建议 + 审阅**的机制，以及更通用的名称清洗规则。

## 3. 核心概念

### 3.1 导入动作（ImportAction）

按资源类型注册的「导入时可做的事」。每个动作独立判定、独立产出建议，互不依赖。

| 动作 | 适用类型 | 产出 |
|---|---|---|
| `clean-title` | 视频 / 番剧 / AV | 清洗后的标题 |
| `parse-episode` | 番剧 / AV | 季号、集号 |
| `guess-category` | 图片 / 视频 | 分类建议 |
| `flag-ai-analysis` | 图片 | 是否值得跑 VLM 分析 |

**扩展要求**：新增资源类型（漫画、小说、游戏、模型）只需注册一个动作模块，**不得改导入主流程**。

### 3.2 建议（Suggestion）

每条建议至少包含：

- `field`：`title` / `category` / `season` / `episode` / `aiAnalysis`
- `value`：建议值
- `confidence`：0–1
- `source`：`rule` / `scrape` / `ai` / `history`
- `reason`：一句人话，说明「为什么这么建议」，例如「去掉了 `[VCB-Studio]` 与 `[Ma10p_1080p]`」
- `status`：待定 / 已采纳 / 已忽略

### 3.3 源名称必须保留

采纳任何改名建议后，**原始文件名/目录名必须仍可查**。这是硬要求：清洗是展示层，不是破坏性改写。

### 3.4 「是否需要 AI 介入」的判定

按顺序判断，**能用规则就不用 AI**：

1. 规则能给出 `confidence ≥ 0.85` → 走规则，不标 AI
2. 规则拿不到，或 `confidence < 0.5`，且该类型在用户白名单内 → 产生 `aiAnalysis` 建议
3. AI 不可用（模型未装 / Ollama 未启动）→ **不产生该建议，也不报错**，静默降级
4. 用户关闭总开关 → 完全不产生 AI 建议

## 4. 范围

### IN

- **名称清洗**：去掉字幕组、分辨率、编码、音轨、CRC、网站水印等噪音，保留真正标题
  - 例：`[VCB-Studio] Sousou no Frieren [01][Ma10p_1080p][x265_flac]` → `Sousou no Frieren`
  - 例：`[Lilith-Raws] 葬送的芙莉莲 - 01 [Baha][WEB-DL][1080p][AVC AAC][CHT][MP4]` → `葬送的芙莉莲`
- **系列解析**：从目录名与文件名提取季号、集号；多集目录正确挂到季/集
- **分类建议**：图片与视频给出 1–3 个候选分类，带置信度，可批量采纳
- **AI 介入判定**：如上 §3.4，产出 `aiAnalysis` 建议而不是直接跑
- **审阅与批量采纳**：见 §5
- **源名称保留**：见 §3.3

### OUT

- 自动重命名磁盘上的文件（只改库内标题，磁盘文件名不动）
- 训练自定义分类器 / 微调模型
- 视频抽帧后送 VLM（后续另立项）
- 导入时自动执行 VLM 分析（本需求只产出建议，执行仍由用户在 AI 页确认）
- 修改用户既有分类体系或自动创建大量分类

## 5. 批量导入的交互要求

图片批量导入是主要场景（一次可能几百张），所以：

- 导入向导在现有 6 阶段后增加一个 **「审阅」** 阶段，展示本次导入产生的建议
- **导入任务不暂停**：审阅发生在任务跑完之后；关掉向导也能从「待审阅」面板继续
- **按建议值分组**而不是逐条罗列：同一分类建议的 N 张合并成一行（`动漫截图 · 128 张`）
- **置信度分档默认勾选**：
  - `≥ 0.85` 默认勾选（可一键全部采纳）
  - `0.5 – 0.85` 展示但不勾
  - `< 0.5` 折叠或只提示
- 单次审阅条目超过阈值（建议 200）时分页，避免一次渲染上千行
- 用户可以「全部忽略」，走当前行为（标题=文件名，分类=空）

## 6. 验收（每条可判定）

**名称清洗**

- V1 `[VCB-Studio] Sousou no Frieren [01][Ma10p_1080p][x265_flac]` 清洗结果为 `Sousou no Frieren`，且 `reason` 说明去掉了哪几段
- V2 `[Lilith-Raws] 葬送的芙莉莲 - 01 [Baha][WEB-DL][1080p][AVC AAC][CHT][MP4]` 清洗结果为 `葬送的芙莉莲`
- V3 纯中文标题（如 `夏日海边 01.mp4`）不被误伤，清洗后仍为 `夏日海边`（或 `夏日海边 01`，取决于 `titleWithEp` 开关）
- V4 清洗规则命中但结果为空串时，**回退原名称**，不得产生空标题

**系列解析**

- V5 `葬送的芙莉莲/Season 1/` 下的 `01.mkv`、`02.mkv` 挂到第 1 季第 1/2 集
- V6 同一作品第二季目录 `Season 2/` 挂到第 2 季，不与第一季冲突

**分类建议**

- V7 图片导入后给出分类建议，且**默认不采纳**（`< 0.85` 不勾选）
- V8 采纳后资源分类即为该值；忽略后分类保持为空

**批量**

- V9 一次导入 100 张图片，审阅阶段按建议值分组显示，不是 100 行
- V10 一键采纳高置信建议后，只有 `≥ 0.85` 的条目被应用

**源名称**

- V11 采纳改名后，原始名称仍可读取（API 可查），并在信息栏可见
- V12 未采纳任何建议时，源名称与标题相同，不产生额外噪音

**AI 判定**

- V13 规则给出高置信时不产生 `aiAnalysis` 建议
- V14 规则低置信且命中白名单时产生 `aiAnalysis` 建议，但**不自动执行**
- V15 模型未安装时不产生 `aiAnalysis` 建议，导入不报错

## 7. 已确认决策（2026-10-25 拍板）

| # | 问题 | 结论 |
|---|---|---|
| Q1 | 源名称落点 | **新增 `resources.source_name` 列**（迁移 `0032`），可查可导出可回滚 |
| Q2 | 图片分类建议来源 | **规则优先**（目录名/文件名 + 已有分类词表），拿不到高置信才走 **CLIP 零样本** |
| Q3 | 审阅时机 | **两处都要**：导入向导内就地审阅 + 导入后仍可回来补 |
| Q4 | 置信阈值与分档 | `≥0.85` 默认勾选、`0.5–0.85` 展示不勾、`<0.5` 折叠（L3 可调） |
| Q5 | 目录名与文件名冲突 | **目录名优先**（番剧目录通常比单集文件名干净） |

范围补充：按用户举例（番剧），本需求覆盖 **视频 / 番剧 / AV / 图片**；漫画、小说、游戏、模型的动作留扩展点，不在本次实现。

「两处都要」的落地口径：导入任务**不暂停**。向导里的审阅是在任务跑完、向导未关闭时就地进行；导入后的入口是「待审阅」面板。两者操作的是**同一批已持久化的建议**，因此不会出现两边状态不一致。

## 8. 已知约束

- 清洗只改**库内标题**，不动磁盘文件名（与「换封面不替换主文件」同类，见 baseline 不变量 13）
- 建议必须**可解释**：没有 `reason` 的建议不展示
- 任何动作失败不得中断导入；失败即「无建议」
- 批量场景必须限流，不得一次渲染上千条
