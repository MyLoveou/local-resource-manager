# 导入（复制入库）· 需求

> 状态：**已定稿**（2026-09-12 用户确认可按此实现）  
> Feature ID：`import-directory-scan`（change 名沿用；行为已不是「登记根再扫描」）  
> OpenSpec：`openspec/changes/import-directory-scan/`  
> 上游：L1 M1；模块地图「导入各种资源类型」

## 1. 问题

用户要把本机文件变成库里的资源。上一轮草案把「选目录」做成持久根、只记账不复制、前端/后端职责不清，无法支撑后续类型（视频附件、模型、游戏等）。

## 2. 已按你的口令收口（本轮规范）

1. **类型可扩展**：导入是管道 + 按类型的入库策略，本轮只接通图片/视频，其它类型加策略不改壳。  
2. **前端只负责选择**：原生对话框选出路径（文件或目录）后交给后端；渲染进程不做复制、移动、哈希、写库、读像素。主进程只开对话框，也不做入库 IO。  
3. **支持单选文件**；也支持选一次目录。  
4. **选目录 ≠ 选库根**：目录只在这一次导入中作为来源；不登记、不监视、不「立即再扫」。要再导入须再选。  
5. **入库 = 复制进库目录**：库内文件是权威副本；源文件改删不影响库（除非以后做同步，本能力不做）。  
6. **库内物理布局按资源包，不按作者/分类建文件夹**（理由见 §7）。作者、分类、标签是数据库里的组织，不是磁盘层级。  
7. **元数据由后端算**；前端只展示任务进度（已处理/总数、当前阶段）。  
8. **复制/移动/重命名**走共享文件操作模块（一类），导入调用它，不在导入器里直接 `shutil` 散落。  
9. **导入向导分步、先选类型**，再选「文件 / 文件夹」，对话框按类型过滤扩展名。

## 3. 本轮做 / 不做

| 做 | 不做 |
|----|------|
| 向导：类型 → 文件或文件夹 → 进度 → 结果 | 持久资源根、`立即扫描`、启动自动扫、文件监视 |
| 图片/视频策略接通；其它类型在注册表里占位不可选或灰掉 | 小说/音乐/模型/游戏真正入库 |
| 复制到 `{library_store}/{type}/{id}/` 资源包 | 按作者、分类、合集建物理目录 |
| 图片：包内一个主文件；封面用**通用 resolve_cover**（无独立封面则回退 primary） | 为图片再生成一张封面图 |
| 视频：本轮只走通用「建包 + 复制 primary」 | 视频专项：字幕、抽帧封面、时长编码等（后续立项） |
| 包布局封装：通用角色方法 + 按类型策略 | 在设置里配置库根路径 / 迁到 userData |
| sha256 已在库中则不重复建资源、不重复占副本 | 丢失重定位、暂停/十万级任务系统（进度有，暂停无） |
| 新库不自动 seed 演示数据 | 清空用户旧库里的演示行 |

## 4. 用户故事

- **US-I.1** 用户点「导入」→ 选类型「图片」→ 选「文件」→ 选出一张图 → 进度走完 → 图片页出现该卡，封面即该图。  
- **US-I.2** 用户选类型「图片」→ 选「文件夹」→ 选出含图与其它文件的目录 → 只入库图片扩展名；该目录不会出现在任何「根列表」里。  
- **US-I.3** 用户选类型「视频」→ 选一个或多个视频文件（或文件夹）→ 每个视频按通用资源包复制 primary → 视频页出现卡片（无封面、无字幕，直到后续专项）。  
- **US-I.4** 同一文件（相同 sha256）再导入 → 跳过，结果里有去重计数。  
- **US-I.5** 导入进行中能看到进度；取消对话框不发请求。  
- **US-I.6** 未实现的类型在向导里不可用，不假装能导。

## 5. 验收

- [ ] 向导顺序：类型 → 来源（文件/文件夹）→ 系统对话框（扩展名随类型）→ 进度 → 摘要。  
- [ ] 文件模式支持 **单选与多选**（一次 `paths[]`）；文件夹模式选一个目录，递归收集该类型扩展名（跳过 `.` 开头）。  
- [ ] 前端/主进程均不把文件写入库目录；库内新文件只由后端文件模块复制产生。  
- [ ] 无 `library_roots`、无「立即扫描」；同一目录导入两次等于用户又选了一次（第二次因哈希去重）。  
- [ ] 每个新资源有库内目录 `{store}/{type}/{id}/`，路径由**包布局模块**生成，导入器不手写拼接。  
- [ ] 图片 `resolve_cover` 得到 primary；视频本轮无 cover 角色，网格可无封面。  
- [ ] 通用方法至少包括：建包、写入 `primary`、写入 `cover`（供后续类型用）、解析封面。类型策略只声明「用哪些角色」，不复制一套 IO。  
- [ ] 去重键：库内已有相同 sha256 → 不新建资源、不追加副本。  
- [ ] 进度：至少 `queued|running|done|failed`、已处理数、总数、阶段（copy/hash/probe）。  
- [ ] 同时只跑一个导入任务；第二个请求 409。  
- [ ] 导入后网格与首页计数无需重启即可更新。  
- [ ] 新库无演示 seed。

## 6. 契约草案

- `POST /library/imports`  
  body：`{ type: ResourceType, sourceKind: "file"|"directory", paths: string[] }`  
  - `file`：`paths` 为文件路径（至少 1 个）  
  - `directory`：`paths` 恰好 1 个目录  
  - 202 + `{ jobId }`；非法类型/空路径/路径不存在 → 400；已有任务 → 409  
- `GET /library/imports/{jobId}` → 进度与结果计数（`imported` / `skippedDuplicate` / `skippedError` / `total` / `done` / `phase` / `status`）  
- `GET /library/resources/{id}/content`：流式返回该资源 **primary**（库内副本）  
- `GET /library/resources/{id}/files/{fileId}/content`：包内非 primary（本轮视频可无此类文件；接口预留）  
- **禁止**：查询参数传任意磁盘路径让后端当下载器用。

`files.path` 存**库内**相对或绝对路径；源路径可写入 `extra.importSourcePath`（审计），不作去重键。

## 7. 库内存储（类型可扩展）

**原则**：磁盘层级表达「这是一个资源包」，不表达「作者/分类/合集」。后三者可变、可多对多，放 SQLite（标签、分类、合集模块）。

**库根路径本轮不产品化**：代码沿用现有后端数据目录旁的约定即可，**不**做设置项、不迁 `userData`。库位置统一放到以后的「设置」模块。

**封装（通用 + 按类型）**

```
ResourcePackage（通用）
  ensure_dir(type, id)
  put_primary(src)      # 所有类型都有主文件
  put_cover(src)        # 多类型可有封面；图片本轮不调用（用回退）
  put_role(role, src)   # 字幕等后续角色
  resolve_cover()       # 有 cover 角色用它，否则若类型声明 cover_falls_back_to_primary 则用 primary

ImagePackageLayout    → primary；cover_falls_back_to_primary = true
VideoPackageLayout    → 本轮仅 primary；专项（字幕/抽帧封面）后续覆盖 Layout
以后其它类型          → 新 Layout，复用 put_cover / put_role
```

示意（本轮磁盘）：

```
{data}/library/
  image/{id}/primary.jpg
  video/{id}/primary.mkv
```

| 类型 | 本轮写入 | 封面 | 后续专项 |
|------|----------|------|----------|
| 图片 | primary | resolve_cover → primary | 一般不需要独立封面文件 |
| 视频 | primary | 无 | 字幕、抽帧/手传 cover、媒体探测 |
| 以后 | 各 Layout | 能用的走 put_cover | 按类型加角色 |

**为何不按作者/分类分层**：导入时常常没有作者；改分类若要搬盘会把路径写死。资源 `id` 稳定，包内可以加字幕/封面而不改主键。

**去重与副本**：内容寻址（只按 hash 存一份 blob）更省空间，但调试和「打开库目录」更绕。本轮用 **type/id 资源包 + sha256 唯一索引跳过第二次复制**。若以后要 blob 层，包内可改成指针，不改导入向导。

## 8. 分步 UI

1. 打开导入  
2. 选资源类型（本轮：图片、视频；其它灰置）  
3. 选来源：文件 / 文件夹  
4. 系统对话框（类型对应扩展名；文件模式允许单选或多选，一次 `paths[]`）  
5. 进度条/阶段文案（后端 job）  
6. 摘要后关闭；刷新列表  

## 9. 已关闭（2026-09-12 第三轮）

1. 文件模式：**允许多选**（也允许只选一个）。  
2. 视频专项（字幕、封面抽帧、媒体探测等）：**本轮不做**，后续单独实现。  
3. 库目录位置 / `userData`：**本轮不处理**，设置模块统一做。  
4. 旧库演示数据：**不管**（不提供清空演示）。新库仍不自动 seed，以免挡住真导入。  
5. 目录结构：**封装**。通用包操作（建目录、primary、cover、resolve_cover）+ 按类型 Layout；禁止各导入器自己拼路径。
