# 导入（复制入库）· 实现方案

> 状态：**已定稿**（与 OpenSpec `design.md` 同一范围）  
> Feature ID：`import-directory-scan`

## 目标 / 不交付

与 [`需求.md`](./需求.md) 一致。沿用现有四层与 `library` 域，**不**新开「导入微服务」。

## 与现有架构的取舍

| 做法 | 为何 |
|------|------|
| 导入器用例在 `library/application`，类型策略可插拔 | 已有 `ResourceType`；禁止平行再做一套资源模型 |
| 文件 IO 在 `shared/fs`，不在 renderer | 基线：渲染只 HTTP；复制必须本机后端 |
| 不用 `settings.library_roots` | 用户否定持久根 |
| 不在前端 `fs.copyFile` | 用户要求后端承担全部入库 IO |

## 模块边界

```
renderer  向导 + 进度轮询
main      仅 dialog（返回路径字符串）
library   ImportService + TypeImporter
          + ResourcePackage（通用角色）+ 按类型 Layout
shared/fs FileOps（copy/move/rename）
shared/db resources + files（path 指向库内副本）
```

## 数据流

**主路径**  
向导选出 `type + sourceKind + paths`（文件可多选）→ POST → job → 按类型列举候选 → hash/去重 → 插 resource → **Layout + ResourcePackage.put_*** 经 FileOps 复制 → 写 files.role → 图片 cover 用 resolve_cover → 轮询 → bump。

**错误**  
对话框取消：无 HTTP。400 校验失败。409 已有 running。单文件失败记 skippedError，job 继续。job failed 仅在无法起步时。

## 契约落点

见需求 §6。`files.role` 迁移本轮仍做（primary 现在就要；cover/subtitle 给后续类型/视频专项）。库根路径不进设置 API。

## 类型策略（后续怎么加）

新类型：新 Layout（复用 put_cover 等）+ Importer 登记。视频字幕/抽帧只改 Video Layout，不改向导与 FileOps。

## UI

顶栏一个「导入」。向导分步见需求 §8。进度来自 GET job，不在前端算 hash。

## 测试

见 change `tests.md`。核心：临时源文件 → 库目录出现副本且源仍在；二次导入不增副本；目录导入不写 roots。
