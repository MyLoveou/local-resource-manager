## 1. 要解决什么

桌面端已经能进设置、下载抽屉和刮削确认窗，主题也能换内置色和一份本机 css。用户要的是这些界面更好用，并且后端能用 Docker 跑在服务器上、桌面去连远程。另外希望实现、架构和算法更深。后一句还没有可观察的失败，不能直接改代码。

## 4. 范围（本草案）

### 暂定 IN（仅当对应开放问题关闭）

- S1–S3：不改数据模型的界面调整，沿用现有设置 API、下载任务 API、刮削确认 API、主题 localStorage。
- S4：若拍板要做，第一刀只交付「后端容器 + 桌面填写一个后端根地址」。库文件在服务器上还是仍在本机，见 Q4。

### 明确 OUT（除非另开需求并改拍板）

- 多用户账号、权限、在线播放站、资源分享。
- 把主题做成设计系统资产库或主题市场。
- 把整库改成微服务，或为 S6 新建第二套后端。
- 未指名的「更深算法」：以图搜图、向量检索、自动打标、换 FTS 以外的检索引擎。
- 远程爬虫农场。D-20260919-09 的远程索引仍是抓取快照，不是本需求的部署第一刀。

## 5. 和已拍板的冲突

远程后端一旦离开本机：

- 现在后端不校验 `BACKEND_TOKEN`，只靠绑 `127.0.0.1`。暴露到局域网或公网之前必须先校验，否则任何人都能读写库。
- 媒体默认复制进库目录。远程后端时，这个目录在服务器上，桌面「打开所在位置」和本机播放都会断。
- 磁力依赖本机 `aria2c`。容器里要不要带 aria2，是 S4 的范围问题，不是现在就能定的。

未关闭这些冲突之前，**不写 Dockerfile，不改启动地址**。
