# 模块拆解 · work-consumption-hub

> 状态：**已定稿**（2026-09-27 · 随 `work-consumption-hub` 定稿，`D-20260927-05`）
> 主需求见 [work-consumption-hub.md](work-consumption-hub.md)。
> 优先级：P0 = 消费渠道 + 工作目录 · P1 = 扩展类型 + 工作概览
> 前置模块：LRM M0–M6（见 [lrm-modules.md](lrm-modules.md)）

## 1. 模块总览

| 模块 | 名称 | 优先级 | 说明 |
|------|------|--------|------|
| M7 | 消费渠道框架 | **P0** | 类型 → 消费动作注册；内嵌/外部/自定义命令；设置与覆盖 |
| M8 | 工作目录 | **P0** | 目录入库、工作区 UI、待办/备注、外部打开 |
| M9 | 扩展资源类型 | P1 | 模型等新型注册；占位 + 消费入口 |
| M10 | 工作概览 | P1 | 首页「进行中工作 / 最近消费」 |

## 2. M7 · 消费渠道框架（P0）

**用户故事**

- US-7.1 用户为视频设置默认消费方式为「系统播放器」→ 双击视频一律唤起系统播放器
- US-7.2 用户为某资源单独设置「用 Cursor 打开」→ 仅该资源覆盖全局默认
- US-7.3 用户右键资源 → 看到「打开」「用…打开」「在工作区中查看」（按类型显示可用项）
- US-7.4 用户在设置页配置某类型的默认消费渠道 → 保存后对新资源生效

**消费渠道类型**

| 渠道 | 说明 | 适用类型示例 |
|------|------|--------------|
| `embedded` | 应用内消费 | 图片预览、视频内嵌播放 |
| `system_default` | 系统默认关联程序 | 通用文件、模型 |
| `external_command` | 自定义命令模板 | 工作目录 → `code "{path}"` |
| `workbench` | 应用内工作区视图 | 工作目录专属 |

**验收标准**

- [ ] 每种 `ResourceType` 注册至少一个默认消费渠道
- [ ] 支持全局默认 + 单资源 `openWith` 覆盖（存 `extra.openWith` 或独立字段）
- [ ] 自定义命令支持 `{path}` 占位符，路径含空格时正确转义
- [ ] 双击行为统一走消费渠道路由，不散落各视图硬编码
- [ ] 设置页「消费渠道」页签：按类型配置默认方式
- [ ] 外部打开失败时给出明确错误（命令不存在、路径无效等）

## 3. M8 · 工作目录（P0）

**用户故事**

- US-8.1 用户添加本地项目文件夹为工作目录 → 扫描入库，出现在「工作目录」列表
- US-8.2 用户选中工作目录 → 右侧工作区展示待办列表与备注
- US-8.3 用户在工作区新增/编辑/删除待办 → 持久化，重启后仍在
- US-8.4 用户在工作区新增/编辑/删除备注 → 持久化，支持多段备注（按时间或标题）
- US-8.5 用户点击「在外部打开」→ 按配置唤起 IDE/文件管理器/自定义程序
- US-8.6 用户双击工作目录卡片 → 进入工作区视图（非直接打开文件夹）
- US-8.7 工作目录路径不存在 → 标记 `lost`，工作区只读并提示重新定位

**数据模型（概念）**

```
Resource (type = work_directory)
  ├── title, description, status, ...
  ├── files[0].path          # 目录路径
  ├── extra.openWith         # 可选，覆盖全局外部打开命令
  └── extra.workContext      # MVP：{ todos[], notes[] }
```

**待办 / 备注结构（MVP）**

```typescript
interface WorkTodo {
  id: string
  content: string
  done: boolean
  createdAt: string
  updatedAt?: string
}

interface WorkNote {
  id: string
  title?: string
  content: string
  createdAt: string
  updatedAt?: string
}
```

**验收标准**

- [ ] `ResourceType` 新增 `work_directory`
- [ ] 添加目录时可选择「作为工作目录入库」（与媒体目录扫描区分或共用入口）
- [ ] 工作区面板：待办 CRUD（增删改、勾选完成、排序）
- [ ] 工作区面板：备注 CRUD（增删改）
- [ ] 「在外部打开」「在文件管理器中显示」按钮可用
- [ ] 每个工作目录可单独配置 `openWith`
- [ ] 目录丢失时 status=`lost`，待办/备注只读保留

**P1 扩展（本模块后续）**

- [ ] 快捷链接（URL 列表）
- [ ] 关联库内其他资源
- [ ] 工作状态：进行中 / 暂停 / 完成

## 4. M9 · 扩展资源类型（P1）

**用户故事**

- US-9.1 用户添加模型文件/目录 → 以 `model` 类型入库（扫描规则待定）
- US-9.2 用户查看模型详情 → 元数据 + 「打开/用…打开」消费入口
- US-9.3 左侧菜单「模型」→ 列表视图，占位态可点击进入（非置灰）

**验收标准**

- [ ] `ResourceType` 新增 `model`（或统一 `extensible` + subtype，实现时二选一）
- [ ] 模型默认消费渠道：`system_default` 或 `external_command`
- [ ] 菜单与路由注册机制：新增类型不需改核心路由硬编码
- [ ] 不做内嵌模型查看器（MVP）

## 5. M10 · 工作概览（P1）

**用户故事**

- US-10.1 用户打开首页 → 看到「进行中的工作」（有未完成待办或最近活跃的工作目录）
- US-10.2 用户打开首页 → 看到「最近消费」（最近打开/播放/预览的资源）
- US-10.3 用户点击进行中工作卡片 → 跳转到对应工作目录工作区

**验收标准**

- [ ] 首页区块：类型统计（保留 LRM 现有）
- [ ] 首页区块：进行中工作（≥1 未完成待办 或 7 日内有活动）
- [ ] 首页区块：最近消费（最近 N 条，N 可配置默认 10）
- [ ] 空态：无进行中工作时友好提示
- [ ] 后端 API：`GET /overview` 扩展字段（或独立 endpoint）

## 6. API 增量

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/resources/{id}/work-context` | 获取工作目录待办/备注 |
| PUT | `/resources/{id}/work-context` | 全量或增量更新工作上下文 |
| POST | `/resources/{id}/consume` | 触发消费动作（返回 action 类型，桌面端执行） |
| GET | `/settings/consumption` | 获取各类型默认消费渠道 |
| PUT | `/settings/consumption` | 更新消费渠道配置 |

> 桌面端负责实际 `shell.openPath` / `spawn` 执行；后端存配置与审计日志。

## 7. 边界与异常（跨模块）

- **空工作区**：新工作目录无待办/备注时展示引导（「添加第一条待办」）
- **并发编辑**：单用户本地应用，MVP 不做冲突合并；最后写入胜出
- **命令注入**：`external_command` 仅允许配置项中的固定模板 + 路径参数，不拼接用户自由文本
- **跨平台**：Windows/macOS/Linux 外部打开命令格式差异，设置页提供平台说明
- **与 LRM 扫描**：工作目录扫描只索引目录本身（路径、修改时间），不递归媒体入库（除非用户显式扫描子目录为媒体）
