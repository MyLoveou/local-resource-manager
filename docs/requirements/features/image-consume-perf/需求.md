# 图片消费性能 · 需求

> 状态：**已并入 `app-performance`**（2026-09-12）  
> 本切片不再单独实现；看图性能是全项目方案的 **S5**。  
> Feature ID：`image-consume-perf`  
> OpenSpec：`openspec/changes/image-consume-perf/`  
> 上游：`image-consume`、`image-viewer-ux`、`grid-media-performance`

## 1. 问题

看图与浏览能用，但大图与词表把主线程和首屏绑在一起：

1. 网格/面板仍可能过早解码原图。  
2. 信息栏预览应只走缩略图（代码已倾向 `thumbnailPath`，弹窗等入口需对齐）。  
3. 分类/标签词表请求不应挡住列表或信息栏字段首绘。  
4. 详情、词表、缩略图缺少统一缓存与失效。  
5. 后端详情多次查询、静态文件无缓存头。  
6. 前端查看器拖拽/窗口缩放、点选重绘仍卡。

## 2. 本轮做 / 不做

| 做 | 不做 |
|----|------|
| 图片懒加载：屏外不解码；查看器原图仅打开后加载 | 视频播放 |
| 信息栏/编辑弹窗预览只用缩略图；原图只在查看器 | 再发明一套缩略图格式（沿用 `thumbs/grid.webp`） |
| 分类、标签词表后台加载，不阻塞列表与字段 | 为性能新开 REST 前缀 |
| 前端内存缓存：详情、词表；静态图 Cache-Control | IndexedDB 长期离线库 |
| 后端：详情少往返、缩略图/content 缓存头 | 换 SQLite / 上 Redis |
| 查看器 rAF/resize 防抖；点选不重绘整表 | PhotoSwipe 灯箱；业务直接 import 看图库 |

## 3. 用户故事

- **US-P.1** 放大拖图跟手。  
- **US-P.2** 最大化窗口，中间栏很快有图。  
- **US-P.3** 点网格或下一张，标题立刻出现，不等原图。  
- **US-P.4** 滚动网格时，只加载可见（及少量预取）卡片图。  
- **US-P.5** 信息栏顶部图是缩略图，点开查看器才是原图。  
- **US-P.6** 进图片页先看到网格，分类下拉可稍后出现选项。

## 4. 验收

- [ ] 卡片 `loading=lazy`（或等价）；查看器未打开不请求 `/content`。  
- [ ] 信息栏与编辑弹窗预览 URL 为 `thumbnailPath`，无则才 `coverPath`。  
- [ ] 首屏列表不 `await` 分类/标签接口。信息栏字段不因词表未返回而空白。  
- [ ] 同一资源短时间内再点选不重复打详情（除非 `library.bump`）。  
- [ ] 缩略图与 content 响应带可缓存头（至少 `Cache-Control`）。  
- [ ] 详情 GET 不按关联表逐条 round-trip（一次 hydrate）。  
- [ ] P1/P2 拖拽与窗口缩放仍满足。  
- [ ] 封装约束不变。

## 5. 契约

无新路径前缀。可给已有 `FileResponse` 加缓存头；详情查询实现可改、JSON 形状不变。

## 6. 假设

1. 先调 Viewer.js；拖拽仍卡再问是否自绘。  
2. 预取 content 仅当前 ±1。  
3. 词表与详情缓存在内存，bump / 保存分类后失效。  
4. 旧资源无缩略图时允许退回 coverPath（已知债）。

Viewer.js 拖拽无法跟手时，是否卸库自绘？未点头不换。
