# 以图搜图 / 相似图检索 · 需求

> 状态：调研与方案（2026-10-23），待确认后进入实现  
> 关联：`ai-search` 提供 CLIP 向量与结构化特征。

## 1. 问题

现在的“以文搜图”是文本查询共享同一个 CLIP 向量空间。用户还需要：

- 从一张已有图片继续找同一次拍摄、同一套衣服、同一场景；
- 找同一个人在不同时间/服装下的照片；
- 找近似重复图、裁剪图、压缩图；
- 从局部物件/服装继续找相似。

这些不是同一个“相似”定义，不能只用一个余弦分数回答。

## 2. 目标

- 在图片查看器和 Inspector 提供「找相似」入口。
- 支持已有资源图；后续支持拖入/选择外部图片。
- 明确区分：
  - 语义相似
  - 视觉相似/同一次拍摄
  - 近似重复
  - 同一个人
- 结果排除查询图自身，显示匹配数量、模式和分数。
- 本地完成，不上传图片。

## 3. 非目标

- 不把 VLM 文案当作以图搜图的唯一相似度。
- 不在首版做跨图物体组合/局部框选。
- 不默认开启人脸身份库。
- 不做云端索引。
- 不先引入专用向量数据库；5 万以内先 NumPy。

## 4. 模式定义

| 模式 | 回答的问题 | 主要信号 |
|---|---|---|
| 语义相似 | 画面主题、人物、服装、场景像不像 | CLIP image embedding |
| 视觉相似 | 同一次拍摄、姿态/构图/背景是否接近 | DINOv2 image embedding |
| 近似重复 | 是否同一张图的裁剪/压缩/缩放版本 | pHash/dHash；后续 SSCD |
| 同一个人 | 是否为同一人物 | 人脸检测 + ArcFace embedding |

## 5. 验收

- 从查看器点「找相似」能在 2 步内看到结果。
- 查询图不出现在结果中。
- 四种模式不混成一个不可解释的总分。
- 结果页显示模式、匹配数、显示数；不把 topK 当命中总数。
- 236 张基准库：结果可复现，有固定查询集。
- 没有人脸模型时，「同一个人」明确不可用，不假装有结果。

## 6. 待确认

- 首版是否只支持库内图片，还是同时支持外部文件。
- 人脸模式是否默认关闭、仅用户主动开启。
- 「综合」是否作为默认结果页，还是先让用户选模式。
