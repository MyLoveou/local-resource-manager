# 视频资源管理 · 需求

> 状态：**L1 评审中**（2026-10-25）
> Feature ID：`video-management`
> 前置：D-20261025-01（图片库阶段手验通过，进入视频阶段）
> 关联：[by-type/video.md](../../by-type/video.md) · [by-type/anime.md](../../by-type/anime.md) · [library-workspace](../library-workspace/需求.md)
> 说明：本文只写需求与边界。L3 方案（`实现方案.md`）与 OpenSpec change 待本文定稿后再出。

## 1. 背景

图片库阶段已收口并完成 Electron 全量手验。视频目前停在 **A-min**：能导入、能播、能刮削、能筛选，但「看了一半」这件事系统完全不记得，播放器也只有全屏与 Esc。

用户已确认第一阶段收 5 块能力，但**不一次做完**，按纵向切片 S1 → S2 → S3 推进。

## 2. 现状（带代码证据）

已具备：

| 能力 | 落点 |
|---|---|
| 导入（单文件/文件夹）、复制入库、sha256 去重 | `library/application/importers/video.py` |
| ffprobe：时长/宽高/编码/帧率/码率/GPS/拍摄时间 | `library/application/media_probe.py` |
| 内置播放器（双击打开，Esc/全屏） | `components/VideoPlayerOverlay` |
| 封面（抽帧/手选）、分类、标签、合集、回收站 | 通用能力 |
| 排序：时长/分辨率/码率 | `library-search-sort` |
| 进入时间线（`creation_time` 优先） | `photo-timeline-map` |
| 刮削：TMDB + B 站 | `scrape/application/providers/` |

缺口（已核实，不是推测）：

| 缺口 | 证据 |
|---|---|
| 无播放进度 | `files` 表无位置列；`consumption_events` 只有 `action`；`stores/videoPlayer.ts` 只有 `visible/playlistIds/currentId/currentFileId` |
| 播放器控件薄 | overlay 内 `keydown` 仅处理 Esc/全屏；无倍速、无上一集/下一集、无快捷键 |
| 字幕只能手动挂 | 有 `POST /library/resources/{id}/subtitles` 与 `subtitle_naming.py`，但无自动匹配、无批量 |
| 无音轨元数据 | `files` 列只有 `codec/fps/bitrate/duration/width/height`，**无音频编码/声道** |
| 刮削站点少、无字段合并 | 仅 TMDB + B 站；多站点冲突不做合并 |

## 3. 范围

### IN

**S1 · 播放进度与续播**

- 记录每个可播放资源的观看位置与总时长
- 再次打开自动续播；接近结尾视为已看完，从头开始
- 首页「最近消费」升级为「继续观看」：显示进度、可直接续播
- 覆盖 `video` / `anime` / `av` 三种类型的播放（共用播放器分发）

**S2 · 播放器体验与字幕**

- 倍速（0.5 / 1 / 1.25 / 1.5 / 2）
- 快捷键：空格暂停、←/→ 前后 5 秒、↑/↓ 音量；输入框聚焦时不生效
- 上一集 / 下一集（仅 `anime` / `av` 且存在相邻集时显示）
- 字幕自动匹配：按 `subtitle_naming` 规则，从同目录与包内 `subtitles/` 挂载
- 字幕轨道切换与关闭

**S3 · 视频专属维度与刮削**

- 筛选：编码、帧率区间、分辨率档、时长区间、码率区间；条件可组合并写进 URL
- 音轨字段（音频编码 / 声道 / 语言）：新增迁移后采集，先只读展示，暂不进筛选
- 刮削：扩大站点覆盖；多站点同字段冲突时按来源优先级合并，并在确认队列里列出冲突项

### OUT

- 视频转码、剪辑、压制
- 内置下载器（下载统一委托第三方，D-20261007-01）
- 播放列表编辑器（当前合集 + 系列选集已够）
- 片头/片尾自动跳过（需章节或指纹，另立项）
- 弹幕、投屏、倍速之外的音频处理

## 4. 切片顺序与不做什么

| 切片 | 交付 | 明确不做 |
|---|---|---|
| **S1** | 迁移 `0031`（播放进度表）、进度上报接口、续播、继续观看 | 不做倍速/快捷键（S2）、不碰音轨（S3） |
| **S2** | 播放器控件、快捷键、选集切换、字幕自动匹配与轨道 | 不改筛选维度、不改刮削 |
| **S3** | 筛选维度、音轨采集迁移、刮削站点与字段合并 | 不做自动追番、不做下载 |

**为什么 S1 先做**：它是唯一一块能立刻改变日常使用体验的；且「继续观看」的入口已经存在（首页最近消费），只差数据。

## 5. 验收（每条可判定）

**S1**

- V1 播放 ≥10 秒后关闭，再次打开同一资源，从上次位置 ±5 秒继续
- V2 播放到 95% 以上视为看完；再次打开从头开始
- V3 首页显示「继续观看」，含封面、进度百分比、剩余时长；点击直接续播
- V4 进度写入 `0031` 新表；后端重启后仍在
- V5 已软删（`trashed`）的资源不出现在继续观看
- V6 `anime` / `av` 按「集」记录进度，切集后各自独立

**S2**

- V7 倍速切换后播放位置不丢失、不跳回开头
- V8 空格 / ←→ / ↑↓ 生效，且在搜索框等输入框聚焦时不抢占按键
- V9 `anime` / `av` 有相邻集时显示上下集按钮，点击切换到该集并从其进度续播
- V10 同目录或包内 `subtitles/` 中按命名规则匹配到的字幕自动挂载，无需手动选择
- V11 多字幕轨道可切换与关闭，切换不重载视频

**S3**

- V12 编码 / 帧率 / 分辨率档 / 时长区间 / 码率区间可组合筛选，刷新后条件仍在
- V13 音轨字段采集后，信息栏可读展示音频编码与声道
- V14 刮削新增站点后，同一字段出现多个候选时，确认队列标出冲突并显示采用哪一条

## 6. 开放问题（需拍板后才能出 L3）

- **Q1** S1 的进度表是否需要「完成度」派生字段（看完/未看完），还是查询时按阈值算？
- **Q2** 续播阈值取多少：低于 10 秒不记、高于 95% 视为看完，是否符合预期？
- **Q3** 字幕自动匹配的搜索范围：仅同目录，还是同目录 + 上一级 + 包内 `subtitles/`？
- **Q4** S3 新增哪些刮削站点？（现状只有 TMDB + B 站，番剧另有 Bangumi + 蜜柑）
- **Q5** 音轨采集要不要并进 S1 的 `0031` 迁移，一次改表省一次迁移？还是守 S3 再动？

## 7. 边界提醒

- 本功能不改 `video` / `anime` / `av` 的类型边界：`video` 仍是单文件，多集仍走 `anime` / `av`（见 [by-type/video.md](../../by-type/video.md) 第 4 节）
- 播放器统一由 `openResource` 分发，S1/S2 不得为视频另起一套打开链路
- 进度是**消费状态**，不是资源元数据；不得写进资源 `extra`
