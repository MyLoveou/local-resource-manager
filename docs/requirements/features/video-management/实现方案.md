# 视频资源管理 · 实现方案（S1：播放进度与续播）

> 状态：**L3 草案**（2026-10-25）
> 对应 L1：[需求.md](需求.md) · 决策：[D-20261025-01](../../../product/decisions.md)
> 范围：**仅 S1**。S2（播放器体验与字幕）、S3（维度与刮削）待 S1 落地后另出。

## 1. 一个决定主键的事实

`episodes` 表把「集」挂在 **`file_id`** 上（`0008_series.sql` 第 53–64 行）：

```
resources(1) ──< files(N) ──< episodes(N) ──< seasons(1)
```

**一个番剧作品 = 1 个 Resource + N 个 file**，「集」不是独立 Resource。

所以进度表主键必须是 `file_id`。若按 `resource_id` 记，整部番剧会共用一个播放位置——第 3 集看到 20 分钟，切到第 5 集也会从 20 分钟开始。这是 S1 最容易写错的地方。

## 2. 数据模型

迁移 `apps/backend/app/shared/db/migrations/0031_playback_progress.sql`：

```sql
-- 0031 · 播放进度 + 音轨元数据（S3 音轨列提前落地，见 D-20261025-01 Q5）

CREATE TABLE IF NOT EXISTS playback_progress (
  file_id     INTEGER PRIMARY KEY REFERENCES files(id) ON DELETE CASCADE,
  resource_id INTEGER NOT NULL REFERENCES resources(id) ON DELETE CASCADE,
  position    REAL NOT NULL DEFAULT 0,          -- 秒
  duration    REAL,                             -- 秒，用于算百分比
  completed   INTEGER NOT NULL DEFAULT 0
              CHECK (completed IN (0, 1)),
  updated_at  TEXT NOT NULL DEFAULT (datetime('now'))
);
CREATE INDEX IF NOT EXISTS idx_playback_updated  ON playback_progress(updated_at DESC);
CREATE INDEX IF NOT EXISTS idx_playback_resource ON playback_progress(resource_id);
CREATE INDEX IF NOT EXISTS idx_playback_resume   ON playback_progress(completed, updated_at DESC);

ALTER TABLE files ADD COLUMN audio_codec    TEXT;
ALTER TABLE files ADD COLUMN audio_channels INTEGER;
ALTER TABLE files ADD COLUMN audio_language TEXT;
```

要点：

- `file_id` 作主键，天然支持「每集独立进度」；
- `resource_id` 冗余存一份，供「某作品的继续观看」按作品聚合，避免每次 join `files`；
- `completed` 是**写入时算好的**（按 Q1 拍板：阈值在写入侧判定，查询不再重复算）；
- 音轨三列按 Q5 提前建好，但 **S1 只建列、不写入**：采集与展示一起放 S3（见 §8），
  否则要动 `media_probe.py` / `import_service.py` / `repositories_resources.py`
  三个已超软目标的存量文件，触发「基线文件不得继续增长」的门禁。

## 3. 契约

统一信封 `{ code, status, message, data }`；字段 camelCase。

### 3.1 上报进度

```
PUT /library/resources/{resource_id}/progress
body: { fileId: number, position: number, duration?: number }
→ data: { fileId, resourceId, position, duration, completed, updatedAt }
```

- `position < 10s` 且原本没有记录 → 不写（Q2 阈值）
- `position / duration >= 0.95` → `completed = 1`，`position` 归 0
- 幂等：同一 `file_id` 反复上报只更新一行
- 资源处于 `trashed` / `lost` → 返回 404，不写进度

### 3.2 取续播位置

```
GET /library/resources/{resource_id}/progress?fileId=123
→ data: { fileId, position, duration, completed } | null
```

### 3.3 继续观看列表

```
GET /library/progress/resume?limit=20
→ data: { items: [{
     resourceId, fileId, title, type, thumbnailPath,
     position, duration, percent, updatedAt,
     episodeNumber?, seasonNumber?
   }], total }
```

- 只取 `status = 'active'` 的资源
- 只取 `completed = 0 AND position >= 10`
- 按 `updated_at DESC`
- 番剧/AV 需带出 `seasonNumber` / `episodeNumber`，前端显示「第 2 季 第 5 集 · 剩余 12 分钟」

### 3.4 清除进度

```
DELETE /library/resources/{resource_id}/progress?fileId=123
→ 204
```

「标记为未看」用；`fileId` 省略时清整部作品的进度。

## 5. 数据流

```
播放器 currentTime 变化（节流 5s）/ 关闭
  → PUT /library/resources/{id}/progress { fileId, position, duration }
  → ProgressService.upsert()
      ├ position < 10 且无记录 → 丢弃
      ├ percent >= 0.95        → completed=1, position=0
      └ 其余                    → 写入/更新
  → repositories_progress.upsert()（SQLite UPSERT）

首页加载
  → GET /library/progress/resume?limit=20
  → JOIN playback_progress + resources + files
  → 补 season/episode 号
  → 渲染「继续观看」

点击继续观看
  → openResource(resourceId, { fileId })
  → 播放器挂载时 GET .../progress?fileId=  → seek
```

## 7. 风险与前置

- **迁移顺序**：`0031` 必须晚于 `0030`；`ensure_db` 按文件名排序执行，命名不能写错。
- **并发写入**：播放器 5 秒一报，多窗口同时播同一集会互相覆盖——按 `updated_at` 后者胜，可接受，不做锁。
- **`percent` 计算**：`duration` 可能为空（ffprobe 失败），此时按秒数而非比例判定，不算完成。
- **不变量**：进度是消费状态，**不得写进 `resources.extra`**（L1 §7）。
- **S2 依赖**：上下集切换要等 S2，S1 只保证「同一 file 能续播」。

## 8. S1 不做

- 倍速、快捷键、上下集（S2）
- 字幕自动匹配（S2）
- 按编码/帧率/音轨筛选（S3）——`0031` 已建好音轨列，但 S1 不写入
- 音轨采集（S3 与信息栏展示、筛选一起做，顺带拆分那三个存量超标文件）
- 跨设备同步、观看历史页（当前只有「继续观看」列表）
