# 图片查看器壳与动作区 · 需求

> 状态：**已定稿**（2026-09-12 · 用户确认可以按此实现）  
> Feature ID：`image-viewer-ux`  
> OpenSpec：`openspec/changes/image-viewer-ux/`  
> 修订：`image-consume` 的查看器占位 / 导航 / 信息栏按钮；**不改**打开规则与 IPC

## 1. 问题

当前实现：固定层从顶栏以下铺满整窗，罩内再复制信息栏；顶条放关闭/上一张/下一张；拖拽和窗口缩放卡。看起来不像「在格子里看图」，像另一张全屏皮。

## 2. 本轮做 / 不做

| 做 | 不做 |
|----|------|
| 查看器只覆盖中间网格（`main`） | 继续全应用遮罩 |
| 右侧信息栏看图时保持原位、不卸载 | 罩内第二份 InfoPanel |
| 关闭在图右上；上一张/下一张在图左右中部 | 顶条三个文字按钮 |
| 信息栏底：保存、编辑、回收站；其余进「更多」 | 重做字段表单、换主题 |
| 封装内减轻卡顿（关过渡、少重建、resize 节流） | 本轮更换 Viewer.js |

## 3. 用户故事

- **US-U.1** 打开查看器后仍能看见并使用右侧信息栏；图只出现在原来网格的位置。  
- **US-U.2** 一眼能点到关闭；在图左右切上一张/下一张。  
- **US-U.3** 放大后拖拽跟手；最大化或拖窗口边时图在中间栏内重算，不整窗刷一层。  
- **US-U.4** 信息栏底部不再排满打开位置/外部应用等按钮。

## 4. 验收

- [ ] 查看器打开时顶栏、侧栏、右侧信息栏可见。  
- [ ] 图的可视区域不超过中间栏。  
- [ ] 无全宽「关闭 / 上一张 / 下一张」顶条。  
- [ ] 「打开所在位置」「用外部应用打开」「选择其他应用」「更换封面」在「更多」内，能力仍在。  
- [ ] Esc 仍关闭；左右键仍切已加载相邻图。  
- [ ] 二次点击 / 批量不打开 规则不变。

## 5. 契约

无新 REST / IPC。

## 6. 假设

1. 用户第 4 点「不要占满整个软件」= 只盖 `main`，不是做中央小弹窗。  
2. 用户第 5 点针对**同一份**信息栏底部，列表页与看图页一起收。  
3. 仍用 Viewer.js；若调完仍严重卡，另立项换库。

## 7. 开放问题

无。若「只盖 main」不是你要的占位，请在确认前改口。
