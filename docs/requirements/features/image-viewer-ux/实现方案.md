# 图片查看器壳与动作区 · 实现方案

> 状态：**已定稿**（与 OpenSpec `design.md` 同一范围）  
> Feature ID：`image-viewer-ux`

## 目标 / 不交付

与 [`需求.md`](./需求.md) 一致。不换看图库、不改 IPC。

## 与现有架构的取舍

| 做法 | 为何 |
|------|------|
| Overlay 挂到 `main` 内（或绝对定位只对准 `.main-content`） | 第 4 点：不要盖住整窗 |
| `App.vue` 始终挂一份 `InfoPanel` | 第 5 点同一面板；避免再 Teleport/复制 |
| 导航按钮做 Overlay 子层，贴 stage | 第 6 点 |
| 封装关 `transition`、切图只改 `img.src`、ResizeObserver+rAF 调 `resize()` | 第 2、3 点；仍满足「第三方只封装层引用」 |

## 模块边界

```
打开查看器     → imageViewer store（不变）
图的位置       → ImageViewerOverlay 只盖 main
元数据         → 壳 InfoPanel（始终挂载）
手势           → createInlineImageViewer（仍是唯一 import viewerjs）
底部按钮       → InfoPanel footer + n-dropdown「更多」
```

## 数据流

**打开** 与现在相同（二次点击 → store.open）。  
**渲染** Overlay 的根不再 `fixed` 铺满视口，而是 `main` 的 `position:absolute; inset:0`。  
**切图** `setSrc` 只改已有 img 的 `src`，等 load 后 `view(0)`，禁止 `destroy`+`new Viewer`。  
**窗口缩放** host ResizeObserver → `requestAnimationFrame` → `instance.resize()`（若 API 无 resize 则只改容器 CSS，避免 `update()`）。  
**错误** 解码失败仍提示走「更多 → 用外部应用打开」。

## 风险

| 风险 | 缓解 |
|------|------|
| Viewer.js 拖拽本身不跟手 | 本轮关动画+缩小重排范围；仍差则换库另立项 |
| 「更多」藏太深 | 打开位置/外部打开仍在同一面板，多一次点击 |
