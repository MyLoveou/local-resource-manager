# 设计 · production-packaging（L2）

> 状态：**评审中**（2026-10-07）
> 需求：`需求.md`（已定稿）

## 1. 设计原则

- **开发态零变化**：所有生产分支以 `app.isPackaged` 判定；`pnpm dev` 仍用仓库 venv 与仓库数据目录
- **用户机器无 Python/Node**：后端冻结为 onedir exe，随安装包/zip 分发
- **安装目录只读**：DB、库包、日志、缩略图全部落 `%APPDATA%/local-resource-manager`（ASCII 目录，卸载保留）
- **失败即阻断**：release 脚本任一步失败非零退出；校验脚本验证「真正会分发的后端」能启动并通过健康检查
- **版本单一来源**：`apps/desktop/package.json` 的 `version`；安装包名与后端运行版本同源
- **不做**：签名/公证、自动更新、安装器无人值守冒烟；多平台图标资产（v1 仅 Windows `.ico`）

## 2. 模型与契约

### 2.1 运行态判定

| 条件 | 后端命令 | cwd | DB | 日志 |
|------|----------|-----|----|------|
| `app.isPackaged === false`（dev/preview） | `<venv>/python -m uvicorn app.main:app …` | `apps/backend` | `apps/backend/data/library.db` | `apps/logs`（沿用） |
| `app.isPackaged === true` | `resources/backend/source-manager-backend.exe --host … --port …` | 后端 exe 目录 | `%APPDATA%/local-resource-manager/library.db` | `%APPDATA%/local-resource-manager/logs` |

- userData 在 `app.whenReady()` 前显式设为 `join(app.getPath('appData'), 'local-resource-manager')`（避免中文 productName 进入路径）
- `initMainLog()` 仍在最先调用（`LOG_DIR` 已由它注入子进程）

### 2.2 BackendConfig 契约（扩展）

```ts
type BackendMode = 'dev' | 'frozen'
interface BackendConfig {
  mode: BackendMode
  // dev
  pythonPath?: string
  backendDir?: string
  module?: string
  // frozen
  backendExe?: string
  // 共用
  host: string
  healthTimeoutMs: number
  healthIntervalMs: number
}
```

`startBackend(cfg)` 负责组合命令：

- dev：`args = ['-m','uvicorn', module, '--host',host,'--no-access-log','--port',port]`
- frozen：`args = ['--host',host,'--no-access-log','--port',port]`
- 两者都注入 env：`BACKEND_TOKEN`、`BACKEND_VERSION=app.getVersion()`、`LOG_DIR`；frozen 追加 `BACKEND_DB_PATH`

### 2.3 冻结后端契约

- 入口：`apps/backend/run_server.py`，参数 `--host` `--port` `--no-access-log`；内部 `uvicorn.run(app, …)`
- 产物：`apps/backend/dist/source-manager-backend/`（exe + `_internal/`）
- migrations 随包：`--add-data "app/shared/db/migrations;app/shared/db/migrations"`；冻结态从 `sys._MEIPASS/app/shared/db/migrations` 读取
- 环境：`BACKEND_DB_PATH`、`BACKEND_TOKEN`、`LOG_DIR`、`BACKEND_VERSION`
- 健康：`GET /health` 200；退出受主进程控制

### 2.4 版本与产物契约

- `version = 0.1.0`（`apps/desktop/package.json`）
- productName `资源管理器`；`appId com.myloveou.local-resource-manager`；`executableName local-resource-manager`
- 产物：
  - `release/local-resource-manager-<version>-win-x64-setup.exe`（NSIS，per-user，可选目录，桌面/开始菜单，卸载保留数据）
  - `release/local-resource-manager-<version>-win-x64.zip`（解压即用）
  - `release/SHA256SUMS.txt`
- `release/win-unpacked/` 为 electron-builder 的未压缩目录，校验用它跑冻结后端冒烟

## 3. 交互与数据流

### 3.1 生产启动

1. main：`app.setPath('userData', %APPDATA%/local-resource-manager)` → 日志目录 → ready
2. `loadBackendConfig()`：`app.isPackaged` → frozen exe 路径 `process.resourcesPath/backend/source-manager-backend.exe`
3. `startBackend()`：空闲端口 + token + DB/日志 env → spawn → `/health` 轮询 → 开窗
4. 后端首启：`ensure_db` 建库 → 执行 migrations（冻结资源）→ 库包目录 = DB 同级 `library/`

### 3.2 发布流水线（本地与 CI 同一入口）

```
pnpm release:win
  ├─ 清 release/、apps/backend/{build,dist}
  ├─ 门禁：typecheck → lint → backend pytest
  ├─ electron-vite build（apps/desktop/out）
  ├─ PyInstaller（spec：run_server.py + migrations + hidden imports）
  ├─ electron-builder（nsis + zip，extraResources=冻结后端）
  └─ verify-release.mjs
       ├─ 产物存在 + 版本/命名一致 + 非零大小
       ├─ 冻结后端冒烟：临时 DB/端口 → /health 200 → DB 文件生成 → 退出
       └─ 生成 SHA256SUMS.txt
```

### 3.3 CI

- `.github/workflows/release-windows.yml`：`workflow_dispatch` + tag `v*`
- windows-latest；Node 24 + pnpm；Python 3.14 + `requirements.txt` + `requirements-packaging.txt`
- `pnpm install --frozen-lockfile` → `pnpm release:win` → `actions/upload-artifact`（setup exe、zip、SHA256SUMS）
- 环境：`CSC_IDENTITY_AUTO_DISCOVERY=false`（不签名）；缓存 pnpm / pip / electron-builder

## 4. 模块划分

| 模块 | 职责 | 不进入 |
|------|------|--------|
| `apps/desktop/src/main/infrastructure/services/config.ts` | 按 `app.isPackaged` 解析 dev/frozen 后端配置 | 打包命令、校验逻辑 |
| `apps/desktop/src/main/infrastructure/services/backend.ts` | 组合命令/参数/env，spawn 与健康检查 | 路径规则（由 config 给） |
| `apps/desktop/src/main/index.ts` | userData 显式路径（打包态） | 后端细节 |
| `apps/backend/run_server.py`（新） | 冻结入口：解析参数 → uvicorn.run | 业务逻辑 |
| `apps/backend/packaging/backend.spec`（新） | PyInstaller 打包描述（datas/hiddenimports/onedir） | 版本号 |
| `apps/backend/app/shared/db/migrations.py` | 冻结态 migrations 路径解析 | 打包 |
| `apps/backend/app/settings/api/router.py` | `_VERSION` 改读 `BACKEND_VERSION`（fallback 0.0.0） | 打包 |
| `apps/desktop/electron-builder.yml`（新） | appId/productName/targets/extraResources/NSIS/产物名 | 构建门禁 |
| `apps/desktop/package.json` | version、electron-builder devDep | — |
| `scripts/release.mjs`（新） | 发布编排（组合根） | 具体检查细节 |
| `scripts/verify-release.mjs`（新） | 产物 + 冻结后端冒烟 + SHA256 | 构建 |
| `.github/workflows/release-windows.yml`（新） | CI 复用同一 release 入口 | 另写一套构建 |
| 根 `package.json` | `release:win` / `release:verify` 脚本 | — |

依赖方向：release 脚本 → pnpm/pyinstaller/electron-builder；主进程 → 冻结产物（运行时）；CI → 同一脚本。

## 5. 功能拆分

本能力不是 UI/功能/算法三层，而是**构建编排 + 运行时切换 + 冻结打包 + 校验**四个功能切片，组合根为 `scripts/release.mjs`：

| 切片 | 提供 | 契约 |
|------|------|------|
| 运行时切换 | dev/frozen 配置与 spawn | `BackendConfig.mode`；frozen 时 exe 路径与 DB env |
| 冻结打包 | 后端 onedir 产物 | `run_server.py --host --port --no-access-log`；migrations 随包 |
| 安装包 | NSIS + zip + 资源嵌入 | `release/` 下固定命名；`resources/backend/` |
| 校验 | 冒烟 + SHA256 + 退出码 | `verify-release.mjs` 0=通过，非 0=失败 |

最后一步必须是：在 `release/win-unpacked` 上跑冻结后端冒烟，再产出 SHA256；禁止只构建不校验。

## 6. 抽象

- **抽**：`BackendMode` 与命令组合（dev/frozen 单点分支）；`run_server.py` 作为冻结入口（不污染 `app.main`）
- **不抽**：不引入 electron-forge / 通用发布框架；不做多平台 matrix；不做签名与更新；不把校验拆成库

## 7. 决策

| 决策 | 选择 | 为何不选备选 |
|------|------|----------------|
| 安装包形态 | NSIS + zip | 用户确认；zip 便于排障与免安装 |
| 后端冻结 | PyInstaller onedir | 稳定、排错容易；onefile 首启慢且解压临时目录 |
| 数据目录 | `%APPDATA%/local-resource-manager` | 安装目录只读；便携模式会让升级/备份复杂 |
| 版本来源 | desktop package.json | 避免根/后端/electron-builder 多处漂移 |
| 校验入口 | 独立 verify 脚本（release 调用） | 不把冒烟塞进构建脚本，便于单独重跑 |
| 签名 | 不签名 | 无证书；接受 SmartScreen |
| 图标 | 自绘渐变文件夹图标（`build/icon.ico`，脚本可复现） | 无品牌资源时先用默认；现已按安装包反馈补齐 |
| 安装目录 | 默认 `%LOCALAPPDATA%\Programs\资源管理器`；`build/installer.nsh` 覆盖 `APP_FILENAME` | 可执行文件保持 ASCII；中文仅用于安装目录与显示名 |
| 依赖归类 | 渲染层依赖移 devDependencies，仅 main 运行时依赖（electron-log/dayjs）留 dependencies | Vite 已打包渲染层；避免 asar 从 197.9MB 膨胀到 9.8MB |

## 8. 风险

| 风险 | 表现 | 缓解 |
|------|------|------|
| PyInstaller 漏包（uvicorn 协议/loop、watchdog、pypdfium2） | 冻结后端启动即崩 | spec 显式 hiddenimports；**release 冒烟强制通过** |
| 冻结态 migrations 路径错 | 首启空库/迁移失败 | `sys._MEIPASS` 路径 + 冒烟断言 DB 文件与表存在 |
| userData 中文路径 | 工具/脚本异常 | 显式 ASCII userData；productName 仅用于显示 |
| electron-builder 下载失败 | 本地/CI 构建卡住 | 文档给镜像 env；CI 缓存；失败即报错 |
| 安装包体积/杀软误报 | 下载/安装受阻 | SHA256 + 文档说明未签名；后续可签名 |
| 开发态被生产分支破坏 | `pnpm dev` 起不来 | 仅 `app.isPackaged` 分支；T6 回归手验 |

## 9. 测试与验收

- 自动（本地与 CI）：R1 门禁（typecheck/lint/pytest）、T1 冻结后端冒烟、T2 产物与 SHA256、T3 版本/命名一致
- 手工：T4 干净机器安装启动（或 CI artifact 下载后本机安装）、T5 zip 解压启动、T6 `pnpm dev` 回归
- 通过标准：`pnpm release:win` 零退出且 `release/SHA256SUMS.txt` 生成；安装后窗口出现、可导入并打开一张图片
