# 生产打包与校验流水线 · 需求

> 状态：**已定稿**（L1 · 2026-10-07，五项范围已确认）
> Feature ID：`production-packaging`
> 复杂度判定：**命中 L2**（跨主进程/生产路径/后端冻结/构建校验/CI，新契约与多个新文件）→ 设计见 `设计.md`

## 1. 背景

当前只有开发态：`electron-vite build` 产出 JS，Electron 主进程用仓库内 venv 的 `python -m uvicorn` 启动后端；无 electron-builder、无安装包、无 CI、无产物校验。目标是让应用能在**未安装 Python/Node 的 Windows 机器**上安装并运行，且打包与校验一条命令完成、失败即阻断。

## 2. IN / OUT（待四项确认后定稿）

| 做 | 不做 |
|----|------|
| Windows x64 生产包（形态见 Q1） | macOS / Linux 安装包（todo P5 后置） |
| 后端冻结为独立可执行（方式见 Q2），随包分发 migrations | 运行时依赖用户机器上的 Python |
| 生产态主进程改为启动随包后端；数据库/日志落 `%APPDATA%`（见 Q4） | 代码签名证书 / 公证（无证书，接受 SmartScreen 提示） |
| 一条命令完成：门禁 → 前端构建 → 后端冻结 → 安装包 → 校验 | 自动更新（v1 OUT） |
| 校验：产物存在性、版本一致、SHA256、冻结后端启动 + `/health` 冒烟 | 多平台图标资产（v1 仅 Windows `.ico` + 预览 png） |
| 版本单一来源；产物命名含版本 | 安装/卸载的无人值守 CI 冒烟（v1 可先手工，见 Q3） |
| 开发态行为完全不变 | 遥测/崩溃上报 |

## 3. 验收（草案）

- **US-P.1** 干净 Windows 机器（无 Python/Node）安装后启动：窗口出现、后端健康、可导入一张图片并在网格看到
- **US-P.2** 数据库、日志、缩略图在 `%APPDATA%/<app>`；升级/重装不丢库
- **US-P.3** 开发态 `pnpm dev` 行为与现在一致
- **US-P.4** `pnpm release`（暂名）一条命令产出安装包 + `SHA256SUMS.txt`；任一步失败则非零退出
- **US-P.5** 冻结后端可独立启动：指定临时 DB + 端口，`GET /health` 200，退出码可控
- **US-P.6** 安装包版本号与 `package.json` 一致；产物名含版本与架构

## 4. 已确认决策（2026-10-07）

1. **产物形态**：NSIS 安装包（per-user、可选安装目录、开始菜单、卸载）+ 绿色版 zip（免安装解压即用），同一构建产出
2. **后端随包**：PyInstaller onedir（`source-manager-backend.exe` + `_internal/`），随包分发 migrations；用户机器无需 Python
3. **校验流程**：本地一键脚本 + GitHub Actions（windows-latest）构建并上传 artifact；自动校验 = 门禁 + 冻结后端启动/`/health` 冒烟 + SHA256；安装/卸载冒烟 v1 不自动化
4. **数据/日志**：`%APPDATA%`（Electron userData）下的 ASCII 目录 `local-resource-manager`；卸载不删用户数据
5. **版本与命名**：version `0.1.0`；productName 中文「资源管理器」；appId `com.myloveou.local-resource-manager`；产物/可执行文件用 ASCII 名
6. **签名与图标**：无证书、不签名（接受 SmartScreen 提示）；不自动更新；应用图标已自绘（`build/icon.ico`，生成脚本 `build/generate-icon.py`）
7. **安装目录**：默认 `%LOCALAPPDATA%\Programs\资源管理器`（与软件显示名一致；可执行名保持 ASCII）
