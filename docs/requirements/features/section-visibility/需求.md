# 分区/功能可见性配置 · 需求

> 状态：**已定稿**（L1 · 2026-10-07，四项范围已确认）
> Feature ID：`section-visibility`
> 复杂度判定：**命中 L2**（新跨切面配置 + 菜单/路由/首页/导入多处消费，≥5 文件，新抽象）→ 设计见 `设计.md`

## 1. 背景与问题

当前左侧菜单一次性暴露全部 13 个分区（首页、图片、视频、番剧、AV、音频、小说、游戏、模型、漫画、工作目录、合集、回收站）。其中部分分区的能力**未实现或未完整实现**（如 AV 刮削、番剧/AV 第二刀、小说/漫画内置阅读器、模型仅 gltf/glb 预览），菜单里仍占位，造成误导与注意力浪费。

需要一种**代码级配置**（改 TS 常量、重启生效；不是设置页开关）来控制隐藏分区/功能入口。

## 2. IN / OUT

| 做 | 不做 |
|----|------|
| 单一代码配置文件列出隐藏的分区 key（按路由 path） | 设置页运行时开关、环境变量、按用户/环境切换 |
| 左侧菜单不渲染隐藏项 | 删除路由/删除页面代码/删除类型 |
| 直接访问隐藏分区的 URL 被拦截（重定向首页） | 后端 API / 表 / 数据变更（资源仍在库，取消隐藏即恢复） |
| 首页概览不展示隐藏类型的统计卡 | 搜索/合集混排过滤隐藏类型（v1 OUT） |
| 导入向导不提供隐藏类型的导入选项 | 隐藏分区内更深层功能的细粒度开关（批量打标、获取元数据等） |
| 未配置时行为与现状完全一致 | 修改 `TYPE_PROFILES` 数据模型/资源类型本身 |

## 3. 用户故事与验收

- **US-V.1** 在配置文件中加入 `'/av'` → 左侧菜单无「AV」；地址栏 `#/av` → 回首页；导入向导类型选项无「AV」；首页概览无 AV 卡
- **US-V.2** 配置为空 → 菜单、路由、导入、首页与当前完全一致
- **US-V.3** 配置了不存在的 key → 忽略，不报错
- **US-V.4** 隐藏某类型后，该类型资源仍可被搜索/合集引用（v1 明确不过滤）
- **US-V.5** 取消隐藏并重启 → 恢复完整入口，数据无迁移

## 4. 已确认决策（2026-10-07）

1. **隐藏链路**：全链路——菜单 + 路由拦截 + 导入向导 + 首页概览卡；搜索/合集混排 v1 不过滤
2. **首份隐藏清单**：`/av`、`/novel`、`/comic`、`/game`、`/model`
3. **表现与拦截**：直接隐藏（不灰显）+ `router.beforeEach` 重定向首页
4. **粒度**：v1 只按分区（配置 key = 路由 path）；单功能开关后续按需扩展
5. **配置形态**：单一 TS 常量 + 纯谓词，重启生效；未知 key 忽略；首页 `/` 不可隐藏（避免重定向死循环）
