# 平台债 · 设计（L2）

> 状态：**已定稿**（2026-09-27 · Q1–Q5 通过，`D-20260927-06`）。已据此写出 `实现方案.md`（L3）并落地。
> L1 见 [需求.md](需求.md)。本文件只覆盖 **D2 token 校验** 与 **D4 事件循环**；D1/D3 已落地，不在此重复设计。
> 约束来源：`openspec/baseline.md`、`docs/design/02-数据模型.md`、`docs/design/03-API设计.md`

## 1. 设计原则

1. **不新分层**：token 校验落在后端 `shared`（跨子应用横切），不塞进 `library/scrape/download` 各自 `api/`。
2. **契约不变形**：401 仍走既有信封 `{code,status,message,data}`，前端 `notify.fromError` 自动出「无访问权限」文案（`mapHttpError` 已支持 401/403）。
3. **不破坏既有能力**：媒体渲染是现网主路径，鉴权不得以「图片全裂」为代价（见 §3）。
4. **D4 只做"不堵"**：把同步 IO 移出事件循环，不改导入的业务语义（仍复制进 owned 包、仍 sha256 去重、仍一次性）。
5. **明确不做**：登录态、权限模型、远程后端、把导入搬进程（Q4 若选另立项）。

## 2. D2 · 模型与不变量

### 2.1 组成

| 要素 | 内容 |
|------|------|
| 凭证 | 单一共享 token，主进程启动时生成随机值 → 子进程环境变量 `BACKEND_TOKEN` |
| 传递 | 渲染进程经 `additionalArguments` 拿到 → axios 拦截器加 `Bearer`（**已实现，不改**） |
| 校验点 | ASGI 中间件（建议 `shared/middleware/auth.py`），在 `wrap_json_envelope` 之内/之外需明确顺序 |
| 豁免 | 白名单路径前缀，配置化到 `shared/constants.py`（沿用 baseline「不变量集中」约定） |
| 失败 | 401 + 信封；不泄露 token 是否存在 |

### 2.2 不变量

- 豁免清单是**唯一**的放行来源；不得在路由内写 `if path == ...`。
- 校验发生在业务路由之前；不依赖任何数据库状态（启动早期即可用）。
- 日志只记 `path + 401`，**不记**收到的 token 值。

### 2.3 状态机（token 配置态）

```
启动
 ├── BACKEND_TOKEN 非空 ──► 强制校验模式（默认，Electron 路径）
 └── BACKEND_TOKEN 为空 ──► Q1 决定：
        (a) 拒绝所有非豁免请求（安全默认）
        (b) 视为未启用鉴权（开发便利）+ 启动日志 WARN
```

## 3. D2 关键取舍：媒体端点（Q2）

`img` / `video` / `model-viewer` 的 `:src` 直连后端，**无法附加请求头**。三条路线：

| 路线 | 做法 | 代价 | 风险 |
|------|------|------|------|
| **A 豁免媒体端点** | 把 media content 与 `proxy-image` 加入豁免白名单 | 改动最小，前端零改动 | 本机任意进程可读媒体字节（但需先知道资源 id；后端仍只绑 127.0.0.1） |
| **B 前端取 blob** | axios 拉 `arraybuffer` → `URL.createObjectURL` | 鉴权完整 | 大图/视频内存与实现成本高，视频拖动体验差；改动面大 |
| **C 签名 URL** | 后端下发带 `exp`+`sig` 的短期媒体链接 | 鉴权完整、语义清晰 | 新机制：签名发放/校验、缓存与过期策略，工作量最大 |

**建议**：本刀取 **A**，并把「豁免端点的取舍」记进 `decisions.md`；B/C 另立项。理由是后端只绑 `127.0.0.1`，威胁模型是"本机其它进程"，与"同机读文件"能力差距有限；而 B/C 会显著拖慢媒体主路径。

> 若你选 B 或 C，`实现方案.md` 的文件清单与验收（A5）都会明显不同，请在确认时指明。

## 4. D2 · 交互（失败态）

| 触发 | 呈现 |
|------|------|
| 应用内 401（理论上不该出现） | `notify.fromError` → Toast「无访问权限」；开发者从日志查 token 注入 |
| 开发态裸跑后端 + 选 (a) | 前端首次请求即 401，提示指向「后端未注入 token」的排障文案 |
| `/docs` 无 token | 正常打开（豁免），便于排障 |

## 5. D4 · 模型与不变量

### 5.1 判定规则（写进编码约定）

> 后端 `async def` 内**不得**直接调用同步阻塞 IO（`os.walk`、`shutil.*`、`subprocess.run`、`PIL.Image.open`、`Path.stat` 之外的批量遍历）。必须 `await asyncio.to_thread(...)` 或改异步实现。

### 5.2 落点

| 位置 | 处理 |
|------|------|
| `ingest/placement.py::comic_pages()` | 调用点改 `await asyncio.to_thread(comic_pages, root)` |
| `ingest/placement.py::find_launch()` | 调用点改 `await asyncio.to_thread(find_launch, root)` |
| 其余已在 `to_thread` 的调用 | 纳入清单核对，不改写 |
| 新增检查 | `实现方案.md` 附「事件循环阻塞点核对表」；改后端时逐项勾 |

### 5.3 备选（Q4）

| 方案 | 说明 | 取舍 |
|------|------|------|
| **本刀：补齐 to_thread + 清单** | 最小改动，直接消除已定位的两处 | 未来新增代码仍可能回退，靠约定与核对表约束 |
| 另立项：导入独立 worker 进程 | 导入彻底隔离 | 架构级：进程生命周期、DB 写并发（SQLite WAL）、进度回传都要重设计 |

**建议**：本刀取前者；后者写入 `docs/product/后续能力规划.md`，作为独立立项。

## 6. 切片与契约

按「UI / 功能 / 算法」三段，本能力无算法切片。

| 切片 | 提供什么 | 落点 | 依赖 |
|------|----------|------|------|
| **功能·鉴权** | `require_token` 中间件 + 豁免表（配置化） | `shared/middleware/auth.py`、`shared/constants.py` | `Settings.token` 环境变量映射修正 |
| **功能·导入并发** | 两处调用改 `to_thread`；核对表 | `library/application/import_service.py` | 无 |
| **UI·失败态** | 无需新 UI；复用 `notify.fromError` | 无新增文件 | 功能·鉴权 |
| **测试·契约** | A1–A6、B1–B3 的可执行形式 | `apps/backend/tests/test_auth.py`（新）、既有测试调整 | 功能两片 |

**组合根**：无页面改动；组合发生在 `app/main.py`（中间件装配顺序）+ 既有 axios 拦截器（已带 Bearer）。因此本能力的"交付"= 中间件生效 + A5 应用内主路径手验通过，而非某一屏 UI。
