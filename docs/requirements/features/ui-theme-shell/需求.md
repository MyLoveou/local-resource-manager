# 壳层 UI 模块化与主题 · 需求

> 状态：**已定稿**（开放问题按默认假设关闭，D-20260918-01）  
> OpenSpec：`openspec/changes/ui-theme-shell/`  
> 对齐：facts 壳分层 `ui/`；module-map「主题 vs 设计系统」；三栏信息栏默认不折叠（L1）  
> **禁止编码**，直至用户说「可以按此实现」。施工图：`实现方案.md`。

## 1. 背景

当前桌面壳「能用」：naive-ui 默认皮肤；颜色写在 `variables.less`（编译期）和组件内硬编码（如 ToolBar `#fff`、InfoPanel 大量局部色）。没有：

- 运行时主题（换一份 CSS 即换肤）
- 设计令牌与 naive-ui 的统一入口（未使用 `NConfigProvider`）
- 布局模块边界：批量操作塞在网格上方一条窄工具条；元数据面板单列长表单，封面/技术字段/编辑区/操作挤在一起

module-map 把「主题系统」标在 A-plus。用户要求**现在**做壳层可换肤 + 模块化，并顺手改批量删除位置、信息栏布局。本切片把主题从「更晚」提前到壳层独立能力，**不等于**做设计系统资产管理（提示词/Skill/导出仍远期）。

## 2. 要解决的问题

| 用户感知 | 现状 |
|----------|------|
| 换主题只能改源码重编 | less 变量编译死；不能加载外部 css |
| 皮肤和业务页缠在一起 | 布局/按钮色散落 `layouts` 与业务组件 |
| 批量删除不好找 | `ResourceBrowser` 网格顶一条，和空态/滚动抢位置 |
| 信息栏难扫 | 封面、季集、码率、描述、待办、保存删除同一滚动流 |

## 3. 范围

### IN

- **主题契约**：一套 CSS 自定义属性（令牌）覆盖壳层背景/文字/边框/主色；内置 default + dark
- **加载外部 CSS**：用户选择本机一份 `.css` 后应用到整个壳（含 naive-ui 映射）；可还原内置
- **模块化**：令牌与布局槽位进 `ui/`；业务页只消费槽位（三栏壳 + 顶栏批量 + InfoPanel；不重写 overlay）
- **批量操作位置**：顶栏 ToolBar 右侧
- **元数据面板布局**：身份 / 技术 / 编辑分区；操作区固定底部；三栏、信息栏默认不折叠

### OUT

- 设计系统资产库、主题工坊上架、云同步主题
- 完整重做所有 overlay 视觉
- 自定义拖拽改三栏比例
- 后端 API / 表结构
- 与 `library-type-platform` 同一 PR

## 4. 更高层模型

| 概念 | 用户看见 | 系统里是 |
|------|----------|----------|
| 令牌 | 颜色/圆角/间距变了 | `:root` 上 `--sm-*` |
| 主题包 | 一份 css | 内置或用户绝对路径 |
| 布局槽 | 顶栏/侧栏/主区/信息栏/批量条 | `ui/layouts`，不按 type 分叉 |
| 信息栏分区 | 封面+标题；只读技术；可编辑；底部操作 | 同一 InfoPanel 内 section |

不变量：换主题不改资源数据、不改导入/播放行为。

## 5. 用户故事

### 换内置主题

- **GIVEN** 应用已启动  
- **WHEN** 在顶栏「主题」选择默认或暗色  
- **THEN** 壳层与按钮主色立即切换，刷新后仍是所选主题

### 加载本机 CSS

- **GIVEN** 用户有一份符合令牌注释的 `.css`  
- **WHEN** 选择该文件作为当前主题  
- **THEN** 文件中的 CSS 变量覆盖壳层；文件无效或读失败时提示并保持上一套可用主题

### 批量删除位置

- **GIVEN** 类型网格有资源  
- **WHEN** 进入批量模式或已有需批量的操作  
- **THEN** 入口在顶栏右侧，网格卡片从主区顶部排起

### 信息栏分区

- **GIVEN** 选中一条资源  
- **WHEN** 查看右侧面板  
- **THEN** 封面与标题在上；技术只读成组；描述/作者/标签/待办成组；保存/编辑/回收站固定底部
