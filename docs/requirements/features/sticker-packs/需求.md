# 表情包 / 贴纸包管理 · 需求

> 状态：**L1 草案，待拍板**（2026-10-24）  
> Feature ID：`sticker-packs`  
> 关联调研：`docs/requirements/features/ai-search/增强能力调研.md`（远程能力部分）  
> 说明：本文只记录需求与边界，不代表已进入开发，也未改变“本地优先”的产品定位。

## 1. 背景

当前应用已经有图片导入、缩略图、标签、分类、合集、搜索、回收站和 AI 检索能力，但没有专门的表情包/贴纸包管理入口。

用户希望：

- 把散落在文件夹里的表情包整理成可浏览、可搜索的本地贴纸库
- 按套组、角色、作品、情绪和来源组织
- 快速复制到剪贴板，贴到聊天工具
- 后续能在多台设备之间备份或同步贴纸包

调研结论：OhMyMeme、SuzuEmojy 等产品已经验证了本地表情包管理的可行性；OhMyMeme 还验证了 S3/WebDAV 等远程同步方案。但它们的代码许可证和本项目不兼容，不能直接复用。

## 2. 目标

1. 在不破坏现有资源库的前提下，提供一个**可选的贴纸包模块**。
2. 复用现有图片资源、缩略图、标签、搜索和去重能力。
3. 支持贴纸包级导入、组织、查找、复制和导出。
4. 为后续远程备份/同步预留清晰的数据边界。
5. 不把应用改造成完整的聊天表情客户端。

## 3. 用户场景

- 从本地文件夹导入一个画师/角色/聊天平台的贴纸包
- 给贴纸打情绪、角色、作品、来源标签
- 搜索“无语”“猫猫”“某角色”并快速复制
- 把一套贴纸导出给朋友或迁移到另一台电脑
- 在另一台电脑恢复贴纸包和标签

## 4. 范围

### IN

- 文件夹导入、ZIP 导入
- 以文件夹/压缩包为单位创建贴纸包
- PNG、JPG、GIF、WebP、APNG
- 贴纸包封面、名称、来源、简介
- 贴纸包套组 / 分组
- 标签：情绪、角色、作品、来源、自由标签
- 网格浏览、动图预览、键盘切换
- 一键复制图片/文件到剪贴板
- SHA-256 去重、dHash 近似重复提示
- 贴纸包导出 ZIP
- 贴纸包重新导入/恢复
- 全局搜索包名和标签
- 回收站、删除、恢复
- 可选模块可见性（默认不进入照片时间线和地图）

### OUT（第一版）

- QQ、微信、Telegram、抖音客户端缓存自动抓取
- `.tgs` Lottie、`.webm` 视频贴纸转码
- 聊天窗口自动发送、自动粘贴 Enter
- 插件系统
- 云端直用（未下载的远端贴纸直接展示和点击使用）
- 多设备实时双向同步
- 移动端
- 贴纸商店、公开分享、社区
- 直接把 SQLite 数据库放进网盘目录

## 5. 产品定位

**不是完整复刻 OhMyMeme。**

本项目的差异化是：

- 贴纸包是统一资源库的一部分，而不是独立聊天工具
- 复用角色、作品、标签、合集和 AI 能力
- 本地优先，远程只作为可选备份/同步
- 先做“整理和取用”，不先做聊天平台集成

建议形态：

- 一级入口“表情包”，可被 `HIDDEN_SECTIONS` 隐藏
- 独立页面，不混入照片时间线、地图
- 全局搜索可检索包名和标签，但默认不把贴纸混入图片网格

## 6. 功能拆分

### S1 · 本地贴纸包

1. 文件夹导入：同名文件夹自动成为一个贴纸包
2. ZIP 导入：读取 `manifest.json`；无清单时按目录结构推断
3. 单张图片导入：进入“未分类”贴纸包
4. 贴纸包 CRUD：名称、封面、简介、来源
5. 贴纸 CRUD：加入/移出包、排序、删除、恢复
6. 网格与预览：GIF/WebP 动图预览，悬停放大
7. 标签：批量打标、标签筛选、包名/标签搜索
8. 复制：复制文件或位图到剪贴板；动图尽量保留动画
9. 去重：SHA-256 完全相同直接跳过；dHash 提示近似图
10. 导出：单包 ZIP + `manifest.json`

### S2 · 工作流增强

1. 拖拽导入
2. 剪贴板粘贴导入
3. 批量移动、批量打标、批量导出
4. 未分类池
5. 最近使用、收藏
6. 导入预览与冲突处理
7. 贴纸包重命名/合并
8. 包级封面自动推荐

### S3 · 远程备份 / 同步

第一阶段只做**包级备份/恢复**，不做数据库实时同步：

- 清单 `manifest.json`：包 ID、名称、版本、文件 SHA-256、大小、MIME、更新时间
- 文件按 SHA-256 内容寻址上传
- 支持 WebDAV 优先，S3 兼容存储第二
- 上传缺失/变更文件；下载缺失文件
- 显示同步状态：已同步、缺失、冲突、失败
- 恢复前校验文件哈希
- 冲突时以贴纸包为单位提示用户选择，不做静默合并

后续如果确有需求，再评估：

- 云端直用 / 按需下载
- 局域网设备同步
- 多端双向同步
- 贴纸包分享链接

### S4 · 可选 AI

- 用现有 AI 能力搜索贴纸（文搜图/以图搜图）
- 自动建议情绪、角色、作品标签
- 不自动写入，需用户确认

## 7. 数据模型建议

第一版不新增 `ResourceType`，避免影响现有类型页、导入向导、时间线和地图。

建议复用：

- `resources`：图片资源、标题、缩略图、文件、回收站
- `resource_tags` / `tags`：情绪、角色、作品、来源
- 现有 `files` / `resource_files`：主文件与缩略图

新增贴纸域表：

```text
sticker_packs
  id
  name
  description
  cover_resource_id
  source
  sort_order
  created_at
  updated_at

sticker_items
  id
  pack_id
  resource_id
  position
  format
  animated
  width
  height
  sha256
  created_at

sticker_pack_tags
  pack_id
  tag_id
```

约束：

- `sticker_items.resource_id` 唯一：一张图片只属于一个贴纸包
- 删除贴纸包默认只删关系，不删资源；资源仍可按现有回收站规则处理
- 包级标签与资源级标签分开，避免污染现有标签筛选
- 包封面必须来自 active 资源

## 8. 远程同步设计边界

### 为什么不直接同步 SQLite

- SQLite WAL 有锁和事务状态，直接放网盘/多端同步会损坏或冲突
- 贴纸包是“文件 + 元数据”的组合，按包级清单同步更安全
- 第一版采用“本地权威 + 远端备份”，不是双向实时数据库

### 清单示例

```json
{
  "version": 1,
  "packId": "sticker-pack-uuid",
  "name": "猫猫表情",
  "updatedAt": "2026-10-24T00:00:00Z",
  "files": [
    {
      "sha256": "…",
      "path": "cat/001.gif",
      "size": 12345,
      "mime": "image/gif"
    }
  ]
}
```

### Provider 顺序

1. WebDAV（Nextcloud、坚果云、Alist 等）
2. S3 兼容（MinIO、R2、B2、OSS）
3. 其他厂商 API 后续再评估

第一版不做 FTP。FTP 明文传输、错误处理弱，不适合作为默认远程方案。

## 10. 验收标准

### 本地

- [ ] 导入一个包含 100 张图的文件夹，自动创建一个贴纸包
- [ ] 重复图片 SHA-256 相同不会重复入库
- [ ] 近似图片能被提示，但不自动删除
- [ ] 重启应用后贴纸包、标签、排序、封面保持
- [ ] 搜索包名/标签能找到贴纸
- [ ] GIF/WebP 可预览，复制后聊天工具能识别
- [ ] 导出 ZIP 后可在另一台机器重新导入
- [ ] 删除贴纸包不误删原始资源
- [ ] 贴纸不出现在照片时间线/地图

### 远程

- [ ] 配置 WebDAV/S3 能测试连接
- [ ] 上传只传缺失/变更文件
- [ ] 下载后哈希校验通过
- [ ] 冲突时提示用户，不静默覆盖
- [ ] 远程失败不阻塞本地使用

## 11. 待确认问题

1. 一级入口叫“表情包”还是“贴纸包”？
2. 第一版是否必须支持 ZIP 导入，还是先只支持文件夹？
3. 复制优先级：复制位图还是复制原文件？GIF 动图如何处理？
4. 远程同步第一选择 WebDAV 还是 S3？
5. 是否需要兼容 OhMyMeme/SuzuEmojy 的导出包？没有公开格式则不做。
6. 贴纸包是否参与全局 AI 索引，还是独立索引？
7. 是否需要“未分类”池和收藏作为第一版必需项？

## 12. 里程碑建议

- **M1**：本地导入、包/标签、网格、复制、导出
- **M2**：批量、去重、拖拽/剪贴板、未分类
- **M3**：WebDAV/S3 包级备份与恢复
- **M4**：AI 标签建议、以图搜图
- **M5**：再评估多端同步和云端直用
