# 提示词管理（Prompt Studio）· 需求草案

> 状态：**分析中**（2026-11-10）｜来源：`PromptForge-交接包`（743 KB 单文件 HTML）
> 目标：把 PromptForge 的能力并入本应用，并补上它最缺的一样东西——**可保存、可检索、可备份的提示词库**。

## 1. 背景

PromptForge 是一个面向 Stable Diffusion 的单文件提示词工具，能力完整（标签库、角色库、预设、模板、反向、体检、ComfyUI 生图），但数据全部存在浏览器 `localStorage`：

| 现状 | 问题 |
|---|---|
| 数据在 `localStorage`（`pg_forge_v1` / `pg_saves_v1` / `pg_custom_v1` …） | 清缓存即丢；换浏览器/换机器要手工导出导入 |
| 无服务端 | 无法与本地媒体库联动（作品、角色、标签） |
| ComfyUI 需同源部署或本地代理 | 跨站 403，部署门槛高 |

本应用已有 SQLite、角色库、标签体系、备份与更新机制，正好补上这些缺口。

## 2. PromptForge 能力清单（需 100% 覆盖的部分）

| 模块 | 规模 | 说明 |
|---|---|---|
| 标签库 | 2742 个 / 25 分类 | 中英文 + 全拼/首字母搜索；收藏、最近、权重（Shift 1.2） |
| 角色库 | 1401 个 / 40+ 作品 | 游戏/番剧/VTuber 分组，收藏，套用带外观标签 |
| 预设 | 299 个 / 14 类 | 叠加组合、自建预设 |
| 模板 | 12 个 | 角色卡、四格漫画、海报、封面等，含 MOSS 布局 JSON |
| 反向生成 | 标准 75+ / 全量 110+ | 按正向推导负面，含冲突互斥 |
| 体检 | 8 项 | 缺主语、缺质量词、正负重复、冲突、数量等，可一键修复 |
| 历史 | 40 条 | 置顶、两条对比、与当前对比 |
| 输出 | 前缀/锁定 | Anima 质量前缀；输出锁定后可手改 |
| 双体系 | Anima / MOSS | 标签流 vs 自然语言 + 布局 |
| 生图 | ComfyUI | 整合包 / UNET 分离，参数预设，画廊 30 条 |
| 导入导出 | JSON | 整体备份迁移 |

## 3. 本应用要新增的能力（PromptForge 没有的）

1. **提示词存档**（核心）：保存为一条记录——标题、模型体系、正向、负面、参数、标签分类、备注、收藏、创建/修改时间
2. **统一检索**：站内搜索（中文/英文/拼音）覆盖存档、自定义标签、预设
3. **与媒体库联动**：存档可关联作品/角色；角色选择器可合并本地「角色」模块
4. **可靠存储**：进 SQLite，纳入现有备份/导出机制；不再依赖浏览器缓存
5. **版本历史**：存档的修改留痕（可选，P2）

## 4. 数据模型（草案）

```sql
-- 内置库（可选方案：JSON 打包 + 启动时索引，避免每次升级都写迁移）
prompt_tags(id, en, zh, category, aliases, weight_hint, nsfw)
prompt_characters(id, name, work, group, tags_json)
prompt_presets(id, name, category, tags_json, layout_json)
prompt_templates(id, name, kind, tags_json, layout_json)

-- 用户数据（必须入库）
prompt_saves(id, title, model, positive, negative, params_json, note,
             tags_text, favorite, created_at, updated_at, resource_id?)
prompt_save_tags(save_id, tag)            -- 便于按标签筛存档
prompt_custom_tags(id, en, zh, category, created_at)     -- 用户自建标签
prompt_custom_presets(id, name, category, tags_json, created_at)
prompt_history(id, save_id?, positive, negative, model, pinned, created_at)
prompt_settings(key, value)               -- 模型选择、前缀、主题、ComfyUI 地址
prompt_gallery(id, save_id?, image_path, params_json, created_at)  -- 生图结果（P3）
```

内置库与用户库用 `source` 区分（`builtin` / `user`），升级内置库时不覆盖用户条目。

## 5. 三种实现路线

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A 内嵌** | 把 743 KB HTML 放进应用，用 webview/iframe 打开 | 功能立刻齐全，零重写 | 数据仍在 localStorage；两套 UI；无法检索与备份 |
| **B 原生化** | 前端 Vue 页面 + 后端 SQLite/API，复用其数据 | 数据统一、可检索、可备份、能与媒体库联动 | 工作量大（相当于重写一个中型模块） |
| **C 混合** | 先内嵌可用，再逐步把「存档/标签选择/预设」原生 | 快速见效，风险低 | 过渡期两套数据，需一次导入迁移 |

**建议 C**：先用 A 让功能可用，同时把用户最痛的三件事（保存、搜索、备份）用原生实现；标签/角色选择器再原生化。

## 6. 分期与验收

| 期 | 内容 | 验收 |
|---|---|---|
| P0 | 路由 `/prompts` + 内嵌 PromptForge；存档表 + 保存/列表/删除 API；从 localStorage 导入 | 能把当前提示词存成一条记录，重启应用仍在；能导入旧导出 JSON |
| P1 | 原生存档页：列表、搜索、标签筛选、复制、编辑；导出/导入兼容 PromptForge 格式 | 搜索命中中文/英文/拼音；导出后可被 PromptForge 导入 |
| P2 | 原生标签选择器与预设/模板（数据来自内置 JSON）；反向生成与体检 | 不打开 HTML 也能拼出完整提示词 |
| P3 | ComfyUI 经后端代理（免 CORS）；生图结果入 `prompt_gallery`，与存档关联 | 应用内出图并可回看 |

## 7. 风险与待定

| 体积 | 743 KB HTML + 约 300 KB 数据；打包进安装包需评估 |
| 升级维护 | 内置库更新要不要跟版本走？还是允许用户手动导入新库 |
