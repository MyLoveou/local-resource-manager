# 主题令牌 · 需求

> 状态：**已定稿**（2026-09-27 · 轮次 1 即收口；方向与 Q1–Q4 均由 `D-20260927-04` 一并通过）
> 来源：`quality-and-deploy` 的 S3 切片（该文件已定稿为边界结论，实施范围以本文件为准）
> 上游：`D-20260918-01` 壳层换肤（内置 default/dark + 一份本机 css，≤256KiB）

## 1. 问题

外置主题的能力上限 = **令牌面**。现在只有 10 个令牌，且组件里散着硬编码颜色，导致用户写一份 css 也换不彻底：

| 现象 | 证据（2026-09-27 核对） |
|------|--------------------------|
| 令牌被引用但**未定义** | `--sm-color-bg-muted`、`--sm-color-danger` 在组件里被 `var(...)` 引用，但 `ui/styles/tokens.css` 没有定义 → 静默走 fallback，外置主题改不动 |
| 缺状态色 | 只有 `--sm-color-primary`，没有 danger / warning / success / info |
| 缺交互态 | `applyTheme.ts` 把 `primaryColorHover` / `primaryColorPressed` 都设成同一个 primary → 悬停/按下无视觉反馈 |
| 组件硬编码颜色 | 8 个 `.vue` 文件里出现 18 个不同 hex（含与令牌重复的 `#4f46e5` `#6b7280` `#e5e7eb` `#f9fafb`） |
| 缺背景层次 | 只有 page / surface，缺 muted（hover、斑马纹、禁用态） |

结果：用户要做暗色或品牌皮肤时，必须逐个覆盖组件内部颜色，等于重写样式。

## 2. IN

- **补令牌**：状态色（danger / warning / success / info）、交互态（primary hover / pressed、primary 上的文字色）、背景层次（`bg-muted`、hover）、圆角档位（sm / lg，保留现有 control）。
- **清零硬编码**：把组件里写死的颜色改为引用令牌（`transparent` / `currentColor` / `inherit` 例外）。
- **契约化**：`ui/styles/tokens.css` 成为唯一令牌清单（含注释说明"内置主题与用户 css 只应覆盖这些变量"）；`dark.css` 同步补齐所有令牌，不留 fallback。
- **Naive UI 映射同步**：`applyTheme.ts` 的 `readNaiveOverrides` 把新令牌映射到对应的 Naive 变量（至少 danger/warning/success/info 与 hover/pressed）。

## 3. OUT

- 主题市场、多文件叠加、远程皮肤、按组件粒度的皮肤。
- 设计系统资产库（皮肤 ≠ 设计资产）。
- 字号 / 行高 / 阴影 / 动效时长的令牌化（第一刀不做，留在后续）。
- 主题入口从顶栏迁进设置页（`D-20260918-01` 明确入口在顶栏）。

## 4. 验收（可测）

| ID | 场景 | 判据 |
|----|------|------|
| T1 | 扫描令牌引用 | `rg -o "var\(--sm-[a-z0-9-]+" apps/desktop/src/renderer/src` 得到的每个名字，都能在 `tokens.css` 找到定义（**0 个未定义**） |
| T2 | 扫描硬编码颜色 | 组件 `.vue` 中不再出现颜色字面量（白名单仅 `transparent` / `currentColor` / `inherit`） |
| T3 | 外置 css 生效面 | 写一份**只覆盖令牌**的 css，能把主色、危险色、背景层次、圆角全部改掉；刷新后保持 |
| T4 | 内置主题完整性 | `default` 与 `dark` 两套主题下所有令牌都有值，界面上不出现 fallback 色 |
| T5 | 回归 | `pnpm --filter desktop typecheck` 通过；主题切换与失败回滚行为与 `ui-theme-shell` 一致（失败回滚到上一套） |
| T6 | 组件观感不回退 | 默认主题下抽查：ToolBar、网格卡片、信息栏、设置弹窗、下载抽屉、导入向导 —— 与改动前视觉一致 |

| # | 问题 | 结论 |
|---|------|------|

## 6. 非功能

- 令牌数量控制在可手写的规模（目标 ≤ 30 个），避免变成设计系统 DSL。
- 外置 css 上限 256KiB 与失败回滚沿用既有实现，不改。
- 改令牌不得引入运行时开销（仍是 CSS 变量 + Naive overrides）。
