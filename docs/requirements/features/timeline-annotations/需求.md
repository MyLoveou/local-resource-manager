# 时间线备注与地点 · 需求

> 状态：**评审中（L1 草案）** · 2026-10-19
> Feature ID：`timeline-annotations`
> 上游：`photo-timeline-map`（时间线/EXIF/未知时间）、`timeline-hub`（保存时间线）、`library-workspace`（资源库）
> 复杂度判定：**命中 L2**（新备注实体/表/迁移、时间线 API、前端时间线交互、地点来源与隐私）→ 本文件只定 L1，需求确认后写 `设计.md` 并 STOP

## 1. 背景

当前时间线已经能按拍摄日聚合照片/视频，并支持保存筛选规则。但用户还不能给「某一天」或「某条时间线」补充人类语义：

- 旅游时想在某天写下「到东京」「住新宿」，而不是只给每张照片单独写描述；
- 漫展时想在某天记下「C104 Day1」「场馆：东京 Big Sight」；
- 保存的「2026 日本行」时间线本身也需要一句备注/地点说明；
- 照片 EXIF 有 GPS 时，希望地点能和日期放在一起看，而不是散落在每张图的信息栏。

目标：在**不破坏 Resource/File 原数据**的前提下，为日期和时间线增加轻量备注与地点信息。

## 2. 推荐 v1（待确认）

| 做（推荐） | 不做（v1） |
|----|--------------|
| 日期备注：时间线某一天可写标题/正文 | 自动识别“旅行/漫展”并命名 |
| 时间线备注：保存的时间线可写标题/正文 | 云端同步、多人协作 |
| 地点：手动地点名 + 可选展示已有 EXIF GPS | 在线反向地理编码（城市/景点名自动补全） |
| 备注编辑/删除、空内容不显示 | 地图打点/轨迹（留给后续地图刀） |
| 备注只存在本地库，不写回照片文件 | 修改/覆盖 EXIF，或伪造拍摄时间 |
| 按现有日期/分类/标签筛选展示 | 资源级地点字段的完整重做 |

> v1 的“地点”优先是**人类可读的地点名**；GPS 只作为已有信息的展示/辅助，不在本刀引入在线地理编码服务。

## 3. IN / OUT

### IN

1. **日期备注**
   - 在时间线的某一天（`takenDate`）添加一条备注；
   - 字段建议：标题（可选）、正文、地点名（可选）；
   - 时间线日标题/日段可显示标题或摘要；点开可编辑；
   - 该日无照片时，是否允许创建备注待定（见开放问题）。

2. **时间线备注**
   - 对某个 `SavedView`（保存的时间线）添加标题/正文/地点；
   - 在时间线列表卡片、详情头部展示；
   - 编辑/删除不改变筛选规则与成员。

3. **地点**
   - 手动填写地点名（如“东京国际展示场”）；
   - 若当天/时间线主文件已有 GPS，可显示坐标或“有 GPS”标记；
   - 地点名与 GPS 分开存储，不用地点名反写 EXIF。

4. **交互**
   - 日期备注入口在时间线日段/日视图；
   - 时间线备注入口在时间线详情/编辑器；
   - 保存后通过既有失效总线刷新，不需要手动刷新页面；
   - 空备注不创建记录；删除后不再显示。

### OUT

- 地图视图、地点聚合、轨迹；
- 反向地理编码、地点搜索/自动补全；
- 把备注写入图片/视频文件元数据；
- 资源级 description/todos 的替代或迁移；
- 多用户、同步、分享；
- 自动行程切分。

## 4. 用户故事与验收（草案）

- **US-A.1** 在时间线某天点“添加备注”，填写标题/正文/地点，保存后刷新页面仍存在。
- **US-A.2** 同一天备注在时间线日段可见；进入该天网格时仍可查看/编辑。
- **US-A.3** 保存的时间线可添加备注，列表卡片/详情头部能看到摘要。
- **US-A.4** 备注可编辑、删除；删除有确认；删除后列表/日段立即消失。
- **US-A.5** 地点名可单独填写；有 EXIF GPS 时可显示坐标/标记，但不会修改原文件。
- **US-A.6** 现有分类/标签/未知时间筛选、时间线排序不受备注影响。
- **US-A.7** 空标题+空正文+空地点不产生记录；不因备注写入而改变资源的 `updated_at`/缩略图/文件。

## 5. 待确认问题（G1）

1. **日期备注的归属**
   - A. 全局日期：同一天在所有时间线共用一条备注；
   - B. 时间线内日期：不同 SavedView 可有不同备注；
   - C. 两者都支持（推荐先选一个，避免模型翻倍）。
2. **一天一条还是多条**
   - 一天一条备注（简单）；
   - 一天多个事件/多段备注（需要排序/列表，模型更接近“事件”）。
3. **地点来源**
   - 只做手动地点名；
   - 手动地点名 + 展示已有 EXIF GPS；
   - 是否允许在线反向地理编码（涉及坐标上传与隐私）。
4. **无照片日期**
   - 允许创建“纯备注日期”，还是只能给已有照片的日期添加备注？
5. **时间线备注字段**
   - 只做正文，还是标题/正文/地点三段？
6. **资源级地点**
   - 是否另行给 Resource/File 增加“用户地点名”；v1 是否保持 OUT？
7. **地图衔接**
   - 备注地点是否需要在后续地图刀中以 marker/聚合展示？

## 6. 数据与约束（记录，不是最终设计）

- 时间线目前是 `saved_views` 规则 + 按拍摄时间查询，无成员表；日期备注不能改变这个模型。
- 已有 `files.exif_taken_at`、`files.exif_lat/lng`；EXIF GPS 是 WGS84，地点名是用户输入，二者语义不同。
- 备注不应写回照片/视频文件，不应修改 `resource.updated_at`；缩略图/列表排序不受影响。
- 时间按本地时间理解；无拍摄时间的资源仍在“未知时间”，不要给未知时间伪造日期备注。
- 备注读取/展示要遵守现有分区可见性与时间线筛选；筛选掉某天时，对应备注不显示。
- 若引入新表，迁移只增不改；需要 L2 定表结构、索引、级联删除（SavedView 删除时日期备注如何处理）。
