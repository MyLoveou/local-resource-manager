# 设计 · photo-timeline-map（L2，v1 时间线）

> 状态：**评审中**（2026-10-18）
> 需求：`需求.md`（方向已确认，回填 GPS 范围待确认）
> 本刀只做**时间线**；地图 UI 下一刀（底图已定 MapLibre+OSM）

## 1. 设计原则

- **时间线是独立视图**：不替代网格；包含合集成员，不受主列表「隐藏合集成员」影响
- **不伪造时间**：无拍摄时间进「未知时间」组；不用导入时间冒充
- **可见性可覆盖**：默认按 EXIF 自动，用户可对单图显式开/关；回填不覆盖手动选择
- **回填只读原图**：重新读 EXIF 写库，不复制、不改原图
- **地图只做准备**：本刀落 GPS 字段与解析（若确认），不做地图 UI/瓦片
- **复用现有分层**：后端 `library` 的 api/application/infrastructure；前端照片页复用 `ResourceBrowser`/`VirtualGrid`/信息栏

## 2. 模型（新迁移 0017）

### 2.1 字段

| 表 | 字段 | 类型 | 含义 |
|----|------|------|------|
| `resources` | `timeline_visible` | INTEGER NULL | 三态：NULL=按 EXIF 自动；1=强制计入；0=强制排除 |
| `files` | `exif_lat` | REAL NULL | WGS84 纬度（primary 文件） |
| `files` | `exif_lng` | REAL NULL | WGS84 经度 |

- 自动规则：`timeline_visible IS NULL` 时，以「primary 文件 `exif_taken_at` 非空」为计入
- 手动覆盖：信息栏开关写入 1/0；回填**不修改** `timeline_visible`
- 不变量：
  - `timeline_visible` 与合集归属无关
  - GPS 为文件级元数据，不改资源主列表过滤

### 2.2 领域/DTO

- `Resource.timelineVisible: bool | null`（effective 值另由 API 计算？见下）
- API `Resource` 增 `timelineVisible: boolean | null`（原始三态）
- `ResourcePatch` 增 `timelineVisible?: boolean | null`（null=恢复自动）
- `ResourceFile` 增 `exifLat/exifLng`（地图刀用，本刀只存不展示）
- 有效可见性（供时间线查询）：`visible = timeline_visible = 1 OR (timeline_visible IS NULL AND has takenAt)`

## 3. 交互

### 3.1 独立「照片」页

- 侧栏新增「照片」（`/photos`，icon `image-multiple`）；与「图片」并存（v1 不合并）
- 页内 Tabs：**网格** / **时间线**
- 网格 Tab：复用 `ResourceBrowser`（type=image）
- 时间线 Tab：
  - 顶部：年/月选择、正序/倒序、「显示全部照片」开关、「回填拍摄时间」按钮
  - 列表：按天分组（日期 + 张数 + 封面缩略图），末尾「未知时间」组（数量 + 封面）
  - 点某天 → `/photos/day/:date`（隐藏菜单）：复用 `ResourceBrowser`，按 `takenDate` 过滤；顶部返回时间线
  - 未知组 → `/photos/day/unknown`

### 3.2 单图可见性

- 信息栏（图片类型）新增「计入时间线」复选框：
  - 显示 effective 状态（自动/显式）
  - 勾选/取消 → PATCH `timelineVisible`（true/false）
  - 提示文案：默认按 EXIF 自动；手动修改后不再跟随
- 时间线「显示全部照片」= 忽略可见性过滤（不是只看被隐藏的）

### 3.3 回填（解释 + 方案）

> 「旧图回填」= 早期导入时没有解析 EXIF 拍摄时间/位置的图片；回填会重新读原图 EXIF，把拍摄时间（及 GPS）写回库内元数据。不复制、不改原图。

- 入口：时间线顶部「回填拍摄时间」（有旧图时才显示/可点）
- 后端：`POST /library/photos/backfill` → 后台线程扫描 active image 的 primary 文件：
  - `Pillow` 读 `DateTimeOriginal` → 更新 `files.exif_taken_at`
  - 读 GPS IFD → `files.exif_lat/lng`
  - 不修改 `resources.timeline_visible`
  - 返回 `{scanned, takenAtUpdated, gpsUpdated, skipped, failed}`（v1 同步等待，前端 spinner）
- 扫描用 `asyncio.to_thread`，避免阻塞事件循环；225 张量级可接受，超大库后续改后台任务

### 3.4 空态/失败

- 无照片：时间线空态，指向导入
- 全部无拍摄时间：全部进未知组 + 回填按钮
- 回填中：按钮 loading；完成 toast 统计
- 单图 PATCH 失败：不改变复选框，notify

## 5. 功能拆分与契约

| 切片 | 提供 | 契约 |
|------|------|------|
| 算法 | EXIF GPS 转换（度分秒→十进制度） | `parse_gps(value, ref) -> float | None`；纯函数，单测 |
| 功能 | 时间线聚合 | `GET /library/photos/timeline?includeAll=&year=&month=` → `{days:[{date,count,coverId,coverThumbnailPath}],unknownCount,total}` |
| 功能 | 按日过滤 | `GET /library/resources?takenDate=YYYY-MM-DD` / `untimed=true` / `timelineVisible=true` |
| 功能 | 回填 | `POST /library/photos/backfill` → `{scanned,takenAtUpdated,gpsUpdated,skipped,failed}` |
| 功能 | 单图开关 | `PATCH /library/resources/{id}` `{timelineVisible: true|false|null}` |
| UI | 照片页/时间线/日网格 | 组合根：`views/Photos` 组装时间线与网格；InfoPanel 开关调功能 |

- 时间线查询只用 active image；合集成员照常计入
- `coverThumbnailPath` 复用后端缩略图 URL 生成（与混排合集卡一致）
- `takenDate` 过滤通过 primary 文件 `substr(exif_taken_at,1,10)`；`untimed` = 无 primary takenAt
- 日网格与时间线计数必须同一过滤规则（visible/includeAll）

## 6. 抽象

- **抽**：EXIF GPS 解析纯函数；时间线聚合 repository 方法；照片页组合根
- **不抽**：不建通用「时间线引擎」；不做地图/瓦片；不做自动行程切分；不把 EXIF 解析放前端

## 7. 决策

| 决策 | 选择 | 为何不选备选 |
|------|------|----------------|
| 可见性 | 三态 NULL/1/0 | 非空布尔无法区分「自动」与「手动开」，回填会覆盖用户选择 |
| 时间线入口 | 独立照片页 | 用户确认；图片分区保留，避免打乱现有入口 |
| 时间线数据 | 后端按天聚合 | 前端分组受分页限制，拿不到全量计数 |
| 日视图 | 复用 ResourceBrowser + `takenDate` | 不重复实现卡片/查看器/信息栏 |
| 回填 v1 | 同步 + `to_thread` + spinner | 225 张量级够用；后台任务下刀 |
| GPS | 本刀落字段与解析（待确认） | 地图刀少扫一遍原图 |

## 8. 风险

| 风险 | 表现 | 缓解 |
|------|------|------|
| EXIF 时间格式/时区 | 部分照片无时间或解析失败 | 未知时间组；回填统计失败数 |
| 回填阻塞 | 大库请求超时 | v1 量级可接受；后续后台任务 |
| 三态语义复杂 | 用户困惑「自动/手动」 | 信息栏文案 + 「恢复自动」入口 |
| GPS 坐标系 | 国内地图偏移 | 地图刀做 GCJ-02 转换；本刀存 WGS84 |
| 迁移默认 | 旧库时间线空白 | 回填按钮 + 空态说明 |

## 11. v2 · Justified 照片流（2026-10-18 已确认）

### 原则

- 照片为主角，日期做骨架；一条连续流，不再按天渲染成小行卡
- 复用现有查看器/选中/信息栏/筛选；不引入第二套视觉语言
- 只选一个布局库；不为了新布局重写后端查询分层

### 模型与契约（增量）

新增照片瓦片 DTO：

```ts
interface PhotoTile {
  id: number
  width: number | null
  height: number | null
  thumbnailPath: string | null
  takenAt: string | null
  title: string
}
```

`GET /library/photos/timeline` 响应扩展（保留现有计数字段以兼容）：

```json
{
  "days": [{ "date": "2026-10-17", "count": 225, "photos": [PhotoTile, ...] }],
  "unknown": { "count": 0, "photos": [] },
  "unknownCount": 0,
  "total": 225
}
```

- 每日照片按 `takenAt` 倒序；`takenAt` 缺失时用 id 倒序
- 宽度/高度取 primary 文件；缺失时前端按 4:3 兜底
- 页大小：v1 直接返回全部可见照片（当前 225 张）；超过约 2000 张再改按月懒加载
- 筛选（年/月/分类/标签/显示全部）与计数使用同一 `_filter`

### 交互

- 顶部筛选/回填保持
- 滚动区：按月分节（可跨年），**年/月标题吸顶**；日标题在月内分段
- 每行用 `justified-layout` 计算：同行等高（窗口宽度决定行高 180–240px），按比例分宽，行内铺满；行间 gap 4–6px
- 照片圆角 4–6px；hover 显示时间/标题浮层；单击选中（信息栏），双击打开查看器（与网格一致）
- 日标题右侧「查看当天」→ 现有 `/photos/day/...` 网格
- 「未知时间」作为最后一段，同样铺 Justified 行
- 窗口 resize 用防抖重算行；照片懒加载

### 模块与文件（增量）

| 路径 | 职责 |
|------|------|
| `apps/desktop/src/renderer/src/components/PhotoTimeline/index.vue` | 月分节/吸顶头/筛选/滚动画布（重写） |
| `apps/desktop/src/renderer/src/components/PhotoTimeline/PhotoRow.vue`（新） | 接收一行瓦片，渲染等高照片 |
| `apps/desktop/src/renderer/src/components/PhotoTimeline/PhotoTile.vue`（新） | 单张缩略图/hover/选中 |
| `apps/desktop/src/renderer/src/domain/photo.ts` | 增 `PhotoTile`；响应类型 |
| `apps/backend/app/library/application/schemas.py` | 增 `PhotoTile`；`PhotoTimelineDay.photos` |
| `apps/backend/app/library/infrastructure/repositories.py` | 时间线查询带瓦片（一次查询，Python 分组） |
| `apps/backend/app/library/application/photos.py` | 组装 days/photos/unknown |
| `apps/desktop/package.json` | 新增 `justified-layout`（ISC） |

### 决策

| 决策 | 选择 | 为何不选备选 |
|------|------|----------------|
| 视觉方向 | Justified 照片流 | 用户确认；Apple 三层点击多、工作量大 |
| 布局库 | `justified-layout` + 现有 TanStack/选中 | 纯函数、体积小、不接管滚动；EGJS 需适配现有交互 |
| 数据 | 接口直接返回瓦片 | 用户确认；225 张量级可接受，避免额外懒加载状态 |
| 虚拟化 | v1 全量渲染 + lazy 图片；>2000 再虚拟化 | 225 张无需复杂虚拟化；保留后续优化点 |
| 点击 | 单击选中、双击打开 | 与现有网格一致，保留信息栏 |

### 风险

- `justified-layout` 需要宽高；缺失时 4:3 兜底，行可能出现轻微空洞
- 一次返回全部瓦片在超大库会变重（阈值后改按月）
- 吸顶月/日头与滚动容器需要处理层叠；避免遮挡筛选条

### 待确认（进入 L3 前）

1. 按此 v2 设计写实现方案并实施？
2. 单击选中/双击打开是否接受（与网格一致）？

## 12. 时间线纳入录制视频（2026-10-18 已确认）

### 模型/范围

- 时间线媒体类型：`image` + `video`；排除 `anime`/`av`（系列）、`audio`
- 视频拍摄时间：`probe_video` 解析 `format.tags.creation_time` → 转本地时间 → 存 `files.exif_taken_at`（字段沿用，语义为「拍摄时间」）
- 无 creation_time：`exif_taken_at=None` → 未知时间组；可在信息栏手动计入
- 视频瓦片：`PhotoTile.kind`（image/video）+ `duration`；时长角标 `mm:ss`
- 双击：图片进查看器，视频进现有播放器
- 日网格：新增 `timelineMedia` 过滤（image+video），ResourceBrowser 透传；照片页网格 Tab 同样使用
- 回填：扫描 `image + video` 的 primary；视频只补拍摄时间（不解析 GPS）
- 信息栏「计入时间线」对视频同样显示；视频信息区展示拍摄时间

### 契约

- `photo tile` 增 `kind: "image"|"video"`、`duration: number|null`
- `GET /library/resources` 增 `timelineMedia=true`：`type in (image, video)`，与 `takenDate`/`timelineVisible` 可组合
- 时间线聚合：`ResourceRow.type.in_((image, video))`
- 回填：`media_primary_files()`（替代 image-only）
- 前端：`PhotoTile.kind/duration`；`PhotoRow` 视频角标；双击按 kind 分流；Photos 网格 Tab 走 `timelineMedia`

### 页面命名（待确认）

- 建议侧栏「照片」→「时间线」，页内 Tab 仍「时间线 / 网格」；路由可继续 `/photos`
- 备选：保留「照片」标题，文案写「照片与视频」

### 风险

- ffprobe 未随包分发：无 ffprobe 时视频无拍摄时间（未知组/手动计入）；后续可内嵌 ffprobe
- creation_time 多为 UTC：转换本地日期可能跨天（以本地为准）
- 视频缩略图缺失时瓦片退化（无图占位）
- 下载视频默认无拍摄时间 → 不进时间线；手动可见性可覆盖

### 已确认

1. 入口标题改为「时间线」
2. 视频范围：仅 `video` 类型；下载视频默认不进，可手动计入
3. 内嵌 ffprobe（随包分发，附 GPL-3.0 许可说明）
