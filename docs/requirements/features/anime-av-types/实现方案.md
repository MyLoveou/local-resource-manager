# 番剧与 AV 系列 · 实现方案

> 与 `openspec/changes/anime-av-types/design.md` 同一清单。  
> 决策：专属子表 + Resource 作品外壳；来源目录 → 预览 → 规范包。

## 1. 对齐

- 作品列表/回收站/词表：`resources` + `LibraryQueryService`  
- 季/集/特典/字幕/女优：library 新 repository，详情组装  
- 播放：现有 overlay + `files/{id}/content`  
- 导入：现有 job；**series_ingest**：检测布局 → 映射 → 用户确认 → copy 规范树  
- 探测：每集/特典走现有 `probe_video`（VIDEO_LIKE 只用于探测，不进 video 列表）  
- 参考：只吸收**模型与能力**（需求 §11），不搬参考仓代码结构  
- **不**新 FastAPI 应用、不新播放器工程

## 2. 目标 / 非目标

**目标：** A-min：作品能进库、能点集播放。A-plus：两种集展示、特典完善、字幕组/女优、异构整理与规范命名。  
**非目标：** 刮削、源路径监视库、Bakabase 式细类型枚举、每集回收站卡片、overlay 内切字幕、合集/成就。

## 2.1 对照后架构取舍

| 参考做法 | 本仓选择 | 原因 |
|----------|----------|------|
| GRM：文件夹=作品、无季表 | Resource 作品 + seasons/episodes | 用户已要求季/集树 |
| Bakabase：源路径 Resource + ParentId 树 + 属性包 | 复制进包；季集专用表；profile 固定列 | facts：导入一次性复制；属性海难验收 |
| Jellyfin：Shows 树 + 刮削 | 只要树与 Episode 分型；刮削 OUT | 本切片手填 |
| 解析器：文件名→字段 | 仅用于预览映射 | 不持久化「解析器状态」 |
| Tellico：条目模板、无文件树 | profile 字段启发 | 不是收藏编目软件 |

## 4. 数据流

### 异构导入（核心）

来源结构 **不**直接当库结构。流水线：

1. **探测布局**（按序命中即停，命中后仍跑文件名解析填 fansub/集号）  
   - `jellyfin_seasons`：`Season 01` / `Specials` / `Season 00` / `extras`|`特典`  
   - `flat_sxxexx`：根目录 `SxxExx` / `第n集`  
   - `anitomy_flat`：`[字幕组] 标题 - 01`（Anitopy）  
   - `numbered_flat`：`01.mkv` `02.mkv` 排序成 S01  
   - `av_folder`：一目录少量视频 + 图（番号作 title）  
   - `unknown`：全部进待分配，**禁止自动建集**  
2. **预览**：返回建议 `season/episode/extra/subtitle/cover` 映射；用户可改。  
3. **确认**：copy 到规范包并 **立刻规范命名**；每视频 `probe_video`；旁路同名图作集封面；旁路字幕作 subtitle files。  
4. 无法解析出任何视频：**不建空作品**。

### 系列内增删 / 重命名

- 追加：选文件 → 指定季集或 extras → copy + probe + 规范名  
- 删除一集/特典：删行 + 包内文件（含配套字幕/集封面）；作品 Resource 保留  
- 批量规范名：按表内季集号重命名磁盘与 files.path

### 浏览播放

1. 列表作品  
2. 详情含树、每集探测、coverFileId、fansub、subtitle files  
3. 栏内 `episodeListMode=cover|index`  
4. 点集 overlay；切路由 close

## 5. 决策

| 决策 | 选择 | 不选 |
|------|------|------|
| 网格单位 | 作品 Resource | 每集 Resource |
| 来源 vs 库 | 预览后写入规范树 | 原样镜像下载目录 |
| 字幕组 | 作品默认 + 集覆盖 | 仅标签 |
| 女优 | performers M2M | 逗号字符串 |
| 集封面 | episode.cover_file_id；两种 UI | 只有作品封面 |
| 探测 | 每集/特典 files 同行 video probe | 只探第一集 |
| 导入错误 | 删集 API | 只能整部进回收站 |
| 旧数据 | 不动 video | 批量改 type |

## 6. 风险

| 风险 | 缓解 |
|------|------|
| 误把系列当一文件一资源 | import 按 type 分支 + 强制 preview |
| Anitopy 误解析 | 预览可改；unknown 不自动 |
| 重命名与播放中文件冲突 | 播时禁 rename；失败回滚 |
| CHECK 漏列 | 对照 0001–0004 |

## 7. 注释

系列子表旁：作品才是 Resource；集与特典不是列表项。规范包路径旁：来源布局不得写进 store。

## 8. 开发流程分析（第一刀 A-min）

### 8.1 现状（未 apply 已有占位，会挡路）

| 点 | 事实 |
|----|------|
| 类型字符串 | 代码里是 `anime-series`，规划是 `anime`。CHECK 仍 `image\|video` → 列表/导入 422 或 400 |
| 页 | `/anime-series`、`/av` 复用 ResourceBrowser，当单文件视频点 |
| 播放 | `Player[type].open/close` 只有 image/video → 切走番剧页 TypeError，路由卡死 |
| 导入 | `importer_for` / `IMPORT_EXTENSIONS` / `layout_for` 只有图和视频 |
| 探测 | `probe_media` 只认 image/video |
| 信息栏 | `isVideo`/`isImage`，无作品树 |

占位不要合进 master。实现必须在 `feat/anime-av-types`，且 **第一件事改枚举+CHECK+安全 close**，否则页面无法开发。

### 8.2 沿用（禁止新分层）

`library` 应用：ImportService → 新 `series_ingest` 分支；详情 `LibraryQueryService` 组装树；播放已有 overlay + `files/{id}/content`。桌面：同一 ResourceBrowser + InfoPanel 系列态，不新壳。

### 8.3 第一刀垂直切片（顺序）

1. **解堵** 枚举 `anime`/`av`；迁移放宽 CHECK；前端类型与路由 `/anime`；`Player` close 仅 image/video；向导出现番剧/AV。验收 T1 T2 T8 T9 R1。  
2. **表与详情** seasons/episodes + files；GET 作品含集树；空 profile 可后补。验收 T3。  
3. **导入** 目录 → 一作品；Season 文件夹或纯序号；copy 规范路径；每集 probe。验收 T4。  
4. **消费** 单击只选中；栏列序号集；点集 overlay；软删作品。验收 T5 T6。  

特典可在切片 3 用目录名 extras/特典落入 extras 表（T7 若顺手），否则 A-plus。

### 8.4 第一刀不做

预览改映射、canonical rename API、删单集、女优、字幕组、双封面列表、anitopy 依赖入库（可用正则够用再加）。

### 8.5 风险

- 占位 `anime-series` 与 `anime` 混用 → 第一刀统一改名。  
- 把系列走现有「一文件一资源」importer → 网格爆炸；必须 type 分支。  
- 第一刀做完 A-plus 档案 → 违反 D-20260917-01。
