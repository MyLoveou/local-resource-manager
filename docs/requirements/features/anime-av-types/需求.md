# 番剧与 AV 系列 · 需求

> 状态：**评审中**（2026-09-15 已拍板季/集树与专用字段；未 apply）  
> Feature ID：`anime-av-types`  
> OpenSpec：`openspec/changes/anime-av-types/`  
> 上游：模块地图「系列」；D-20260915-01

## 1. 问题

用户要在库里管理 **番剧** 和 **AV**，交互不是「每个视频一张卡」，而是：

- 网格里 **一部作品一张封面**
- 点选后右侧信息栏展示 **作品级数据**（含集数等专用字段）
- **选某一集再播放**
- 作品下还有 **特典/花絮** 等非正片

现有 `Resource` 是单文件媒体（图/视频一条一卡）。把季/集塞进 `files[]` 或每集一条 Resource，都会把网格、信息栏、播放入口做坏。前端占位路由 `/anime-series`、`/av` 尚未按此模型实现。

## 2. 已拍板

| # | 决定 |
|---|------|
| 1 | **必须有季/集树**。不能接受「每集一条独立资源、无结构」。 |
| 2 | 菜单文案 **「番剧」**。API/路由建议 `anime` / `/anime`（实现时改掉占位 `anime-series`）。 |
| 3 | **已有 `video` 不改类型、不迁移。** |
| 4 | 信息栏要 **专用字段** → 要专属模型（见 §3），不是只加标签。 |
| 5 | 特典等附属资源要进模型，与正片集分开展示。 |
| 6 | 网格点作品 ≠ 立刻播放；播放发生在信息栏选集之后。 |

参考（本环境未能下载「绿色资源管理器」安装包；对齐 Jellyfin/Emby/Plex/TinyMediaManager 的 Shows 惯例）：

- 目录：`作品/Season 01/`、`Season 00` 或 `Specials`、作品级 `extras/`
- 文件名：`SxxExx`；特典不要当成 S01E01
- 特典分两类：**剧情特别篇**（OVA/SP，可挂季）与 **花絮/访谈/预告**（extras，不计入正片集数）

## 3. 模型：专属表 + Resource 外壳（不选「只扩 files」）

**为何不把季/集只写进 `Resource.extra` 或 `files.role`：** 网格会误列出每一集；`primary` 无法表示「选中的那一集」；信息栏选集没有稳定 id；特典会和正片抢封面。

**为何不完全离开 Resource：** 封面、评分、分类、标签、软删/回收站、导入任务已按 Resource 工作。作品仍是列表上的「一条资源」。

| 实体 | 存哪 | 职责 |
|------|------|------|
| 作品 | `resources` 一行，`type=anime` 或 `av` | 网格封面、回收站、词表 |
| 番剧档案 | `anime_profiles` 1:1 `resource_id` | 原名、话数、放送等 |
| AV 档案 | `av_profiles` 1:1 `resource_id` | 番号、片商等（字段清单见开放问题补全后定稿） |
| 季 | `seasons` | `season_number`（0=Specials）、标题 |
| 正片集 | `episodes` | 集号、标题、指向 `files.id` |
| 特典 | `extras` | `kind` + 标题 + `files.id`；可选挂 `season_id` |

正片文件仍用现有 `files` 表（探测宽高时长）。一集/一条特典 **不是** 独立 `resources` 行，**不出现**在番剧/AV 网格。

磁盘（与「不按作者建树」不冲突：这是作品包内部结构）：

```
{store}/anime/{id}/
  cover.*
  thumbs/grid.webp
  seasons/01/S01E01.mkv
  seasons/00/…          # 可选，特别篇
  extras/…               # 花絮
```

AV 同构：`{store}/av/{id}/`。只有一集的作品仍建 `seasons/01` + 一集，便于信息栏「选集播放」。

## 4. IN / OUT

| 做 | 不做 |
|----|------|
| 作品级网格；信息栏季/集/特典列表；选集播放（复用视频 overlay） | 把旧 video 改成番剧/AV |
| 导入：**一文件夹 = 一部作品**，解析季目录与 SxxExx；特典目录 | 本切片自动刮削 Bangumi/Jav 站点 |
| 专用 profile 表字段手填/保存（与面板草稿同一套「点保存」） | 合集模块、加密、新播放器 |
| 卸载/切页安全关闭播放器 | 本切片修 Windows 10054 |
| 回收站软删作品级 Resource（子表随库策略 CASCADE 或禁删） | 每集单独进回收站网格 |

## 5. 交互（信息栏）

1. 单击作品卡 → 选中；信息栏展示作品封面、profile 字段、**正片集数**、季列表。  
2. 展开季 → 列出集；点某一集 → **播放该集**（覆盖层只盖中间栏）。  
3. 「特典」分组单独列出，**不计入正片集数**；点特典同样播放对应文件。  
4. 二次点击作品卡 **不**直接播第一集（避免和「选集」冲突）。若未选自集，可在栏内提供「播放最新/第一集」按钮（实现时二选一，默认第一集）。  
5. 离开番剧/AV 页 → 关 overlay，路由可切走。

## 6. 用户故事

- **US-S.1** 打开「番剧」→ 列表 200（可空）；点「视频」主区切走且无 Player close 抛错。  
- **US-S.2** 导入一个含 `Season 01` 与若干 mkv 的文件夹、类型番剧 → 网格 **一张卡**；信息栏能看到集列表并可播 E01。  
- **US-S.3** 同目录含 `extras` 或 `特典` → 信息栏有特典分组；正片集数不含这些文件。  
- **US-S.4** AV 导入同构；网格在 AV 页；信息不出现在视频页。  
- **US-S.5** 信息栏保存番剧/AV 专用字段后 GET 详情仍在。  
- **US-S.6** 软删作品 → 番剧网格消失，进回收站；恢复后季/集仍在。

## 7. 验收

- [ ] `GET /library/resources?type=anime|av` 只返回 **作品** 行，不返回单集。  
- [ ] `GET /library/resources/{id}` 作品详情含 `profile`、`seasons[].episodes[]`、`extras[]`、正片集数。  
- [ ] 播集走已有 content 流（按 **file id** 或 episode content 端点），不误播成「作品 primary」。  
- [ ] SQLite 迁移后旧 image/video 行不变；CHECK/枚举含 `anime`、`av`。  
- [ ] 菜单「番剧」；占位「动漫系列」去掉。  
- [ ] 向导可选番剧/AV；目录导入建一棵季/集树。  
- [ ] 特典不计入正片集数。  
- [ ] 从番剧/AV 切走路由不抛 TypeError。

## 8. 契约草案

- `ResourceType`：`image` \| `video` \| `anime` \| `av`  
- 列表/overview 仍 `/library/resources`，作品才是 item  
- 详情扩展字段（camelCase），空季合法  
- `GET /library/resources/{id}/files/{fileId}/content` 播集/特典（已有）  
- 导入 `POST /library/imports`：`type=anime|av` 且 `sourceKind=directory` **本切片主路径**；纯散文件是否允许拼一部 → 见开放问题
