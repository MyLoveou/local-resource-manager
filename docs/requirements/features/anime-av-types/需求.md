# 番剧与 AV 系列 · 需求

> 状态：**评审中**（2026-09-16 已收口字幕/女优/整理/乱目录/集封面；未 apply）  
> Feature ID：`anime-av-types`  
> OpenSpec：`openspec/changes/anime-av-types/`  
> 上游：模块地图「系列」；D-20260915-01、D-20260916-01  
> 参考仓（gitignore `reference/`）：番剧/AV 对照见 §11；**全产品能力与本仓路线建议**见 [reference-landscape.md](../../../product/reference-landscape.md)。

## 1. 问题

用户要在库里管理 **番剧** 和 **AV**，交互不是「每个视频一张卡」，而是：

- 网格里 **一部作品一张封面**
- 点选后右侧信息栏展示 **作品级数据**（含集数、字幕组、女优等专用字段）
- **选某一集再播放**
- 作品下还有 **特典/花絮** 等非正片
- 下载来源目录结构不一，入库后要能 **整理、增删、统一命名**

现有 `Resource` 是单文件媒体。把季/集塞进 `files[]` 或每集一条 Resource，都会把网格、信息栏、播放入口做坏。

## 3. 模型

| 实体 | 存哪 | 职责 |
|------|------|------|
| 作品 | `resources` 一行，`type=anime` 或 `av` | 网格封面、回收站、词表 |
| 番剧档案 | `anime_profiles` 1:1 | 原名、中文名、放送季节、工作室、**默认字幕组**；话数由 episodes 衍生 |
| AV 档案 | `av_profiles` 1:1 | 番号、片商、系列名；时长由文件衍生 |
| 女优 | `performers` + `av_work_performers` | 多值；作品↔女优 M2M |
| 季 | `seasons` | `season_number`（0=Specials）、标题 |
| 正片集 | `episodes` | 集号、标题、`file_id`、可选 `cover_file_id`、**字幕组（可覆盖作品默认）** |
| 特典 | `extras` | `kind` + 标题 + `file_id`；可选挂 `season_id` |
| 字幕轨 | `files.role=subtitle` + `episode_id` | 外挂 `.ass/.srt/.vtt`；语言码 |

正片/特典/字幕文件都走现有 `files` 表。一集 **不是** `resources` 行。

规范磁盘（与来源解耦；导入后只认这套）：

```
{store}/anime/{id}/
  cover.*
  thumbs/grid.webp
  seasons/01/S01E01.mkv
  seasons/01/S01E01.webp      # 可选集封面
  seasons/01/S01E01.zh.ass    # 可选外挂字幕（或 subtitles/ 下同名）
  seasons/00/S00E01.mkv
  extras/{kind}-{slug}.mkv
```

AV 同构：`{store}/av/{id}/`。单集作品仍建 `seasons/01` + E01。

## 5. 交互

1. 单击作品卡 → 选中；栏展示封面、profile、正片集数、季、女优/字幕组。  
2. 集列表可切换 **封面模式 / 序号模式**（本地记住）。点集 → 播该集。  
3. 特典单独分组。栏内「播放第一集」。二次点击作品卡不直接播。  
4. **整理**：预览解析结果；改集号/季；确认后拷贝并规范命名。事后可向作品 **追加文件**、**删除某集/特典**（删包内文件+行，作品仍在）。  
5. **批量重命名**：按当前季集号写成 `SxxExx`（及配套字幕/封面同名）。  
6. 离开页 → 关 overlay。

## 6. 用户故事

- **US-S.1** 打开「番剧」→ 列表 200；切「视频」无 Player close 抛错。  
- **US-S.2** 导入含 `Season 01` 的文件夹 → 网格一张卡；可播 E01。  
- **US-S.3** 目录含 `extras`/`特典` → 特典分组；正片集数不含它们。  
- **US-S.4** AV 同构；女优可多选绑定。  
- **US-S.5** 保存专用字段（含字幕组）后 GET 仍在。  
- **US-S.6** 软删作品 → 回收站；恢复后季/集仍在。  
- **US-S.7** `[字幕组] 标题 - 01.mkv` 扁平目录 → 预览为 S01E01 + fansub；确认后规范名入库。  
- **US-S.8** 导入多进一集 → 可删该集，作品与其余集保留。  
- **US-S.9** 向已有作品追加一集。  
- **US-S.10** 每集有 jpg → 封面模式可见；切序号模式只显示第几集。  
- **US-S.11** 每集写入 duration/width/height（与 video 探测同类）。

## 8. 契约草案

- `ResourceType`：`image` \| `video` \| `anime` \| `av`  
- 详情扩展：`profile`、`seasons`、`extras`、`performers`（av）  
- 导入：`type=anime|av` + directory **或** 多文件（须 preview payload）  
- 整理 API（建议）：预览、确认入库、`POST .../episodes` 追加、`DELETE .../episodes/{id}`、`POST .../rename-canonical`  
- 播：已有 `files/{fileId}/content`

## 9. 字段（本切片第一批，已关）

**番剧 profile：** 原名、中文名（可与 `resources.title` 同步）、放送季节、工作室、默认字幕组。话数 = episodes 计数。

**集：** 季号、集号、标题、字幕组（空则用默认）、`file_id`、`cover_file_id`、探测字段来自 files。

**AV profile：** 番号、片商、作品系列名。时长取主视频 files。

**女优：** `performers.name` 唯一；作品多对多。本切片不做女优独立网格页。

**字幕轨：** 语言码 + 文件；不在此切片做播放器内嵌切换。

## 10. 非功能

- 类型扩展继续走映射表。  
- 抓取 OUT；字段手填。  
- 文件名解析的**结果形状**对齐 Anitopy 元素（标题/季/集/字幕组），不把 Jellyfin/Bakabase 进程搬进来。

## 11. 参考产品：模型与能力（对照）

只回答两件事：它们把什么当成一条「库记录」、用户能做什么。不写类名/文件路径。

### 11.1 列表单位 vs 播放单位

| 产品 | 库里的一条记录是什么 | 季/集怎么表示 | 和本切片 |
|------|----------------------|---------------|----------|
| 绿色资源管理器 | 按类型分页。**电影=单文件**；**番剧=一个文件夹**（作品路径 + 封面 + 标签/演员数组）。磁盘原路径，不拷进库。 | **没有季/集实体**。播的是文件夹里扫到的视频。 | 取「番剧≠电影、作品一卡」。不取「无集树、原路径索引」（与已拍板复制入库冲突）。 |

### 11.3 对本切片模型的结论（不改已拍板）

参考产品分成三类，**不能混抄**：

1. **文件夹当作品**（GRM）：交互对，结构不够（无季集）。  
2. **路径资源+属性包**（Bakabase）：类型极全，季集不是一等公民。  
3. **Shows 树**（Jellyfin/Bangumi）：季集/特典分型最完整，但是刮削+登记源库。

本产品已拍板走 **3 的树 + 1 的作品一卡交互 + 本仓的复制入库**。收藏类只提供档案字段启发。解析器只服务导入映射。

Bakabase 把 Anime / OVA / Av 拆成很多预设类型：**本切片仍只 `anime` 与 `av` 两种 ResourceType**；OVA 用 Season 00 / extras.kind，不新枚举。
