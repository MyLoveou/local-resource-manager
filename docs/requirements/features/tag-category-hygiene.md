# 标签与分类词表治理

> 状态：**已定稿**（2026-09-27 · 轮次 2 关闭全部开放问题；拍板 `D-20260927-02`）。定稿后仍须 L2/L3 才可编码。  
> Feature ID：`tag-category-hygiene`  
> 所属产品：[local-resource-manager](local-resource-manager.md)（已定稿）的 **P1 增量**  
> 依赖：M4 标签 CRUD / 按标签浏览（路线图 MS4 · T-4.2～T-4.4）先落地  
> 规划落点：[00-路线图与里程碑](../../design/00-路线图与里程碑.md) · MS4.1

## 1. 背景

抓取回填、批量打标、手填都会持续写入标签；分类若做成独立词表，同样会随库膨胀。只增不治会出现：

- 近义/错拼标签堆积，过滤列表过长
- 零引用标签残留（资源改标或删除后词条仍在）
- 无法判断哪些词真正在用，清理成本高

当前代码与模型：

- `tags` + `resource_tags` 已在 [02-数据模型](../../design/02-数据模型.md) 中定义；删标签会 `ON DELETE CASCADE` 摘掉关联
- **分类独立词表**已在 `metadata-panel` 拍板（将建 `categories` + 资源 FK）；本需求做治理，不改「面板保存时创建词条」
- **尚无**标签/分类管理页、引用计数、批量清理
- 勿把资源 **type**（图片/视频）当成分类词表

## 2. 目标用户与问题

- 库规模到万级、标签/分类条目开始膨胀的个人用户
- 要解决：看见用量、安全删掉无用词条、避免误删正在使用的词

## 3. 范围

### IN SCOPE（本需求定稿后、MS4.1 实现）

- **统计**：每个标签（及若定稿为独立实体的分类）的引用次数；可按用量/名称排序；标出 0 引用
- **删除**：删除词条；0 引用可直接删；有引用须明确策略（见开放问题）
- **入口**：独立「标签/分类管理」界面（设置页签或库内管理页，入口待定）
- **空态/错误**：无词条、全部 0 引用、删除失败均有明确反馈（走全局 Notify）

### OUT OF SCOPE（本需求不交付）

- 本轮不实现：不改 MS2 浏览、不提前做管理 UI
- 标签合并/重命名（可列后续，默认不做进 MS4.1）
- 自动聚类、同义词、AI 清洗
- 多用户权限、回收站式「词条软删」（词条删除默认硬删记录）
- 把资源 **type**（图片/视频）当成可删分类

### 与 M4 的边界

| M4（MS4） | 本需求（MS4.1） |
|-----------|-----------------|
| 给资源打标、摘标、按标签过滤/浏览 | 治理词表本身：看统计、删词条 |
| 面板上操作**一条资源**的标签 | 管理页操作**全局词表** |

## 4. 假设（可在后续轮次推翻）

1. 实现排在 **MS4 标签 CRUD 之后**（MS4.1），不挡 v0.1 浏览闭环。
2. 统计以 **当前 `active` 资源** 的引用为准；回收站内资源是否计入，见开放问题。
3. 删除 0 引用标签：直接删 `tags` 行。
4. 「分类」在开放问题关闭前，**不当作已有表**；若确认为独立单选词表，再补 `categories` + 资源外键。

## 6. 场景草稿（轮次 2 再写成验收清单）

- 打开管理页 → 看到标签列表与引用次数，可按次数排序  
- 选中 0 引用标签 → 删除 → 列表消失，库过滤不再出现该词  
- 选中仍被引用的标签 → 按第 2 题策略拦截或确认后摘标  
- 无标签 → 空态，不假装已有分类体系  

## 7. 非功能

- 统计查询须能支撑万级资源、千级标签（目标：打开管理页可接受延迟 ≤ 1s，可后续用 COUNT 聚合 + 索引）
- 删除须事务：词条与关联同成同败
- 不在渲染进程直接改库

| Q2 | 删除仍被引用的词条 | **B：二次确认后级联摘标**（确认框显示「将从 N 条资源上摘掉」） | schema 已是 `resource_tags … ON DELETE CASCADE`，删词条天然摘标；选 A（禁止删除）会让打错的标签永远清不掉；选 C（两种模式）在本 schema 下两种模式行为等价，属无意义选择 |

| Q5 | 是否要「一键清理全部 0 引用」 | **要**（二次确认 + 单事务） | 这是本需求存在的理由（词表膨胀治理）；0 引用删除无副作用 |
