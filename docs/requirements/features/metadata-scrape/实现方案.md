# 获取元数据 · 实现方案（L3）

> 状态：**已落地**  
> L2：`设计.md`。第一刀已编码：视频 TMDB、番剧 Bangumi。

仅本刀：视频 TMDB、番剧 Bangumi。httpx 已在 `requirements.txt`。

## 1. 对齐

- search **只**写 `scrape_jobs` + `candidates`，不改 Resource。  
- `POST .../select` 才覆盖 title/`synopsis`、写入 catalog、追加标签；封面按确认页选择写入（user 封面需显式覆盖）。不改 `description`。  
- 导入成功后 `enqueue`，失败不回滚入库。  
- 渲染进程禁止直连 TMDB/Bangumi。

## 2. 契约

### REST（前缀 `/scrape`）

| 方法 | 路径 | 作用 |
|------|------|------|
| POST | `/jobs` | body `{ resourceId }`；type 非 video/anime → 400。入队 search，立即返回 job |
| GET | `/jobs/{id}` | 含 status/error/matchCount |
| GET | `/jobs/{id}/candidates` | 候选列表（缩略图可用外链，仅弹层预览） |
| POST | `/jobs/{id}/select` | `{ candidateId }`；fetchDetail + apply；失败不改 title |
| GET | `/resources/{resourceId}/latest-job` | 该资源最新 job（信息栏「查看候选」） |

`POST /jobs`：若已有 `queued|running` 则返回该 job，不重复入队。若已有 `done` 且未选且 match_count>0，返回该 job（批量可直接确认）。`?force=true` 重新 search。

### 列表角标

`Resource` 增加可选 `scrapePending: bool`（camelCase）。list 查询 LEFT JOIN：最新 job 为 done、match_count>0、该 job 无 selected 候选。  
不改 extra JSON。详情 GET 同样带该字段。

### 凭证

环境变量优先：`TMDB_API_KEY`（视频必填）。Bangumi 本刀可无 token，有则 `BANGUMI_ACCESS_TOKEN` 带头。都不做设置页（T-4.5 后置）。无 TMDB key 时视频 job → failed「未配置 TMDB API Key」。

### 候选 `url`

存稳定键，不是易变页面：`tmdb:movie:{id}` / `tmdb:tv:{id}` / `bangumi:{id}`。`source` 为 `tmdb` | `bangumi`。`thumbnail_url` 官方图 URL，仅 UI 预览；apply 时重新拉字节进包。

## 5. 数据流

```text
导入成功 --> enqueue search --> worker httpx --> candidates
网格 scrapePending
用户 select --> detail httpx --> PATCH title/desc + union tags
             --> 非 user 则封面进包 --> bump
```

## 6. 队列与导入

- worker 单协程消费 Queue，避免 80 部同时打 TMDB。  
- enqueue 只 push job_id。  
- 进程重启：启动时把 `queued`/`running` 的 search 重新入队（running 视为未完成，重跑 search，先删该 job 旧 candidates）。

## 7. 明确不做

SearXNG、设置页填 key（用环境变量）、AV/图、登录、远程爬虫、确认前改标题、候选缩略图进包（apply 才下海报）。
