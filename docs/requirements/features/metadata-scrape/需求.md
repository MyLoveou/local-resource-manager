## 1. 问题

资源已能导入、手填、本地抽封面。网上标题/简介/站点封面/标签仍空。`/scrape` 只有 health。

## 2. 已按口令收口

1. 同一 FastAPI `/scrape`，不是独立元数据服务。  
2. 禁止默认定时写 Resource。  
3. 没选候选不写库。  
4. RAG = SearchProvider → 候选 → 详情；不含大模型。  
5. 不做应用内站点登录；本刀直连公开 API。  
6. `coverOrigin=user` 永不被抓取覆盖。  
7. 远程快照 / 绿管刮削库交换后置；接口预留 SearchProvider。  
8. 失败可读，可手填，可再点。  
9. **本刀类型：视频 + 番剧。** 图片 / AV / 其它类型 OUT。  
10. **发现：视频 TMDB；番剧 Bangumi 为主 + 蜜柑附加。** SearXNG 后置。渠道不唯一。  
11. **确认后覆盖标题与作品简介（`synopsis`）。** 用户评价 `description` 不改。标签只追加不删已有。封面非 user 才默认写；确认页可选封面。站点档案进 `catalog`。  
12. **支持批量**：多选队列，逐条确认或跳过。  
13. **导入后自动 search，不回填**；有候选则角标/入口待确认。

## 3. 范围

### IN

- 视频 → TMDB search/detail；番剧 → Bangumi 为主、蜜柑计划（Mikan）为附加发现源。查询词默认用当前 `title`。  
- 同一类型可多渠道：主源失败时其它渠道命中仍可确认；选蜜柑候选时若页上有 bgm.tv 条目则回落到 Bangumi 详情。  
- 蜜柑 **不** 当下载器（磁力/RSS 后置 `/download`）。  
- Job + candidates 表落地；创建/轮询/列候选/选择回填 API。  
- 信息栏「获取元数据」；候选弹层；确认后 PATCH 等价回填 + 封面 ingest 锁定规则。  
- 批量：已选资源中仅 video/anime；其它跳过并计数。  
- 导入成功（video/anime）入队 search-only job，失败不挡导入。  
- 网格或卡片「有候选」可感知（角标或信息栏提示）。  
- TMDB/Bangumi 未配 key 或 HTTP 失败：job.failed，中文原因。  
- 单测：search 不写 Resource；select 后标题变；user 封面不变。

### OUT

- AV、图片、音频、小说、漫画、游戏、模型刮削。  
- SearXNG、豆瓣、B 站登录、远程爬虫、CLIP、FTS。  
- 女优/字幕组、下载原片、覆盖 user 封面、删已有标签。  
- 导入同步等待刮削完成（只后台入队）。

## 4. 用户故事

- **US-S.1** 视频/番剧点获取 → 候选 → 选一条 → 标题简介被覆盖；非 user 封面进包。  
- **US-S.2** 零命中/断网/无 key → 不写库；有原因；可手填。  
- **US-S.3** user 封面不换。  
- **US-S.4** 再获取可改选。  
- **US-S.5** 多选视频+番剧 → 逐条确认/跳过；混选里的图片不计刮削。  
- **US-S.6** 导入一部番剧或视频 → 导入成功即可用；稍后出现「有候选」；未确认则标题仍是文件名。

## 5. 验收

- [ ] US-S.1 视频、番剧各至少一条真实或夹具路径。  
- [ ] 未选：标题与导入时一致。  
- [ ] user 封面保持。  
- [ ] 批量跳过非本刀类型。  
- [ ] 导入不因刮削失败而失败。  
- [ ] 无登录页、无 SearXNG 进程。
