# 设计 · batch-tag-export（L2）

> 状态：**已定稿**（2026-10-07 三项默认已确认，已实现）
> 需求：`需求.md`

## 1. 设计原则

- 复用现有词表与批量机制：批量打标走既有 batch 端点与标签仓储，不加新表
- 导出不改库：纯读合集成员 → 复制主文件到外部目录；失败不污染库
- 导出命名是纯函数（算法切片），可单测
- 标签语义与刮削一致：「只加不删」，重复标签幂等

## 2. 模型

无新表/字段。复用：
- `tags` 词表 + `ResourceRepository.add_tags_union`
- `collections` / `collection_items`（成员顺序即导出顺序）
- 批量端点 `POST /library/resources/batch`

## 3. 交互

### 主路径
1. **批量打标**：图片页多选（顶栏「批量选择」已有）→ 批量条新增「打标」按钮 → 弹小输入框（Enter 切词，与信息栏一致）→ 确认 → toast「已为 N 个资源添加标签」→ 列表刷新
2. **导出合集**：合集成员页头部新增「导出」按钮 → `selectDirectory`（复用现有 IPC）→ 后端按成员顺序复制主文件 `{序号3位}_{清理后标题}{后缀}` → 返回数量 → toast「已导出 N 个文件到 …」

### 空态与失败
- 未选中任何资源：打标按钮禁用
- 合集无成员：点击导出提示「合集没有成员」
- 成员主文件缺失（lost/被删）：跳过并计入「跳过 N 个」
- 目标目录不可写：报错不半途成功（先校验目标可写，再逐文件复制）

## 4. 模块划分（落在现有分层）

| 模块 | 职责 | 不进入 |
|------|------|--------|
| 算法 `library/application/export_naming.py`（新） | `safe_title`（去非法文件名字符）+ `export_name(index, title, ext)` 纯函数 | IO |
| 功能 `library/application/use_cases.py` | 批量打标用例（复用 add_tags_union）；导出用例（读成员 → 复制） | 像素/UI |
| 基础设施 `library/infrastructure/repositories.py` | 无新增（成员查询已有 `CollectionRepository.members`） | — |
| API `library/api/resources.py` / `collections.py` | batch 扩展 `add_tags`；`POST /collections/{id}/export` | 命名规则 |
| UI `components/BrowseControls` 旁批量条 + `views/CollectionDetail` | 按钮 + 输入框 + 目录选择 | 命名规则、复制逻辑 |

## 5. 功能拆分（组合式）

| 切片 | 提供 | 契约 |
|------|------|------|
| 算法 | `export_name(index, title, ext) -> str`（`001_标题.jpg`） | 纯函数，无 IO |
| 功能 | 批量打标用例 `batch_add_tags(resource_ids, tag_names) -> int`；导出用例 `export_collection(collection_id, target_dir) -> (exported, skipped)` | 后端用例 |
| UI | 批量条打标按钮/输入、合集页导出按钮/目录选择 | 调 HTTP |

组合根：图片页批量条（打标）+ 合集成员页（导出）。

## 6. 契约（03-API设计.md 同步）

- `POST /library/resources/batch`：`{action: "add_tags", ids: number[], tagNames: string[]}` → `{ok, failed}`
- `POST /library/collections/{id}/export`：`{targetDir: string}` → `{exported: int, skipped: int, targetDir}`
