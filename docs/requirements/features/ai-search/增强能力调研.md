# AI 增强能力调研

状态：调研记录，未实现。调研日期：2026-10-24。

## 结论摘要

| 能力 | 成熟方案 | 必要性 | 建议 |
|---|---|---|---|
| 训练型 LTR | LightGBM LambdaMART / XGBoost / CatBoost / 逻辑回归 | 当前低，数据多了以后中高 | 先继续收集曝光和反馈，不急着训练 |
| OpenAI-compatible UI + 视觉检测 | LM Studio / llama.cpp server / vLLM 均兼容 | 高 | 下一批实现 |
| 扮演者自动识别 | InsightFace / ArcFace / OSNet | 中低 | 需要明确产品需求，采用可选、聚类、人工确认 |
| DINOv2 | DINOv2 ViT-S/B，Apache-2.0 | 中 | 先做离线对比，不作为当前主力 |
| OSNet | Torchreid / OSNet，可导出 ONNX | 低 | 仅在“找回同一个人”需求成立时做 |
| OCR 搜索 | PaddleOCR（Apache-2.0）/ Tesseract | 中高 | 适合截图、漫画、文档图片，优先级高于人脸 |
| 视频 AI | 关键帧 + CLIP/DINOv2/OCR + Whisper | 中长期 | 先做好视频消费和索引规模，再立项 |
| 音频 AI | Whisper 转写，后续可做文本/向量检索 | 中低 | 先做音频转写搜索，不做音频 embedding |

## 1. 训练型 LTR

### 成熟方案

- **LightGBM**：原生支持 `lambdarank`、`rank_xendcg`，CPU 足够，模型小；适合 Top-K 重排。
- **XGBoost**：支持 pairwise/listwise ranking，生态成熟。
- **CatBoost**：YetiRank 等 ranking 目标，适合类别特征。
- **逻辑回归**：最便宜的基线，可解释，适合先验证特征是否有用。

### 必要条件

- 查询、曝光、点击、收藏、标记相关/不相关、结果位次。
- 位置偏差处理：不能把“没被看见”当成负样本。
- 特征快照：CLIP 分数、文案命中、人数/方向、标签、图片质量、历史 CTR、查询-结果共现。
- 按查询分组评估 NDCG@10、MRR；离线训练、影子模式、A/B、回退。

### 判断

目前是个人本地图库，反馈量远未达到训练稳定排序模型的程度。**现在没有必要训练**；反馈重排 v0 已能工作。应继续采集数据，达到足够样本后再做逻辑回归或 LightGBM。

风险：反馈稀疏、位置偏差、用户自己反复点同一张导致自我强化、模型过拟合到少数查询。

## 2. OpenAI-compatible UI 与视觉能力检测

### 成熟方案

- LM Studio 提供 OpenAI-compatible `/v1/models`、`/v1/chat/completions`，支持图片输入。
- llama.cpp server、vLLM 也提供 OpenAI-compatible Chat Completions。
- 应用侧只需要 base URL、API key、模型名，不需要为每个服务写一套协议。

### 视觉能力检测的难点

- OpenAI 的 `/v1/models` 没有标准的“是否支持 vision”字段。
- LM Studio 的 REST API 有更丰富的模型元数据，但不属于 OpenAI-compatible 标准。
- 可靠做法：
  1. 允许用户手动标记“视觉模型”；
  2. 选择模型后用一张很小的测试图和极短提示做一次探测；
  3. 记录探测结果，失败不自动停用，只提示。

### 判断

**有必要，优先做。** 它能解除当前对 Ollama 的强绑定，让 LM Studio、llama.cpp、远端兼容服务都能接入。UI 和协议本身成熟，主要成本是配置、探测和错误提示。

风险：远端服务可能上传图片，必须明确“本地/远端”标识和隐私提示；不要默认把本地图库发给外部地址。

## 3. 扮演者自动识别

### 成熟方案

- **InsightFace**：SCRFD 检测 + ArcFace 识别 + 可选 PersonAnalysis（人脸 + 身体 ReID）。
- **DeepFace**：封装多种模型，上手快。
- **dlib/face_recognition**：更老，精度和部署体验不如 InsightFace。
- **OSNet / Torchreid**：身体 ReID，可用于没有人脸或背影场景。

### 关键限制

- InsightFace 代码 MIT，但官方模型通常只允许非商业研究；分发模型前必须确认授权。
- 动漫/cosplay 的妆容、假发、遮挡、滤镜会显著降低人脸识别可靠性。
- 需要处理隐私、同意、误认、删除和“不自动落库”。
- 需要聚类而不是直接命名：检测人脸 → embedding → 聚类 → 用户确认人物 → 才关联。

### 判断

**当前没有必要自动识别。** 产品还没有明确“自动认人”的强需求，且风险高于收益。若要做，建议作为可选功能：本地人脸聚类 + 人工确认，不做自动命名，不默认开启。

## 4. DINOv2、OSNet、OCR、视频/音频

### DINOv2

- ViT-S/14 约 21M 参数，ViT-B/14 约 86M；官方代码/权重 Apache-2.0。
- 优势：通用视觉相似度通常强于 CLIP，适合图搜图、近似图、跨风格检索。
- 限制：没有文本对齐，不能直接文搜图；需要额外模型和向量；CPU 推理成本高于当前 CLIP；现有 CLIP 已经能工作。
- 判断：**中等必要性**。先做离线 A/B：同一批查询比较 CLIP、CLIP+dHash、DINOv2 的 Top-K 命中率，再决定是否接入。不要直接替换 CLIP。

### OSNet

- Torchreid 提供 OSNet/OSNet-AIN，可导出 ONNX，适合行人重识别。
- 需要先有人体框（YOLO）和裁剪图；只在“找同一个人/同一扮演者”场景有价值。
- 判断：**低必要性**。当前没有稳定的“人物追踪/找同一个人”需求，先不做。

### OCR 搜索

- PaddleOCR Apache-2.0，中文和文档场景成熟；Tesseract 更轻但中文效果弱。
- 可对截图、漫画、海报、文档图片做 OCR，写入 FTS/关键词索引。
- 已有 VLM OCR 字段但未参与搜索；可复用 `ai_documents.ocr_text`，先做文本搜索，不必新增模型。
- 判断：**中高必要性**。特别适合截图/漫画/资源封面文字。优先于 DINOv2/OSNet。

### 视频 AI

- 成熟组合：关键帧抽取 + CLIP/DINOv2 + OCR + Whisper 字幕/转写。
- 成本：抽帧、存储、索引、片段定位、播放器联动、失败重试。
- 判断：**中长期**。当前先完成视频消费稳定性和规模基准，不做视频向量索引。

### 音频 AI

- Whisper MIT，中文转写成熟；可先做音频/视频字幕转写搜索。
- 音频 embedding（CLAP 等）收益不明确，且模型和索引成本高。
- 判断：**先做转写搜索，不做音频向量**；排在 OCR 之后。

## 推荐优先级

1. **OpenAI-compatible UI + 视觉探测**（高价值、低成本）
2. **OCR 文本搜索**（复用现有 OCR 字段，先不引入重模型）
3. **DINOv2 离线对比**（只在 CLIP 召回不足时接入）
4. **训练型 LTR**（继续收集反馈，不立即训练）
5. **扮演者/OSNet**（等明确产品需求，可选、人工确认）
6. **视频/音频 AI**（视频消费和规模稳定后再立项）

## 不做/暂缓

- 不在当前阶段训练 LTR。
- 不自动识别人脸并写库。
- 不默认接入远端视觉服务。
- 不用 DINOv2 直接替代 CLIP。
- 不在没有关键帧/字幕管线前做视频/音频向量索引。
