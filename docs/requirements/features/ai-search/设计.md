# AI 本地搜图 · 设计

> 状态：首版已确认并实现（2026-10-23）  
> 上游：`需求.md`  
> 四种模式详细设计：`四种检索模式详细设计.md`

## 1. 模型

| 项 | 选择 |
|---|---|
| 模型 | Chinese-CLIP ViT-B/16 |
| 来源 | `Xenova/chinese-clip-vit-base-patch16` ONNX |
| 文件 | `model_quantized.onnx`，约 182 MiB |
| 文本 | `tokenizer.json`，BERT WordPiece |
| 人数特征 | `yolov8n.onnx`，COCO person，约 12 MiB |
| 维度 | 512 |
| 输入 | 图像 224×224；文本最大 52 token |
| 推理 | ONNX Runtime CPU，默认 4 intra-op 线程 |
| 输出 | `image_embeds` / `text_embeds`，L2 normalize 后做余弦 |

不选：
- 远程 CLIP API：隐私和离线目标不符。
- 全量 ViT-B/16 ONNX：约 720 MB，首版过大。
- PyTorch / transformers：当前 Python 3.14 与安装包体积不合适。
- 人脸模型：与搜图目标不同，先不做。

## 2. 存储

模型目录：

```text
<db_dir>/models/chinese-clip-vit-base-patch16/
  model_quantized.onnx
  tokenizer.json
  person_detector.onnx
```

迁移：

- `0025_ai_vectors.sql`：CLIP 向量。
- `0026_ai_attributes.sql`：人数、方向、标签、描述等结构化特征。

```text
ai_vectors(
  resource_id PK/FK resources ON DELETE CASCADE,
  model_id,
  dim,
  vector BLOB,          -- float32 little-endian
  source_path,
  updated_at
)

ai_attributes(
  resource_id, feature, value_json, value_num, value_text,
  confidence, model, updated_at,
  PK(resource_id, feature)
)
```

- 一个 active 图片资源一条向量。
- 重新索引先删除该 `model_id` 的全部旧向量。
- 软删资源保留向量，但搜索时过滤 `status='active'`；彻底删除由 FK 级联清理。
- 不建向量索引表；首版 NumPy 暴力余弦。
- 属性采用通用 `feature` 行，后续增加场景、OCR、颜色不需要改主表。

## 3. 索引

- 输入：active image 资源，优先 primary 文件，缺失时用 thumbnail。
- 批大小 8；每批 ONNX + 数据库提交。
- 每批同时提取：
  - CLIP 图片向量；
  - YOLOv8n `person_count`；
  - `orientation`（landscape / portrait / square）；
  - 用同一 CLIP 图片向量对固定中文标签词表做零样本分类，存 `label:*`；
  - 由选中的标签合成 `caption`，作为可读描述。
- 每批更新任务进度；失败保留已写入的部分，任务标记 error，可重跑。
- 手动触发，不随导入自动跑。
- 同一时间只允许一个 AI 任务（下载或索引）。

## 4. 搜索

```text
q → 查询解析（人数/横图/竖图 + 标签 + 语义文本）
  → 人数/方向硬过滤
  → 标签硬过滤（有标签命中时）
  → CLIP text_embeds → normalize
  → 只对过滤后的 active 图片算余弦
  → topK 30
  → ResourceRepository.get(id)
```

- `一个人` → person_count = 1
- `两个人 / 双人` → person_count = 2
- `合影 / 合照` → person_count >= 2
- `多人 / 一群人` → person_count >= 3
- `没人 / 空镜` → person_count = 0
- `横图 / 竖图 / 方图` → orientation
- 人数/方向是**硬过滤**；标签（如 `跑步`、`红色帽子`）有命中时也作为硬过滤。
- 标签词表由 `labels.py` 固定维护；后续可替换成 VLM 生成的自由文案。
- 返回 `indexed / matched / returned / filters`，不再把索引总数当命中数。
- topK 上限 100，UI 默认 30。
- 不使用绝对相似度阈值；低分结果仍在 topK 内。

## 5. API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/ai/status` | 依赖、模型、索引数量 |
| POST | `/ai/models/install` | 后台下载模型 |
| POST | `/ai/index` | 后台建立/重建索引 |
| GET | `/ai/jobs/{id}` | 任务进度 |
| GET | `/ai/search?q=&limit=` | 文字搜图 |

响应字段：

```text
indexed    已索引且 active 的图片数
matched    经过人数/方向/标签过滤后的候选数
returned   本次实际返回数（最多 30）
filters    识别出的条件，例如 ["人数=2", "标签=帽子"]
```

资源使用现有 `Resource` API 模型。

  - 已安装未索引 → 建立索引 CTA + 进度。

## 7. 安全与隐私

- 模型下载是唯一外部网络请求；图片和查询不出本机。
- 模型文件路径由后端控制，不接受前端任意路径。
- 搜索接口受现有 Bearer token 中间件保护。
- 不在日志中打印查询全文或图片路径（模型下载进度除外）。

## 8. 性能

- 236 张图：索引约 40 秒（CLIP + 人数检测）；文本搜索约 1 秒（含首次加载）。
- 1 万张：预计索引约 5 分钟，搜索仍可接受；5 万张前不引入向量库。
- 模型会话懒加载；搜索/索引线程通过锁串行访问 ONNX session。

## 9. 已知限制

- 图片文件变更后需手动重建索引。
- 没有以图搜图；下一刀基于已存向量即可做。
- 人数检测会受遮挡/远景影响；硬过滤仍可能误判。
- 标签由 CLIP 零样本打分，主观/细粒度语义仍可能误判；OCR、身份尚未接入。
- 模型下载不支持断点续传；失败后重新开始。
- 任务状态在当前后端进程内，重启后不保留历史。
- 打包体积会增加 ONNX Runtime / tokenizers；需独立验证安装包。

## 18. 文搜图 / 图文融合 / 文案标签复核

前面的决定需要分线复核，不能把“文搜图”当成一个已经完成的单一功能。

### 18.1 仍然有效的决定

- 本地优先，图片和查询不上传；
- Chinese-CLIP 作为默认文本/图片语义向量；
- SQLite + NumPy 在 236–5k 规模继续使用；
- 人数、方向、角色、时间等结构化条件先过滤；
- AI 中心作为入口；
- 不默认引入 Jina v4、Qdrant、远程 VLM；
- 不默认开启人脸。

### 18.2 需要修正的决定

| 原决定 | 问题 | 修正 |
|---|---|---|
| 固定 `labels.py` 词表做标签 | 闭集、误标、红帽子等组合不可靠 | 改为 VLM 生成 caption/tags/attributes；固定词表最多做兜底 |
| 搜索直接返回 top 30 | 没有阈值，没命中也会硬凑 | 返回 `matched/returned`；低置信度可空；可选阈值 |
| 所有文本查询都交给 CLIP | 计数、OCR、颜色、局部属性不可靠 | 先解析硬条件，再走 CLIP + 文案/标签检索 |
| 文搜图和图搜图共用一套排序 | 两种查询目标不同 | 分模式，融合时用 RRF |
| 合成 caption 仅存不用 | 文案没有真正参与检索 | 文案写入文本索引，参与召回/重排 |

## 19. 文搜图目标架构

```text
用户文本
  → 查询解析
      硬条件：人数/方向/时间/角色/标签
      语义：场景、动作、颜色、关系
      否定：不要帽子、不是夜景
  → 结构化过滤
  → 三路召回
      A. CLIP text → image vector
      B. FTS5/trigram → caption/tags/OCR
      C. 结构化 tag/属性
  → RRF 融合
  → 可选 VLM topK 重排
  → 阈值/空结果判断
  → 返回 indexed/matched/returned
```

### 查询解析

至少支持：

- `一个人 / 两个人 / 合影 / 多人`
- `横图 / 竖图 / 方图`
- `红色 / 黑色 / 蓝色`（颜色作为软条件或标签）
- `跑步 / 自拍 / 跳舞`（动作标签/语义）
- `室内 / 海边 / 夜景`（场景）
- `有文字 / 截图`（OCR）
- `不要红色 / 不是夜景`（否定）
- `2025 年 / 最近 / 今天`（时间）

解析结果必须可展示，例如：

```text
识别条件：人数=2 · 横图 · 标签=帽子
```

### 三路召回

| 路 | 输入 | 强项 | 弱项 |
|---|---|---|---|
| CLIP | 文本查询 | 自由语义 | 计数、局部、OCR 弱 |
| FTS/caption | 查询词 | 精确属性、可解释 | 依赖 caption 质量 |
| 结构化 | 人数/方向/标签 | 可控、可过滤 | 只覆盖已提取特征 |

RRF：

```text
score = Σ 1 / (k + rank_i)
```

不要把 CLIP 分数和 FTS 分数直接相加。

## 20. 图文融合检索

图文融合不是把文本向量和图片向量取平均，而是分别检索后融合。

### 支持的查询

- 以图为主 + 文字修正：像这张图，但要有红色帽子；
- 以文为主 + 图片参考：找类似这张构图的双人照；
- 同一张图 + 属性过滤：这张图 + 横图；
- 外部图片 + 文字：上传图 + 描述。

### 流程

```text
查询图 → image embedding / hash / face
查询文本 → text embedding + parsed filters
  → 候选过滤
  → 图片召回 topK_image
  → 文本召回 topK_text
  → RRF 融合
  → 可选 VLM 重排
```

### 语义边界

- 「像这张图」：CLIP/DINO 图像相似；
- 「红色帽子」：标签/颜色/检测/VLM，不是 CLIP 单独决定；
- 「同一个人」：OSNet/ArcFace，不是图文融合；
- 「同一次拍摄」：时间/连拍 + 视觉相似；
- 融合结果必须显示两类来源，不能只给一个不可解释的分数。

## 21. 文案 / 标签 / OCR

### 数据

```text
ai_documents
  resource_id
  caption
  short_caption
  tags_json
  attributes_json
  ocr_text
  model_id
  prompt_version
  created_at

ai_tags
  resource_id, tag, category, confidence, source, model
```

### 生成

- 本地 VLM 可选包：Qwen2.5-VL-3B（中文好，重）或 Florence-2-base（轻，英文强）；
- Prompt 要求 JSON：
  - caption / short_caption
  - scene / actions / colors / objects
  - people count（仅参考，最终以 YOLO 为准）
  - OCR
  - confidence / uncertain
- 原始输出与规范化标签都保存，便于重跑和审计；
- 模型/prompt 版本变化时重建。

### 检索

- caption/tags 进入 FTS5（trigram）或文本 embedding；
- 标签可做结构化过滤；
- 文案只用于文本检索和解释，不参与图像视觉相似度；
- 不允许一条 caption 作为唯一索引。

### 成本

- 236 张：可后台一次性生成；
- 1 万张：需要队列、分批、失败重试；
- 5 万张：默认不跑 VLM，只对新增/重要资源按需生成；
- 不把 VLM 放进默认安装包。

## 22. 评估与顺序

固定查询集至少覆盖：

- 计数：一个人、两个人、合影；
- 属性：红帽子、蓝发、室内、夜景；
- 动作：跑步、自拍、跳舞；
- 否定：不要帽子、不是夜景；
- 时间/角色/标签；
- 图片参考 + 文本；
- 无匹配查询（检查是否硬凑结果）。

指标：

- Recall@K / nDCG；
- 计数条件准确率；
- caption/tag precision；
- 空结果准确率；
- 文搜图、图搜图、融合各自延迟。

修正后的顺序：

```text
P1  查询解析 + 结构化过滤 + 返回 matched/returned
P2  文案/标签表 + FTS/trigram + CLIP 文本 RRF
P3  图文融合：图片召回 + 文本召回 + RRF
P4  可选本地 VLM caption/tags
P5  VLM topK 重排 / 负结果判断
P5.5 学习型重排器：反馈日志 + TopK 精排（见 `学习型重排器.md`）
P6  DINO/OSNet 图片模式接入融合
```

结论：**文搜图不是一个“CLIP 搜 top30”功能，而是查询解析、结构化过滤、CLIP、文案/标签、融合和阈值共同组成的检索系统。图文融合必须分路召回后 RRF，文案/标签必须由图片分析生成，固定标签词表退役。**
