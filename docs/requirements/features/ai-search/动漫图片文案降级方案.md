# 动漫图片文案降级方案

状态：v1 已实现 WD14 可选安装和 token-repeat 自动兜底（2026-10-24，本地）；参数矩阵、模型对比和 CLIP 兜底仍在后续。

## 背景

本地 `qwen2.5vl:3b` 对普通照片能正常生成文案，但对一批二次元插画/动漫图持续返回：

```text
HTTP 500
{"error":"prediction aborted, token repeat limit reached"}
```

这是 Ollama/llama.cpp 在模型反复生成相同 token 时触发的保护性中止，不是 SQLite、索引或文件格式错误。已确认：

- 前面照片批次成功。
- 失败集中在动漫图片，例如资源 257、283、284、285、297～322。
- 中文/英文提示词、不同分辨率、灰度、透明背景处理仍会失败。
- 换普通照片可恢复成功。
- 结论：当前这个 `qwen2.5vl:3b` 量化版本对这批图存在能力/退化边界。

## 目标

- 单张动漫图片失败不能中止整批文案任务。
- 先用低成本参数降低失败率。
- 通用 VLM 失败时有明确的标签/CLIP 降级路径。
- 兜底文案必须标记来源，不能冒充 VLM 自然语言描述。
- 失败原因、样本和日志可本地追溯。
- 不阻塞普通照片的文案分析。

## 阶段 0：Ollama 参数矩阵

用 20～30 张失败动漫图做小规模对比，不直接改全部任务。

| 参数 | 候选值 | 目的 |
|---|---|---|
| `temperature` | 0.1 / 0.2 | 降低随机重复 |
| `top_p` | 0.9 | 保持基本质量 |
| `repeat_penalty` | 1.2 / 1.3 / 1.4 / 1.5 | 抑制重复 token |
| `repeat_last_n` | 64 / 128 | 控制惩罚窗口 |
| `num_predict` | 128 / 256 | 限制长循环 |
| `num_ctx` | 4096 | 当前上限 |
| `stop` | `\n\n`、代码围栏 | 尝试提前截断 |

每组记录：

- 成功率、失败类型
- 单张耗时
- 文案质量 1～5 分
- 标签/OCR 是否可用

建议把参数调整作为失败后的第二次尝试，不要默认对全部图片使用高 repeat penalty，避免正常照片文案变差。

## 阶段 1：模型对比

同一批失败图分别测试：

- `qwen2.5vl:3b` 当前版本
- `qwen2.5vl:3b` 的 Q5/Q8 量化版本（如可用）
- `qwen2.5vl:7b`
- `minicpm-v`
- `llava` 系列
- `moondream`

指标：

- 成功率、总耗时、显存占用
- 中文文案质量 1～5 分
- 动漫角色、服饰、构图、颜色标签准确率
- 是否仍触发 `token repeat limit`

结论只选一个主力模型和一个备用模型；不建议每张图自动串行调用多个大模型。

## 阶段 2：动漫标签模型

候选：

- WD Tagger / wd14-tagger
- DeepDanbooru

触发条件：

- VLM 返回 `token repeat limit reached`
- 连续 JSON/描述失败
- 或图片判定为插画/动漫

流程：

1. 标签模型输出结构化标签。
2. 映射为中文短语。
3. 拼接短文案，例如：`动漫插画，1位女性，粉色头发，制服，室内，暖色`。
4. 入库标记 `caption_source=wd14`。
5. UI 显示「标签兜底」，不显示为 VLM 文案。

模型和标签词表均作为可选下载，不进入默认安装包。

## 阶段 3：CLIP 兜底

不安装额外模型时复用现有基础设施：

- CLIP 已有标签：人物、场景、颜色、服饰。
- 图片向量检索最近邻，借用相似图片描述作为参考。
- 聚合最近邻标签生成粗粒度文案。
- 入库标记 `caption_source=clip`。

目标是避免空白结果、保留文本检索能力，不追求自然语言质量。

## 预处理重试

只在参数重试仍失败后有限尝试：

- 降低饱和度
- 灰度
- 边缘/线稿提取
- 局部裁剪后合并

每种预处理最多一次；失败后进入标签/CLIP 降级，不无限重试。

## 工程稳健性

### 失败分类

日志和任务详情区分：

- `token_repeat_limit`
- `ollama_500`
- `ollama_timeout`
- `invalid_json`
- `image_missing`
- `model_unavailable`

### 连续失败策略

- 连续 10 张 `token_repeat_limit`：暂停任务，提示切换模型。
- 连续 5 张连接失败：停止任务，提示检查 Ollama。
- 单张 JSON/图片错误：记录后继续。

### 失败样本归档

本地目录：

```text
data/ai-failures/
  <job_id>/
    manifest.json
    <resource_id>-thumb.jpg
    <resource_id>-error.txt
```

不复制原图，只保存缩略图和错误摘要；不上传网络，按现有日志保留策略清理。

### 数据字段

建议扩展文案结果：

- `caption_source`：`vlm` / `wd14` / `clip` / `none`
- `caption_status`：`ready` / `fallback` / `failed`
- `failure_kind`
- `attempts`
- `model_id`

任务历史保留总体失败数；逐图细节进入日志或失败样本目录。

## 推荐降级链

```text
qwen2.5vl:3b（当前参数）
  ↓ 失败
qwen2.5vl:3b（高 repeat_penalty / 低 num_predict 重试一次）
  ↓ 失败
WD Tagger（已安装时）
  ↓ 未安装或失败
CLIP 标签 / 最近邻文案
  ↓ 仍然没有
标记待人工处理
```

`qwen2.5vl:7b`、`minicpm-v` 只作为对比后的主力/备用，不建议每张图自动串行调用。

## 验收标准

- 20～30 张失败动漫图完成参数对比。
- 单张失败不中止整批。
- 连续同类失败达到阈值会暂停并告警。
- 兜底文案来源可见。
- 失败样本和日志可按日期追溯。
- 普通照片的文案成功率不下降。
- 不把动漫标签兜底伪装成 VLM 文案。

## 不做

- 不默认打包 WD Tagger 或大模型权重。
- 不上传失败图片、文案或错误日志。
- 不因动漫图片失败阻塞普通照片分析。
- 不在没有对比结果前直接替换主力模型。
