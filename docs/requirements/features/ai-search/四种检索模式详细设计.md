# AI 检索四种模式 · 详细设计

> 状态：L2 详细设计（2026-10-23），待确认后实现  
> 上游：`ai-search/设计.md`、`image-similarity/设计.md`  
> 范围：文搜图、图搜图、图文融合、文案/标签/OCR。  
> 不属于本设计：模型内部算法推导、云端检索、视频完整语义理解。

## 0. 结论

四种模式不能共用一套“取 top 30”的逻辑：

```text
文搜图     = 查询解析 + 结构化过滤 + CLIP + 文案/标签 + RRF
图搜图     = 模式路由 + CLIP/DINO/OSNet + pHash + 分模式结果
图文融合   = 图片召回 + 文本召回 + RRF + 可选 VLM 重排
文案/标签  = 图片分析文档 + 文本索引 + 可选编辑/审核
```

当前固定 CLIP 标签词表、无阈值 top30、caption 只存不用，这三项都要退役或改造。

## 1. 共同索引层

### 1.1 数据表

```text
ai_embeddings(
  resource_id INTEGER,
  kind TEXT,              -- clip_image / dino_image / osnet_person / caption / ocr
  model_id TEXT,
  dim INTEGER,
  vector BLOB,
  source_path TEXT,
  updated_at TEXT,
  PRIMARY KEY(resource_id, kind, model_id)
)

ai_documents(
  resource_id INTEGER PRIMARY KEY,
  caption TEXT,
  short_caption TEXT,
  tags_json TEXT,
  attributes_json TEXT,
  ocr_text TEXT,
  model_id TEXT,
  prompt_version TEXT,
  status TEXT,            -- pending / ready / failed
  created_at TEXT,
  updated_at TEXT
)

ai_tags(
  resource_id INTEGER,
  tag TEXT,
  category TEXT,
  confidence REAL,
  source TEXT,            -- vlm / detector / user
  model_id TEXT,
  PRIMARY KEY(resource_id, tag)
)

ai_hashes(
  resource_id INTEGER PRIMARY KEY,
  dhash INTEGER,
  phash INTEGER,
  updated_at TEXT
)

ai_jobs(
  id TEXT PRIMARY KEY,
  kind TEXT,              -- analyze / clip / dino / osnet / hash
  status TEXT,
  total INTEGER,
  done INTEGER,
  message TEXT,
  model_id TEXT,
  created_at TEXT,
  updated_at TEXT
)
```

- `ai_vectors` 迁移到 `ai_embeddings(kind='clip_image')`；
- 一个资源可以有多类向量；
- 只索引 active 图片；软删保留数据但查询过滤；
- OCR 和 caption 属于 `ai_documents`，不混入视觉向量。

### 1.2 模型注册

| 能力 | 默认 | 可选 |
|---|---|---|
| 语义图文 | Chinese-CLIP ViT-B/16 | — |
| 视觉相似 | — | DINOv2-small 384d |
| 人物/造型 | — | OSNet 512d |
| 重复 | dHash/pHash | SSCD |
| 文案/标签 | — | Qwen2.5-VL-3B / Florence-2-base |
| OCR | — | RapidOCR / PaddleOCR |

每个模型记录：

```text
model_id, version, sha256, dim, preprocess, prompt_version, installed
```

模型或 prompt 升级时，旧向量保留到新版本完成后切换。

### 1.3 查询公共结构

```text
QueryPlan
  text_semantic: string
  hard_filters: count / orientation / time / type / role / tag
  soft_filters: color / scene / action
  labels: []
  negation: []
  image_query: resourceId | upload | null
  mode: text | image | fusion | duplicate | person | auto
```

响应公共字段：

```text
indexed     active 图片已索引数
matched     通过硬过滤/标签后的候选数
returned    本次实际返回数
filters     识别出的条件
confidence  strong / medium / weak
```

## 2. 文搜图

### 2.1 目标

把自然语言查询解析成“硬条件 + 语义文本”，而不是把整句话直接丢给 CLIP。

### 2.2 查询解析

支持：

- 人数：一个人、两个人、合影、多人、空镜；
- 方向：横图、竖图、方图；
- 时间：2025 年、最近、今天；
- 类型：图片、视频；
- 现有元数据：标签、分类、角色、扮演者、合集；
- 属性：颜色、场景、动作、物体；
- 否定：不要帽子、不是夜景。

示例：

```text
输入：两个人在室内，红帽子，横图
解析：
  hard_filters: 人数=2, 方向=横图
  labels: 红色帽子
  text_semantic: 室内
  display: 人数=2 · 横图 · 标签=红色帽子
```

无法识别的部分保留在 `text_semantic`，不强行丢弃。

### 2.3 三路召回

```text
候选集 = active 图片
  → 硬过滤（人数/方向/时间/角色/类型）
  → 标签过滤（有命中时）
  → CLIP text → image 相似度
  → FTS5/trigram 搜 caption/tags/OCR
  → RRF 融合
  → 可选 VLM rerank
```

候选倍数：

```text
recall_k = max(limit * 5, 100)
rrf_k = 60
```

### 2.4 排序与阈值

- CLIP 分数不能直接和 BM25 相加；用 RRF。
- 人数/方向/标签是硬条件，不参与软分。
- 标签命中但 CLIP 分数低时，仍可因标签召回。
- `confidence`：
  - `strong`：有硬条件命中或 RRF 前几名明显高；
  - `medium`：只有 CLIP 召回；
  - `weak`：无标签/无硬条件且分数低。
- 无 caption/标签时，不阻止 CLIP 搜索；降级为 `medium/weak`。
- 无结果判定不能只看 top30；没有候选或硬条件无命中时必须返回空。

### 2.5 API

```text
GET /ai/search?q=...&limit=30&mode=text
```

响应：

```json
{
  "mode": "text",
  "indexed": 236,
  "matched": 18,
  "returned": 10,
  "filters": ["人数=2", "标签=帽子"],
  "confidence": "medium",
  "items": [],
  "scores": []
}
```

### 2.6 UI

- 查询框；
- 识别条件 chips；
- `已索引 / 匹配 / 返回`；
- `weak` 时提示“结果可能不准确”；
- 空结果显示“没有符合当前条件的图片”，不硬凑。

### 2.7 失败与降级

| 情况 | 行为 |
|---|---|
| 模型未安装 | 不显示可用搜索，给安装 CTA |
| caption 未生成 | CLIP-only，标记弱置信度 |
| 标签词表未覆盖 | 保留语义文本 |
| 硬条件无命中 | 立即空结果 |
| CLIP 分数低 | 返回空或 weak，不假装命中 |

## 3. 图搜图

### 3.1 模式

| 模式 | 信号 | 回答 |
|---|---|---|
| semantic | CLIP image | 主题/服装/场景相似 |
| visual | DINOv2 | 同拍摄/构图/姿态 |
| duplicate | dHash/pHash | 缩放/压缩/轻裁剪重复 |
| person | OSNet | 同一个人/同一套造型 |
| auto | 以上融合 | 默认综合 |

### 3.2 查询来源

- 库内 resource；
- 外部文件上传；
- 剪贴板；
- 拖放。

外部图片只编码查询，不写入索引。

### 3.3 流程

```text
query image
  → 读取/计算对应向量
  → active 候选
  → 排除自身
  → hash / CLIP / DINO / OSNet
  → 模式结果
  → auto 用 RRF 合并 semantic+visual
  → duplicate 置顶
```

### 3.4 排序

- duplicate：Hamming 距离，阈值按数据校准；
- CLIP/DINO：cosine；
- OSNet：cosine，取最大 person embedding；
- auto：RRF，不把不同模型原始分数直接相加；
- 查询图永远排除。

### 3.5 API

```text
GET  /ai/similar?resourceId=49&mode=auto&limit=30
POST /ai/similar/file
```

响应按模式分组：

```json
{
  "mode": "auto",
  "indexed": 236,
  "returned": 30,
  "groups": {
    "duplicates": [],
    "semantic": [],
    "visual": [],
    "person": []
  }
}
```

### 3.6 UI

- 查看器「找相似」；
- Inspector AI tab；
- AI 中心「以图」；
- 模式 tabs；
- 查询图 chip；
- 结果按模式分组，避免不可解释混合分。

### 3.7 不采用

- 不用 caption 替代图搜图；
- 不默认人脸；
- 不在 236–5k 上 HNSW/Qdrant；
- 不把“同一拍摄”误称为“同一个人”。

## 4. 图文融合

### 4.1 目标

支持“像这张图，但要符合某文字条件”。

### 4.2 查询结构

```text
reference: resourceId | upload | clipboard
text: 自由描述/属性条件
weights: image 0.5 / text 0.5（高级）
strict: false（默认并集）
```

### 4.3 流程

```text
查询图 → CLIP/DINO/OSNet/hash
查询文本 → 解析 + CLIP text + caption/标签
  → 硬过滤
  → 图片候选 topK
  → 文本候选 topK
  → RRF 融合
  → 可选 VLM topK 重排
```

### 4.4 融合规则

- 默认软融合：`score = w_img/(k+rank_img) + w_text/(k+rank_text)`；
- 严格模式：取交集，适合“必须是红帽子”；
- 人数/方向/时间/角色是硬过滤，不参与权重；
- 文本中的属性标签命中时优先标签过滤；
- 查询图排除；
- 结果标记来源：`image` / `text` / `both`。

### 4.5 典型查询

| 查询 | 处理 |
|---|---|
| 这张图 + 红色帽子 | 图片召回 + 标签/颜色/ VLM 重排 |
| 类似这张构图的双人照 | 图片召回 + 人数=2 |
| 这张图同一个人 | 转 person 模式，不走向量融合 |
| 这张图 + 横图 | 图片召回 + 方向过滤 |
| 这张图 + 不要帽子 | 图片召回 + 否定标签/重排 |

### 4.6 冲突处理

- 图片没有红色帽子但文本要求红色帽子：返回空或明确“条件冲突”；
- 不静默把不符合的图片排前面；
- VLM 重排只能调整，不可绕过硬过滤。

### 4.7 API

```text
POST /ai/search/fusion
{
  "resourceId": 49,
  "query": "红色帽子",
  "weights": { "image": 0.5, "text": 0.5 },
  "strict": false,
  "limit": 30
}
```

### 4.8 UI

- 图片 chip + 文本框；
- 「更像图片 / 更像文字」滑块；
- 严格匹配开关；
- 识别条件 chips；
- 结果来源标记。

## 5. 文案 / 标签 / OCR

### 5.1 目标

让图片拥有可读、可搜索的分析文档；不是为了替代视觉向量。

### 5.2 分析输出

```json
{
  "caption": "两个人在室内合影，右边的人戴粉色帽子。",
  "short_caption": "室内两人合影，粉色帽子",
  "scene": ["室内", "摄影棚"],
  "actions": ["合影", "看镜头"],
  "colors": ["粉色", "黑色"],
  "objects": [{"name": "帽子", "color": "粉色", "confidence": 0.91}],
  "people": {"count": 2},
  "clothing": ["黑色外套"],
  "ocr": [],
  "tags": ["两个人", "室内", "粉色帽子"],
  "uncertain": []
}
```

### 5.3 模型

- 可选本地 VLM：
  - Qwen2.5-VL-3B：中文质量好，重；
  - Florence-2-base：轻，英文强；
  - 后续可接 Ollama/llama.cpp Provider。
- OCR：RapidOCR/PaddleOCR，后续；
- 不使用 Jina v4 作为默认；
- 不把 VLM 放进默认安装包。

### 5.4 生成流程

```text
active image
  → 缩略图/主图
  → VLM JSON 分析
  → schema 校验
  → 规范化标签/属性
  → ai_documents + ai_tags
  → FTS/caption embedding
```

- 批处理、失败重试、可暂停；
- 记录 `model_id/prompt_version`；
- 模型升级后重建；
- 用户可以查看/编辑/删除标签（后续）。

### 5.5 文本索引

- caption/tags/OCR 进入 FTS5 trigram；
- 中文查询用 trigram 或分词列；
- 需要语义搜索时再加 caption embedding；
- 文案只服务文本检索，不参与图搜图视觉相似；
- 一条 caption 不能作为唯一索引。

### 5.6 成本

- 236 张：可一次性后台生成；
- 1 万张：队列、分批、失败重试；
- 5 万张：默认不跑 VLM，只对新增/重要资源生成；
- 提供“仅分析当前选择”入口。

### 5.7 失败

| 情况 | 行为 |
|---|---|
| 模型未安装 | 显示未启用，保留 CLIP |
| 分析失败 | 记录失败，不写假 caption |
| JSON 非法 | 重试/回退短 caption |
| OCR 空 | 不写入空文本 |
| 用户删除标签 | 标记 user override，重跑不覆盖 |

## 6. 评估

固定查询集至少覆盖：

- 人数：一个人、两个人、合影；
- 属性：红帽子、蓝发、室内、夜景；
- 动作：跑步、自拍；
- 否定：不要帽子、不是夜景；
- 时间/角色/标签；
- 图片参考 + 文本；
- 无匹配查询。

指标：

- Recall@10/20；
- nDCG@10；
- 计数准确率；
- caption/tag precision；
- 空结果准确率；
- 文搜图/图搜图/融合延迟；
- 用户点击率（后续）。

## 7. 落地顺序

```text
P0  统一 ai_embeddings/ai_documents/ai_tags 模型
P1  查询解析 + 硬过滤 + matched/returned/empty
P2  文搜图：CLIP + FTS + RRF
P3  图搜图：CLIP + dHash + 连拍会话
P4  图文融合：图片/文本双路 + RRF
P5  文案/标签：可选 VLM + OCR + FTS
P6  DINOv2 / OSNet / VLM rerank
```

每个阶段的完成标准：

- 不破坏现有图库/时间线/地图/角色；
- 有固定查询集的前后对比；
- 不允许“没有匹配仍返回 30 张”而不标记；
- 任务可取消/失败可重试。

## 8. 明确不做

- 不用固定 CLIP 标签词表作为正式标签；
- 不把 caption 当视觉相似度；
- 不把图文向量直接相加；
- 不默认 Jina v4 / Qdrant / 云端 VLM；
- 不在 5k 以下引入 ANN/向量数据库；
- 不默认人脸识别；
- 不允许无结果时静默硬凑。
