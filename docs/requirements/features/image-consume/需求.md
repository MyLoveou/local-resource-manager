# 图片资源消费 · 需求

> 状态：**已定稿**（2026-09-12 · 用户确认可以按此实现；Viewer.js 须封装）  
> Feature ID：`image-consume`  
> OpenSpec：`openspec/changes/image-consume/`  
> 所属：[local-resource-manager](../local-resource-manager.md) M2 预览；[module-map](../../product/module-map.md)「消费」子集  
> 上游：网格单击选中 + 右侧 InfoPanel；列表用缩略图；详情可改描述/待办。**无查看器、无打开位置、无外部应用**

## 1. 问题

图片只能在网格和信息栏封面里看到小图/封面，不能认真看原图（缩放、旋转、相邻张），也不能从本应用打开资源管理器或系统看图软件。看图时改描述/待办还要回到三栏，打断消费。

`lrm-ui` 已写双击大图预览、面板「在文件管理器中打开」。与刚拍板的批量模式并存：平时单击仍只选中。

## 2. 本轮做 / 不做

| 做 | 不做 |
|----|------|
| 图片查看器：缩放、拖拽平移、旋转、适应窗口/原尺寸、全屏、当前列表上一张/下一张、键盘 | 视频播放器；小说/音乐消费 |
| 查看器布局：**左元数据（复用现有描述/待办/评分等）+ 右看图** | 独立「画廊」模块（沉浸连看可后置） |
| 已选中后再点同一张卡片打开查看器；信息栏封面也可打开 | 改批量删除模式；右键菜单全集 |
| 打开库内 primary **所在文件夹**（资源管理器选中该文件） | 打开用户当初的导入源路径（库不登记源根） |
| 用外部应用打开库内 primary：系统**默认关联**；并可**选择其他应用**（走系统「打开方式」或挑选可执行文件） | 自建应用商店式列表；记忆上次第三方 exe（本轮不做） |
| 浏览器无法解码（如部分 HEIC）时提示改用外部应用 | 像素编辑、标注、滤镜 |

## 3. 用户故事

- **US-C.1** 图片页单击选中 → 再点该卡 → 打开查看器，右侧是原图，左侧可改描述/待办并保存（待办仍立刻请求）。  
- **US-C.2** 查看器内滚轮缩放、拖拽、旋转、适应/1:1；Esc 关闭后仍在图片页且选中不变。  
- **US-C.3** 左右方向键或按钮切到当前网格已加载列表的相邻图片。  
- **US-C.4** 信息栏「打开所在位置」→ 资源管理器打开库内副本所在目录并选中文件。  
- **US-C.5** 「用外部应用打开」→ 系统默认关联程序打开该文件；「选择其他应用」→ 系统打开方式对话框（或挑选 .exe / .app），用所选程序打开同一库内文件。  
- **US-C.6** 批量删除模式下单击只勾选，不打开查看器。  
- **US-C.7** 视频卡不打开本查看器。

## 4. 验收

- [ ] 未选中时单击只选中并刷新信息栏（与 D-20260912-16 一致）。  
- [ ] 已选中图片再点同一张（或点信息栏封面）打开查看器：左面板、右原图。  
- [ ] 查看器内能改描述（点保存）和待办（立刻请求），与主界面信息栏同一套 API。  
- [ ] 缩放/平移/旋转/适应/原尺寸可用；全屏可用；Esc 关闭。  
- [ ] 相邻张只在**当前已加载**的图片列表内切换，不跨视频、不跨未加载页。  
- [ ] 打开位置：资源管理器可见 `{library}/image/{id}/` 下的 primary 文件。  
- [ ] 外部打开：默认应用能启动；「选择其他应用」能换程序打开同一文件；本应用不崩溃。  
- [ ] 路径须走主进程 `shell`；渲染进程不 `require('fs')`、不自己拼盘符打开。  
- [ ] 批量模式不打开查看器。

## 5. 契约草案

无新 REST。看图仍用已有 `GET .../files/{id}/content`（原图）与 `GET /library/resources/{id}`（元数据、`files[].path`）。

新增 **Electron IPC**（preload 暴露，仅本机）：

| 通道 | 入参 | 行为 |
|------|------|------|
| `shell:showItemInFolder` | `{ path: string }` | `shell.showItemInFolder`；文件必须存在 |
| `shell:openPath` | `{ path: string }` | `shell.openPath`（系统默认应用） |
| `shell:openWith` | `{ path: string }` | 弹出系统「打开方式」；Win：`OpenAs_RunDLL`；macOS：选 .app 后 `open -a`；Linux：选可执行文件后主进程 spawn（参数为文件路径，禁止拼进 shell 字符串） |

禁止：渲染进程对库目录复制/移动/哈希；把任意 URL 交给 `openPath`；`/v1`。

路径来源：详情里 `files` 中 `role=primary` 的 `path`（库内副本绝对路径）。主进程校验：是本地文件、存在。本轮可再限制「必须落在库目录下」（实现方案写清如何取库根）。

## 6. 假设（未另拍板则按此实现）

1. **只做图片**；视频消费另立项。  
2. 查看器壳自己做左右分栏；右侧集成成熟看图库。**推荐 Viewer.js**（见 §7.1 选择标准）。未另指定则按此实现。  
3. 打开入口：已选中再单击同一张 = 打开；**双击**同等打开（对齐 lrm-ui）。  
4. 外部应用：默认关联 + 系统级「选择其他应用」。不维护本应用内的软件目录，不记忆上次选择。  
5. 定位/打开的是**库内副本**，不是导入源。  
6. 查看器覆盖**中间网格**；壳右侧信息栏在看图时仍可用。（`image-viewer-ux` 拟修订，待确认。）

## 7. 开放问题

### 7.1 看图库选择标准（本切片）

必须同时满足，缺一则扣分：

| # | 标准 | 为何是本产品的硬条件 |
|---|------|----------------------|
| S1 | 能嵌进**右侧容器**（inline），不要强制独占整页 lightbox | 左边要长期放元数据面板 |
| S2 | 开箱：缩放、拖拽平移、**旋转**、适应窗口、1:1、全屏 | 需求写死的手势，不要自己叠一套矩阵 |
| S3 | Vue 3 可封装、能 `destroy`，不泄漏监听 | 覆盖层反复开关 |
| S4 | 许可证宽松（MIT / Apache） | 桌面闭源/自用均可 |
| S5 | 原图走 HTTP `content` URL，不要求瓦片服务 | 我们没有 IIIF |
| S6 | 体积与维护：有人在维护，包不要拖一串 jQuery | Electron 已够重 |

对照：

| 标准 | Viewer.js | PhotoSwipe 5 | OpenSeadragon |
|------|-----------|--------------|----------------|
| S1 嵌进右栏 | 有 inline，合适 | 以全屏灯箱为主，和左栏抢层 | `div` 容器，合适 |
| S2 旋转 / 适应 / 1:1 | 工具条现成 | 缩放平移一流；旋转、1:1 要自做 | 深缩放一流；工具条几乎要自做 |
| S3 Vue 生命周期 | 无官方 Vue 3，薄封装即可 | 有社区包装，灯箱模型要改 | 官方 JS，封装量中等 |
| S4 许可 | MIT | MIT | BSD |
| S5 单张 HTTP 图 | 正是这个模型 | 正是这个模型 | 为巨图/瓦片设计，普通照片杀鸡用牛刀 |
| S6 体量 | 小，专注看图 | 中，交互现代 | 大，API 陡 |

**建议：Viewer.js。** 本切片是「右栏完整看图 + 左栏元数据」，S1+S2 权重最高。PhotoSwipe 更适合不要左栏、追求跟手缩放的灯箱。OpenSeadragon 留给以后真有超大图/深缩放再立项。

若你否决 Viewer.js：缺旋转可接受 → PhotoSwipe；明确要博物馆级深缩 → OpenSeadragon。
