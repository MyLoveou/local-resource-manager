# 图片资源消费 · 实现方案

> 状态：**已定稿**（与 OpenSpec `design.md` 同一范围）  
> Feature ID：`image-consume`

## 目标 / 不交付

与 [`需求.md`](./需求.md) 一致。沿用 library 文件流 + 现有 InfoPanel 字段 API；**不**新表、不新 REST 前缀。看图 IO 仍是 HTTP 文件流；**打开磁盘位置/外部应用只走主进程 shell**。

## 与现有架构的取舍

| 做法 | 为何 |
|------|------|
| 覆盖层只盖中间网格，右侧仍用壳 InfoPanel | 看图时改元数据；不另开窗口 |
| 原图 URL = 已有 content 路由 | 渲染只 HTTP，不读盘 |
| IPC `showItemInFolder` / `openPath` / `openWith` | 默认打开 + 系统打开方式；渲染无 Node |
| Viewer.js 放右侧容器 | 对照 §7.1：S1 嵌栏 + S2 旋转/适应/1:1 现成 |
| 不新开 BrowserWindow | 与壳同一窗口，元数据 Pinia/HTTP 现成 |

## 模块边界

```
网格单击        → selection（未选中=选中；已选中且为图片且非批量模式=打开覆盖层）
覆盖层           → 只盖 `main`；关闭/切张在图上（见 `image-viewer-ux`）
元数据           → 壳右侧 InfoPanel（看图时不卸载）
看图             → 封装后的 Viewer.js；源 img 不可见，只一层画布
打开位置/外部   → preload → main：showItemInFolder / openPath / openWith
```

**不改**：后端路由（除非库根校验必须加一个 `GET` 库根，本轮优先用详情里已有绝对路径 + 主进程 `exists`）。

库根限制（建议）：主进程用 `path.resolve` 后 `fs.existsSync` + `stat.isFile()`；若能从配置读到 library 目录则 `path.relative` 禁止 `..`。配置暂无设置项时，**本轮只校验存在的本地文件**（假设 7 开放：是否必须库根——暂定先存在性校验）。

## 数据流

**打开查看器**  
已选中 + 再点 → 取 id → `getResource` → 右侧 `resolveLibraryMediaUrl(coverPath 或 primary content)` 喂给 Viewer.js；左侧绑同一 `selectedId`。

**改描述/待办**  
与信息栏相同：`patchResource` / todo HTTP；`library.bump` 仅在需要刷新网格标题时。

**打开位置**  
`files` 找 `role===primary` → IPC showItemInFolder(path)。失败：文件缺失则提示（资源可能 lost）。

**外部打开**  
默认：`shell.openPath`。选择其他：`openWith`（系统对话框或挑选应用）。主进程 `spawn`/`open -a` 只传文件路径数组，不拼 shell。失败返回文案。

**错误**  
IPC 拒绝非文件；查看器解码失败 → 文案 + 引导外部打开。

## 风险

| 风险 | 缓解 |
|------|------|
| Viewer.js 与 Vue 卸载泄漏 | onUnmounted destroy 实例 |
| 超大原图撑爆内存 | 仍用原图 content（本轮不另做预览档）；可后置大图档 |
| 第二击与批量模式冲突 | 批量模式只 toggle |
| 绝对路径进渲染 | 详情已有；不新增任意路径输入框 |
