# AI 智能助手 · 需求

状态：后续功能，未实现。当前不并入 AI 建议页。

## 定位

AI 智能助手是“语言驱动的资源处理代理”，不是单纯的建议列表。

用户可以用自然语言描述条件，助手先检索匹配资源，再调用受控工具执行操作。典型请求：

- “把海边、两个人的照片加入‘夏日’合集”
- “找出粉色头发的动漫图，给它们打上‘粉色头发’标签”
- “把这些图里符合条件的角色建立为新角色”
- “先给我看会改动哪些资源，我确认后再执行”

## 与 AI 建议页的边界

AI 建议页 v1 只做：

- 未落地标签建议
- 匹配现有角色/扮演者/合集
- 用户逐条确认后应用

以下属于智能助手，不塞进建议页：

- 没有现成实体时自动创建角色
- 没有现成合集时自动创建合集
- 通过语言批量筛选和处理资源
- 多步骤任务、工具调用、执行计划和回滚

## 工具边界

建议首版工具：

- `search_resources`：按文本、标签、角色、人数、方向等条件查询
- `add_tags`：给资源增加标签
- `add_to_collection`：加入已有合集
- `create_collection`：创建新合集
- `create_character`：创建角色
- `link_character`：关联角色到资源
- `set_category`：设置分类

暂不开放：

- 删除资源
- 修改原文件
- 批量覆盖人工编辑的元数据
- 自动执行未经确认的写操作

## 执行安全

1. 先检索、后预览、再执行。
2. 写操作必须展示影响数量和资源列表。
3. 默认需要用户确认；可对白名单操作提供“本次会话自动确认”。
4. 每步写操作记录到操作日志，可查看和回滚。
5. 助手不能绕过现有权限、模块开关和硬过滤。
6. 失败时保留已完成部分和失败清单，不伪装全部成功。

## 技术实现方向

- 语言模型负责解析意图、生成工具调用计划，不直接写数据库。
- 工具层由后端实现，复用现有资源、标签、角色、合集 API。
- 前端提供执行计划、资源预览、确认/取消、失败重试。
- 资源选择可以来自当前搜索结果、当前筛选器或用户勾选集合。
- 工具调用参数和结果结构化记录，便于审计和回归测试。

## 分阶段

### A1 只读预览

- 自然语言转检索条件
- 返回匹配资源、数量和解释
- 不写数据库

### A2 单步写操作

- 添加标签、加入已有合集
- 执行前确认
- 操作日志

### A3 创建实体

- 无现成实体时创建角色/合集
- 先显示新建计划，确认后创建并关联
- 支持撤销

### A4 多步骤任务

- 条件筛选 → 创建合集 → 批量加入
- 失败清单与部分重试
- 会话级审计

## 不做

- 不自动执行删除或不可逆操作。
- 不让模型直接生成 SQL 并执行。
- 不上传资源内容或操作记录。
- 不在 AI 建议页混入自动创建实体的行为。
