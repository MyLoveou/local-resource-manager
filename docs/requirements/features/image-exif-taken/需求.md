# 图片拍摄时间 · 需求

> 状态：**已落地**（小切片直接实现；可手改；不回填）  
> Feature ID：`image-exif-taken`  
> OpenSpec：未建独立 change（列与 API 字段已在，风险低）  
> 上游：`metadata-panel-fields`（Pillow 宽高）、`library-search-sort`（`takenAt` 排序键）、探索稿 `image-library-depth` D1  
> 对齐：开发阶段测试库可清库重导；**不做旧库回填**

## 1. 问题

`files.exif_taken_at` 列、详情字段 `exifTakenAt`、图片排序键 `takenAt` 都已存在，但导入 `probe_image` 只写宽高，仓储 `add_file` 不接收拍摄时间，信息栏也不展示。清库重导后按拍摄时间排序仍全是空。

## 2. 已按口令收口

1. **本刀只做 D1**：新导入图片写入拍摄时间，并在信息栏看见；让已有 `takenAt` 排序有数。  
2. **不做旧库回填**。开发数据清库再导入即可。  
3. **不**做 D2–D6、画廊、EXIF 机身/GPS、以图搜图、写回文件。  
4. 漫画 / 视频 / 其它类型本刀不写拍摄时间。  
5. **可手改**：编辑区保存后 PATCH `exifTakenAt`；空则清空；非法/非图片 400。

## 3. 范围

### IN

- 图片类型 `ingestKind=file`：复制进库后，与宽高同一趟 Pillow 探测，解析 EXIF 拍摄时间写入 **primary** 的 `files.exif_taken_at`。  
- 详情 API 已有 `files[].exifTakenAt`：补写入即可被前端读到。  
- 信息栏：技术信息只读展示；编辑区可改拍摄时间，随面板保存 PATCH。  
- 面板或 PATCH 手改拍摄时间。  
- 失败不挡导入（与无 EXIF / Pillow 读失败 / 宽高失败同一策略）。  
- 单测：带 DateTimeOriginal 的夹具图导入后列有值；无 EXIF 图导入成功且列为 null。

### OUT

- 扫描已有资源补列。  
- 把拍摄时间写回磁盘 EXIF / XMP。  
- 机身、镜头、ISO、GPS、时区转换、按拍摄日分组网格。  
- 视频/音频容器创建时间；漫画页 EXIF。  
- 新排序键、新搜索字段、FTS。  
- 新表、新 HTTP 资源。

## 4. 用户故事

- **US-T.1** 导入一张带 EXIF 拍摄时间的 jpg → 点选后信息栏「拍摄」有本地日历时间；图片页按拍摄时间排序时该卡位置正确。  
- **US-T.2** 导入一张无 EXIF 的 png → 导入成功；「拍摄」为「—」；该键排序时沉底（沿用现有 NULLS LAST）。  
- **US-T.3** 探测失败或损坏图 → 导入仍成功，拍摄为空。  
- **US-T.4** 手改拍摄时间并保存 → 详情与按拍摄排序用新值；清空后为「—」。

## 5. 验收

- [ ] 新导入有 EXIF 拍摄时间的图片：详情 `exifTakenAt` 非空；信息栏可见。  
- [ ] 新导入无该字段：导入成功；展示「—」。  
- [ ] 图片网格选「拍摄时间」排序：有值的按时间，无值在后（降序时）。  
- [ ] 不出现回填任务/按钮/启动扫描。  
- [ ] 非图片导入路径不写 `exif_taken_at`。  
- [ ] 不改磁盘原图；库内副本也不改像素/EXIF。

## 6. 契约草案

- `PATCH /library/resources/{id}` 增加可选 `exifTakenAt`（仅图片；写 primary `files.exif_taken_at`）。  
- `GET` 详情：沿用 `files[].exifTakenAt`。  
- 库列：已有 `files.exif_taken_at TEXT`，不迁新列。存储为可排序的日历字符串（设计锁定格式）。  
- 探测失败：字段 null，资源 `active`。

禁止：渲染进程读盘解析 EXIF；GET 任意磁盘路径。

## 7. 与探索稿关系

`image-library-depth` 仍是盘点。本目录是 **D1 独立切片**。D2+ 与 N* 不随本刀授权。

## 8. 开放问题

无。已锁：可手改、只新导入、不回填、不写回文件。
