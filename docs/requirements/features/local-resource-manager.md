## 1. 背景

用户需要一个**本地资源管理器**，统一管理本地多种类型资源（视频、图片、小说、番剧、AV 等），并提供两类外部能力：

1. **元数据抓取**：从网上抓取资源元数据（标题、封面、简介、演员、标签等）。
2. **下载平台对接**：支持多种下载来源/平台。

## 2. 目标用户

- 拥有大量本地媒体资源的个人用户
- 需要批量整理、补全元数据、建立可检索资源库的用户
- 通过多个渠道（BT/磁力/网盘等）获取资源、希望集中管理的用户

## 3. 要解决的问题

- 本地资源分散在各目录，缺乏统一视图与检索
- 手动补全元数据（标题/封面/演员/标签）成本高
- 多种下载来源操作割裂，缺少统一入口
- 无法按类型（番剧按季/集、小说按卷/章）组织与消费

## 4. 初步 IN SCOPE

- 本地资源扫描、入库、目录/文件管理
- 资源类型抽象：视频、图片、小说、番剧、AV 及扩展类型
- 元数据抓取与清洗（来源待定，见开放问题）
- 资源展示与检索（列表/详情/标签/搜索）
- 下载平台对接框架（来源插件化，见开放问题）
- 本地数据存储（初始倾向 SQLite）

## 5. 初步 OUT OF SCOPE

- 在线播放/流媒体服务
- 移动端
- 多用户/账号体系（单机本地优先）
- 资源分享/发布

## 6. 开放问题（须用户回答）

> 技术栈/范围/类型优先级/来源策略/下载方式已定（见 §0）。以下为**仍待后续定稿**的问题，本次初始化不阻塞：

1. 自建抓取的具体站点清单与接口契约（针对图片、视频）
2. 番剧/小说等结构化内容是否纳入后续版本（本次 OUT OF SCOPE）
3. 内置下载器支持协议范围（HTTP / BT / 磁力）
4. 数据存储确认 SQLite，以及库表设计（待 L3 方案）

## 7. 非功能要求（初稿）

- 资源库规模预估（万级/十万级），索引与检索性能要求
- 抓取失败与网络异常处理策略
- 数据本地化、可备份
