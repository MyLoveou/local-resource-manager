> 状态：**草案**（探索盘点；第一刀已拆 `image-exif-taken`）

## 1. 背景

图片是库内最早闭环的类型：能导入复制、网格浏览、信息栏改通用元数据、二次点击看原图、系统定位文件。用户现在问的是：**在「能进能看」之后，图片这一类还值不值得加深、还能加什么。**

路线已拍板（D-20260917-01）：抓取、下载、合集、画廊沉浸、词表治理、以图搜图均属 **A-plus**，不得挡其它类型最低消费。其它类型最低消费已合入 master，因此图片加深**可以排期**，但仍须单独立项、一刀一条主路径。

## 2. 现状（已能做什么）

| 域 | 已有 | 缺口（代码或验收未关） |
|----|------|------------------------|
| 入库 | 文件/目录复制；sha256 去重；Pillow 宽高 | 不写 EXIF 拍摄时间（列 `exif_taken_at` 在，探测未填）；旧资源无缩略图不回填 |
| 列表 | 虚拟网格；包内 `thumbs/grid.webp` | 旧卡可能仍拉原图；无日期分组/瀑布流 |
| 消费 | Viewer.js 只盖中间栏；缩放/旋转/切已加载相邻张 | 未加载页不能切；HEIC 等不能解码只提示外部；无幻灯片 |
| 定位 | 信息栏常驻「打开所在位置」；图另有默认/其他应用 | 不记忆上次 exe；不打开导入源根 |
| 元数据 | 标题/描述/作者/评分/分类/标签/待办；分辨率 | 面板不展示拍摄时间、相机、GPS |
| 检索 | 本类关键词 + 标签 AND；图可按宽/高/面积/拍摄时间排（搜排切片） | 拍摄时间多为空所以排序虚；无以图搜图 |
| 不做（已明文） | — | 像素编辑/标注/滤镜；漫画阅读器；独立画廊模块 |

## 3. 候选：先加深现有（债与半成品）

这些不发明新产品形态，只把已有模型做满。适合作为**小切片**。

| 编号 | 能力 | 用户感知 | 备注 |
|------|------|----------|------|
| D1 | **写入并展示 EXIF 拍摄时间** | 信息栏有拍摄；按拍摄排序真正有数 | 列已在；Pillow/`exif` 只读；旧库是否回填要拍板 |
| D2 | **旧库补网格缩略图** | 老图滚动不再解原图 | `grid-media-performance` 已知债 |

| D5 | **动画图** | GIF/动 WebP 在查看器里动起来 | Viewer.js 能力核对后再立项 |
| D6 | **回收站看图** | 已删仍可预览再决定彻底删 | `image-consume` §7.2 暂定能看，未单独验收 |

## 5. 明确不纳入本探索的实现包

- 修图、图层、导出设计系统资产。  
- 把漫画并进图片。  
- 在线图床、社交分享、移动端。  
- 监视文件夹自动入库（基线：一次选择、不登记可再扫源根）。  
- 把 N11 塞进当前 LIKE 搜排切片。

## 6. 建议怎么拆版本（未确认）

若只加深、不加新产品：

1. **第一刀（债）**：D1 拍摄时间写入+面板展示（可选旧库回填）→ 搜排 `takenAt` 才有意义。  
2. **第二刀（体验）**：D2 旧缩略图回填；D3 HEIC 失败路径。  
3. **第三刀（A-plus 产品）**：你从 N1 / N6 / N11 / N12 里只圈一个主路径。

若你更想「图库感」：优先 N1 画廊，不要先做 CLIP。  
若你更想「找图」：优先 N11 或 N12，不要先做地图。
