# 网格媒体性能 · 实现方案

> 状态：**已定稿**（与 OpenSpec `design.md` 同一范围）  
> Feature ID：`grid-media-performance`

## 目标 / 不交付

与 [`需求.md`](./需求.md) 一致。沿用 `library` + `ResourcePackage` + 现有文件 content 路由，**不**新开缩略图服务或全局缓存盘。

## 与现有架构的取舍

| 做法 | 为何 |
|------|------|
| 导入时 Pillow 生成，写进包内 `thumbs/` | 用户要求导入期生成；路径跟资源走，删除/回滚简单 |
| 新角色 `thumbnail` + 列表 `thumbnailPath` | `cover_path` 已被信息栏当原图用，不能改指小图 |
| 复用 `GET .../files/{id}/content` | 不新路由；信封中间件已跳过非 JSON |
| 视频不抽帧 | D-20260912-07；无封面则占位 |
| VirtualGrid 对 `width` 节流 | 只改现有网格，不换虚拟列表库 |

## 模块边界

```
ImportService  copy → probe → generate_thumb → add_file(role=thumbnail)
ResourcePackage.put_thumbnail → {root}/thumbs/grid.webp
media_probe / 新 thumb 纯函数   Pillow 缩放 WebP
LibraryQueryService.replace_cover  换封面后覆盖同一 thumb
GET /library/resources             items[].thumbnailPath
ResourceBrowser                    thumbnailPath ?? coverPath
VirtualGrid                        节流后的 width 再算 lanes
```

渲染进程仍只 HTTP，不写盘。

## 数据流

**导入主路径**  
copy primary → probe → 选源图（cover 否则图片 primary）→ Pillow 缩放 → `put_thumbnail` → `add_file(role=thumbnail, sha256=null)` → 提交。  
列表：`thumbnailPath = /library/resources/{id}/files/{thumbFileId}/content`。

**换封面**  
`put_cover` → 从新封面生成 → 覆盖 `thumbs/grid.webp` → 已有 thumbnail 行更新 size/format，或插入一行。

**错误**  
Pillow 打不开 HEIC 等：记日志，无 thumbnail 行，导入成功。半写入：先写临时文件再替换，失败则不留坏 `grid.webp`。

**浏览**  
网格：`resolveLibraryMediaUrl(thumbnailPath ?? coverPath)`。信息栏：只 `coverPath`。  
resize：对 `useElementSize` 的 width 做 100–200ms debounce/throttle，用节流值算 `columns` / `estimateSize`。

## 包内路径

```
{store}/{type}/{id}/thumbs/grid.webp
```

只允许 `ResourcePackage` 拼接。根上禁止 `thumbnail.webp`。

## 风险

| 风险 | 缓解 |
|------|------|
| 导入变慢 | 一档 480 边；失败跳过；不优化吞吐 |
| 旧库仍慢 | 需求明确不回填；回退 coverPath |
| 信息栏被糊 | 不改 cover_path |
| GIF/动画 | 取首帧静态 WebP |
