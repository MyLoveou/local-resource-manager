# 网格媒体性能 · 需求

> 状态：**草案**（2026-09-12 · 轮次 1）  
> Feature ID：`grid-media-performance`  
> 所属产品：[local-resource-manager](../local-resource-manager.md) 的 **M2 体验债**  
> 规划落点：[00-路线图与里程碑](../../../design/00-路线图与里程碑.md) · MS2 · T-2.1（缩略图懒加载 / 万级滚动）  
> 触发：用户口述「图片加载和窗口缩放慢」

## 1. 背景

图片/视频页已有虚拟网格与触底分页，卡片封面目前直接用库内**原图 HTTP 流**（`coverPath` → `/library/resources/{id}/files/{fileId}/content`）。窗口宽度变化时，`useElementSize` 连续改列宽，虚拟器每帧重算格子，同时浏览器按卡片尺寸解码原图。

可感知结果：

- 滚入可视区时封面出得慢，或一次解码多张大图把主线程打满
- 拖窗口改大小时网格明显卡、列跳动、封面反复重绘

这与 L1 已写的「缩略图懒加载、滚动流畅（万级）」不一致：虚拟滚动已有，**缩略图与缩放节流尚未做**。

## 2. 目标用户与问题

- 本地图库已经导入一批照片/视频的个人用户
- 要解决：列表封面尽快出现；拖窗口时界面跟手、松手后布局稳定，不卡死

## 3. 范围

### IN SCOPE（本需求定稿后实现）

- **封面加载**：网格卡片不再依赖原图像素当缩略图；可视区优先、不可见不抢带宽
- **窗口缩放**：拖动过程中网格列宽/卡片尺寸不要每像素全量重算+重解码；松手或节流后再对齐
- **范围表面**：图片页、视频页的虚拟网格封面；列表滚动与窗口 resize 两条路径都要验收
- **空态**：无封面仍占位，不因优化变成空白闪烁或错图

### OUT OF SCOPE（本需求不交付）

- 应用冷启动、导入复制入库速度、ffprobe/Pillow 探测耗时
- 视频内嵌播放、双击大图预览（T-2.5 / T-2.6）
- 抓取远程封面（M3）
- Electron 窗口自身的原生缩放动画、DPI 切换专项
- 十万级库的检索/索引（M4）
- 元数据面板大封面的精细优化（可顺带受益，不作为本轮验收）

## 4. 现状（代码事实，供方案阶段用）

- 网格：`VirtualGrid` + `useElementSize(width)` + TanStack `lanes`；`watch([virtualItems, items, width], …)`
- 封面 URL：`resolveLibraryMediaUrl(coverPath)`，卡片 `<img :src="coverUrl">`，无缩略图尺寸参数
- 后端：`FileResponse` 原文件；导入 probe 只写宽高，不生成小图文件

## 5. 假设（可在后续轮次推翻）

1. 先优化**已导入库的浏览**，不挡当前 `metadata-panel-fields` 合入；实现可另开切片。
2. 网格封面目标是卡片像素量级（约 160px 起的列宽），不是原图预览。
3. 视频网格同样走封面图，不在本需求里抽帧（无封面就占位）。
4. 不引入新的对外产品功能（无新菜单、无设置项），除非开放问题里确认要「清晰度档」开关。

## 6. 场景草稿（轮次 2 再写成验收清单）

- 打开图片页 → 首屏卡片封面较快出现，滚动时新卡按需加载，不一次打满原图
- 拖窗口变宽/变窄 → 拖动期间界面可跟手；停止后列数与卡片对齐，无长时间假死
- 无封面资源 → 占位稳定，不因加载失败整页重排

## 7. 开放问题（须用户回复）

1. **缩略图从哪来？**  
   A. 导入时后端生成一档小图并落盘  
   B. 首次浏览时按需生成并缓存  
   C. 先只做前端：不解码原图到卡片（例如限制显示尺寸 / 懒加载），本轮不落盘小图  
2. **窗口缩放要做到什么程度？**  
   A. 拖动中冻结列数，松手再重排  
   B. 节流重排（例如 100–200ms），拖动中允许偶尔跳列  
   C. 只修卡顿，列数仍实时变  
3. **验收规模？**  
   首屏几十张 / 库内约 1k / 按 L1「万级」必须本轮达标（建议先 1k 可感流畅）  
4. **右侧信息栏大封面、编辑弹窗封面**是否纳入本轮，还是只修网格？  
5. **本切片排期**：等 `metadata-panel-fields` 合入后再做，还是可以并行？
