# 设计 · series-import-explain（L2）

> 状态：**已落地**（D-20260919-06）  
> 需求：`需求.md`。

## 0. 复杂度

跨 `series_plan`、导入 job DTO、向导一行文案。不改季集表、不改复制布局。不可跳过 L2（失败分类与 DTO 字段要锁死）。

## 1. 设计原则

| 原则 | 含义 | 不做 |
|------|------|------|
| 只读 | 解释计划或失败 | 用户改映射后再拷 |
| 不静默乱入 | `None` 仍不建作品 | 猜集号硬导入 |
| 向导可见 | 原因进 job DTO | 只写 logger |
| 稳定 code | 单测钉 code | 一段随缘长字符串当唯一契约 |
| 目录化 | 分类函数在 plan 旁 | ImportWizard 里 if 文件名 |

## 2. 模型

不新增表。扩展进程内 `ImportJobState` + API `ImportJob`：

```text
message: str | None
details: list[str]   # 默认 []，最多 20 条
```

失败 **code**（内部枚举，message 由 code 生成中文）：

| code | 何时 |
|------|------|
| `no_videos` | 目录无视频文件 |
| `mixed_season_dirs` | 有的正片在 Season/Sxx 目录，有的不在 |
| `unrecognized_names` | 正片无法全部解析出集号，且构不成 dir/sxx/flat/extras-only |
| `missing_episode` | 已选定布局，仍有文件抽不出集号 |
| `duplicate_episode` | 两个文件落到同一 (season, episode) |

成功摘要不需要 code；`message` 如「已识别 1 季 · 12 集 · 2 特典」。

`plan_series_videos` 可保持返回 `list \| None`；旁边增加 `explain_series_plan(root, videos) -> ExplainedPlan`（ok+items 或 fail+code+details），ingest 调 explain，成功再按 items 复制。避免两套逻辑分叉：优先 **explain 为唯一入口**，plan 变成它的 ok 分支或内部实现。

## 3. 交互

导入向导进度步：

- 进行中：现有进度条。  
- 结束：保留「新增 / 重复 / 错误」计数。  
- **有 message**：展示在计数下方；失败用错误色，成功用次要文案。  
- **有 details**：等宽或普通列表，最多 20 行；超出写「另有 n 个文件未列出」。  
- 弹窗可略加宽（约 520px），仍单步结束，无「确认映射」按钮。

## 4. 模块划分

| 模块 | 边界 | 不进入 |
|------|------|--------|
| `series_plan.py` | 分类 + 计划；中文 message | HTTP |
| `ImportService._ingest_series` | 把 explain 写入 job.message/details | 整理 API |
| `ImportJob` / 前端 `ImportJob` | 字段透传 | 改网格 |
| `ImportWizard` | 展示 message/details | 解析文件名 |

## 5. 功能拆分（一刀）

| 切片 | 可感知结果 |
|------|------------|
| A | explain 五种 code + 单测 |
| B | job DTO + 向导展示 |
| C | 成功摘要；回归可识别夹具 |

## 6. 抽象

**抽**：`ExplainedPlan` 一次返回。  
**不抽**：独立 preview 资源、两阶段 POST confirm。
