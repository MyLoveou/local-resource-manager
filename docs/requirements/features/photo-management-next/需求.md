# 图片管理下一阶段需求（批量动作 / 多时间线 / 角色 / 人脸）

> 状态：**R1 已落地（2026-10-18）；R2–R4 需求收集中（L1）**，未进入设计
> 记录日期：2026-10-18
> 来源：2026-10-18 时间线/合集实测反馈与后续构想
> 关联：`photo-timeline-map`、`library-collections`、`batch-tag-export`

## 1. 背景

当前图片管理已经具备：类型页/时间线浏览、EXIF 时间与 GPS、合集、分类、标签、批量打标/导出、回收站。
但仍存在四个方向性缺口：

1. 批量选中后能做的动作不完整，例如**无法把选中的图片加入合集**。
2. 只有一条全局时间线，无法把「旅游」「漫展」「日常」分成独立时间线。
3. 角色（coser 所扮演的角色）没有被建模，只能靠分类/标签绕。
4. 没有本地人脸识别与模型管理，无法按人物聚类、批量确认。

本文件只记录需求与开放问题，不承诺实现顺序；涉及数据模型/UI 的大项需先出 L2 设计并 STOP 确认。

## 2. 需求总表

| ID | 需求 | 优先级 | 类型 | 说明 |
|----|------|--------|------|------|
| R1 | 批量选中加入合集 | P0 | 现有能力补齐 | 选中 → 加入已有/新建合集；同时梳理批量动作栏 |
| R2 | 多时间线 | P1 | 新维度 | 旅游/漫展等独立时间线，可切换、可筛选 |
| R3 | 角色维度 | P1 | 新数据模型 | 角色 / 作品 / 扮演者（coser）分组与聚合 |
| R4 | 人脸识别与模型管理 | P2 | 新能力 | 参考 digiKam：检测、聚类、命名、模型管理 |

建议落地顺序：**R1 → R3（先有角色/人物基础）→ R2 → R4**。R2 也可先做“保存筛选器”轻量版，不依赖 R3。

## 3. R1 批量动作统合（P0）

### 现状
- 批量模式已有：移入回收站、获取元数据、打标、取消。
- 缺少：加入合集、移出合集、设置分类、批量导出（已有部分从合集导出）、批量复制/移动。
- 用户明确缺口：选中的图片无法移到一个合集。

### 需求
- 批量模式新增「加入合集」：选择已有合集（可多选？）或输入新名称现场创建。
- 语义是**建立合集成员关系**，不是把资源从主库移走；资源仍保留在类型页/时间线。
- 与单个资源信息栏的「加入合集」保持同一套交互与幂等逻辑。
- 批量动作统一入口，避免每加一个动作就改一次工具栏结构。
- 部分失败要有汇总提示（成功 N / 失败 M），不能静默。
- 操作完成后刷新列表/合集计数，但保留当前滚动位置。

### 验收
- 选中 10 张图 →「加入合集」→ 选择/新建合集 → 合集详情出现 10 项，主库资源不丢。
- 重复加入同一合集不产生重复成员。
- 退出批量模式后选中态清空，列表可继续加载下一页。

### 开放问题
- 加入多个合集是否要支持？还是先单选合集。
- 是否同时提供「从当前合集移出」批量动作。
- 批量动作栏是否改成「更多」下拉，避免按钮膨胀。

### 实现记录（2026-10-18）
- 后端：`POST /library/collections/{id}/items/batch`，请求 `resourceIds`；返回 `added/skipped/missing`；去重、跳过已存在/不存在资源，按现有顺序追加。
- 前端：批量工具栏新增「加入合集」；弹窗支持选择已有合集或新建；成功后退出批量、刷新列表并提示结果；超过 200 项自动分批提交。
- 语义：只建立合集成员关系，不移动/删除资源；重复加入不产生重复成员。
- 测试：后端 1 个批量服务测试；CDP 实测选中 2 项 → 新建合集 → 成功提示。
- 未做：批量加入多个合集、批量移出合集（仍为开放问题）。

## 4. R2 多时间线（P1）

### 场景
- 旅游：按行程日期范围，可能跨多个城市。
- 漫展：按展会日期 + 场馆/城市 + 分类/标签。
- 日常：默认全部，或按月份。
- 同一张图可能同时属于「2026 日本旅行」和「2026 漫展」吗？需要明确。

### 候选模型
| 方案 | 描述 | 优点 | 风险 |
|------|------|------|------|
| A. 智能时间线（保存筛选器） | 名称 + 条件（日期范围/分类/标签/合集/地点/人物），资源自动匹配 | 复用现有筛选；无需成员表；一图可属多条 | 规则复杂后难解释；手动排除弱 |
| B. 手动时间线 | 显式加入/排序，类似合集 | 可控、可排序 | 与合集重复；大库维护成本高 |
| C. 混合 | 智能规则 + 手动加/排除 | 灵活 | 数据模型和 UI 最复杂 |

**倾向**：先做 A 的轻量版，验证“切换时间线”是否真的解决旅游/漫展分离；若需要手动策展再演进到 C。

### 需求
- 顶部/侧栏可切换时间线；默认「全部」。
- 每条时间线有名称、封面、排序（拍摄时间/加入时间）、是否显示未知时间。
- 新建时间线时可用现有筛选条件作为规则；保存后显示匹配数量。
- 时间线内保留现有的年/月/日分组、Justified 照片流、视频、分类/标签筛选。
- 「计入时间线」三态与多时间线规则的关系要明确：全局排除的资源是否不出现在任何时间线。
- 时间线可编辑/删除；删除不删资源。

### 验收
- 创建「2026 日本旅行」（日期范围 + 标签/地点）→ 时间线只显示匹配资源。
- 创建「2026 漫展」（日期 + 分类/标签）→ 与旅游时间线互不干扰。
- 切换时间线后滚动位置/筛选状态符合预期。

### 开放问题
- 时间线是“视图”还是“实体”？是否需要成员顺序？
- 规则匹配用拍摄时间还是导入时间？未知时间资源如何处理？
- 一条资源是否允许属于多条时间线？默认允许，需确认。
- 与合集的关系：合集是手动策展，时间线是时间视图，是否要互相引用。

## 5. R3 角色维度（P1）

### 术语
- **角色（Character）**：虚构人物/角色名，如某个动漫角色。
- **作品（Work/Series）**：角色所属 IP/系列。
- **扮演者（Coser/Person）**：现实中出镜的人。
- 一张图可以有多个角色、多个扮演者；角色与扮演者是多对多。

### 为什么不是普通标签
- 角色需要聚合页、封面、别名、作品关联、角色/扮演者区分。
- 人脸识别最终要落到“人”（扮演者），而角色是内容维度；两者不能混为一谈。
- 但初期可用标签过渡，避免一次改太多表。

### 需求
- 角色 CRUD：名称、别名、作品、简介、封面、颜色/图标（可选）。
- 资源可关联多个角色；支持批量设置角色。
- 角色页：该角色的图片/视频、时间线、合集、作品信息。
- 类型页/时间线/合集支持按角色筛选（与分类/标签 AND）。
- 角色合并/别名：同一角色的不同写法可合并。
- 角色与扮演者分开：角色页可显示“扮演者”，扮演者页可显示“角色”。
- 人脸识别结果只做建议，人工确认后才写入关联。

### 验收
- 给 20 张 coser 图批量设置角色“角色 A” → 角色页聚合 20 张。
- 同一图设置两个角色 → 两个角色页都能看到。
- 按角色筛选时间线，结果正确。

### 开放问题
- 角色和 coser 是否都建一等实体，还是先只做角色、coser 继续用标签/人物？
- 是否需要“作品”实体，还是角色名里带作品前缀。
- 角色是否参与合集封面/导出命名（如 `角色A_001.jpg`）。
- 与现有分类的边界：分类是资源类型/主题，角色是内容人物，是否允许分类自动派生。

## 6. R4 人脸识别与模型管理（P2）

### 参考
- digiKam：人脸检测、人物标签、相似脸聚类、人工确认/合并、模型管理。
- 目标不是“全自动打标”，而是**本地辅助整理**。

### 需求
- 本地离线检测/识别，不上传人脸数据。
- 批量检测：选中图片/整个时间线/合集；显示进度、可取消、失败可重试。
- 未知人脸聚类：相似脸归组，人工命名、合并、拆分、忽略。
- 已命名人物：对新高置信度结果给出建议，默认不自动写入。
- 人物页：该人物的图片、出现次数、时间线、合集。
- 模型管理：模型列表、下载/导入、启用/停用、版本、体积、许可证、CPU/GPU 选择、失败回退。
- 视频可选抽帧检测（后续）。
- 与 R3 的关系：人脸先识别“扮演者/人物”，角色由人工或服装/作品规则辅助；不把角色名直接当人脸标签。

### 非目标（v1）
- 云端人脸库、跨设备同步。
- 无确认的全自动人物打标。
- 训练自定义模型（先只做推理与模型管理）。

### 验收
- 导入一组 coser 图 → 批量检测 → 未知人物聚类 → 命名“Coser A” → 人物页聚合。
- 同一人不同角度可合并；误检可忽略/删除。
- 断网可用；模型缺失时有明确引导。

### 开放问题
- 模型选型（InsightFace/ONNX/其他）、许可证、体积、最低硬件。
- 人脸模板存哪里、如何加密/删除；是否需要“遗忘某人”。
- 误识别责任边界：默认建议而非自动写入。
- 是否先做“人物”而不做“角色”，等 R3 落地后再关联。

## 7. 与现有能力的整合原则

1. **一个资源，多维度归属**：类型/分类/标签/合集/时间线/角色/人物，互不替代。
2. **批量动作统一**：先有统一的选中动作栏，再逐个加动作；所有动作支持部分失败汇总。
3. **默认不破坏主库**：加入合集/时间线/角色都是加关系，不移动、不删除原资源。
4. **AI 只建议**：人脸/模型结果需人工确认；保留可撤销。
5. **先轻后重**：R1 先补；R2 先做保存筛选器；R3 先做角色实体；R4 最后接模型。

## 8. 开放问题汇总

- 多时间线：视图 vs 实体；是否允许一图多时间线；未知时间如何处理。
- 角色：角色/作品/扮演者三实体是否一次建齐；与分类/标签的边界。
- 人脸：模型选型与许可证；模板存储与隐私；视频抽帧是否 v1。
- 批量：加入合集是单选还是多选；是否需要批量移出合集/设置分类。
- 交互：批量动作栏如何避免按钮膨胀；是否需要“更多”菜单。
