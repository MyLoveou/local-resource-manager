# 设计 · app-update（L2）

> 状态：**已定稿**（2026-10-18，用户确认「现在实现更新」）
> 需求：`需求.md`（L1 草案；本设计按推荐项落定）

## 1. 设计原则

- 只做 Windows 安装版自更新；绿色 zip 不自动更新
- 更新源 = 本仓库 GitHub Releases（`latest.yml` + NSIS 安装包 + blockmap）
- 未签名：接受 SmartScreen 提示；不做签名/公证
- 首次启用 updater 的版本（0.1.1）需手动装一次；之后 0.1.2+ 可应用内更新
- 不做：灰度、强制更新、差分、macOS/Linux

## 2. 模型与契约

### 版本

- 单一来源 `apps/desktop/package.json` `version`；本次 `0.1.1`
- 后续发版：改版本 → 打 tag `v0.1.2` → CI 构建并发布 Release

### 更新状态

```ts
type UpdatePhase =
  | 'idle' | 'checking' | 'available' | 'downloading'
  | 'downloaded' | 'up-to-date' | 'error' | 'unsupported'

interface UpdateStatus {
  phase: UpdatePhase
  currentVersion: string
  version?: string
  releaseNotes?: string
  percent?: number
  message?: string
}
```

- 主进程 `autoUpdater`（electron-updater）状态广播到渲染进程
- `autoDownload=false`：先展示公告，用户点下载；下载完提示重启安装
- 启动后 8s 自动检查（仅打包态）；设置页可手动检查

### IPC

| 通道 | 方向 | 作用 |
|------|------|------|
| `update:get-state` | invoke | 当前状态 |
| `update:check` | invoke | 检查更新 |
| `update:download` | invoke | 下载更新 |
| `update:install` | invoke | quitAndInstall |
| `update:status` | main→renderer | 状态推送 |

- 打包态 `app-update.yml` 由 electron-builder `publish` 生成（GitHub provider）
- 开发态：检查返回 `unsupported`（提示仅安装版支持）
- 可选 `UPDATE_FEED_URL` 覆盖 feed（本地联调）

## 3. 交互

### 启动/横幅

- 发现新版本：顶栏下方出现横幅「发现新版本 x.y.z」+「更新公告」+「下载更新」+「稍后」
- 「更新公告」展开 release notes（纯文本/换行）
- 下载中：进度条 + 百分比；失败：可读错误 + 重试
- 下载完成：「重启安装」+「稍后」；安装会退出应用

### 设置页

- 「设置 → 更新」：当前版本、状态、检查按钮、公告、下载/重启按钮
- 无更新：显示「已是最新版本」
- 开发态：显示「仅安装版支持自动更新」

## 4. 模块划分

| 层 | 模块 | 职责 |
|----|------|------|
| 主进程 | `main/infrastructure/services/update.ts`（新） | autoUpdater 初始化/事件/IPC 注册/广播 |
| 主进程 | `main/index.ts` | 注册 IPC、启动检查 |
| preload | `preload/index.ts` | 暴露 update API 与状态订阅 |
| 渲染 | `application/stores/update.ts`（新） | 状态/动作单例 |
| 渲染 | `components/UpdateBanner/index.vue`（新） | 横幅/进度/公告/安装 |
| 渲染 | `components/SettingsModal` | 新增「更新」Tab |
| 渲染 | `App.vue` | 挂载横幅 |
| 构建 | `electron-builder.yml` | `publish: github` |
| 构建 | `scripts/release.mjs` | `--publish never`（本地产物；CI 负责发布） |
| CI | `.github/workflows/release-windows.yml` | tag 时 `gh release create` 上传安装包/latest.yml/blockmap |

## 5. 功能拆分

| 切片 | 提供 | 契约 |
|------|------|------|
| 功能 | 更新状态机 | `UpdateStatus`；检查/下载/安装 IPC |
| UI | 横幅 + 设置 Tab | 消费 store，不直接调 electron-updater |
| 组合根 | `App.vue` + `SettingsModal` | 同用一个 store |

## 6. 风险

| 风险 | 缓解 |
|------|------|
| 未签名更新被杀软拦截 | 文档说明；后续签名 |
| GitHub 网络不可达 | 错误提示 + 手动下载链接（release 页） |
| 首次 0.1.1 无 updater 的旧版无法自更新 | 明确：0.1.1 手动装一次 |
| `latest.yml` 未上传 | CI 校验/上传；release 失败即红 |
| 版本号忘记 bump | 发版说明：先改版本再打 tag |

## 7. 验收

- 0.1.1 打包后 `resources/app-update.yml` 存在，`release/latest.yml` 生成
- 安装版启动能检查（无 Release 时显示错误，不崩溃）
- 发 0.1.2 Release 后：0.1.1 显示公告 → 下载 → 重启 → 版本变 0.1.2
- 绿色 zip 不触发更新
