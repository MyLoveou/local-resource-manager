# 应用更新与更新公告 · 需求

> 状态：**已定稿**（L1 · 2026-10-18，用户确认现在实现；设计见 `设计.md`）
> Feature ID：`app-update`

## 1. 背景

0.1.0 已能产出 Windows 安装包与绿色版 zip。后续版本发布后，用户需要：
1. 知道有新版本与本次更新内容（更新公告）
2. 在应用内完成检查/下载/安装，或至少一键到达下载页

当前完全没有更新入口，只能手动找安装包。

## 2. IN / OUT（草案，待确认）

| 做 | 不做（草案） |
|----|--------------|
| 启动时检查更新 + 设置页手动「检查更新」 | 灰度/分批发布、强制更新 |
| 应用内展示更新公告（版本号、日期、变更点、当前版本） | 差分更新（v1 用整包） |
| 下载并安装更新（NSIS，安装后重启） | macOS/Linux 更新 |
| 检查/下载失败提示 + 手动下载兜底链接 | 账号体系/推送通道 |
| 版本信息单一来源（现有 `app.getVersion()`） | 应用内富文本公告编辑器 |

## 3. 用户故事与验收（草案）

- **US-U.1** 启动后如有新版本，顶部/设置出现「有更新」入口，展示版本与公告要点
- **US-U.2** 设置页可手动检查；无更新时提示「已是最新版本」
- **US-U.3** 点击下载 → 进度可见 → 完成后提示「重启安装」→ 重启后版本更新
- **US-U.4** 网络失败/未签名拦截时，展示可读错误与「手动下载」链接
- **US-U.5** 更新检查不影响启动速度（后台异步）

## 4. 开放问题（待评审）

1. **更新源**：GitHub Releases（仓库已有，electron-builder 已产 `latest.yml`/blockmap）+ `electron-updater`？还是自建静态 manifest？
2. **检查时机**：仅手动 / 启动静默检查 + 手动 / 定时检查？
3. **公告形态**：设置页「更新公告」列表 / 有新版本时弹窗 / 两者？
4. **安装方式**：应用内下载并拉起 NSIS 安装（`electron-updater`）vs 打开浏览器下载页？
5. **发布流程**：CI 是否在 `v*` tag 时自动创建 GitHub Release 并上传产物/`latest.yml`？
6. **未签名风险**：当前无代码签名，electron-updater 在 Windows 的签名校验/杀软提示如何兜底？
7. **更新公告数据来源**：Release notes / 仓库 `CHANGELOG.md` / 独立 JSON？

## 5. 依赖与风险（记录）

- 依赖现有 `production-packaging` 产物（NSIS + `latest.yml` + blockmap）
- 需要 GitHub Release 或静态服务器；涉及 CI 权限（token）
- 未签名更新可能触发 SmartScreen；是否先要求签名再开自动更新，待评审
