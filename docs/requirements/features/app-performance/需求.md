# 全项目性能 · 需求

> 状态：**已定稿 / 实现中**（2026-09-12）  
> Feature ID：`app-performance`  
> OpenSpec：`openspec/changes/app-performance/`  
> 取代单独切片：`image-consume-perf`（并入本需求，不再单独 apply）

本切片覆盖**整个已落地产品**：SQLite、FastAPI 计算与 IO、Electron 壳、Vue 加载与显示。不是「只优化看图」。

**本轮补充目标（2026-09-12）**

1. 哪些事可以只在前端做、哪些必须留在后端，且**不堵死以后把后端部署到服务器**。
2. **大批量导入**时窗口与列表不假死（卡死不可接受）。
3. **万级**资源网格可滚动、可点选，不卡死。
4. 优化落地后做一次**数据卫生**：清空当前脏库，并处理无缩略图等残缺记录。
5. 分层、契约、显示、导入、维护路径要一次想全，避免只改一处。

## 1. 现状分析（仓库事实）

单机：Electron 渲染进程 axios → 本机 FastAPI 单进程 → SQLite（WAL）+ 库目录文件。

### 1.1 数据库

| 事实 | 路径 |
|------|------|
| WAL + foreign_keys + busy_timeout=5s；无 `cache_size` / `mmap_size` / `synchronous` 调优 | `shared/db/db.py` |
| 索引：`resources(type)`、`resources(status)` **分开**；无 `(status, type, created_at, id)` 复合索引 | `migrations/0001_init.sql` |
| `files(resource_id)`；无 `(resource_id, role)` | 同上 |
| `files.sha256` UNIQUE（导入去重） | 0001 |
| 列表：先 `count` 再 `list` 两次往返 | `LibraryQueryService.list_page` |
| 详情 `_hydrate`：category / tags / files / todos **串行多次 await** | `repositories.py` `_hydrate` |
| 概览 stats：按类型 count + trashed + lost + **SUM(files.size) 子查询** | `stats()` |
| 每 HTTP 请求一个 AsyncSession | `get_session` / `deps.get_repos` |

### 1.2 后端计算与 IO

| 事实 | 路径 |
|------|------|
| 导入对每个文件 **串行**：hash → 去重 → 复制 → probe → 写库 → 缩略图 | `import_service.py` `_ingest_one` |
| hash / copy / Pillow / ffprobe 已 `to_thread`，但文件之间不并行 | 同上 |
| 全文件 sha256（1MB chunk） | `hash_file` |
| 缩略图 Pillow 缩放 webp | `thumbnails.py` |
| 视频 probe 调 ffprobe 子进程 | `media_probe.py` |
| 每个 content 先查 DB 再 `FileResponse`，**无 Cache-Control** | `api/resources.py` |
| 访问日志每请求两行 | `middleware/logging.py` |

### 1.3 前端加载与显示

| 事实 | 路径 |
|------|------|
| 分页 80，虚拟网格 + overscan 4 | `useResourcePage` / `VirtualGrid` |
| 卡片 `loading=lazy`；无缩略图时列表仍可能用 cover/原图 URL | `Card` / `ResourceBrowser` |
| 点选必 `getResource`；词表曾与详情绑在一起（分类已内存缓存雏形） | `InfoPanel` |
| axios **每条 JSON 打 info 日志** | `http/client.ts` |
| 查看器 Viewer.js：`update`/`initImage`、拖拽易掉帧 | `createInlineImageViewer` |
| 主进程启动开 DevTools | `main/index.ts` |

### 1.4 不在本轮（未落地模块）

抓取引擎、下载引擎、token 校验、设置页库路径：无代码可优化；不预支架构。

## 1.5 架构取舍：前端直操 vs 后端（含远期服务器）

基线已禁止：渲染进程对库目录做复制 / 移动 / 哈希。远期若后端上服务器，客户端会变成「浏览器或另一台桌面」，**库文件与 SQLite 不在用户机器上**。因此：

| 操作 | 放哪 | 远期服务器是否仍成立 |
|------|------|----------------------|
| 选路径、窗口布局、虚拟滚动、点选、草稿标签、缩放拖拽 | **前端 / Electron 壳** | 成立（壳可换成 `<input type=file>` / 上传） |
| 列表/详情 JSON、写评分分类标签、软删、回收站 | **HTTP API** | 必须同一契约 |
| 复制入库、sha256 去重、probe、缩略图、读库内文件 | **后端（及以后的 worker）** | 必须；浏览器不能直写服务器磁盘 |
| 用 `file://` 或 IPC 读 SQLite / 库目录 | **禁止** | 服务器部署后直接失效，且破坏鉴权 |

**结论（本轮拍板，未反对则照此）**

- **不为了快把入库 IO、去重、缩略图、元数据写入搬到前端。** 那会让以后上服务器必须重写核心。
- **为了快可以把「显示与交互」留在前端**：虚拟列表、Intersection 懒加载、详情/词表内存缓存、乐观 UI（失败再回滚）、导入进度轮询。这些对本地 sidecar 和远程 API 一样有效。
- 本地与服务器共用 **同一套 REST + camelCase JSON**。Electron 只是一个客户端：主进程负责选文件、拉起本机后端；渲染进程只打 HTTP。
- 本地优化（WAL、线程池、Cache-Control）不引入「只有 Electron 才有的写库通道」。
- 以后上服务器时再加的是：鉴权校验、上传替代「本地路径导入」、对象存储替代 `FileResponse` 直出。**不在本切片实现部署**，但本切片不设计与之相反的捷径。

列表 DTO 保持精简（id、缩略图 URL、标题等），详情另拉。这样万级网格与远程延迟都能扛。

### 1.6 不变量：除查看器外只用缩略图（本轮补写为硬规则）

此前只散落在网格/信息栏验收里，现升为**全局规则**：

| 展示面 | 用什么 |
|--------|--------|
| 图片/视频网格卡片（含回收站） | `thumbnailPath` → 缩略图文件；**禁止** `coverPath` / `/content` 回退 |
| 右侧信息栏预览 | 同上 |
| 编辑资源弹窗预览 | 同上 |
| 概览「最近」等若展示图 | 同上 |
| **图片查看器**（二次点击打开） | 才请求 `/content` 原图 |
| 无缩略图 | **占位**（「无封面」），不解码原图；S6 补生成或删除该资源 |

说明：

- `coverPath` 仍可表示「封面原文件」供换封面、外部打开等业务，**不用于任何 `<img>` 展示**（查看器除外）。
- 视频没有图片查看器，网格与面板同样只出缩略图。
- 换封面成功后应重生成网格缩略图；在新缩略图可用前继续占位，不闪原图。

现状债：`ResourceBrowser` 仍 `thumbnailPath ?? coverPath`；`domain/resource.ts` 注释仍写「信息栏用 coverPath」。本切片必须改掉。

## 2. 本轮做 / 不做

| 做 | 不做 |
|----|------|
| 测量基线后再改（列表/详情/导入/滚动/看图） | 无数据就换 SQLite 引擎或上 Redis |
| DB：复合索引、hydrate 一次加载、列表 count / keyset | 改表业务含义 |
| 导入：CPU 进线程/进程池；**单写者**写 SQLite；文件间有上限并发；进度可轮询；大批量不堵 HTTP | 把 hash/复制/缩略图改到渲染进程 |
| HTTP：静态/缩略图/content 缓存头；降噪访问日志 | 新 REST 前缀；本机改 `/v1` |
| 前端：除查看器外所有 `<img>` 只用缩略图；万级虚拟网格；词表不挡首绘；详情缓存；少日志 | 重写 UI 框架；一次把万条 DOM 挂上；用原图当卡片/面板图 |
| 查看器跟手（并入原 image-consume-perf） | PhotoSwipe 灯箱；无确认卸 Viewer.js |
| 数据卫生：一次性清空脏库；无缩略图补生成或删除 | 启动时自动 DROP 用户库（须显式执行） |

## 3. 用户故事

- **US-G.1** 打开图片/视频页，格子尽快出现，滚动只加载可见**缩略图**；未打开查看器不请求原图。  
- **US-G.2** 点选资源，标题/描述马上能看；分类下拉可稍后。  
- **US-G.3** 大批量导入（成百上千文件）时窗口不假死，进度仍更新，同时仍能打开列表（列表可短暂旧数据）。  
- **US-G.4** 首页概览在万级库上可接受（count/sum 不把 UI 卡死）。  
- **US-G.5** 看图拖拽/最大化不长时间空白。  
- **US-G.6** 约 **10000** 条活跃资源：滚动只绘制可见格；点选信息栏可用。  
- **US-G.7** 优化后能**清空当前脏库**再干净导入；无缩略图残缺记录可补或删，不长期混在网格里当原图打。  
- **US-G.8** 除图片查看器外，卡片、信息栏、编辑弹窗、概览缩略预览一律缩略图；缺则占位。

## 4. 验收（分阶段，声称完成须有证据）

**测量（先于优化）**

- [ ] 记录：空库/约百条/约千条（若有）下列表 P50、详情 P50、导入单张耗时、滚动时网络面板请求数。

**数据库 / 后端**

- [ ] 列表过滤走复合索引（EXPLAIN 或注释+迁移）。  
- [ ] 详情关联非逐条 get。  
- [ ] 缩略图与 content 带 Cache-Control。  
- [ ] 导入 CPU 工作不在事件循环线程同步跑（hash/copy/probe/thumb 均 thread 或进程）。  
- [ ] 导入文件间有上限并发；**SQLite 写入串行**（避免写锁把库打爆）。HTTP 列表在导入进行中仍能 200。  
- [ ] 导入数千文件时渲染进程不因「等一个超大请求」卡死（后台 job + 进度查询）。

**前端加载 / 显示**

- [ ] **除查看器外**所有图片展示只绑定 `thumbnailPath`；网络面板在查看器关闭时无 `/content`。  
- [ ] 网格 / 信息栏 / 编辑弹窗 / 概览：无缩略图时占位，**绝不**回退 `coverPath`。  
- [ ] 屏外卡片 `loading=lazy`。  
- [ ] 进类型页不 await 词表。  
- [ ] 同一 id 在 bump 前不重复详情 GET。  
- [ ] 生产路径 JSON 成功响应不打满 info 日志。
- [ ] 万级：网格 DOM 仅为可视区 + overscan；列表项不带完整文件/待办 hydrate；滚动时缩略图请求有并发上限（浏览器自然限流 + lazy）。
- [ ] `library.bump` 不导致把已滚动窗口整表重拉到卡死（局部失效或保持 keyset 窗口）。

**查看器**

- [ ] 拖拽跟手；最大化无长时间空白。

**数据卫生**

- [ ] 有文档化、可执行的「清空库」步骤（SQLite + 库目录），不写进每次启动。  
- [ ] 有一次性维护：扫描无 `thumbs/grid.webp`（或无 thumbnail 文件行）的资源 → 补生成；仍失败则删除该资源包（或软删，方案见实现方案）。  
- [ ] 卫生跑完后网格不再依赖原图当卡片图。

## 5. 契约

- 对外 JSON 字段不删。  
- 列表可增加 cursor/keyset 查询参数；`offset` 可暂时兼容。  
- 可新增 SQLite 索引迁移。  
- FileResponse 可加头。  
- 导入进度字段语义不变；POST 导入须尽快返回 job，不得把整批文件处理完才响应。

## 6. 假设

1. 当前交付仍是单机 sidecar；优化目标是可感知卡顿，但 **API 形状按「将来可远程」来约束**。  
2. 先测量再动最热路径：列表+缩略图、点选详情、导入、看图。  
3. 导入：CPU 可多工人，磁盘与 SQLite 必须限流；默认工人数 `min(4, CPU-1)`，写库始终 1。  
4. 万级指约 10⁴ 条 **元数据在列表中**；不同时解码 10⁴ 张原图。  
5. DevTools 默认关闭（`ELECTRON_DEVTOOLS=1` 才开）。  
6. 「清空数据库」是优化后的**一次性运维**，针对当前开发/脏数据，不是产品里给终端用户的默认按钮（设置页未做；可用后端维护脚本或带确认的开发命令）。

## 7. 开放问题

1. 无缩略图且补生成失败：默认 **删除库内包 + 行**（脏数据），还是只标 `lost`？未另说则 **删除包并去掉记录**（本次就是清脏）。  
2. Viewer.js 仍卡是否自绘？未点头不换库。  
3. 列表是否从 `offset` 改为 `created_at+id` keyset？未另说则 **S1 改为 keyset（可保留 offset 兼容一版）**，避免万级深翻页。
