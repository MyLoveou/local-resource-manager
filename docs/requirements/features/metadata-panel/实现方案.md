# 元数据面板 · 实现方案

> 状态：**已定稿**（与 OpenSpec `design.md` 同一套分层与清单）  
> Feature ID：`metadata-panel`

## 目标 / 不交付

与 [`需求.md`](./需求.md) 一致。沿用 InfoPanel + `library` 域。词表**管理**不在此做。

## 与现有架构的取舍

| 做法 | 为何 |
|------|------|
| 继续 InfoPanel + 编辑弹窗 | 约定：选中用 Pinia，面板不嵌进网格 |
| `categories` 新表 + `resources.category_id` | 已拍板独立词表；不用自由文本列 |
| tags 用 0001 已有表 | 不平行再做一套标签 |
| 面板/弹窗共用一份草稿，点保存才 PATCH | 已拍板；禁止改星/Enter 即写库 |
| POST cover 仍走 FileOps + put_cover | 渲染不写盘 |
| 删除后 bump/滤掉卡片 | 修已知债 |

## 模块边界

```
renderer  InfoPanel 草稿 + 保存/编辑/删除/换封面
          EditResourceModal 同一套字段草稿（含封面路径）
library   GET 详情（tags + category 对象 + files）
          GET /categories、GET /tags
          PATCH categoryName + tagNames + rating + title…
          POST cover
shared/db categories；resources.category_id；tags / resource_tags
```

## 数据流

**展示**  
选中 → GET 详情 + 可选 GET 词表 → 填面板（已保存值）。封面 `resolveLibraryMediaUrl`。

**面板草稿**  
改星、选/新建分类、Enter 切标签 → 只改内存。点「保存」→ 一次 PATCH（rating、categoryName、tagNames）。切换选中：丢弃未保存草稿，不自动提交。

**编辑弹窗**  
打开时从当前**已保存**详情拷草稿（若面板有未保存草稿，打开弹窗前以面板草稿为准，避免丢星）。保存 → PATCH，若草稿含新封面 path 再 POST cover，关窗。取消 → 不请求。

**面板换封面**  
「更换封面」选图后立即 POST cover（该按钮即确认）。

**删除**  
`n-popconfirm` / `n-modal` 确认 → DELETE → clear + 网格去掉该 id。

## 决策

| 决策 | 选择 | 不选 |
|------|------|------|
| 分类 | `categories` + FK | 自由文本列 |
| 写入 | 显式保存 | 即时 PATCH / 标签失焦提交 |
| 评分 UI | 5 星半星 ×2 | 0–10 滑条 |
| 词条管理 | 本切片只创建 | 本切片做删除/统计 |

## 风险

| 风险 | 缓解 |
|------|------|
| 词条膨胀 | 用户已知；治理在 hygiene |
| files.sha256 UNIQUE 与封面 | cover 行可不写相同 sha256 或仅 primary 唯一 |
| 面板未保存就开弹窗 | 弹窗承接面板草稿 |
