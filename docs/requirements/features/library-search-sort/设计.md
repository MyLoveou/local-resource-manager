## 0. 复杂度

新查询契约、keyset 随排序变化、TypeProfile 扩展、顶栏跨类型结果页、标签 AND 筛选。不可跳过 L2。

## 1. 设计原则

| 原则 | 含义 | 不做 |
|------|------|------|
| 作品是命中单位 | 一张卡一部作品 | 把集/页/文件搜成独立网格项 |
| 一套字段、两处入口 | 顶栏与类型页关键词语义相同 | 两套互不相认的语法 |
| 目录化 | 搜排键在 TypeProfile（前后端同名） | `if (type==='video')` 复制页面 |
| 条件在服务端 | LIKE / JOIN 在仓储 | 前端拉全库再滤 |
| 本刀 LIKE | 子串包含即可 | 本刀上 FTS5、分词插件 |
| 行为不变 | 导入/打开/软删不动 | 改删除 API |

### LIKE 与 FTS5（本刀锁定 LIKE）

| | LIKE `%词%` | FTS5 |
|--|-------------|------|
| 匹配 | 子串（「海边」能打中「去海边」） | 倒排索引；默认按 token，中文往往要额外分词才「像搜索引擎」 |
| 索引 | 前导 `%` **用不上**普通 B-Tree，库大了会慢 | 有倒排，大库关键词更快，可相关度排序 |
| 工程 | 现表加 `WHERE`，无新表 | 虚拟表 + 触发器与 resources/tags/files 同步，迁移更重 |
| 失败态 | 实现简单 | 漏同步会搜不到刚改的标题 |

本刀库是本机 SQLite、目标先「能搜到」。**用 LIKE**（用户确认「本次使用 LIKE」）。FTS5 与其余后补进 `todo.md`「后续优化与功能」，不在本切片混做。

## 2. 模型

```text
QuerySession
  scope       type | all | trash     // 路由决定
  q           关键词（trim，空=不限）
  tagIds      多选，AND（同时挂这些标签）
  sort        SortKey
  order       asc | desc

SortKey
  共用        createdAt | updatedAt | title | rating | size
  类型        width | height | pixelArea | takenAt      // 图片
              duration | resolution | bitrate           // 视频（分辨率=像素面积或宽）
              duration                                  // 音频
              pageCount                                 // 漫画
              episodeCount                              // 番剧/AV
              （游戏/小说/模型无额外排序）

SearchHaystack（q 非空时 OR）
  共用        title, author, description, category.name, tag.name, basename(files.path)
  类型        files.format（图/视频/音频/模型）
              files.path 全路径（游戏 indexed 源路径；启动文件名已含在 basename）
              视频清晰度：q 像 1080/720/2160 时比宽或高（不维护「高清」词表）
```

不变量：

- `tagIds` 与 `q` 同时生效（AND）：关键词命中字段集合，**并且**资源含所选标签
- `q` 单独也可命中标签名（没有选标签时）
- 缺测值（无时长、无体积）排序：该键 `DESC` 时 NULL 在后，`ASC` 时 NULL 在后（用户先看到有值的）
- 体积 = 该作品 `files.size` 之和；NULL 当 0 再按上面 NULL 规则（全 NULL 仍置后）
- 漫画页数 = `role` 为页的文件数；算不出则 NULL
- 集数 = episodes 行数（不含特典）
- 非法 `sort`（当前 scope 不允许）→ **422**，不 500、不静默改键
- 顶栏搜索 **status=active**；回收站页 **status=trashed**，不混进顶栏结果

持久化（Pinia persist / localStorage），按 `scopeKey`：

- 类型页：`type:<ResourceType>` → `{ q, sort, order, tagIds }`
- 跨类型结果页：`scope:all` → `{ sort, order, tagIds }`（`q` 以这次输入为准，也可记住上次 q）
- 回收站：`scope:trash` → 同上

换类型：读该类型记住的会话，不把视频的「时长」带到小说。

## 3. 交互

### 顶栏跨类型搜索

1. ToolBar 在「导入」旁放搜索框（防抖，如 300ms；Enter 立即）  
2. 有非空 `q` → 路由 `/search?q=`（hash 路由），主区用现有虚拟网格，**不限 type**  
3. 结果卡仍按作品打开/点选；卡片或信息栏能看出类型（已有类型字段）  
4. 清空搜索或离开：可回上一类型或首页；空 q 不停留在「搜全部」的无意义全库墙（空 q 访问 `/search` 提示输入）  
5. 此页排序只有**共用五键** + 标签多选（混合列表不能按时长排全体）

### 类型页

1. 主区顶（网格上方，**不是**顶栏批量那一行）放：排序下拉、升降、标签多选；可选本页关键词框与顶栏同步语义——**锁定：类型页也显示关键词框**（与顶栏同一套字段，但 **只滤当前 type**）。顶栏再输入则跳转 `/search` 跨类型。  
   - 避免两个框打架：顶栏 placeholder「全库搜索」；类型页 placeholder「在本类中搜索」。  
2. 排序选项 = 共用 ∪ 该 TypeProfile 额外键  
3. 无匹配：EmptyGuide 文案「无匹配」，不是「请先导入」  
4. 有资源但筛空与从未导入：用 `total` 无条件 vs 有 `q|tagIds` 区分

### 回收站

与类型页同一套控件（关键词+共用排序+标签多选），无类型额外键（混合类型）。只列出 `trashed`。

### 标签多选

选项来自已有分类标签 API（当前库词表）。多选 AND。与 `q` 命中标签名并存：只打字「旅行」可命中带该标签的卡；只多选该标签不打字同样只留带标的卡；两者都有则既要 AND 标签又要 q 命中任一 haystack 字段。

## 4. 模块划分

| 模块 | 边界 | 不进入 | 依赖 |
|------|------|--------|------|
| TypeProfile + 前端 libraryTypes | searchKeys / sortKeys 白名单 | SQL | 无 |
| ResourceRepository.list | q、tagIds、sort、动态 keyset | UI | resources/files/tags |

| application/stores/browseQuery | 按 scope persist、拼请求 | 网格虚拟 | Pinia |
| ToolBar | 全库搜索框 → `/search` | 算 LIKE | router、browseQuery |

依赖：UI → store → HTTP → API → 仓储。不反向。

## 5. 功能拆分

| 切片 | 可感知结果 | 本版本 |
|------|------------|--------|
| A 共用 q+sort+keyset | 类型页能搜标题等、能按标题/时间/评分/体积排 | 是 |
| B 标签多选 AND | 控件筛标签；q 仍能命中标签名 | 是 |
| C TypeProfile 类型键 | 视频时长等；非法 sort 422 | 是 |
| D 顶栏 `/search` | 跨类型同一套字段 | 是 |
| E persist | 换类型/重启记住该 scope 的排与筛 | 是 |

顺序：A → B → C → D → E。A 不过不要做 D。

## 6. 抽象

**抽**：QuerySession、SortKey 白名单、Haystack OR、动态 keyset（排序列 + id）。

**不抽**：通用搜索引擎；筛选 DSL；Elasticsearch。

Keyset（L3 再写 SQL）：游标必须带当前 `sort` 列值 + `id`，不能在按标题排时仍用 `afterCreatedAt`。前端 `useResourcePage` 随 sort 换游标字段。
