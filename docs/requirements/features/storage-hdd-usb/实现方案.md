# 机械硬盘 / U 盘适配 · 实现方案

> 状态：**暂停**（2026-10-31）｜前置：无｜预计 3–4 次提交

## 1. 现状（已核实）

| 事实 | 值 |
|---|---|
| 库目录 | `apps/backend/data`（项目内），`db_path` 固定在此 |
| 库已占用 | 75.4 GB / 1377 个 files 行 |
| 路径存储 | **绝对路径**（`D:\Project\资源管理器\...`） |
| 导入复制 | `ResourcePackage.put_relative` → `file_ops.copy` → `shutil.copy2` |
| 已有能力 | `file_ops.move` 已存在，但导入未使用 |

## 2. 改动拆解

### P0 · 库根目录 + 相对路径（1 次提交）

- `settings.library_root`（默认现有目录），迁移时不移动已有文件。
- `files.path` 存**相对路径**；读取时用 `library_root` 拼绝对路径。
- 存 `volume_serial`（Windows `GetVolumeInformationW`）用于「这块盘是不是原来那块」。
- 启动校验：`library_root` 不存在 → 提示重新定位。
- 兼容：存量绝对路径原样读取，读取层统一走 `LibraryPaths.resolve()`。

### P1 · 存储模式（2 次提交）

`import_storage_mode = auto` 时按顺序尝试：

1. 同卷且 NTFS → `os.link`（硬链接）
2. 同卷 → `file_ops.move`
3. 跨卷 → `file_ops.copy`，并给预估（总大小 ÷ 目标盘写入速度）

需要新增：

- `file_ops.link()`（失败返回 False，不抛）
- `same_volume(a, b)`（盘符 + 序列号）
- 导入向导显示「预计 X 分钟 / 约 X GB」与模式说明
- `reference` 模式：`files.path` 指向源文件，`storage_kind = referenced`，删除时只删记录

### P2 · 廉价指纹（1 次提交）

- `content_hash_mode = cheap`（默认）：`size + mtime_ns + blake2b(首 1 MiB + 尾 1 MiB)`
- 去重索引改为该指纹；`full` 模式仍写 sha256（用于「深度校验」动作）
- 现有 1377 行的 sha256 保留，指纹列可空并逐条回填

### P3 · 懒抽帧（1–2 次提交）

- 导入不再调用 `generate_episode_covers`（或仅对首个可见集生成）
- `GET /episodes` 返回时若 `cover_file_id` 为空，异步排队生成（带并发上限与去重）
- `cache_dir` 可配置；封面文件名不变，只是在需要时才产生

### P4 · 可移动介质安全（1–2 次提交）

- 检测 `DriveType == DRIVE_REMOVABLE`：`PRAGMA synchronous=FULL`、`wal_autocheckpoint` 调小
- 「安全拔出」：checkpoint WAL → 关闭连接 → 提示可拔
- 文件缺失：列表/详情标记「缺失」，提供重定位（按文件名 + 大小匹配）

## 4. 验证

| 层 | 检查 |
|---|---|
| 单元 | `same_volume`、`link` 失败回退、指纹稳定、相对/绝对路径互转 |
| 集成 | 同卷硬链接导入后源仍存在；跨卷走 copy；换根目录后仍能打开 |
| 手工 | S1–S6（见 `需求.md`），需真实机械盘/U 盘 |

## 5. 为什么暂停

当前用户主要在内置盘工作，这项属于「换存储介质」的整体改造，涉及路径模型、导入策略、缓存位置三层，
与正在推进的导入准确性（AI 结构/标题）相比优先级靠后。等确定要上机械盘/U 盘时再启动，
届时按 P0 → P1 先行，能立刻把 50 GB 导入从分钟级降到秒级。
