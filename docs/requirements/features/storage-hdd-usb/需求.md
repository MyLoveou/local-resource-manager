# 机械硬盘 / U 盘适配 · 需求

> 状态：**暂停**（2026-10-31 记录，未排期）｜触发：用户要把程序与媒体库放在机械硬盘、U 盘上
> 现状：库数据目录在项目内 `apps/backend/data`，路径存**绝对路径**，导入是 `shutil.copy2` 复制

## 1. 背景与实测数据

一次真实导入（`[VCB-Studio] Kami nomi zo Shiru Sekai`）：**113 个文件 / 52.7 GB**，耗时 **5–6 分钟**。

| 环节 | NVMe 实测 | 机械盘估算（120 MB/s） | U 盘估算（30 MB/s） |
|---|---|---|---|
| 复制 52.7 GB | 主体耗时 | **约 7 分钟** | **约 30 分钟** |
| 全量 sha256 | 35s（1.5 GB/s） | **约 7 分钟** | **约 30 分钟** |
| 抽帧封面 113 集 | 53s（0.47s/集） | **约 5 分钟**（随机读慢） | 更慢，且伤闪存 |
| AI 结构 + 标题（已并发 3 路） | 约 20s | 同 | 同 |
| ffprobe 113 次 | 7s | 约 10-20s | 更慢 |

**结论**：现有「复制入库 + 全量哈希 + 导入时抽帧」在机械盘/U 盘上不可用，必须换存储模型。

## 2. 范围

### IN

1. 库根目录可配置（不再固定在项目内），且**不绑盘符**。
2. 导入存储模式：硬链接 / 移动 / 复制 / 引用原位，按同卷与文件系统自动选择。
3. 去重指纹改成廉价指纹，全量哈希降级为可选动作。
4. 封面抽帧改为按需生成。
5. 可移动介质的安全写入与「文件缺失」提示。

### OUT

- 网络盘 / SMB / NAS 场景（另议）。
- 多库切换（同时管理多块盘上的多个库）。
- 跨盘硬链接（文件系统不支持，不做假装）。

## 3. 关键判断

| 操作 | 同卷 50 GB | 源文件 | 库自包含 |
|---|---|---|---|
| 复制 | 7–30 分钟 | 保留 | 是 |
| 移动 | **< 1 秒** | 消失 | 是 |
| 硬链接 | **< 1 秒** | 保留（同一份数据） | 是 |

- **硬链接优先**：不占额外空间、源目录还能继续做种/校验。
- 跨卷（如 `E:\动漫` → `D:\库`）只能是复制，必须在导入前**预估并提示**。
- 仅移动/硬链接还不够：不清掉「全量哈希 + 导入时抽帧」，用户仍要等十几分钟。

## 4. 配置项

| 设置 | 默认 | 说明 |
|---|---|---|
| `library_root` | 当前数据目录 | 库文件存放位置（可指向机械盘/U 盘） |
| `cache_dir` | 内置盘 | 封面、缩略图、字幕渲染缓存，避免写 U 盘 |
| `import_storage_mode` | `auto` | `auto` / `hardlink` / `move` / `copy` / `reference` |
| `content_hash_mode` | `cheap` | `cheap`（大小+mtime+首尾哈希）/ `full` |

## 5. 验收

| # | 场景 | 判定 |
|---|---|---|
| S1 | 源与库同一块机械盘导入 50 GB | **≤ 10 秒**完成，源目录保留（硬链接） |
| S2 | 跨盘导入 | 导入前显示预估耗时；完成后文件可播放 |
| S3 | 库盘换盘符（E: → F:） | 改设置后可继续使用，无需重建库 |
| S4 | 拔掉 U 盘后打开库 | 显示「文件缺失」，不崩溃、不丢元数据 |
| S5 | 打开选集列表 | 封面按需生成，首次可见范围优先 |
| S6 | exFAT/FAT32 同卷 | 自动退回移动/copy，不报硬链接错误 |

## 6. 已知风险

- exFAT 无日志：直接拔线容易损坏 SQLite，建议 NTFS；提供「安全拔出」。
- 硬链接会让「删除源目录」不再释放空间（直到库内路径也删除）——需在 UI 说明。
- 移动会破坏 BT 做种路径；对做种用户默认用硬链接或引用模式。
