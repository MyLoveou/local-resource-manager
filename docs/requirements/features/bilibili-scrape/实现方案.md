## 1. 对齐

- 沿用 `app/scrape` + `ScrapeConfirmQueue`，禁止新分层。  
- search 不写 Resource；select 走现有 `apply_scrape_detail`。  
- 手填 `query` 有 BV/av/链接则按稿件搜；否则当名称搜 TMDB + B 站关键词（job 仍 force）。
- 名称搜时 TMDB/B 站查询词 = `job.query`，不拼接文件名。有 ID 时 TMDB 仍用 `resource.title`，B 站吃 query+title+文件名。

## 2. 契约

### REST

`POST /scrape/jobs` body：

```json
{ "resourceId": 1, "query": "BV1xx411c7mD" }
```

`query` 可选。可含 `BV1…`、`av`+数字、`bilibili.com/video/BV…`、`b23.tv/…`（短链：能从路径解析 BV 则不必跟跳；不能则 httpx 跟跳一次且最终 host 必须是 bilibili.com / b23.tv，再取 BV）。

非空能解析 ID → 规范化 BV/av 写入 query。解析不到 → 原文当名称。
有 `query` → 等价 **force 新 job**（写入 `scrape_jobs.query` 后入队）。
无 `query` → 现网复用/force 语义不变。

Job JSON 增加可选 `query`（回显手填原文）。

候选 `url`：`bilibili:BV1…`；`source`：`bilibili`。

不新增其它路径。`proxy-image` 白名单加列出的 `i0/i1/i2.hdslb.com`（L3 编码时按 view 返回 host 补全**精确**项，禁止 suffix）。

### 表

## 4. 数据流

```text
手填 BV --> POST /jobs {resourceId, query} force
        --> 解析失败 400
        --> job.query 落库 --> worker
        --> Bilibili view（先）+ TMDB(title)
        --> candidates --> 确认队列 --> select --> apply
自动获取 --> query 空 --> title+文件名解析 --> 同上（无 400）
导入     --> enqueue 无 query（与现网）
```

`run_search`：B 站 `search(合成串)`；TMDB `search(title)`。有任一 B 站 ID → 先 extend B 站再 TMDB。

## 5. Provider 行为

- `search`：从合成串抽最多 3 个 ID，逐个 view 做成 SearchHit（relevance 高）。无 ID 且非手填路径：关键词接口尽力，失败返回 `[]`。  
- `detail(bilibili:BV…)`：view → title、desc 作 synopsis、封面、分区作标签、catalog。  
- Referer `https://www.bilibili.com`；无 Cookie。

## 6. 前端要点

- 仅 `resource.type==='video'` 显示输入。占位：`BV号、av 或视频链接`。  
- 「获取元数据」：有字则 `force=true` + query；空则现网（pending 则 preferLatest）。  
- 队列：有输入时「按此重新搜索」=`createScrapeJob(id, true, query)`。  
- `source` 已展示则不必新文案组件。
