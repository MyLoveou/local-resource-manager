# 设计 · bilibili-scrape（L2）

> 状态：**已定稿**（D-20260922-03）  
> 施工：`实现方案.md`

## 0. 复杂度

跨 scrape provider、job 查询、手填 BV、封面白名单、apply 作者。不可跳过 L2。无新表以外可仅加 `scrape_jobs.query` 列。确认 UI 沿用队列，增加输入而非新页面。

## 1. 设计原则

| 原则 | 含义 | 不做 |
|------|------|------|
| 确认闭环 | select 才写库 | 填 BV 立刻改标题 |
| 视频附加渠道 | 同蜜柑之于番剧 | 替换 TMDB；番剧挂 B 站 |
| ID 优先 | 手填 / 文件名 / 标题里的 BV 走 view | 手填失败再拿标题糊搜 |
| 手填即新搜 | 有 `query` 则 force 新 job | 把 BV 写进复用的旧候选 job |
| 渠道失败隔离 | 单源挂不影响另一源命中 | 无 TMDB Key 且 B 站有条仍整单 fail |
| 公开接口 | 无 Cookie | 登录 |
| 精确白名单 | 列出的 hdslb 主机 | 后缀匹配任意子域 |

## 2. 模型

沿用 job/candidate。新增可选列 **`scrape_jobs.query`**（TEXT，可空）：用户手填原文，供 worker 使用。

| 对象 | 用法 |
|------|------|
| `SearchHit.key` | `bilibili:{bvid}` |
| `source` | `bilibili` |
| `source_ref` | `bilibili:{bvid}` |
| `WorkCatalog` | `source=bilibili`，`source_id=bvid`；UP/分区/时间进 infobox |
| `author` | 仅空时写 UP |

**查询合成：**

- B 站解析输入 = `job.query`（优先）+ title + 文件 basename。  
- TMDB 仍只用 **title**（避免把 BV 当电影名搜）。  
- `job.query` 非空：能解析出 BV/av/URL 则规范化后搜稿件；否则当作品名称，TMDB 与 B 站关键词均用该名（不混文件名）。

**不变量：** 未 select 不改标题；分 P 当一条稿；封面须 `allowed_poster`。

## 3. 交互

### 自动（无手填）

与第一刀相同；search 额外吃文件名。有 ID 则 B 站在前，再 TMDB。

### 手填 BV（US-B.6）

仅 **视频** 信息栏：输入框「BV 号 / av / 视频链接 / 名称」。点「获取元数据」把 `query` 交给 `POST /jobs?force=true`。  
确认队列顶部同样可改该框并「按此重新搜索」（force + query）。  
**查看候选**（已有 pending、框空）：不 force，不带 query。  
批量获取：不传 query。

### 失败

手填名称 → 按名称搜 TMDB 与 B 站。view 404 → 该键无候选。无 TMDB Key + B 站有条 → done。
