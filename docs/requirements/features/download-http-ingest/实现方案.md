# 下载第一刀 · 实现方案（L3）

> 状态：**已落地**  
> L2：`设计.md`。已按「按这个做」编码。

## 1. 对齐

- 只挂现有 `app/download`，单进程队列，对标 `scrape/application/queue.py`。  
- 入库只调用 `ImportService.run`，类型 `video`，`source_kind=file`。  
- 渲染进程禁止自己 fetch 大文件；只打 `/download`。  
- 不改导入向导契约。

## 2. 契约

前缀 `/download`。JSON 信封与现网一致。

| 方法 | 路径 | 作用 |
|------|------|------|
| GET | `/health` | 现网保留 |
| POST | `/tasks` | `{ url }` → 201 任务；非法 400 |
| GET | `/tasks` | 列表，新在前 |
| GET | `/tasks/{id}` | 单条 |
| POST | `/tasks/{id}/pause` | running → paused |
| POST | `/tasks/{id}/resume` | paused → 再入队 |
| POST | `/tasks/{id}/cancel` | → failed「已取消」 |

响应字段对齐已有 `DownloadTask` camelCase。`engine` 增加 `httpx`。

`POST /tasks`：

- 必须 `http://` 或 `https://`。  
- 禁止用户信息、禁止非 80/443 以外的**本机**端口放行例外——**一律**按解析后的 IP 查私网。  
- 扩展名（URL 或后续 Content-Disposition）须落在 video 导入表；否则 400。

## 4. 数据流

```
贴 URL → POST /tasks → queued → worker httpx
     → save data/downloads/{id}/name.mp4
     → ImportService → resources + files
     → done / targetResourceId
     → 删暂存
```

启动：把 `queued`/`running`/`paused` 中 `running` 改回 `queued` 再入队（避免双 worker 写同一文件）。paused 等用户点恢复。

## 8. 风险

- 直链实际是 HTML 播放页：以 Content-Type 与魔数判断，失败文案明确。  
- 无 Content-Length：进度条不确定，仍可 done。  
- Windows 文件占用：入库前关闭写句柄。
