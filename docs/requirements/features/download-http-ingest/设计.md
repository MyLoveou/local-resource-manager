# 设计 · download-http-ingest

> 状态：**已定稿**（已编码）

沿用已有 `download_tasks` 与 `DownloadTask` 状态机。禁止新表以外可只加一列。禁止新扫描根。跨 library 入库必须走 `ImportService`，禁止手写第二套复制逻辑。

## 1. 原则

| 约束 | 做法 |
|------|------|
| 编排权威 | 状态只写 SQLite；httpx 是执行器 |
| 复制进库 | 暂存 → `ImportService.run`（video / file） |
| 无扫描根 | `data/downloads/` 不是 library.roots |
| 不挡 UI | 进程内 asyncio 队列，单 worker（与 scrape 同模式） |
| 安全 | 创建时解析 host，拒绝私网与非 http(s) |

## 2. 数据

现表够用。本刀约定：

- `protocol` = `http`（https 也记 http，与现枚举一致）  
- `engine` = `httpx`（扩展 `DownloadEngine`，不必改列类型）  
- `save_path` = 暂存文件绝对路径  
- `target_resource_id` = 入库后的 Resource；去重则指向已有行  

可选迁移 `0013_download_task_filename.sql`：加 `filename TEXT`（展示用）。没有则 UI 从 URL basename 推。

重启：`running` 视为可续（已有字节写在 `save_path`）；worker 按 `downloaded_bytes` 发 Range。

## 3. 执行

```
POST /download/tasks { url }
  → 校验 URL / DNS / 私网
  → insert queued
  → enqueue task id

worker:
  queued|paused 续 → running
  httpx stream → save_path
  进度定期 UPDATE
  文件齐 → ImportService（video）
  done + target_resource_id
  删暂存（入库成功后）
```

暂停：设 `paused`，打断 stream。恢复：重新入队。取消：`failed` + 删暂存。

## 4. 协议与引擎

本刀不读 `PROTOCOL_TO_ENGINE` 的 aria2/rqbit。`validate_http_url` 仍拒绝磁力。创建任务时磁力改走 [download-magnet-aria2](../download-magnet-aria2/需求.md)（D-20260923-06）。

## 5. UI

顶栏「下载」→ 抽屉（宽度约 420，高度跟刮削确认类似约束：列表可滚、底栏固定）：

- 输入框 +「开始」  
- 任务行：文件名、状态、进度条、速度、错误  
- 行操作：暂停/恢复/取消；done 且有 `targetResourceId` →「查看」跳转视频页并选中  

空态：「粘贴视频文件的直接下载地址」。不在信息栏做下载。

轮询 `GET /download/tasks` 2s；进行中才轮询。

## 6. 失败

| 情况 | 表现 |
|------|------|
| 非直链 HTML | failed「不是可下载的文件」 |
| 非视频扩展 | 400 或 failed「本刀仅视频」 |
| 入库失败 | 任务 failed，暂存保留便于重试（本刀可再点恢复=重入队入库） |
| 去重 | done，关联旧资源 |

## 7. 不做

设置页限速、Push、多 worker、站点 extractor。
