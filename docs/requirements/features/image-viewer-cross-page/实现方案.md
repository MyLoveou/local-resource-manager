# 查看器跨页切图 · 实现方案（L3）

> 状态：**已落地**（D-20260919-08）  
> L2：`设计.md`。

仅前端。不改 REST、IPC、Viewer.js。绑定方式锁定 **A**：`ResourceBrowser` 同步 playlist 并注入 `loadMore`。

## 1. 对齐

- 切图顺序 = `useResourcePage.items` 当前顺序。  
- 翻页只走已有 `loadMore`（`afterKey`/`afterId`，limit 80）。  
- 不环绕；不一次拉全库。  
- 图片页 / 回收站 / 顶栏搜索都走 `ResourceBrowser`，只改这一处即可覆盖。  
- `library.bump` → 现有 `reset()`；查看器打开则 `close()`。

## 2. 锁定

| 项 | 锁定 |
|----|------|
| `hasPrev` | `index > 0` |
| `hasNext` | `index < length-1` **或** 已绑定列表 `hasMore` **或** `loadingMore` |
| `next` | 非末张：现有 `show`。末张：`await loadMore()`，成功且 playlist 变长后再 `show` 下一 id |
| 预拉 | `visible` 且 `index >= length-2` 且 `hasMore` 且未在飞 → `void loadMore()` |
| 原图 Image() 预取 | 仍只预取 playlist 里已有邻张 |
| 封面打开 | `browse` 当前 `items` 含该 id → 传入全部已加载图片 id；否则 `[id]` |
| 连点 | `loadMore` 已有 `loading` 门闩，不并行第二页 |
| bump | `watch(library.revision)` 里若 `imageViewer.visible` 则 `close()` |

`loadMore` 为 `Promise<void>`：若已有请求在飞则 **await 同一 Promise 后返回**（不并行第二页）。`next` await 后再用 `pager.imageIds()` 写 playlist（不等 Vue watch flush）。失败时长度不变，停在当前张。

## 3. Store

`imageViewer.ts`：

- 增加可选绑定：`listHasMore`、`listLoadingMore`（ref，由页面写入）。  
- 或 `bindPager({ hasMore, loadingMore, loadMore })`，`unbindPager` 在 `ResourceBrowser` `onUnmounted`。  
- `next` 改为 `async next()`；末张先 `await loadMore()`。  
- Overlay / 键盘：`void next()`（已是 click handler）。  
- **不**在 store 里 `getResources`。

推荐 `bindPager`，避免 InfoPanel 再抄一份 hasMore。

## 4. ResourceBrowser

- `setup`：`imageViewer.bindPager({ hasMore, loadingMore, loadMore })`。  
- `watch(items)`：若 `visible`，`playlistIds = ids(当前打开那条的 type)`（图片页即 `image`；搜索混排则按 `currentId` 的 type 过滤，与现 `ids(type)` 一致）。  
- `watch([visible, currentId, items.length, hasMore])`：满足预拉条件则 `loadMore()`。  
- `handleCardClick` 仍 `open(id, ids(type))`。  
- `onUnmounted`：`unbindPager`；若本页关掉可 `close()`（切路由）。  
- bump：在现有 revision watch 旁 close 查看器（revision 已 reset 列表，playlist 会过期）。

搜索混排：`ids(item.type)` 只收同类。跨页 `loadMore` 可能掺进视频；**playlist 只追加 type===image 的 id**（与打开时过滤一致）。`hasMore` 仍是整页列表的 hasMore——下一页可能全是非图片，则 loadMore 后 playlist 不增长，`next` 停住；再点则再拉，直到 hasMore 假或出现图片。可接受（搜索本就混排）。图片类型页无此问题。

## 5. InfoPanel

`openViewerFromCover`：不要只用 `playlistIds.includes`。改为：若 `bindPager` 的当前 ids（或 `items` 快照）含该 id，传入过滤后的图片 id 列表；否则 `[id]`。

实现：`imageViewer.boundIds(): number[]` 由 pager 的 getIds 提供，ResourceBrowser 传入 `() => ids('image')` 不够（搜索要按资源 type）。封面仅图片：`getIds: () => ids('image')` 在图片页正确；搜索页混排时封面打开应对 **当前资源 type**。锁定：`getIds: () => ids(row.type)` 打不开——bind 时无 row。

锁定封面：`getIds()` 返回当前 `items` 里 **type===image** 的 id。封面入口本就 `row.type === 'image'`。搜索混排切图只在图片之间跳，中间视频页被 `loadMore` 吃掉但不进入 playlist。与 §4 一致。

## 6. Overlay

- `:disabled="!hasNext"` 随新 hasNext。  
- 可选：`loadingMore && 末张` 时按钮 loading（naive `loading`），非必须。  
- 不改 Host / Viewer.js。

## 7. 文件清单

| 路径 | 动作 |
|------|------|
| `application/stores/imageViewer.ts` | bindPager、hasNext、async next |
| `components/ResourceBrowser/index.vue` | 绑定、watch 同步/预拉、bump close |
| `ui/layouts/InfoPanel/index.vue` | 封面用 bound 图片 ids |
| `components/ImageViewerOverlay/index.vue` | 仅当需要 loading 态 |
| `hooks/useResourcePage.ts` | 可不改；loadMore 门闩已够 |
| 测试 | 抽 `canAdvance(index, length, hasMore)` 单测；或 store 单测 bind+next mock loadMore |

不改后端、`getResources`、VirtualGrid。

## 8. 数据流

```text
二次点击 → open(id, ids)
items 变长 → watch → playlistIds 对齐
next 末张 → loadMore → items 追加 → watch 更新 playlist → show(新 id)
距末 2 张 → loadMore（不换图）
bump/reset → close
```

## 9. 风险

| 风险 | 缓解 |
|------|------|
| 搜索下一页没有图片 | 再点 next 继续 loadMore；hasMore 完则禁用 |
| watch 与 next 竞态 | next await loadMore 后再读 playlist；show 用 index+1 |
| 切走图片页 pager 解绑 | unbind 后 hasMore 当 false，避免脏 next |
| 预拉与网格触底重复 | 同一 loadMore 门闩 |

## 10. 明确不做

- beforeKey、环绕、全库 id、视频 overlay、N1 画廊  
- Overlay 自己打列表 API
