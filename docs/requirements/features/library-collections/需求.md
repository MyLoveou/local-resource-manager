## 1. 问题

用户要把若干已入库的资源收成一组（「想看」「截图」「旅行」），类型可以混在一起。现在只能靠标签，标签不能表达顺序，也不能单独打开成一页。

## 2. 本刀收口

1. 用户能新建、改名、删除合集。删除合集不删除里面的资源。
2. 一条资源可以加入多个合集，也可以移出。移出不删除资源。
3. 合集内成员按用户调整的顺序排列，可以跨类型。
4. 侧栏有「合集」。点开一个合集，网格只显示其中仍在库里的资源。
5. 空合集可以存在。
6. 回收站里的资源不出现在合集网格里；恢复后仍在原合集、原位置。彻底删除资源时，从所有合集去掉。

## 3. 范围

### IN

- 合集名称（必填）、可选说明。
- 成员：已有资源 id + 手动顺序。
- 从信息栏把当前资源加入已有合集，或新建合集后加入。
- 在合集页移出成员、调整顺序。
- 合集列表与一个合集的成员列表。

### OUT

- 智能合集、按规则自动收成员。
- 合集嵌套、合集里再放合集。
- 把合集做成一种 `ResourceType`，或用番剧的季/集表装分组。
- 合集自己的刮削、下载、播放列表连播。
- 导入时自动建合集。
- 全库搜索改成「只搜某个合集」（本刀成员页即该合集的全部成员）。

## 4. 验收

| ID | 当 | 则 |
|----|----|----|
| C1 | 新建名为「想看」的合集 | 侧栏进入后能看到它，成员为空 |
| C2 | 把一张图片和一条视频加入同一合集 | 合集页两张卡都在，类型各自仍能按原方式打开 |
| C3 | 同一资源加入两个合集 | 两个合集里都能看见它 |
| C4 | 从合集移出一张卡 | 该卡从合集消失，类型页里资源还在 |
| C5 | 删除合集 | 合集没了，成员资源还在 |
| C6 | 成员被软删 | 合集页不再显示它；恢复后回到原顺序 |
| C7 | 调整顺序 | 刷新后顺序不变 |
| C8 | 名称为空 | 拒绝创建，不写出空合集 |

## 5. 开放问题

设计稿里已给默认，确认设计时可以改口：

1. 一条资源进多个合集：默认允许。
2. 跨类型：默认允许。
3. 顺序：默认手动，不按加入时间锁死。
4. 封面：默认用顺序第一张仍在库中的成员缩略图，不单独上传合集封面。

## 6. 轮次 2 · 决策清单（2026-09-27）

> 现状核对：**合集完全未实现** —— 后端无 `collections` / `collection_items` 表、无 `/library/collections` 路由，桌面无对应页面与菜单项。同目录 `设计.md`（L2）已给出全部默认，本清单只做确认。

| # | 问题 | 建议 | 依据 |
|---|------|------|------|
| Q1 | 一条资源进多个合集 | **允许** | 多对多才符合「想看 / 截图 / 旅行」的使用方式；成员是 `resourceId` 引用，无复制成本 |
| Q2 | 跨类型 | **允许** | 需求 §2.3 已写；合集是"分组"而非"类型"，限制类型会逼用户建多个合集 |
| Q3 | 顺序 | **手动**（`position`），不按加入时间锁死 | 标签无法表达顺序正是本需求存在的理由（需求 §1） |
| Q4 | 合集封面 | **取第一张仍 active 成员的 `thumbnailPath`**，不单独上传 | 避免新增封面文件与 `coverOrigin` 语义（设计 §6「不抽」）；空合集显示空态 |
| Q5 | 成员被软删 | **保留成员行**（不删 `collection_items`），恢复后回原位 | 需求 §2.6 已写；设计 §2 不变量一致 |
| Q6 | 菜单入口 | `/collections` 进侧栏，`/collections/:id` 不进 | 设计 §4：菜单由 `menuFromRoutes` 生成，已是既有约定 |
