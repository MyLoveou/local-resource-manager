## 0. 复杂度

新表、前后端、新的侧栏页和信息栏入口。不可跳过 L2。

## 1. 设计原则

| 原则 | 含义 | 不做 |
|------|------|------|
| 合集是分组 | 用户给已有资源起的一个名字和顺序 | 把合集做成作品、季或集 |
| 系列保持原样 | 番剧/AV 仍是 Resource + seasons/episodes | 用合集代替系列，或用系列表装「想看」 |
| 成员是资源 | 网格里仍是原来的 Resource 卡 | 为合集成员复制一份文件或新资源行 |
| 删除不连带 | 删合集、移出成员都不删资源 | 删合集时清空库 |
| 沿用库分层 | library 的 API、用例、仓储 | 新开一个平行的 collections 服务进程 |

## 2. 模型

合集不是 `resources` 行。系列表不参与。

```text
Collection
  id
  title            非空，trim 后至少 1 字
  description      可空
  createdAt
  updatedAt

CollectionItem
  collectionId
  resourceId       → resources.id
  position         同一合集内唯一，从 0 起，用户排序用
```

关系：

- 一个合集有多条成员；一条资源可出现在多个合集。
- 同一合集内同一 `resourceId` 只出现一次。
- 不嵌套：成员只能是资源，不能是另一个合集。

不变量：

- 成员列表只返回 `status=active` 的资源，按 `position` 升序。
- 软删不删 `collection_items` 行。恢复后按原 `position` 再出现。
- 资源行被彻底删除时，成员行随外键级联删除。
- 合集封面不落新文件：展示时取该合集里第一张仍 active 的成员的 `thumbnailPath`；没有成员则为空。
- 标题空白 → 422，不插入。

和系列的边界：

| | 系列 | 合集 |
|--|------|------|
| 是什么 | 一部作品的季和集 | 用户起的一组资源 |
| 存在哪 | `resources` + `seasons` / `episodes` | `collections` + `collection_items` |
| 成员 | 集不是 Resource | 成员就是 Resource |
| 谁创建 | 导入目录 | 用户手建 |

## 3. 交互

### 主路径

1. 侧栏「合集」进入列表。空态写明可以新建。
2. 新建：只问名称。成功后进入该合集。
3. 在类型页选中一条资源，信息栏「加入合集」：勾选已有合集，或输入新名称现场创建并加入。
4. 合集页是现有资源网格，只含该合集的 active 成员。点卡仍走原来的选中与打开。
5. 合集页可以把当前成员移出，或上移/下移。移出后其余成员的顺序收拢，不留空洞。

### 空态与失败

- 没有任何合集：列表空态，只有新建。
- 合集没有 active 成员：网格空态。若成员都在回收站，说明恢复后会回到这里。
- 加入一个已经在该合集里的资源：保持原位置，不重复插一行（当成功，不报错）。
- 合集 id 不存在：404。
- 资源 id 不存在：422，不合进幽灵 id。

### 数据流

```text
侧栏 / 信息栏
  → HTTP /library/collections
  → library 用例
  → collections 仓储
  → SQLite collections、collection_items
成员网格仍读 Resource 列表形状（已有卡片能画）
```

信息栏不直接写 SQLite。

## 4. 模块划分

落在现有 `library`，不新建顶层包。

| 模块 | 做 | 不做 |
|------|----|------|
| `apps/backend/app/library` | 合集用例、仓储、路由 | 改导入、刮削、下载 |
| `apps/backend/app/shared/db` | 下一号迁移，两张表 | 改 `resources` 的类型 CHECK |
| 桌面 `views` + `infrastructure/http` | 合集列表、合集网格、加入合集 | 重写全部类型页 |
| 系列 `seasons` / `episodes` | 不读不写 | — |

依赖：桌面 HTTP → library API → 用例 → 仓储 → SQLite。领域规则不依赖 Vue。

侧栏菜单来自路由表（`menuFromRoutes`）。`/collections` 出现在菜单；`/collections/:id` 不出现在菜单。

## 5. 功能拆分

仍是一个版本、一个能力。实现时再切，本设计不排文件。

| 切片 | 内容 |
|------|------|
| 功能 | 创建/改名/删除合集；加入、移出、排序；列出时滤掉回收站 |
| UI | 侧栏入口、合集列表、成员网格、信息栏加入 |
| 组合 | 合集页用现有资源卡；加入合集写在信息栏 |

没有单独的算法切片。排序就是交换 `position`。

## 6. 抽象

抽：合集与成员两张表，成员指向已有资源。

不抽：

- 通用「容器」同时装系列和合集。
- 智能合集规则引擎。
- 合集封面文件与 `coverOrigin`。
