# 非目标与边界

> 明确“不做/暂不做”，避免每个类型都把边界重新吵一遍。

## 1. 产品边界

- 单机、本地优先；不做账号体系、多用户、云同步、社交分享。
- 下载不自建；统一委托第三方成熟下载器（D-20261007-01），本仓不做 BT/HTTP 下载器。
- 不做在线流媒体/在线书源/在线漫画源。
- 不接管游戏安装/卸载，只登记与启动。
- 不把图片库做成修图软件：不做图层、滤镜、裁切写回、像素编辑。
- 不做移动端。

## 2. 数据边界

- 库内副本是元数据真源；不默认写回原文件 EXIF。
- 不伪造拍摄时间；无拍摄时间进入未知时间。
- 不把漫画合并进 image 类型（漫画是独立 type）。
- 不把 AV 合并进 anime 类型。
- 不把索引目录（游戏/工作目录）默认复制入库。

## 3. 更新/发布边界

- 不做灰度、强制更新、自动回滚。
- 不做第三方下载镜像；更新源默认 GitHub。
- 当前不做代码签名；正式分发前需补。
- 不做 macOS/Linux 包（当前范围）。

## 4. 需求判定

某个想法进来时先问：

1. 是某个资源类型的差异，还是跨类型能力？
2. 会不会引入新实体/表/状态机/对外契约？是 → 走 L2 设计。
3. 是否已有共用能力可复用？
4. 是否触碰上面的非目标？

如果只是“看起来应该做”，先放候选，不直接排期。
