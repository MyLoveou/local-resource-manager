# 后续能力规划

> 状态：**草案 / 待确认**（2026-09-23）  
> 不是已拍板方向。确认前不改 `facts.md` 的「近期顺序」，不写 `decisions.md`，不编码。  
> 清单底稿：`todo.md`。对照：[facts.md](facts.md) · [module-map.md](module-map.md) · [reference-landscape.md](reference-landscape.md)

## 1. 还要成为什么

产品仍然是单机媒体库：文件进自己的库，按类型打开，人确认后才改元数据。后面能加的功能都落在三件事上。

| 作业 | 现在 | 还能加深 |
|------|------|----------|
| 获取 | 复制导入；视频/番剧刮削；HTTP 直链 | 更多渠道、磁力交给外部客户端、Pixiv 浏览入库 |
| 组织 | 九种类型、词表、LIKE、番剧季集 | 电影档案、通用系列、合集、作者页、库健康 |
| 消费 | 最低打开（看/播/系统打开） | 进度、连续播放、阅读器、画廊 |

书签、密码、加密、三系统安装包，是这三件事旁边的新产品面。壳只有一层路由时，先加这些会把类型页复制一遍。

## 2. 建议顺序

手验过刮削、直链下载、设置里的 Key 之后，按下面六段走。每一段只开一个 `features/<id>/`，做完再开下一段。

### P0 · 把现有库用起来

不新做能力。点完：导入能看见、BV 或直链能播、设置里填 TMDB Key 后刮削不再靠环境变量。

### P1 · 壳能长

| 能力 | 用户得到什么 | 依赖 |
|------|----------------|------|
| 搜索与信息栏布局 | 搜索不必只跳 `/search`；评分、编辑、删除不必堆在「更多」里 | 无新表 |
| 嵌套路由 | 类型下能有详情、系列、设置以外的子页 | 布局定稿后做 |

电影、书签、密码、私密空间都等 P1 再进菜单。

### P2 · 作品，而不是文件

| 能力 | 用户得到什么 | 沿用 |
|------|----------------|------|
| 电影 | 单片档案：演员、时长、观看记录、封面 | 现有 `video` 播放；新类型或视频上的档案，立项时二选一 |
| 通用系列 | 电影、番剧、专辑都能收成一部作品 | 番剧季集树。番剧第二刀（增删集、字幕组、女优）是本段的一块 |
| 继续观看 | 首页看到看到哪、上次打开哪张图 | 新的进度字段，不另做播放器 |
| 合集 | 自己把若干资源收成一组 | 与系列分开：系列是作品结构，合集是用户分组 |
| 作者 / 演员页 | 点一个名字看见其全部资源 | 先用现有 `author` 文本，不先建独立人物表 |
| 库健康 | 缺封面、缺简介、游戏路径失效的列表 | 不扫用户源目录 |

### P3 · 消费加深（每种只做一条）

| 能力 | 先做 | 后做 |
|------|------|------|
| 音乐 | 应用内歌词、切歌、离开页面仍播 | 再接入落雪音乐 |
| 图片 | 动图、HEIC 打不开时交给外部程序 | 以图搜图 / CLIP |
| 漫画 / 小说 | 仍系统打开，直到单独立项阅读器 | 内置翻页 |
| 视频 | 记住播放位置 | 多音轨、批量字幕包（`metadata-panel-fields`） |

画廊沉浸连看放在「继续观看」之后，避免和「打开一张图」抢同一套查看器。

### P4 · 获取：确认后写入，重活交给外面

| 能力 | 做法 |
|------|------|
| 刮削渠道 | 仍是人选候选再写库。可加图片/AV 源，一次加一个站 |
| 磁力 | 应用内用本机 aria2c 下磁力（D-20260923-06）。搜索、以及交给 Motrix / qBittorrent，仍后置 |
| Pixiv | 单独登录、浏览、选图入库。不并进「刮削不登录」那一刀 |
| 追更 | 只提醒有新集或新刊，不自动下载、不自动改标题 |

不在本段做：再嵌 rqbit、SearXNG、远程爬虫进 Electron、默认定时写库。

### P5 · 新种类与信任

按这个次序，前一项不稳不开后一项。

1. 书签（最接近现有资源：标题、URL、封面、标签）
2. Pixiv 入库（若 P4 已单独立项，这里只接库）
3. 加密与私密空间一起设计：先定是「单条资源加密」还是「一整块看不见的空间」
4. 密码条目（依赖第 3 步的可见范围）
5. 模型管理：在 gltf 预览之外管权重、版本、来源
6. Windows 每天能用之后，再出 macOS / Linux 安装包。外部下载器和落雪按该系统有没有这个程序来接

### P6 · 工作台与资产（A 成为日常工具之后）

工作目录、按类型打开的渠道、设计系统、提示词、Skill、导出内容。导出第一刀仍未定（整库备份已有 SQLite backup，不等于导出产品包）。

## 3. 值得做、但还没写进 todo 的

这些是对照绿色资源管理器 / Bakabase 之后，本仓还缺、且符合「复制进库」的能力。

| 能力 | 为何现在值得记 |
|------|----------------|
| 右键菜单 | 主需求已定「右键编辑和信息栏并存」，菜单还没有 |
| 全局提示 | 失败仍散落。不挡功能，但 P2 起操作变多时需要一条统一出口 |
| 快捷键 | 看图切张、播放暂停、保存信息栏。不新做业务 |
| 播放与阅读进度 | 视频、小说、漫画以后的「继续」都靠它。先只做视频 |
| 同一作品的多个文件 | 一部电影多条压制、一套字幕。用系列或「版本」挂在作品下，不要变成多张互不相干的卡 |
| 刮削可撤销 | 确认写错标题后能回到文件名。现在确认即覆盖标题和简介 |
| 导入忽略规则 | 跳过样片、`sample`、过小文件。仍是一次性复制，不是监视目录 |
| 游戏时长 | 启动时刻到退出。游戏类型已能启动，计时是下一块，不是另一套库 |

## 4. 不做

已拍板或对照后明确不跟：

- 常驻监视、把用户目录登记成可再扫的根
- 移动端、多用户、在线播放站、对外分享
- 云同步、社群、成就、桌宠
- ED2K、WebDAV
- 把密码库、Pixiv 客户端、BT 引擎和媒体库同一刀交付
- 游戏化主线、*arr 全自动订阅下载

## 5. 版本（待确认后才写进路线图）

| 版本 | 包含 |
|------|------|
| 收口 | P0 |
| 下一版 | P1 + 电影与通用系列的第一刀 |
| 再下一版 | 继续观看、合集、音乐连续播放；磁力只交给外部客户端 |
| 更后 | 书签、Pixiv；加密与私密空间 |
| 桌面可安装 | 三个桌面系统能装这套库 |

## 6. 确认之后

选定一段里的**一个**能力，再写 `docs/requirements/features/<id>/需求.md`。壳、电影、系列、Pixiv、加密都跨模块，要先有 `设计.md`，不能从清单直接编码。
