## 2. 各产品：模型 + 完整能力

### 2.1 绿色资源管理器

**定位：** 一站式本地多媒体壳 + 游戏化。目标用户是海量本地文件的「仓鼠」。

**模型：** 按**类型分页**（游戏、软件、图片、单图、电影、番剧、小说、网站、音频、其它）。  
- 电影等 = **单文件**记录（路径、封面、标签、演员、时长、观看记录）。  
- 番剧 = **文件夹**记录（路径当作品，无季/集实体）。  
- 磁盘：**登记源路径**，不强制拷进应用库。

**能力（完整）：**

| 域 | 有什么 |
|----|--------|
| 类型覆盖 | 游戏 / 软件 / 图 / 漫画 / 视频 / 番剧文件夹 / 小说 / 网站 / 音频 |
| 浏览组织 | 首页、最近、搜索、多维筛选（标签/作者/系列）、合集、自定义页面与动态路由 |
| 消费 | 游戏启动（含 Flash/Ruffle）、漫画阅读、视频播放、音频播放、小说/EPUB/PDF/文本 |
| 记录 | 游戏时长、漫画阅读次数、视频观看进度、游戏内截图 |
| 获取 | 批量导入、书签导入、智能解压（密码库） |
| 元数据 | 独立刮削库、把刮削结果套到资源 |
| 壳 | 设置、帮助、更新日志、消息中心、用户页、工坊、赞助 |
| 游戏化 | 成就（收集阈值）、桌宠、放置养成（规划还要剧情/每日任务） |
| 规划中（他们自己） | 社群登录、评论、同步；站点刮削 Steam/DLsite 等 |

**弱项：** 番剧无季集树；源路径漂移要用户自己改路径；产品重心在「好玩」而不在「库结构严谨」。

**对本仓：** 交互壳（类型页、筛选、内置消费、观看记录）最像我们。游戏化/社群/Flash **不跟**。

---

### 2.2 Bakabase

**定位：** 二次元向本地媒体操作系统：属性驱动组织 + 自动抓取 + 强文件操作。Windows。

**模型：** **媒体库**挂路径；**资源**是路径上的文件或目录（可父子）。类型是细预设（动画、OVA、剧集、AV、VR、漫画、同人志、Galgame、小说、Mod…）。元数据是**属性池**（内置/保留/自定义），不是每种类型一张宽表。另有「数据卡片」把演员/IP/品牌做成可反查的实体。

**能力（完整）：**

| 域 | 有什么 |
|----|--------|
| 库 | 多媒体库、路径标记、资源发现/匹配建议、档案/Profile、播放历史、播放列表 |
| 元数据 | 增强器（含 Kodi nfo、正则等）、别名、第三方（Bangumi、Steam、DLsite、ExHentai、Jav*、B站） |
| 获取 | 下载任务、订阅、帖子解析、油猴脚本、采集线索 |
| 整理 | 批量修改、文件名修改器、资源移动、工作流、比较、健康度评分 |
| 消费 | 内置播放器 |
| 展示 | 数据卡片、自定义详情布局、GUI 选项 |
| 扩展 | AI/聊天、远程访问、通知、缓存、更新器、移动端（另工程） |
| 工具 | 文本、组件、自定义属性、扩展组 |

**弱项：** 季集不是一等公民（靠属性和 nfo）；绑定**源路径同步**，和「拷进库」是另一条路；能力面极大，学习成本高。

**对本仓：** 属性/卡片/工作流/下载/刮削是 **A 后段到远期的功能目录**，不是第一年要做完的产品。细类型枚举不要照抄。

---

### 2.3 Vnite

**定位：** 游戏生涯管理：记录、启动、刮削、多设备同步。不是通用媒体库。

**模型：** 一部游戏拆两层——**档案**（名、原名、厂商、平台、类型、外站 ID、NSFW）与 **本地**（路径、启动器：文件/URL/脚本、存档路径）。另有游玩记录、计时、存档备份、回忆笔记。

**能力（完整）：** 海报墙库、扫描器（可配目录结构与数据源）、多源刮削（Steam/IGDB/Bangumi/VNDB/YMGal/DLsite 等）、元数据变换（正则/合并/排除）、主题、插件市场、云同步、年/月/周报告、启动增强（区域、放大、模拟器）、Steam 库导入（保留时长）、动态分类与强筛选、会话计时。

**弱项：** 不管番剧/图/AV。

**对本仓：** 「远期游戏类型」的功能上限。档案与路径分离可借鉴；云同步、插件市场、年报 **不做**（方向级已排除多用户/社交，云同步也未拍板）。

---

### 2.4 Jellyfin Bangumi 插件

**定位：** 给 Jellyfin/Emby **补番剧元数据**，不是独立资源管理器。

**模型：** 作品 Subject → Season → Episode；集类型含正片/特别篇/OP/ED/预告等。

**能力：** 季集识别（含中文季名、多季同目录、连续编号）、刮削 Bangumi、缺集清理、重复集检测、补 ID/标题工具、播放打卡。

**对本仓：** 只参考 **季集/特典分型与乱目录识别能力**。不做成「必须挂媒体服务器」。刮削仍 OUT，直到 M3 立项。

---

### 2.5 Tellico / GCstar

**定位：** 桌面收藏编目（书、影碟、音乐、游戏、漫画、钱币、酒…）。GCstar 还有条码扫描伴侣和发布到 Web。

**模型：** **条目 + 类型模板 + 自定义字段**。Tellico 影视模板含介质、年份、分级、类型、地区、演职员表、导演、片长、音轨/字幕语言、封面、评分、购入/借出等。不管理「第 12 集那个 mkv」。

**能力：** 多集合、分组筛选、网站抓取器、导入导出、报表、借出。GCstar：插件刮削、条码录入。

**对本仓：** 手填档案、多值演职员、类型模板。条码/借出/实体收藏不是当前用户场景。

---

### 2.6 Anitomy / anitopy / guessit

**定位：** 文件名解析库。输出标题、季、集、字幕组、分辨率、语言等。guessit 更偏西式剧集 `SxxExx`。

**对本仓：** 仅导入预览与规范命名的输入，不出现在产品菜单。

## 4. 本仓定位（方向已部分确认）

**一句话：** 单机入库工作台——拷进自己的库，类型可插拔，先让**每种库都能进能用**，再做深。

**已拍板（D-20260917-01）：** A 第一刀 = 所有库导入 + 最低消费；高级后置。

**仍待确认：** 是否把「不跟游戏化 / 不跟云同步」升为方向级禁止。

## 5. 实现路线（已拍板分层）

| 阶段 | 做什么 |
|------|--------|
| **A-min** | 图片、视频、番剧、AV、音频、小说、游戏、模型：导入复制 + 列表/详情/回收站 + 该类型打开/读/播/启动。番剧/AV 要能点一集播放（作品级，不是每集一张卡）。 |
| **A-plus** | 系列整理与专用档案、词表/搜索、合集、抓取、下载、画廊沉浸、主题 |
| **B** | 工作目录 + 按类型打开（工作台，不是再做一个库） |
| **远期** | 游戏计时/云同步不做；设计系统、提示词、Skill、导出；加密 |
| **不跟** | 桌宠成就主线、社群、*arr 内核、条码实体收藏（建议，待升格禁止） |

与 [module-map.md](module-map.md) 对齐。`anime-av-types`：第一刀 A-min（进库+播），第二刀 A-plus（整理/字幕组/女优/双列表）。
