# 版本与动工门禁

> 与 `project-spec` Skill、既有「L1 定稿 → L3 方案 → 编码」对齐。  
> 浓缩约束见 [`../product/baseline.md`](../product/baseline.md)。

## 文档版本

| 层级 | 落点 | 状态词 |
|------|------|--------|
| L1 规范 | `docs/requirements/features/<id>/需求.md`（存量可为扁平 `*.md`） | 草案 / 评审中 / 已定稿 |
| L3 架构 | 同目录 `实现方案.md` + OpenSpec `design.md` | 与 L1 范围一致才可 apply |
| 执行 | `openspec/changes/<id>/` | propose 规划 / apply 实现 / archive 归档 |
| 项目真源 | `docs/product/facts.md` · `decisions.md` | 跨会话必读 |

`<id>` 与 change 名同一 kebab-case。

## 动工门禁

| 门 | 要求 | 未过则 |
|----|------|--------|
| G0 | 已读 facts + 最近决策 + 浓缩基线；摸清现有分层 | STOP，先补文档 |
| G1 | 该能力 `需求.md`（或存量 L1）IN/OUT、验收可测 | 不准 apply |
| G2 | `实现方案.md` / `design.md` 含**文件路径清单**与数据流 | 不准新分层、不准开写主路径 |
| G3 | OpenSpec `tasks.md` 可勾选；`tests.md` 每场景一行检查（新 change） | 不准声称完成 |
| G4 | 实现不超出清单；改范围先改文档 | 扩 scope 须用户点头 |
| G5 | archive 仅用户要求；有效不变量浓缩进 baseline | 禁止自作主张归档 |

## 分流（不要用错 Skill）

| 场景 | 走 |
|------|-----|
| 新能力 / 改契约 / 主流程 | `project-spec` propose → apply |
| 现有行为错了 | `project-spec-fix` |
| 只改观感 | `project-spec-style` |
| 只定界面方向 | `project-spec-design` |
