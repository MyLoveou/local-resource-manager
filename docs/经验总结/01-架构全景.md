# 01 · 架构全景

## 三进程数据流

```
┌─ Electron 渲染进程 (Vue 3 + naive-ui + pinia + vue-router) ──────┐
│        │ axios → http://127.0.0.1:<动态端口>                      │
│        │ （地址由 additionalArguments 注入，见 03）                │
├─ Electron 主进程 (TS) ───────────────────────────────────────────┤
│        │ 窗口/IPC/进程编排                                        │
│        └─ infrastructure/services/ 拉起后端子进程                │
│            （见 02）                                              │
├─ 后端单进程多应用 (Python FastAPI, 127.0.0.1) ───────────────────┤
│    ├── /library    资源库应用（资源/概览/仓储）                   │
│    ├── /scrape     抓取应用（SearXNG + 站点适配器）               │
│    └── /download   下载应用（aria2c + rqbit 双引擎）              │
└─ 存储：SQLite 单文件（WAL + 迁移 + 仓储层）───────────────────────┘
```

## 统一四层约定

| 层 | 前端 (renderer) | 后端 (每个子应用) | 职责 |
|----|----------------|-------------------|------|
| UI 层 | `ui/`（layouts/views/styles）+ `components/` + `views/` | `api/`（路由，薄层） | 展示/契约入口 |
| 业务层 | `hooks/` + `application/`（Pinia stores） | `application/`（用例+DTP） | 用例编排 |
| 领域层 | `domain/`（interface 类型） | `domain/`（实体+端口） | 实体/规则 |
| 基础设施 | `infrastructure/`（http/ipc/cache） | `infrastructure/`（仓储/引擎/适配器） | 技术细节 |

依赖方向：**UI → application → domain ← infrastructure**（domain 不依赖任何上层）。

## 关键技术选型（已定稿）

- **桌面**：Electron 44 + Vue 3.5 + Vite 8 + naive-ui + pinia + vue-router + motion
- **后端**：Python FastAPI（单进程多应用 mount）；SQLite 单文件
- **下载**：aria2c（HTTP+BT）+ rqbit（现代 BT/流式）双引擎，协议路由分流
- **抓取**：httpx + selectolax + SearXNG 自托管检索 + 可插拔站点适配器
- **契约**：Pydantic snake_case ↔ JSON camelCase；后续 OpenAPI 生成前端类型（单一事实源）

## 为什么这样拆

- 桌面单机场景：**进程隔离收益≈0**，单后端进程共享 SQLite 免跨进程锁；真正的隔离边界在引擎子进程（aria2/rqbit），崩溃不拖垮后端。
- 四层拆分的意义：改动各自落位、可替换实现（如换 HTTP 客户端不影响用例）、测试友好。
