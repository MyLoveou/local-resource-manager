# 29 · 踩坑：测试依赖本机环境，本地绿 CI 红

> 来源：v0.2.5 / v0.2.6 两次发布都卡在 CI 的后端测试步骤，本地却 292 passed。

## 现象

```
本地：292 passed
CI  ：6 failed / 285 passed + 2 skipped
```

两次失败各不相同：

1. `test_auth.py::test_media_content_requires_token`
   `sqlalchemy.exc.OperationalError: no such table: files`
2. `test_ai_search.py` 的 5 个检索用例
   `AIServiceError: 请先安装 AI 模型`

第二次发布时只修好了第 1 条，第 2 条仍然红——因为只 patch 了一半。

## 根因一：TestClient 不走 lifespan

```python
TestClient(app)          # 不会执行 startup，因此不会 ensure_db()
```

`get_session` 依赖默认的 `settings.db_path`。CI 上没有这个库文件，于是建了个空库，查询直接 `no such table: files`。

**为什么本地一直绿**：本机有开发库（还是我中途手动迁移过的），测试恰好命中了它。这等于把"环境依赖"伪装成了"通过"。

## 根因二：`from ... import` 各绑一份，patch 一处无效

```python
# service.py:39
from app.ai.infrastructure.model_store import MODEL_ID, is_installed
# search.py:25
from app.ai.infrastructure.model_store import MODEL_ID, is_installed
```

两处是**独立的模块级绑定**。`patch("...service.is_installed")` 不会影响 `search` 里那份，于是相似图、融合、文本检索仍走真实检查，在没模型的 runner 上抛错。

## 修法

```python
# 测试自带库，不依赖机器状态
self._tmpdir = tempfile.TemporaryDirectory(ignore_cleanup_errors=True)
settings.db_path = Path(self._tmpdir.name) / "auth.db"
db_module._engine = None
db_module._async_session_factory = None
conn = db_module.connect(settings.db_path); migrate(conn); conn.close()
```

```python
# 每个导入绑定都要 patch
for target in (
    "app.ai.application.service.is_installed",
    "app.ai.application.search.is_installed",
):
    patcher = patch(target, return_value=True)
    patcher.start()
    self.addCleanup(patcher.stop)
```

`ignore_cleanup_errors=True` 是因为异步引擎会持有数据库文件，Windows 上 `cleanup()` 会 WinError 32。

## 教训

1. **测试不许依赖机器状态**：库、模型、缓存、环境变量，要么自己造，要么显式 patch。
2. 本地能过不等于能发布。凡是"本机恰好有某个东西"的测试，都要假设 CI 没有。
3. `patch` 要盯着**导入绑定**而不是定义处；`from x import y` 是复制引用。
4. CI 日志能直接给出 `FAILED` 行与 `N failed, M passed` 汇总，先看这两处，别猜。
