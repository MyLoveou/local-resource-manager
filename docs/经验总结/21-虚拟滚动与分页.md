# 21 · 虚拟滚动与分页

> 正式学习向设计见 [design/06-虚拟滚动与分页.md](../design/06-虚拟滚动与分页.md)。
> 实现前契约草案：[design/05-资源分页与无限滚动.md](../design/05-资源分页与无限滚动.md)。
> 本文只收口：**原则 + 代码入口 + 踩坑**。

当前列表同时支持：

- 普通 `limit/offset` 分页；
- 按排序键的 **keyset/cursor** 追加（`afterKey` / `afterId`）；
- 全库混排首页（资源 + 合集卡）；
- 前端只保留已加载的 `items`，DOM 由虚拟列表再裁一次。

## 原则（背下来）

1. **虚拟滚动管 DOM，分页管内存/磁盘。** 只做一层不够。
2. 下一页看 **已加载 `items.length`**，不要用全库 `total` 当虚拟列表 `count`。
3. 网格 **不发 HTTP**；`useResourcePage` 管 `hasMore` / 单飞 / 过期响应。
4. keyset 追加用服务端返回的 `nextKey`/`nextId`，不要在前端自己算排序键。
5. 列数、行高是 **Card 布局契约**，TanStack 算不了，换库也消不掉。
6. 滚动必须发生在 **固定高度** 的 `overflow: auto` 容器上。

## 三层规模

```text
SQLite 全库
  --limit/offset 或 keyset-->  items[]（已加载窗口）
  --TanStack Virtual-------->  DOM 几十张卡
```

## 入口

| 层 | 文件 |
|----|------|
| 信封 | `ResourcePage`（`nextKey` / `nextId` / `hasMore`） |
| 用例 | `LibraryQueryService.list_page` |
| Hook | `hooks/useResourcePage.ts` |
| 网格 | `components/VirtualGrid/index.vue`（`lanes` + `nearEnd`） |
| 接线 | `components/ResourceBrowser/index.vue` |

## 追加流程

```text
初始 reset()
  → getResources(limit, sort, order)
  → items = page.items
  → cursorKey = page.nextKey
  → cursorId = page.nextId

滚动 nearEnd / 点击加载更多
  → loadMore()
  → getResources({ afterKey: cursorKey, afterId: cursorId })
  → 去重后 append
```

`useResourcePage` 内部用 `requestId` 丢弃过期响应，用 `inflight` 防止重复追加。

## 踩坑（我们真实遇到的）

| 现象 | 原因 | 处理 |
|------|------|------|
| 启动失败 sentinel column | `Mapped[int \| None]` 主键 | `Mapped[int]` + autoincrement |
| `created_at` NOT NULL | ORM 插入显式 NULL | 仓储写时间戳 + server_default |
| 封面极慢 / 空白 | 远程图片 + CSP | 本地缩略图；CSP 放行必要来源 |
| 每次启动都「初始化库」 | 日志/seed 语义不对 | 有库则连接；无库才创建+迁移 |
| 改后端不生效 | Python 无 HMR | 重启 `pnpm dev` |
| 追加重复/跳页 | 只用 offset，数据在翻页时插入 | 用 keyset（`nextKey`/`nextId`） |
| 刷新后回到顶部 | 直接 reset 整个列表 | `refreshTop()` 只插新数据 |

## 验收一眼看

- Network：首屏一页；再滚才第二页。
- Elements：卡片节点数约一屏，不是 200。
- URL 返回：筛选条件还在，列表从第一页恢复。
