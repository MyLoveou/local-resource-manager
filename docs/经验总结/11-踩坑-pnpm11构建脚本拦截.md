# 11 · 踩坑：pnpm 11 构建脚本被拦截

## 现象

`pnpm install` 报：

```
[ERR_PNPM_IGNORED_BUILDS] Ignored build scripts: esbuild@0.25.12
```

且 `pnpm build` / `pnpm typecheck` 前置的 deps 检查直接失败（exit 1）。

## 根因

pnpm 11 默认**拦截依赖的 postinstall 构建脚本**（供应链安全），esbuild/electron 等需要跑脚本的包必须显式放行。

## 修复（推荐：配置文件，勿用交互命令）

`pnpm-workspace.yaml`：

```yaml
packages:
  - "apps/desktop"

allowBuilds:
  esbuild: true
  electron: true
```

然后 `pnpm rebuild esbuild electron` 触发构建。

## 二次坑：交互命令残留

曾用 `pnpm approve-builds`，交互未完成会往 `pnpm-workspace.yaml` 写入**占位值**：

```yaml
allowBuilds:
  esbuild: set this to true or false   # ❌ 无效占位，污染配置
```

导致 esbuild 仍被判定未放行。**排查命令**：

```powershell
pnpm config get allowBuilds   # 看到占位字符串 → 手改 yaml
```

## 教训

1. 先写配置文件（`allowBuilds`），别用交互式 `approve-builds`（非交互 shell 里会卡/残留）。
2. `pnpm config list` 能看出配置是否生效。
3. 换依赖版本后注意构建脚本是否被重新标记为 ignored。
