# 48 · 图解：启动时序与发布流水线

> 一个讲"点开图标之后发生了什么"，一个讲"推一个 tag 之后发生了什么"。两端都容易出问题，且都不在业务代码里。

## 1 启动：从图标到能点

```mermaid
sequenceDiagram
  autonumber
  participant U as 用户
  participant M as Electron 主进程
  participant P as Python 后端
  participant W as 窗口
  participant R as 渲染进程

  U->>M: 双击启动
  M->>M: 单实例检查（已有窗口则聚焦）
  M->>M: 选空闲端口 + 生成一次性 token
  M->>P: spawn（注入 token / 端口 / DB 路径 / ffprobe 路径）
  loop 最多等 N 秒
    M->>P: GET /health
    P-->>M: ok / 未就绪
  end
  alt 超时或进程退出
    M->>W: 显示启动失败（含日志入口）
  else 就绪
    M->>W: createWindow
    W->>R: 加载页面 + additionalArguments 注入端口与 token
    R->>R: axios 设置 baseURL 与 Authorization
    R-->>U: 可用
  end
```

**为什么必须等 `/health`**：Python 进程"起来了"不等于"能服务"（迁移可能还在跑）。直接开窗口会出现首屏 500。

```mermaid
stateDiagram-v2
  [*] --> spawning
  spawning --> waiting: 进程已创建
  waiting --> ready: /health ok
  waiting --> failed: 超时 / 进程退出 / 端口占用
  ready --> stopping: 用户关窗
  stopping --> [*]
  failed --> [*]
```

**排障对照**：

| 现象 | 位置 |
|---|---|
| 窗口空白且无报错 | 是否等了 `/health`；渲染层 baseURL 是否拿到 |
| 请求全 401 | token 注入链路（additionalArguments → preload） |
| 启动即退出 | 迁移失败 / DB 被占用 / 端口冲突 |
| `electron.app` undefined | `ELECTRON_RUN_AS_NODE=1` 被继承（见 31） |

## 2 发布：从 tag 到 Release

```mermaid
flowchart TD
  A["本地：pnpm release:publish"] --> B{"版本号 x.y.z?"}
  B -->|否| X1["中止"]
  B -->|是| C{"docs/releases/vX.md 存在?"}
  C -->|否| X2["中止"]
  C -->|是| D{"工作区干净?"}
  D -->|否| X3["中止"]
  D -->|是| E{"分支 = master?"}
  E -->|否| X4["中止：只允许 master"]
  E -->|是| F{"tag 已存在?"}
  F -->|是| X5["中止：不重复发版"]
  F -->|否| G["push 提交"]
  G --> H["创建并推送 tag"]
  H --> I["GitHub Actions 触发"]
```

```mermaid
sequenceDiagram
  autonumber
  participant GH as Actions runner
  participant PY as Python venv
  participant NJ as Node
  participant PK as PyInstaller
  participant EB as electron-builder
  participant REL as Release

  GH->>GH: checkout / 缓存恢复
  GH->>PY: 建 venv + 装依赖
  GH->>NJ: pnpm install
  GH->>GH: 跑测试与门禁（typecheck / lint / file-size / pytest）
  alt 任一失败
    GH-->>REL: 不发布（本次 0.2.5 / 0.2.6 即如此）
  else 通过
    GH->>PK: 冻结后端为 sidecar
    PK->>EB: 产物 + icon + 配置
    EB->>EB: 生成 NSIS 安装包 + zip
    EB->>REL: 上传 artifacts
    GH->>REL: 创建 Release + 上传 latest.yml
  end
```

**关键认知**：CI 里的测试是**发布闸门**。0.2.5 / 0.2.6 两次都是测试失败导致"tag 有了、包没有"——tag 本身不会回滚。

## 3 自动更新：装完之后

```mermaid
sequenceDiagram
  autonumber
  participant M as 主进程
  participant UP as electron-updater
  participant GH as GitHub Releases
  participant U as 用户

  M->>M: 启动 8 秒后
  M->>UP: checkForUpdates
  UP->>GH: 读 latest.yml
  alt 有新版本
    UP-->>M: available(version)
    U->>M: 点下载
    M->>UP: downloadUpdate
    UP->>GH: 下载安装包 + 校验
    UP-->>M: downloaded
    U->>M: 立即重启安装
  else 无新版本
    UP-->>M: not-available
  end
```

- `latest.yml` 由 CI 自动生成，**不要手改**
- 检查失败不影响主业务（更新是独立通道）
- zip 版用户不会自动更新，需要手动替换

## 4 三处"看起来成功其实没有"的坑

| 坑 | 表现 | 真相 |
|---|---|---|
| 只看 tag 有了就以为发成功 | Release 页面空 | 构建可能在测试步骤失败 |
| 本地门禁过了就推 tag | CI 红 | 本地有开发库/模型，CI 没有（见 29） |
| `/health` 通了就认为后端可用 | 首屏 500 | 迁移可能还没跑完，或首个请求触发了懒加载 |

## 5 一次发布的检查单

```mermaid
flowchart LR
  A["版本号 +1"] --> B["写 docs/releases/vX.md"]
  B --> C["全量 pytest"]
  C --> D["typecheck / lint / build / size"]
  D --> E["release:publish"]
  E --> F["等 Actions 绿"]
  F --> G["确认 Release 有安装包"]
  G --> H["确认 latest.yml 版本一致"]
```
