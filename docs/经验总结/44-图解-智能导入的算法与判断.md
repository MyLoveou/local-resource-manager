# 44 · 图解：智能导入的算法与判断

> 导入是"规则密集"的功能：切片、判噪、判类型、算置信度、再给建议。没有模型参与，所以每一步都能追。

## 1 名称清洗的流水线

```mermaid
flowchart TD
  RAW["原始名：<br/>[VCB-Studio] Frieren [01][Ma10p_1080p][x265_flac]"] --> SPLIT["按括号切段"]
  SPLIT --> S1["[VCB-Studio]"]
  SPLIT --> S2["Frieren"]
  SPLIT --> S3["[01]"]
  SPLIT --> S4["[Ma10p_1080p]"]
  SPLIT --> S5["[x265_flac]"]
  S1 --> R1{"短段且无中文?"}
  R1 -->|是| D1["判发布组 → 丢"]
  S3 --> R3{"纯数字?"}
  R3 -->|系列作品| D3["集号进季集树 → 丢"]
  R3 -->|单文件| K3["保留为 01"]
  S4 --> R4{"token 全命中噪音表?"}
  S5 --> R4
  R4 -->|是| D4["丢"]
  R4 -->|否| K4["保留"]
  D1 --> OUT["Frieren<br/>剥掉 4 段 → 置信度 0.95"]
  D3 --> OUT
  D4 --> OUT
  K3 --> OUT
  K4 --> OUT
```

## 2 噪音词表为什么分七类

| 类别 | 例子 | 单独列出的理由 |
|---|---|---|
| 分辨率 | `1080p` `2160p` `BDRip` | 与编码组合出现 |
| 编码 | `x265` `H264` `10bit` `HEVC` | 常和位深连写 |
| 音轨 | `flac` `aac` `DTS` | 中文组还会写「自压」 |
| 来源 | `WEB-DL` `BluRay` `TV` | 与分辨率混排 |
| 语言 | `CHS` `JPN` `简繁` `双语` | 与字幕组标记混排 |
| 容器 | `mkv` `mp4` | 常和音轨挤在一段 |
| 站点 | `dmhy` `mikan` `nyaa` | 有时放在末尾括号 |

**为什么要分词而不是整段匹配**：`[x265_flac]` 这种把编码和音轨写在一段里的很常见，整段匹配会漏。

## 3 类型判断：番剧还是单文件

```mermaid
flowchart TD
  IN["待导入的文件"] --> T{"导入类型"}
  T -->|番剧 / AV| S["系列模式"]
  T -->|视频 / 图片| F["单资源模式"]
  S --> S1{"目录名/文件名命中特典标记?"}
  S1 -->|是| EX["归入 extras"]
  S1 -->|否| S2{"能解析出集号?"}
  S2 -->|能| EP["进 episodes，挂到对应 season"]
  S2 -->|不能| AUTO["自动编号 + 记一条「自动编号」说明"]
  F --> F1["每个文件 = 1 条资源"]
  F1 --> F2{"保留集号?"}
  F2 -->|是| F3["标题带 01，避免多集同名"]
```

**最容易搞错的点**：同一套目录，选「番剧」还是「视频」，归档语义完全不同（见 [39](39-技术-番剧目录结构识别.md)）。

## 4 集号解析：为什么用"首个括号里的数字"

```mermaid
flowchart LR
  N["[Group] Title [03][1080p].mkv"] --> T["按括号切段"]
  T --> C["候选段：['Group','Title','03','1080p']"]
  C --> F{"段内是 1–4 位数字?"}
  F -->|'03'| OK["集号 = 3"]
  F -->|'1080p'| NO["不是纯数字 → 跳过"]
  OK --> PAD["归一为 03（两位）"]
```

规则刻意简单：**纯数字段才是集号**。这样 `1080p`、`10bit`、`2024` 都不会被误判成集号——年份会，但年份通常出现在标题里而不是独立括号段，风险可接受。

## 5 两阶段导入：复制与建议分离

```mermaid
flowchart TD
  A["开始导入"] --> B["阶段一：复制 + 哈希 + 落库"]
  B --> C{"每个文件都处理完?"}
  C -->|否| B
  C -->|是| D["阶段二：逐资源产出建议"]
  D --> E{"动作抛异常?"}
  E -->|是| F["记日志，跳过该动作"]
  E -->|否| G["写 import_suggestions(pending)"]
  F --> H["任务结束，报告计数"]
  G --> H
  H --> I["用户审阅：分组 + 分级勾选"]
  I --> J["apply：只写非空字段"]
```

**两个阶段必须分开**：阶段一失败要让整个任务失败（文件没进库）；阶段二失败**不能**影响导入（建议只是锦上添花）。

## 6 建议分组与分级的算法

```mermaid
flowchart LR
  S1["建议 A：title=夏日海边 0.85"] --> G["按 (field, value) 分组"]
  S2["建议 B：title=夏日海边 0.72"] --> G
  S3["建议 C：title=夏日海边 0.91"] --> G
  G --> M["组置信度 = min(0.85, 0.72, 0.91) = 0.72"]
  M --> T{"分级"}
  T -->|≥0.85| H["默认勾选"]
  T -->|0.5–0.85| B1["展示不勾"]
  T -->|<0.5| L["折叠"]
```

**为什么取最小值而不是平均**：一组里只要有一条拿不准，整组就不该被默认采纳。取平均会把"一条很确定 + 一条很瞎"抬到中等，诱导误操作。

## 7 写入侧的空值闸门

```mermaid
flowchart TD
  A["apply(title=..., catalog=...)"] --> C1{"title 非空?"}
  C1 -->|否| K1["跳过（不覆盖）"]
  C1 -->|是| W1["写 resources.title"]
  A --> C2{"catalog 非空?"}
  C2 -->|否| K2["跳过"]
  C2 -->|是| W2["写 resources.catalog"]
```

这条闸门是事故换来的：早期解析失败时把数字 id 当标题写进去了（见 [33](33-踩坑-解析失败不要编造内容.md)）。
