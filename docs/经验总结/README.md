## 5. 维护规则

- 新增长文：编号递增，加入本索引；最好同时给出“学习指南/自检问题”。
- 旧文过时：优先在原文件顶部加“历史”说明，不要直接删掉踩坑记录。
- 架构变化：更新 01/24/25 + `facts.md`；拍板写入 `decisions.md`。
- 发布流程变化：更新 23/26；不要只改 workflow 不写文档。
- 迁移/表变化：更新 07/27；迁移文件只增不改。
- 文档中的路径、命令必须能直接执行；不能执行的示例要标注“历史”。
