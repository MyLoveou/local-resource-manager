# 28 · 学习路线图

> 这份路线图面向“想从零读懂这个项目，或照着做一个类似桌面应用”的人。
> 不按语言教材的顺序，而按本项目真实依赖的顺序：先能跑，再能改，再能发布。

## 1. 先定位：这是一个什么项目

三层结构：

```text
Electron + Vue 3        桌面外壳与界面
        │ HTTP
FastAPI + SQLAlchemy    本地业务服务
        │
SQLite                  单机数据库
        │
文件系统 / ffprobe       媒体文件
```

```mermaid
flowchart LR
  A["阶段 0<br/>语言 / Git / HTTP"] --> B["阶段 1<br/>Electron 三进程"]
  B --> C["阶段 2<br/>Vue / Pinia / 路由"]
  C --> D["阶段 3<br/>FastAPI / SQLite / 迁移"]
  D --> E["阶段 4<br/>媒体 / 时间线 / 分类"]
  E --> F["阶段 5<br/>打包 / Release / 更新"]
```

它同时涉及：

- 桌面应用进程模型；
- 前端组件化与状态管理；
- HTTP API 与数据建模；
- SQLite 迁移；
- 媒体元数据；
- Windows 打包与自动更新；
- CI 质量门禁。

不要一开始就试图把所有东西学完。按下面的阶段推进。

## 2. 阶段 0：前置能力

### 2.1 必须会

| 能力 | 最低要求 |
|------|----------|
| JavaScript/TypeScript | 变量、函数、Promise、async/await、类型、模块 |
| HTML/CSS | 盒模型、Flex、选择器、响应式基础 |
| Python | 函数、类、异常、类型标注、虚拟环境 |
| Git | clone/commit/branch/tag/push |
| HTTP | 方法、状态码、Header、JSON、Bearer token |
| 命令行 | PowerShell、环境变量、路径 |

### 2.2 可以先跳过

- Kubernetes；
- 微服务拆分；
- 复杂 DDD 战术模式；
- 大规模分布式；
- 前端 SSR。

这个项目是单机应用，过早引入这些概念会干扰主线。

### 2.3 自检

- 能解释 `async/await` 和事件循环的基本关系？
- 能写一个带 JOIN 的 SQL 查询？
- 知道 `git tag` 和 `git branch` 的区别？
- 能在 PowerShell 里创建 venv 并运行 pytest？

## 3. 阶段 1：跑起来并理解进程

目标：知道“窗口、后端、数据库”分别在哪里。

阅读：

- [01-架构全景.md](01-架构全景.md)
- [02-Electron后端子进程编排.md](02-Electron后端子进程编排.md)
- [03-主进程传参additionalArguments.md](03-主进程传参additionalArguments.md)

代码：

```text
apps/desktop/src/main/index.ts
apps/desktop/src/main/infrastructure/services/
apps/desktop/src/preload/index.ts
apps/desktop/src/renderer/src/main.ts
```

动手：

1. `pnpm backend:install`
2. `pnpm dev`
3. 在任务管理器里找到 Electron 主进程、渲染进程、Python 后端。
4. 关掉后端进程，观察 UI 的错误提示。
5. 在 `main/index.ts` 的启动路径加日志，确认“先后端、后窗口”。

验收：

- 能画出启动时序图；
- 能解释 token 为什么不放 URL；
- 能解释 `will-quit` 为什么必须清理后端。

## 4. 阶段 2：Vue 页面与状态

目标：能新增一个页面，并正确接入列表、筛选、详情。

阅读：

- [24-桌面端分层与模块封装.md](24-桌面端分层与模块封装.md)
- `docs/design/05-资源库页面与滚动.md`
- [21-虚拟滚动与分页.md](21-虚拟滚动与分页.md)

代码：

```text
apps/desktop/src/renderer/src/router/route.ts
apps/desktop/src/renderer/src/views/
apps/desktop/src/renderer/src/application/stores/
apps/desktop/src/renderer/src/hooks/useResourcePage.ts
apps/desktop/src/renderer/src/infrastructure/http/
```

动手：

1. 新增一个 `/about` 页面，显示当前版本和数据库路径。
2. 复用 `useResourcePage` 做一个“最近添加”列表。
3. 把页面筛选状态写进 URL query，刷新后保持。
4. 用 Pinia 增加一个“仅看未分类”的持久化开关。
5. 给新页面加空态、加载态、错误态。

验收：

- 页面不直接 import axios；
- 列表分页不重复、不丢滚动；
- 刷新 URL 后筛选条件还在；
- 新增组件有显式 import，typecheck 通过。

## 5. 阶段 3：FastAPI、SQL 与迁移

目标：能新增一个字段/表/接口，并且有测试。

阅读：

- [25-后端分层与数据访问.md](25-后端分层与数据访问.md)
- [07-SQLite迁移与仓储.md](07-SQLite迁移与仓储.md)
- [06-领域模型-状态机值对象常量.md](06-领域模型-状态机值对象常量.md)

代码：

```text
apps/backend/app/library/api/
apps/backend/app/library/application/use_cases.py
apps/backend/app/library/infrastructure/repositories.py
apps/backend/app/shared/db/
apps/backend/app/shared/api_envelope.py
```

动手：

1. 给 `resources` 加一个 `source_url` 字段。
2. 写 `0020_resource_source_url.sql`。
3. 在 domain/schema 加字段，在 repository 读写。
4. 加一个 PATCH 接口。
5. 写测试：迁移后字段存在、PATCH 能保存、列表能返回。
6. 用 curl 或前端调用验证。

验收：

- 迁移只新增、不改旧文件；
- 测试用临时库，不碰 `library.db`；
- API 返回 camelCase；
- 非法状态返回 422/404，而不是 500。

## 6. 阶段 4：媒体、时间线与分类

目标：理解“作品/文件/分类/时间线”的模型差异。

阅读：

- [27-媒体库领域与时间线.md](27-媒体库领域与时间线.md)
- `docs/requirements/features/library-workspace/`
- `apps/backend/app/library/application/photos.py`
- `apps/backend/app/library/domain/models.py`

动手：

1. 导入 3 张有 EXIF、1 张无 EXIF 的图片。
2. 建一个图片时间线，排除某个分类。
3. 验证新导入图片自动进入时间线。
4. 加一个视频，观察 ffprobe 读取的时长/分辨率。
5. 手动改拍摄时间，确认时间线位置变化。

验收：

- 未知时间不被伪造成 1970；
- 分类筛选包含后代；
- 时间线没有成员表；
- 删除分类时引用保护生效。

## 7. 阶段 5：打包、发布、自动更新

目标：能独立完成一次 `vX.Y.Z` 发布，并解释每个资产。

阅读：

- [23-GitHub-Releases与自动更新.md](23-GitHub-Releases与自动更新.md)
- [26-发布构建与测试门禁.md](26-发布构建与测试门禁.md)

代码：

```text
scripts/release.mjs
scripts/verify-release.mjs
.github/workflows/release-windows.yml
apps/desktop/electron-builder.yml
apps/desktop/src/main/infrastructure/services/update.ts
```

动手：

1. 本地跑 `pnpm release:win`，检查 `release/` 的 5 个关键产物。
2. 改一个版本号，打 tag，观察 Actions。
3. 故意上传一个错误版本号，看客户端是否拒绝。
4. 用 `UPDATE_FEED_URL` 指向本地静态服务器，做一次不依赖 GitHub 的更新。
5. 记录一次下载速度和失败重试行为。

验收：

- 能解释 tag、Release、latest.yml、app-update.yml 的关系；
- 能读懂 Actions 失败日志；
- 能判断“构建成功但客户端不更新”的问题在哪一层；
- 知道当前没有代码签名，以及它的影响。

## 8. 推荐学习顺序（4 周版）

| 周 | 主题 | 产出 |
|----|------|------|
| 1 | Electron + Vue 基础、启动链路 | 能画出三进程图；新增一个页面 |
| 2 | Pinia、路由、HTTP、列表分页 | 一个带筛选 + 分页的列表页 |
| 3 | FastAPI、SQLAlchemy、SQLite 迁移 | 一个新增字段 + 接口 + 测试 |
| 4 | 打包、Release、自动更新 | 一次完整 tag 发布 |

如果每天只有 1 小时，把每周拆成 2 周；不要压缩第 3、4 周的动手部分。

## 10. 用这个项目练手的 10 个任务

按难度递增：

1. 在设置页显示 Electron/Chrome/Python 版本。
2. 给资源列表加“按添加时间/拍摄时间”切换。
3. 给分类树加拖拽排序（先只改前端顺序）。
4. 给时间线增加“仅未知时间”筛选。
5. 增加批量修改评分。
6. 增加一个“最近导入”首页卡片。
7. 给后端加一个 `/library/stats/type` 聚合接口。
8. 给导入流程加取消。
9. 做一次不依赖 GitHub 的更新源联调。
10. 给 Release 加代码签名（需要证书）。

每个任务都要求：

- 先写清楚输入/输出/失败路径；
- 加测试或手动验收步骤；
- 不破坏现有分层；
- 更新相关文档。

## 11. 不要这样学

- 只看视频不动手：这个项目的难点在进程、迁移、打包链路，必须跑。
- 一上来重构分层：先理解现有 `api/application/domain/infrastructure` 为什么这么分。
- 把 `TestClient` 当万能测试：先测服务层，再测 HTTP。
- 把 GitHub Release 当网盘：版本、latest.yml、哈希必须配套。
- 为了下载速度接不可信代理：更新包是代码执行入口，供应链安全优先。
- 追求“0 warning”再发布：当前 lint 有历史 warning，先保证 0 error 和测试通过，再逐步清理。

## 12. 学完后的自检

能独立回答：

- 一个请求从 Vue 页面到 SQLite 再回来，经过哪些层？
- token 如何从主进程到后端？
- 为什么分类要按资源类型分树？
- 时间线为什么没有成员表？
- 迁移为什么不能改历史文件？
- `TestClient` 为什么会触发 lifespan？
- `latest.yml` 和 `app-update.yml` 各是什么？
- 164 MB 安装包由什么组成？
- 发布成功但客户端不更新，先查什么？

如果这些问题能答清楚，并且能完成第 10 节的 1-5 个任务，就已经具备独立维护这个项目的基础。
