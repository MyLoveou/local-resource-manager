# 20 · 日志系统（electron-log + 后端 logging）

> 正式设计稿见 [design/03-日志系统.md](../design/03-日志系统.md)。本文偏学习：为什么这么拆、怎么用、容易踩的坑。

## 要解决什么问题

桌面应用有三处会「说话」：

1. Electron **主进程**（窗口、spawn 后端）
2. **渲染进程**（Vue / axios）
3. **Python 后端**（FastAPI，被主进程拉起）

如果各写各的 `console.log`，会出现：

- 后端在子进程里，终端默认看不到（`stdio: pipe`）
- uvicorn access log 和自写 middleware **打两遍**
- 日志散落在不同目录、格式不统一，排障困难

目标：**同一目录、同一格式；文件为权威；终端只做开发预览。**

## 总览（记这张图）

```
渲染 ──IPC──► 主进程 electron-log ──► {LOG_DIR}/main.log
                 │
                 ├─ process.env.LOG_DIR = …
                 └─ spawn uvicorn（继承 LOG_DIR，--no-access-log）
                        │
                        ▼
                   LoggingApp ──► {LOG_DIR}/backend.log
                                ──► {LOG_DIR}/backend.error.log
                        │ stdout pipe
                        └─► 开发期转发到当前终端（方便看，不是权威）
```

## 统一约定（背下来）

**格式：**

```text
YYYY-MM-DD HH:mm:ss - [scope] - LEVEL - message
```

`scope` ∈ `main` | `renderer` | `backend`

**目录 `LOG_DIR`：**

| 优先级 | 规则 |
|--------|------|
| 1 | 环境变量 `LOG_DIR` |
| 2 | 开发（有 `ELECTRON_RENDERER_URL`）→ `{repo}/apps/logs` |
| 3 | 生产 → `{userData}/logs` |
| 后端单独跑且无 env | 回退 `apps/logs` |

同目录文件：`main.log` / `backend.log` / `backend.error.log`

## 桌面端怎么接

### 模块

```
src/main/log/index.ts              # getLogDir + initMainLog + log
src/main/index.ts                  # 文件最开头 initMainLog()
src/preload/index.ts               # import 'electron-log/preload'
src/renderer/.../logging/logger.ts # 渲染用 logger
```

### 为什么必须最先 `initMainLog()`

1. 尽早落盘，启动失败也有日志  
2. `log.initialize()` 之后，渲染 / preload 的 IPC 桥才可用  
3. 先写入 `process.env.LOG_DIR`，后面 `spawn` 后端才能继承同一目录  

```ts
// main/index.ts 顶部
import { initMainLog, log } from './log'
initMainLog()
```

### 主进程怎么打

```ts
import { log } from './log'   // 或相对路径
log.info('[main] backend ready', url)
log.error('[main] failed to start', err)
```

### 渲染进程怎么打

contextIsolation 下渲染碰不到 Node `fs`，所以：

- preload：`import 'electron-log/preload'` → 暴露 `__electronLog`
- 渲染：`import log from 'electron-log/renderer'`（我们包成 `logger`）

```ts
import { logger } from '@/infrastructure/logging/logger'
logger.warn('[http] GET /library/overview -> 500')
```

axios 失败已在响应拦截器里打 warn；**不要把 token 打进日志。**

### 格式为什么用自定义函数

electron-log 默认主进程 `processType` 叫 `browser`，和我们说的 `main` 不一致；级别默认小写。  
`unifiedFormat` 做两件事：`browser`→`main`、级别转大写；时间用 `dayjs(...).format('YYYY-MM-DD HH:mm:ss')`。

## 后端怎么接

### 模块

```
app/shared/config.py           # resolve_log_dir / LoggingConfig
app/shared/log.py              # LoggingApp（幂等）+ logger
app/shared/middleware/logging.py
```

### 为什么要幂等

`setup` 多次 `addHandler` 会让同一条日志打 N 遍。  
用「锁 + `_configured`」保证进程内只配一次；**不要**靠 `logger = None; if logger is None`（模块每次执行都会重置）。

### 业务怎么打

```python
from app.shared.log import logger

logger.info("正在初始化数据库")
logger.error("初始化数据库失败: %s", e)
```

路径在 **第一次配置时**读 `LOG_DIR`（由 Electron 注入），所以必须先 `initMainLog` 再 spawn。

## 和子进程编排的关系（易混）

| 点 | 结论 |
|----|------|
| 删掉 stdout 转发 | 开发终端看不到后端输出（管道没人读） |
| 保留转发 | 方便预览；**权威仍是 backend.log** |
| `--no-access-log` | 关掉 uvicorn 自带 access，避免和 middleware 重复 |
| `stdio: 'inherit'` | 终端能直接看，但不好分级/汇聚，当前不采用 |

完整 spawn 说明见 [02-Electron后端子进程编排](02-Electron后端子进程编排.md)。

## 使用 checklist

- [ ] 主进程改日志 → `import { log } from '…/log'`
- [ ] 渲染改日志 → `import { logger } from '@/infrastructure/logging/logger'`
- [ ] 后端改日志 → `from app.shared.log import logger`
- [ ] 新中间件不要 `from …main import app`（循环依赖）；由 `main` 注册
- [ ] 不记 token / 密码

## 踩坑对照

| 现象 | 原因 / 处理 |
|------|-------------|
| 终端无后端日志 | 子进程 + pipe；需转发或看 `backend.log` |
| Request 打两遍 | uvicorn access + middleware → 加 `--no-access-log` |
| 后端日志不在 apps/logs | 未继承 `LOG_DIR`，或单独启动未设 env |
| 渲染日志不进 main.log | 未 `initialize()` 或 preload 未接 `electron-log/preload` |
| Handler 重复 | `setup_logging` 被多次调用且未做幂等 |

启动成功看一行：`[main] log dir <路径>`，即当前统一目录。
