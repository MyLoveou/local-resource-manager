# 34 · 踩坑：两个静默的数据层陷阱

> 来源：AI 建议缩略图全部 401；播放进度接口返回旧值。

## 陷阱一：媒体 URL 必须签名

媒体元素（`img` / `video` / `model-viewer`）发不出 `Authorization` 头，所以本仓的媒体流用「路径绑定 + HMAC」的临时签名：

```
/library/resources/533/files/1068/content?exp=1792916545&sig=42d6ca99...
```

未签名一律 401。全仓正常路径都走 `file_content_url()` / `media_path()` 自动签名，但**手拼路径的地方就漏了**：

```python
# 错：AI 建议接口里手拼的裸路径
thumbnails[rid] = f"/library/resources/{rid}/files/{file_id}/content"
```

结果是网格封面正常、唯独 AI 建议的封面全糊——因为只有这一处没签名。

修法：把构造收进 `media_paths.resource_thumb_url()`，两个分支都签名，调用方不再拼字符串。

## 陷阱二：裸 SQL 更新后的脏读

```python
# session 是 expire_on_commit=False
await session.execute(text("INSERT ... ON CONFLICT DO UPDATE ..."))
await session.commit()
row = await session.execute(select(Row).where(...))   # ← 拿到更新前的实例
```

实测：上报 590/600，接口返回 `completed=false position=120`，而库里已经是新值。**接口说没记上，其实记上了**。

修法：裸 SQL 提交后显式 `session.expire_all()`（`delete` 之后同理）。

## 为什么这两个都属于"静默"

- 不抛异常、不报错，只是**返回了看起来合理但错误的数据**；
- 单测容易漏：签名问题只在开启 token 时出现，脏读只在"同一 session 内二次写同一行"时出现；
- 都是我用真实 HTTP 链路打出来的，纯 CRUD 单测覆盖不到。

## 教训

1. **凡是拼 URL 的地方，都问一句"签了吗"**；正确做法是让调用方拿不到裸路径。
2. 裸 SQL + ORM 混用时，写后读必须显式过期；`expire_on_commit=False` 是性能选择，不是语义保证。
3. 关键接口要用**真实 HTTP 链路**验一次（写→读→再写→再读），不要只信单元测试。
4. 单测要覆盖「同一会话内对同一行连写两次」，这是最容易漏的路径。
