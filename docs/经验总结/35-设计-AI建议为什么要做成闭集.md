# 35 · 设计：AI 建议为什么要做成「闭集」

> 来源：用户反馈「AI 建议把分析出的标签摊出来，对人毫无意义」。根因不是模型不行，是建议没有对齐用户已维护的词表。

## 问题在哪

旧实现的 prompt 写着：

```
以下是用户已整理的人工信息，仅作参考，不要机械重复……
```

等于**明确叫模型别用你的词表**。于是建议里全是「人物」「室内」「白色」这类新造泛词——它们对「要不要给这张图加这个标签」没有任何决策价值。

## 闭集的三条通道

现在的建议只有三种来源，且**都只会落在用户已有数据上**：

| 区块 | 判定 | 闭集保证 |
|------|------|----------|
| 标签 | AI 标签 ∩ `tags` 词表，且这张图还没挂 | 只会是已有词 |
| 分类 | 同标签资源的分类投票 → 无票则 CLIP 近邻投票 | 只会是已有分类 |
| AI 新词 | AI 标签 ∉ 词表 | 单独一处；能映射到近义标签就只建议那个 |

标签侧的过滤是一句 SQL：

```sql
AND EXISTS (SELECT 1 FROM tags t WHERE t.name = ai.tag)
AND NOT EXISTS (   -- 已经打上的不重复建议
  SELECT 1 FROM resource_tags rt JOIN tags t ON t.id = rt.tag_id
  WHERE rt.resource_id = ai.resource_id AND t.name = ai.tag
)
```

原始 AI 标签仍然保留在 `ai_tags`（检索要用），**只是不再进入建议**——「降噪」发生在建议层，不是采集层。

## 分类建议的两级

```python
hints = await category_hints(...)          # ① 同标签资源投票
gaps  = [r for r in ids if r not in hints]
hints.update(await vector_category_hints(...))   # ② 只有没命中的才走向量，省一次全量加载
```

- ① 一条 GROUP BY；`MIN_VOTES=2`，单邻居不足以成议；置信度 = 该分类票数 / 总票数
- ② 取视觉最像的 8 张（相似度 ≥ 0.82），按相似度加权投票；置信度 = 加权占比

## 新词为什么单列而不是丢弃

完全屏蔽会让建议长期为空（词表小的时候）。所以给一个独立区块：

- 能匹配到近义标签 → 按钮显示 `≈ 兽耳`，**点的还是你的词**
- 匹配不到 → 显示 `+ 蒸汽波`，悬停说明「会新建该标签」

**扩词表永远是显式点击**，不会静默发生。

## 教训

1. 「AI 建议没用」通常不是模型问题，是**没有把模型的输出收敛到用户的决策范围**。
2. 闭集能同时解决三件事：噪音、可解释性、是否采纳的边界。
3. 采集与建议要分开：原始标签可以宽，建议必须窄。
4. 闭集会让建议变少甚至为空——这是预期，空态文案必须说清楚，否则会被当成 bug。
