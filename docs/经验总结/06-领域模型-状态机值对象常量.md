# 06 · 领域模型：状态机 + 值对象 + 常量（2026-10-19 现状）

> 本文用当前 `library` / `scrape` 领域模型说明：哪些规则应该放在 domain，哪些不应该。
> 早期的 `DownloadTask` 已随下载模块移除，不再作为当前示例。

## 1. 实体 vs 值对象

| 归类 | 当前项目中的类 | 依据 |
|------|----------------|------|
| 实体 | `Resource`、`ResourceFile`、`ResourceTodo`、`Tag`、`Category`、`Collection`、`SavedView`、`ScrapeJob`、`Candidate` | 有 id、生命周期、可变状态 |
| 值对象 | `Rating`（0–10）、`Dimension`（宽高比）；`Progress` 为下载模块遗留，当前业务未使用 | 不可变、按值语义、内聚计算 |
| 枚举/常量 | `ResourceType`、`StorageKind`、`ResourceStatus`、`ScrapeJobStatus`、`FILE_ROLE_*` | 防散落裸字符串 |
| 读模型 | `ResourcePage`、`Overview`、`CollectionCard`、`PhotoTimeline` | 组合查询结果，不是实体 |

判断标准：

- 需要 id、需要跟踪生命周期 → 实体；
- 只由值定义、替换即等价 → 值对象；
- 只是查询结果的形状 → schema/read model，不强行做成实体。

## 2. 状态机：非法迁移在 domain 拦截

`ResourceStatus`：

```text
active → trashed → active
active → lost
```

`Resource`：

```python
def to_trash(self) -> None:
    self.status = ResourceStatus.TRASHED
    self.deleted_at = datetime.now()

def restore(self) -> None:
    if not self.is_trashed:
        raise InvalidStateError(f"cannot restore resource in status {self.status}")
    self.status = ResourceStatus.ACTIVE
    self.deleted_at = None
    self._touch()

def mark_lost(self) -> None:
    if self.status != ResourceStatus.ACTIVE:
        raise InvalidStateError(f"cannot mark lost from status {self.status}")
    self.status = ResourceStatus.LOST
    self._touch()
```

`ScrapeJob`：

```text
queued → running → done
   │        │
   └────────┴──────→ failed
```

```python
def start(self) -> None:
    if self.status != ScrapeJobStatus.QUEUED:
        raise InvalidStateError(...)
    self.status = ScrapeJobStatus.RUNNING

def finish(self, match_count: int = 0) -> None:
    if self.status != ScrapeJobStatus.RUNNING:
        raise InvalidStateError(...)
    self.status = ScrapeJobStatus.DONE

def fail(self, error: str) -> None:
    if self.is_terminal:
        raise InvalidStateError(...)
    self.status = ScrapeJobStatus.FAILED
```

红线：

- domain 方法只放状态迁移、校验、计算属性；
- 不写 SQL、HTTP、文件 IO、Vue/React；
- application 负责“什么时候调用”，domain 负责“允不允许”。

## 3. 值对象

`app/shared/value_objects.py`：

```python
Rating = Annotated[float, Field(ge=0, le=10)]

@dataclass(frozen=True)
class Dimension:
    width: int
    height: int

    @property
    def aspect_ratio(self) -> float:
        return self.width / self.height

@dataclass(frozen=True)
class Progress:
    downloaded: int
    total: int | None
    speed: int = 0

    @property
    def percent(self) -> float | None:
        if self.total and self.total > 0:
            return min(100.0, self.downloaded / self.total * 100)
        return None
```

> `Progress` 是下载模块移除后留下的通用值对象示例，当前 library/scrape 没有业务使用；保留它是为了说明“值对象如何写”，不要误以为还有下载任务。

实体保留原始字段，值对象作为只读视图：

```python
@property
def dimension(self) -> Dimension | None:
    if self.width is not None and self.height is not None:
        return Dimension(self.width, self.height)
    return None
```

不是所有字段都值得抽值对象。路径、URL、标题通常保持普通字符串；只有“有校验/有行为/被多处复用”的值才抽。

## 4. 枚举与角色常量

`ResourceType`：

```python
class ResourceType(str, Enum):
    IMAGE = "image"
    VIDEO = "video"
    ANIME = "anime"
    AV = "av"
    AUDIO = "audio"
    NOVEL = "novel"
    GAME = "game"
    MODEL = "model"
    COMIC = "comic"
    WORK_DIRECTORY = "work_directory"
```

`StorageKind`：

```python
class StorageKind(str, Enum):
    OWNED = "owned"       # 导入库内，应用管理
    INDEXED = "indexed"   # 只登记源路径
```

文件角色：

```python
FILE_ROLE_PRIMARY = "primary"
FILE_ROLE_PAGE = "page"
FILE_ROLE_COVER = "cover"
FILE_ROLE_SUBTITLE = "subtitle"
FILE_ROLE_THUMBNAIL = "thumbnail"
FILE_ROLE_EPISODE = "episode"
FILE_ROLE_EXTRA = "extra"
FILE_ROLE_LAUNCH = "launch"
```

角色常量决定“谁是资源主文件”“哪些是辅助文件”，不要在各处硬编码字符串。

## 5. 分类树的不变量

`Category` 是当前最复杂的领域对象之一：

- 按 `type` 分树；
- `parent_id` 形成最多 4 层；
- 同一父节点下名称唯一；
- 不能移动到自己的后代；
- 有子节点或资源引用时不能删除；
- `is_system` 分类受保护。

这些规则在 `CategoryService` 中编排，仓储提供 `descendant_ids`、引用计数等查询。domain 不适合直接做“查数据库”的判断。

## 6. API 契约：snake_case ↔ camelCase

`app/shared/models.py`：

```python
class ApiModel(BaseModel):
    model_config = ConfigDict(
        alias_generator=to_camel,
        populate_by_name=True,
    )
```

约定：

- SQLite 列：`snake_case`
- Python 字段：`snake_case`
- API JSON：`camelCase`
- 前端 TypeScript：`camelCase`

示例：

```python
class Resource(ApiModel):
    cover_path: str | None = None
    created_at: datetime | None = None
```

输出：

```json
{
  "coverPath": "...",
  "createdAt": "..."
}
```

不要在前端手写两套字段名；类型应跟 API 契约一致。

## 7. 读模型不是实体

| 读模型 | 用途 |
|--------|------|
| `ResourcePage` | 列表 + total + hasMore + nextKey/nextId |
| `Overview` | 首页统计 + 最近资源 + 任务 + 消费 |
| `CollectionCard` | 全库混排中的合集卡 |
| `PhotoTimeline` | 按天分组 + 未知时间 + 密度统计 |
| `CategoryNode` | 分类树的节点 + 计数 |

它们可以有 Pydantic 校验，但不需要 `Resource` 那样的状态方法。不要把读模型硬塞进领域实体。

## 8. 平衡原则

- 只在有行为/校验/不变式时抽值对象。
- 读模型保持扁平，不要为了“纯”增加转换层。
- 前端 `domain/` 放 DTO 类型和联合类型；纯规则可放函数，不必造 class。
- 状态机规则只写一次，router/UI 只做入口。
