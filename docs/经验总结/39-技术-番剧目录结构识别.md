# 39 · 技术：番剧目录结构的识别（季 / 集 / 特典）

> 来源：`series_plan.py` 与 `SERIES_EXTRA_DIR_MARKERS`。用「番剧」类型导入整个目录时，正片进季集树，特典进 `extras`。

## 数据形状

```
resources (anime, 1 条)
├── seasons (season_number)
│     └── episodes (episode_number, file_id, title)
└── extras (file_id, title, sort_index)     ← 特典 / PV / NCOP 等
```

**一个作品 = 1 条 Resource + N 个 file**，集不是独立资源。这条决定了播放进度必须按 `file_id` 记（见 35/34 相关篇目），也决定了特典的挂载方式。

## 特典识别（两处命中任意一条）

**目录名**（`&` 和 `,` 会先切开再查表）：

```
特典 / 映像特典 / 特典映像 / tokuten / extra(s) / special(s)
menu(s) / pv / ncop / nced / cm / credit
```

**文件名 token**：

```
NCED NCOP OVA OAD SPECIAL EXTRA 特典 SP MENU PV CM NC+数字
```

`NCOP&NCED` 这种写法靠 `&` 切分后分别命中。

## 归位与落盘

- 正片 → `seasons/<NN>/`，集号解析失败时自动编号（导入说明里会写「自动编号 N 个」）
- 特典 → `extras/<文件名>`，`title` 取文件 stem
- 导入结束的任务消息会给出「已识别 N 季 · N 集 · N 特典」，**这是判断识别对不对的第一现场**

## 一个容易踩的认知差

同一套目录，用**不同资源类型**导入，结果完全不同：

| 导入类型 | 结果 |
|---|---|
| 番剧 | 整个目录 = 1 部作品，特典归 `extras` |
| 视频 | 每个文件 = 1 条独立资源，特典变成「散装视频」 |

用户库里出现过「特典成了独立 video 资源」，`importSourcePath` 明明在番剧目录里——原因是当时选的类型是「视频」。**类型选择决定了归档语义**，不是文件名决定的。

## 已知边界

1. 特典**没有封面、没有字幕**（`extras` 表只有 `file_id/title/sort/status`），和「每集封面/字幕」是同一个缺口。
2. 特典排序按文件名小写字典序，`Tokuten 10` 会排在 `Tokuten 2` 前面。
3. **没有事后归并**：已经作为独立 `video` 资源入库的 PV，不能一键挂成某作品的特典，只能删掉重导。

## 教训

1. 目录结构识别要"两处都认"：只看目录名会漏掉平铺的 `xxx NCED.mkv`，只看文件名会漏掉整个 `特典/` 目录。
2. 归档语义由**导入类型**决定，UI 上要让用户意识到这一点（导入向导的类型选择比后续整理更重要）。
3. 识别结果必须回显（「N 季 · N 集 · N 特典」），否则用户无法判断是识别失败还是本来就没有。
