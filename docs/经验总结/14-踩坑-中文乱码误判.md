# 14 · 踩坑：中文乱码误判（别信终端显示）

## 现象

API 返回/数据库里的中文显示成 `????` 或 `������`，第一反应"数据损坏了"。

## 真相

**Windows PowerShell 控制台默认 GBK/代码页，UTF-8 中文直接打印必然乱码——但数据本身可能是对的。**

本次实测：
- 存 `"测试视频_東京"`，终端打印显示 `????`
- 用 `ensure_ascii` 转义 + **等值断言**验证，结果 `True`：

```python
print(api_title == EXPECTED)          # True
print(json.dumps(api_title, ensure_ascii=True))  # "\u6d4b\u8bd5\u89c6\u9891..."
```

`\u6d4b\u8bd5\u89c6\u9891` = 测试视频，数据完好无损。

## 排障铁律

1. **不要用终端目视判断中文对错**——控制台编码不可信
2. 用**程序化断言**（`== 期望值`）或 `ensure_ascii` 转义输出验证
3. 若是真的乱码（写入时就错了），多半是请求体编码问题（如 PowerShell `Invoke-RestMethod -Body` 默认非 UTF-8 发送），用 Python/HTTP 工具发 UTF-8 验证

## 补充

- 写文件时确保 UTF-8（`write`/`encoding='utf-8'`）。
- PowerShell 里内联 `python -c "中文"` 也常因转义和编码双双出错，**优先写临时脚本文件执行**。
