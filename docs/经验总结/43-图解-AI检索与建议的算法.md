# 43 · 图解：AI 检索与建议里的算法

> 这一篇讲"为什么这个分数是 0.87"、"为什么要 top-k"、"为什么门槛是 0.82"。公式不多，但都对应代码。

## 1 向量与余弦：相似度到底是啥

一张图被 CLIP 编码成向量 **v**（512 维）。两张图是否相似，看两个向量的**夹角**：

$$
\cos(\theta) = \frac{a \cdot b}{\lVert a \rVert \, \lVert b \rVert}
$$

因为写入时已归一化（长度 = 1），分母恒为 1，于是：

$$
\text{similarity} = a \cdot b
$$

```mermaid
flowchart LR
  A["图 A → 512 维"] --> N1["归一化 |a|=1"]
  B["图 B → 512 维"] --> N2["归一化 |b|=1"]
  N1 --> D["点积 a·b"]
  N2 --> D
  D --> S["相似度 ∈ [-1, 1]<br/>1=同向 · 0=无关"]
```

**代码上就是一行矩阵乘**：

```python
scores = matrix @ query_vector      # 一次算完 N 张图
```

代价是 `N × 512` 次乘加。500 张图 ≈ 25 万次，毫秒级；几万张就要考虑索引或预计算。

## 2 top-k 与"为什么不用全排序"

```mermaid
flowchart TD
  S["全部相似度数组"] --> P["np.argsort(-scores)"]
  P --> T["取前 k 个"]
  T --> F{"低于门槛?"}
  F -->|是| DROP["丢弃"]
  F -->|否| KEEP["进入结果"]
```

`argsort` 是 O(N log N)。本仓规模下无所谓；真要快可以用 `argpartition` 取 top-k（O(N)）。**门槛过滤必须在排序之后**，否则"先过滤再排序"会丢掉本该靠前的结果。

## 3 四个检索模式为什么不能共用一个排序

| 模式 | 打分来源 | 回答的问题 |
|---|---|---|
| 文搜图 | 文本向量 · 图向量 | "哪些图符合这句话" |
| 图搜图 | 图向量 · 图向量 | "哪些图像这张" |
| 图文融合 | 两路分数合成 | "像这张 **且** 符合这句" |
| 文案/标签 | 关键词命中 | "描述里有这个词" |

分数语义不同 → **不可直接相加**。融合用的是 **RRF（Reciprocal Rank Fusion）**：

$$
\text{score}(d) = \sum_{i} \frac{1}{k + \text{rank}_i(d)}, \quad k \approx 60
$$

它只看"排第几"，不看绝对分，所以能把两套不同量纲的排序合起来。**严格模式**则取交集（必须同时命中）。

```mermaid
flowchart LR
  Q["一张图 + 一句话"] --> S1["图路：CLIP 相似度排序"]
  Q --> S2["文路：CLIP 文本相似度排序"]
  S1 --> R["RRF 合并"]
  S2 --> R
  R --> O["统一排序结果"]
  Q -.->|严格模式| I["交集"]
  I --> O
```

## 4 近似重复：为什么不用向量

向量相似度对"同一张图被重压缩"不敏感——它可能只给 0.93，和"很像的两张不同图"拉不开。

所以重复检测用**感知哈希（dHash）**：缩到 9×8 灰度、逐像素比相邻、得到 64 位指纹，比**汉明距离**。

```mermaid
flowchart LR
  IMG["图片"] --> G["灰度 + 缩放"]
  G --> D["相邻像素差分"]
  D --> H["64 位指纹"]
  H --> C{"汉明距离 ≤ 阈值?"}
  C -->|是| DUP["近似重复"]
  C -->|否| NOT["不同图"]
```

好处：对缩放、轻微压缩、亮度变化稳；坏处：对裁剪、旋转不稳。所以它和向量检索是**两套互补信号**，不是替代关系。

## 5 分类建议的加权投票

前提：先找到"同标签的资源"，或"视觉最像的邻居"。

```mermaid
flowchart TD
  T["目标图"] --> L{"有共同标签的邻居?"}
  L -->|有| V1["按标签共现投票<br/>每邻居 1 票"]
  L -->|没有| V2["CLIP 近邻投票<br/>每邻居 w=相似度"]
  V1 --> AGG["按分类聚合"]
  V2 --> AGG
  AGG --> MIN{"票数 ≥ 2?"}
  MIN -->|否| DROP["不产生建议"]
  MIN -->|是| CONF["置信度 = 该分类票数 / 总票数"]
  CONF --> TOP["取前 2 个"]
```

三个数字的来历：

| 参数 | 值 | 理由 |
|---|---|---|
| `MIN_VOTES` | 2 | 1 个邻居不足以成议，避免单张图带偏 |
| 邻居数 | 8 | 太多引入噪声，太少覆盖不足 |
| 相似度门槛 | 0.82 | 低于此"不算像"；越高越保守，冷启动越难触发 |

**置信度是"占比"不是"概率"**：它回答"这批邻居里有多一致"，不是"我有多确定对"。

## 6 标签同义映射：为什么门槛更高

同一套 CLIP 文本编码器，把标签名编码成向量，算最近邻：

```mermaid
flowchart LR
  NEW["AI 新词：猫耳"] --> E["CLIP 文本编码"]
  V["词表：兽耳/风景/夜景..."] --> EV["逐个编码（进程级缓存）"]
  E --> C["余弦对比"]
  EV --> C
  C --> M{"最大相似度 ≥ 0.86?"}
  M -->|是| MAP["建议写成「兽耳」"]
  M -->|否| RAW["只展示原词，点击才新建"]
```

**词-词门槛（0.86）比图-图（0.82）高**：短词向量容易"看起来都挺像"，放宽会乱配。

## 7 名称清洗的置信度

$$
\text{confidence} = \min\left(0.95,\; 0.55 + 0.1 \times n_{\text{removed}}\right)
$$

```mermaid
flowchart LR
  N0["剥 0 段<br/>0.00 → 不出建议"] --> N1["剥 1 段<br/>0.65"]
  N1 --> N3["剥 3 段<br/>0.85 → 默认勾选"]
  N3 --> N9["剥 9+ 段<br/>0.95 封顶"]
```

为什么用"剥掉几段"而不是模型打分：**可数、可解释、可复现**。用户问"为什么 0.85"，答案就是"去掉了 3 段：（分辨率）（编码）（音轨）"。

## 8 一次文搜图的完整计算

```mermaid
sequenceDiagram
  autonumber
  participant Q as 查询"海边 两个人"
  participant QP as query.parse
  participant M as CLIP 文本编码
  participant DB as ai_vectors
  participant R as 排序 + 过滤

  Q->>QP: 文本
  QP->>QP: 槽位抽取（人数/颜色/场景）
  QP->>M: 纯语义部分
  M-->>R: 512 维查询向量
  DB-->>R: N × 512 矩阵
  R->>R: scores = matrix @ q
  R->>R: top-k + 相似度门槛
  R->>R: 硬条件过滤（person_count=2）
  R-->>Q: 结果 + 解释（"人数=2"）
```

**槽位先抽、再向量化**的原因：让"两个人"这类条件走**精确过滤**，而不是指望向量理解数量——向量对数字不敏感。
