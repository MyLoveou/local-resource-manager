# 50 · 图解：搜索与筛选的组合逻辑

> 这个应用有**两套搜索**：列表筛选（确定性）和 AI 语义检索（概率性）。混用会得到无法解释的结果。

## 1 两套搜索的边界

```mermaid
flowchart TD
  Q["用户输入"] --> T{"输入形态"}
  T -->|"类型/标签/分类/关键词"| L["列表筛选<br/>SQL 精确匹配"]
  T -->|"一句话描述画面"| S["AI 文搜图<br/>向量相似度"]
  T -->|"一张图"| I["AI 图搜图"]
  T -->|"图 + 一句话"| F["图文融合"]
  L --> R1["可解释：命中了哪些条件"]
  S --> R2["可解释：相似度 + 槽位条件"]
  I --> R2
  F --> R2
```

**判断依据**：用户要的是"必须是"（筛选）还是"像这样的"（语义检索）。

## 2 列表筛选：维度之间 AND，维度之内 OR

```mermaid
flowchart LR
  subgraph DIM["筛选维度"]
    TY["类型 ∈ {视频, 番剧}"]
    TG["标签 ⊇ {漫展}"]
    CT["分类 ∈ {街拍, 夜景}"]
    KW["标题/简介 LIKE %海%"]
    ST["status = active"]
  end
  TY --> AND["AND 组合"]
  TG --> AND
  CT --> AND
  KW --> AND
  ST --> AND
  AND --> SQL["一条 SQL<br/>WHERE 各条件"]
  SQL --> PAGE["keyset 分页"]
```

| 层级 | 关系 | 例子 |
|---|---|---|
| 维度之间 | **AND** | 类型=视频 **且** 有「漫展」标签 |
| 同一维度内 | **OR**（集合成员） | 分类 ∈ {街拍, 夜景} |
| 标签多选默认 | **AND**（全部包含） | 同时有「漫展」和「夜景」 |

**为什么标签默认 AND**：多选标签时用户通常在做"缩小范围"，交集更符合直觉。若要做并集，需要显式提供"任一"选项。

## 3 分页为什么用游标而不是 offset

```mermaid
sequenceDiagram
  autonumber
  participant U as 用户
  participant API as 后端
  participant DB as SQLite

  U->>API: 第一页 limit=60
  API->>DB: ORDER BY updated_at DESC, id DESC LIMIT 60
  DB-->>API: 60 行
  API-->>U: rows + nextCursor(最后一行的时间与 id)
  U->>API: 第二页 cursor=...
  API->>DB: WHERE (updated_at, id) < cursor LIMIT 60
  DB-->>API: 后续 60 行
```

对比：

| | offset 分页 | keyset 分页 |
|---|---|---|
| 深翻页性能 | 越翻越慢（要跳过 N 行） | 恒定（走索引定位） |
| 并发插入 | 会重复或漏行 | 稳定 |
| 代价 | 简单 | 需要稳定的排序键（时间+id 复合） |

排序键必须是**唯一且稳定**的组合（`updated_at, id`），否则游标会跳过数据。

## 4 AI 语义检索的组合

```mermaid
flowchart TD
  A["查询文本"] --> B["抽槽位<br/>人数/颜色/场景/时间"]
  A --> C["剩余语义部分"]
  C --> D["CLIP 文本编码"]
  D --> E["向量相似度打分"]
  B --> F["硬条件"]
  E --> G["top-k + 门槛"]
  F --> G
  G --> H["最终结果 + 解释"]
```

**槽位为什么要单独抽**：向量对数量、颜色这类**离散属性**不敏感（"两个人"和"三个人"的向量非常接近）。所以走精确过滤，而不是指望模型。

## 5 两套结果为什么不能混排

```mermaid
flowchart LR
  L["筛选命中（布尔）"] --> M{"混排?"}
  S["语义分数（0–1）"] --> M
  M -->|"直接相加"| BAD["无法解释：<br/>为什么一个必然命中的结果排在后面"]
  M -->|"分开展示"| GOOD["列表视图 / AI 检索视图各自独立"]
```

结论：**筛选与检索分开展示**。硬条件筛选用列表，语义查找用 AI 检索；需要同时满足时，用融合检索（图+文）而不是把筛选分数和余弦分数相加。

## 6 常被问到的三个问题

| 问题 | 答案 |
|---|---|
| 为什么标签筛选没结果，但我确实有这个标签？ | 标签默认 AND；两个标签的交集可能为空 |
| 为什么 AI 搜「三个人」搜不到？ | 数量走槽位过滤，需要索引里有 `person_count` |
| 为什么刚导入的图搜不到？ | 索引还没跑（30 秒一轮），最终一致 |
| 为什么翻页时内容跳动？ | 用 offset 或排序键不唯一 |
