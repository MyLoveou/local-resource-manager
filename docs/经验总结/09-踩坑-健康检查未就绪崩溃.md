# 09 · 踩坑：健康检查未就绪即崩溃

## 现象

spawn uvicorn 后立刻 `http.get` 健康检查，服务还没起来 → `ECONNREFUSED` → 未捕获异常/直接崩；或随机成功（偶发 200 才通过）。

## 错误版代码

```ts
function waitForHealth(url, timeoutMs): Promise<void> {
  return new Promise((resolve, reject) => {
    const timer = setTimeout(() => reject(new Error('超时')), timeoutMs)
    const req = http.get(url, (res) => {   // ❌ 无 error 监听
      clearTimeout(timer)
      resolve()                            // ❌ 不校验 statusCode
    })
  })
}
```

三个问题：
1. **无 `req.on('error')`**：连接被拒触发 `error` 事件，没人接 → 崩溃/未处理异常
2. **不校验 statusCode**：任何响应（404/500）都算成功
3. **无重试**：进程启动需要几百 ms，只请求一次几乎必失败

## 修复版

```ts
function waitForHealth(url, timeoutMs, intervalMs): Promise<void> {
  return new Promise((resolve, reject) => {
    const deadline = Date.now() + timeoutMs
    const retry = (timer) => Date.now() > deadline
      ? reject(new Error('后端健康检查超时'))
      : setTimeout(attempt, intervalMs)
    const attempt = () => {
      const req = http.get(url, (res) => {
        res.resume()
        res.statusCode === 200 ? resolve() : retry(timer)   // 成功 = 200
      })
      req.on('error', () => retry(timer))                    // 未就绪 → 重试
      req.setTimeout(intervalMs, () => { req.destroy(); retry(timer) })
    }
    const timer = setTimeout(() => reject(new Error('超时')), timeoutMs)
    attempt()
  })
}
```

## 教训

- **任何网络操作必须三件套**：`error` 监听 + 超时 + 明确成功条件（200）。
- 子进程启动是异步的，健康检查必须轮询重试，别期望"立刻就好"。
- spawn 的 python 路径不存在不会抛同步异常，而是子进程 `error` 事件——同样要监听（`child.once('error', reject)`）。
