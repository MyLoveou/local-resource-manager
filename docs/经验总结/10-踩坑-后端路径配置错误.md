# 10 · 踩坑：后端路径配置错误

## 现象

后端起不来，或起来了但 `spawn` 报找不到 python / cwd 错误。

## 错误版 config

```ts
function defaultPythonPath(root: string): string {
  return join(root, 'app/backend/.env/Scripts/python.exe')   // ❌ 三处错
}
function resolveProjectRoot(): string {
  return process.env.PROJECT_ROOT ?? resolve(__dirname, '../..')  // ❌ 算错根
}
```

## 根因（三处）

| 错误 | 正确 | 影响 |
|------|------|------|
| `.env` | `.venv` | python 路径指向不存在的目录 |
| `app/backend` | `apps/backend` | 目录名少个 s |
| `resolve(__dirname, '../..')` | `resolve(app.getAppPath(), '../..')` | `__dirname` 编译后=`out/main`，只上两级=`apps/desktop`，不是仓库根 |

加上 env 变量前缀混乱（`PYTHON_PATH`/`MODULE`/`HOST` 无 `BACKEND_`，与 `BACKEND_DIR` 混用）。

## 修复

```ts
function resolveProjectRoot(): string {
  return process.env.PROJECT_ROOT ?? resolve(app.getAppPath(), '../..')  // dev: apps/desktop → 仓库根
}
function defaultPythonPath(root: string): string {
  return process.platform === 'win32'
    ? join(root, 'apps/backend/.venv/Scripts/python.exe')   // 平台感知
    : join(root, 'apps/backend/.venv/bin/python')
}
// env 前缀统一 BACKEND_：BACKEND_PYTHON_PATH / BACKEND_DIR / BACKEND_MODULE / BACKEND_HOST ...
```

## 教训

1. **`__dirname` 是编译产物路径**，不是源码路径——推断项目根必须用 `app.getAppPath()`（dev 下指向带 package.json 的目录）。
2. 目录名/文件名照抄时易漏 `s`（`apps`）或混淆（`.venv`/`.env`），建完即验证一次 `Test-Path`。
3. **环境变量前缀统一**：所有 `BACKEND_*`，避免不同前缀混用难排查。
4. 平台差异（`Scripts/` vs `bin/`）必须 `process.platform` 分支。
