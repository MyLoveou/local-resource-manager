# 18 · 最佳实践清单

> 这份清单只收本项目反复验证过的做法，不写通用口号。
> 新功能开工前、提交前、发布前各过一遍。

## 1. 需求与设计

- [ ] 新能力先写 `docs/requirements/features/<id>/需求.md`，明确 IN/OUT 与验收。
- [ ] 涉及新实体/表/状态机/跨模块/多页面组合 → 先写 `设计.md`，不要直接写页面。
- [ ] 设计确认后再写 `实现方案.md`，列文件路径、数据流、组合根。
- [ ] 拍板写入 `docs/product/decisions.md`，实现变化同步 `facts.md`。
- [ ] 复杂需求不要用“文件清单”代替能力设计。

## 2. 前端

- [ ] 页面只做组合：读路由、调 store/hook、组合组件。
- [ ] 列表分页统一走 `useResourcePage`，不要在组件里手写 `limit/offset`。
- [ ] 浏览筛选状态优先放 `browseQuery`，需要分享时同步 URL query。
- [ ] 跨页面刷新用 `library.invalidate({ resources/categories/... })`，不要用组件引用互相调用。
- [ ] 组件必须显式 import；构建通过不代表运行时能解析。
- [ ] Boolean prop 缺省不要依赖 `undefined`；需要三态时显式处理。
- [ ] 更新说明不要 `v-html`；远程文本按纯文本处理。
- [ ] 外链走 `window.electron.openExternal`，只允许 HTTPS。
- [ ] 新样式优先用 design token，不硬编码颜色/圆角。

## 3. 后端

- [ ] router 保持薄：参数、依赖、调用 service。
- [ ] 业务规则放 application/domain，不写进 router。
- [ ] API 输出走统一信封 `{code,status,message,data}`。
- [ ] 字段命名：DB/Python `snake_case`，JSON `camelCase`。
- [ ] 新表/字段写新迁移，不改历史迁移文件。
- [ ] 迁移后同步 ORM、domain、repository、schema、测试。
- [ ] SQLite 外键、WAL、busy_timeout 不能漏。
- [ ] 列表查询注意 N+1；批量附分类/标签/缩略图。
- [ ] 删除/恢复等操作在 domain 校验状态，不靠 UI 约束。
- [ ] 错误返回 4xx 带可读 message，不把内部异常直接暴露。

## 4. 测试

- [ ] 业务用例优先测 service，不启动整个 app。
- [ ] 测试用临时目录 + 临时 DB + `migrate`，不碰开发库。
- [ ] 每个测试 dispose engine，避免连接泄漏。
- [ ] 不依赖测试执行顺序；测试之间不共享全局 engine。
- [ ] 改 bug 先写能失败的测试，再修。
- [ ] 发布前跑：`typecheck` → `lint` → `pytest` → `build`。
- [ ] 发布后做一次冻结后端 `/health` 冒烟。

## 5. Electron / 进程

- [ ] 先起后端，再创建窗口。
- [ ] 端口让系统分配；不要固定 8000。
- [ ] 后端 token 随机生成，不进日志/URL。
- [ ] spawn 监听 `error`，health 检查校验 200、带超时/重试。
- [ ] 退出时等待子进程 `exit`，避免孤儿进程。
- [ ] 渲染层不直接 require Node 模块；走 preload 白名单。
- [ ] 自定义 IPC 要校验参数和协议，尤其是打开外链/执行命令。

## 6. 发布

- [ ] `apps/desktop/package.json` 版本 = tag = `latest.yml` 版本。
- [ ] `pnpm release:win` 全绿，`verify-release` PASS。
- [ ] Release 资产齐全：setup、blockmap、zip、latest.yml、SHA256SUMS。
- [ ] 仓库 public，`app-update.yml` 的 provider 是 github。
- [ ] 重发前确认旧 Release 是否已存在；不要覆盖已有人下载的 tag。
- [ ] 更新说明按纯文本展示，不使用 `v-html`。
- [ ] 当前未签名，接受 SmartScreen；正式分发前补签名。

## 7. 文档

- [ ] 新功能更新 `facts.md` 的“实现现状”。
- [ ] 方向/取舍写入 `decisions.md`。
- [ ] 复杂实现补 `handoff.md`，写清下一步。
- [ ] 经验文档写“为什么/坑/验证”，不是操作流水账。
- [ ] 文档里的路径、命令、版本要能直接执行。
- [ ] 新增文档加入 `docs/经验总结/README.md` 索引。

## 8. 安全

- [ ] 不在仓库/日志/截图里放 token、密钥、证书。
- [ ] API 默认绑定 `127.0.0.1`，不暴露局域网。
- [ ] 文件操作校验路径存在性与类型。
- [ ] 外部链接只允许 `https://`。
- [ ] 更新包只从可信源下载，并校验哈希。
- [ ] 不把可执行文件交给不可信镜像代理。

## 9. 提交前 30 秒

```text
git status
git diff --check
pnpm --filter desktop typecheck
apps/backend/.venv/Scripts/python -m pytest -q apps/backend/tests
```

确认：

- 没有误提交 `release/`、日志、临时 DB、token；
- 文档和实现一致；
- 新增文件已加入索引；
- 没有把“本地能跑”当成“CI 能跑”。
